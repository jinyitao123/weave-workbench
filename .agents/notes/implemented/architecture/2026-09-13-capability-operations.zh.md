# Agent Note: Workbench 能力运行

Status: implemented

[English](2026-09-13-capability-operations.md) | 中文

## Problem

Workbench 需要展示可复用能力运行和额度，同时不能要求用户编辑定义、引擎配置或运行记录。执行控制需要保留持久检查点、工作空间身份和已发布流程规则，确定性工作也不能被强制加入研究步骤。

## Decision

Workbench 通过对话创建可复用能力。能力运行设置只展示持久运行和工作空间额度，不暴露能力定义或引擎配置。

已发布能力的每次调用记录认证用户、步骤检查点、状态变化和已消费步骤额度。人工复核会暂停调用，并从已保存检查点恢复。工作租约过期后从该检查点重新排队，不重复已经完成的模型和工具步骤。

能力可以使用本地 Loom 推理或符合条件的远程 CLI 运行时。已发布的运行要求选择执行路径，已发布定义继续负责角色、步骤、输入输出验证、分支、有界循环和最终业务结果。

团队与能力创建指令在生成方案时选择执行方式。已知流程直接执行；只有阻止选择方法的具体未知才进行有证据、有备选路径、有尝试上限和停止条件的探索。混合任务只探索不确定部分。外部访问、权限和副作用风险本身不触发研究；输入错误、缺少权限和暂时故障仍按各自规则处理。明确约束和冻结的已发布流程始终优先。

该选择属于模型指导，不是运行时强制分类器。结构化团队定义仍编译为负责人、并行成员和汇总者。指令和角色名称不能添加顺序依赖、自动返工循环或人工等待；这些行为需要受支持的自定义流程图。自动复核者不等同于人工确认。运行完成也不能证明交付验收或回退路径实际成功。

## Alternatives considered

JSON 能力编辑器会暴露执行内部细节，并把 schema 维护交给用户。强制研究会拖慢确定性工作。Workbench 自建调度器会重复平台任务租约、重试和终态责任。

## Consequences

用户在对话中审查业务意图，并通过产品页面查看运行和额度。Weave 继续负责执行、检查点、额度和终态。仍需通过真实浏览器验收所选运行时、人工复核、恢复过程和最终业务成果。
