# 测试发行入口

手动工作流 `test-release.yml` 在GitHub构建环境直接取回官方QA归档，核对准确源码、三平台必要门禁、归档摘要、服务端实际启动证明与私有包可见性，再生成安装组合并发布未签名RC预发布。完整交付规则见[开发与发布方式](../../docs/architecture/开发与发布方式.md)。

输入为准确总仓提交、RC版本、成功桌面QA运行、完整服务端私有发布运行和已审发行说明。桌面QA与总仓提交不同时，要求整个desktop树及全部桌面工作流逐字一致。服务端仅允许完整证明；若工作流只在可选宿主缓存传送失败，保留其失败状态，不能写成整轮成功。

附件通过名称、大小及GitHub回显SHA256独立核对后才公开draft。已有发行拒绝覆盖，已有标签须准确指向产品提交；不设Latest，不生成更新feed，不部署，不改变镜像可见性。服务端包包含固定镜像锁、原始构建证明和图文安装指南，镜像读取授权仍由部署方提供。

需要同仓工作流令牌的contents写、actions读与packages读权限；令牌只用于官方API，不转发至官方归档的短期存储链接。运行结果保留公开组合清单、校验表和附件读回。

当只调整桌面或发行元数据时，可显式提供准确server_revision复用原服务器发布；版本锁以及Forge／Weave完整Git树必须与发行提交一致。组合清单分别记录镜像与安装器来源，任一树或锁不同均拒绝，不以版本名称替代源码一致性。
