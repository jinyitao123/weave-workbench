# 任务授权与工作消息接入

共享字段和调用顺序以[产品总仓契约](https://github.com/jinyitao123/weave-workbench/blob/main/contracts/v1/README.md)为准。本文说明Forge实现边界与组件验证，不维护另一份项目/部署状态。

## 原生身份与任务权限

`TaskDelegationPlugin`用原生员工会话取得主体、组织和父会话；`forge_task_delegation`只保存固定任务的范围摘要、幂等键、代际、父会话引用和时间，不保存员工Bearer或另一套登录身份。对象关闭通用API、搜索、动态和克隆，授权只能通过受控接口取得。

ObjectStack的server-only `signJWT`签发令牌。原生通用`verifyJWT`固定默认audience，无法验证本连接的独立audience，因此使用与原生MCP verifier相同的JOSE库和原生`getJwks`公钥，严格核验稳定部署身份`FORGE_IDENTITY_ISSUER`、专用audience、有效期和签名；没有自建密钥。JOSE沿用锁中既有6.2.12，仅显式声明直接依赖。员工令牌不能用于任务执行接口，任务令牌不能成为员工会话或访问通用CRUD、原生MCP及再次发行。

每次任务请求核对原生员工及当前权限、当前组织成员资格、最新授权代际和不可变范围。任务独立于桌面会话，有效期默认24小时且不可超过24小时（部署可用`FORGE_TASK_DELEGATION_MAX_HOURS`收窄）；桌面会话过期或退出不撤销已交接工作。MCP连接复用SDK原生桥、参数定义、RLS/FLS和业务动作执行，只收窄动作、记录与文件；原生审计区分agent on behalf of human，trace关联任务授权。已允许动作声明的`objectOverride`字段仅在内部用原生元数据校验；不把目标对象扩展为团队可列举、描述、查询或读取的对象。原件读取复用原员工/审批快照读取函数及原生Storage。未知发送结果不声称无副作用，只有进入原生MCP之前的授权拒绝才能携带该证明。

组织资格由原生`resolveUserAuthzGrants`实时读取，并绕过授权缓存。绑定组织必须存在于`accessible_org_ids`；父会话仍有效、平台管理员权限或没有文件/动作的空范围均不能替代组织资格。员工签发与收件箱读取共用此检查，任务current、原件与MCP在调用前分别核验。

### 原输入的永久撤销围栏

同一`grant_key`的任一历史代际记录出现`employee_cancel`、`subject_inactive`或`run_terminal`后，原输入永久关闭。发行前、同发行键重放和插入后均查询此历史证明，拒绝返回409；`current`也查询历史，不能因新代尚未标记撤销而放行。旧发行键在关闭后返回409，不返回可被误解为仍有效的原凭据。只有原输入尚未关闭的授权过期可以沿原范围续期，实际运行终态没有例外。

撤销使用ObjectQL公开的条件批量更新，关闭同一`grant_key`所有尚未撤销的代际，每行已有的首次原因保持不变。插入晚于撤销更新时，发行后置检查沿历史原因补关新代；即使此补关中断，`current`仍以历史证明拒绝。旧任务令牌仅可对自身已永久关闭的原输入重复清理，不能撤销仍有效的新代或其他原输入。

原生账号停用hook以已发生的`banned=true`事件为依据，不因紧随其后的启用把当前账号读回为false而漏关旧授权。现有授权对象的`issuance_pending`记录发行确认，旧记录默认为已确认，新插入显式为待确认。签名前在事务提交之后复验当前调用者的原生会话，以同记录`pending=true AND revoked_at IS NULL`条件确认，并读回确认状态及历史永久围栏；`current`拒绝待确认记录。会话失败只以相同条件关闭未确认候选为`issuance_aborted`，不能关闭并发请求已经确认交接的记录。已交接授权的`current`继续与父会话是否存活无关。

原生事务内首次复验前发生停用可回滚记录和发行键，新登录可重试原键；复验后、提交前发生停用则由提交后复验拒绝，已提交的中止候选和失败发行键保留。中止候选只关闭该代际，旧键重放409；重新登录可用新键沿原范围重新授权。代际分配取全部记录的最大值，`expected_generation`与当前已确认代际比较；最高候选尚未完成时拒绝另一新键竞争。`current`与任务自撤销使用已确认权威代际，待确认或中止的新代不会替换或关闭已交接旧代；员工取消也可处理首次待确认记录，并始终关闭同键全部开放记录。未出现授权记录前不创建另一套账号生命周期或撤销库；此处不声称账号更新与所有授权更新具有整体跨对象事务原子性。

## 原生消息分页

17.3的`listInbox`硬限制200行，未提供offset/cursor；因此`WorkbenchInboxPlugin`提供本人收件箱的只读keyset连接，查询原生`sys_inbox_message`并关联`sys_notification_receipt`。没有新增消息、通知或待办表。游标由原生auth签名，绑定员工、原生组织、第一页上界和最后一行的created_at/id；完整保留毫秒与同时间戳的id次序。原生回执状态仍决定已读，失败不能伪称读取完整。

## 已批准订单接项目的本人边界

本批源码复用 `customer_create_project`、`project_link_contract`、`project_start` 三个正式动作。它们为 `employee_only`，在团队授权签发、团队目录、对象动作元数据及实际任务调用四处拒绝委托；`project_read_delivery_scope` 保持只读。销售客户／合同负责人沿原 `forge_project_operator` 资格立项，明确选择合法类型、计划日期、实际经理及 `approved_order_id`，再以原 `forge_project_operator + sales_contract_operator` 资格关联准确合同／订单。经理仅以原 `forge_project_manager` 资格启动自己当前负责的待执行项目，且需有效原生岗位、组织任职和经理成员关系。没有新增组织、审批、待办队列或团队替人办理入口。

订单批准以原生请求的准确 `approved` 结论、提交内容摘要和原始行一致为依据；现有正式应用处理将该订单置为 `active / approval_outcome=approved`，不能只按字面 `status=approved` 筛选。多个合法订单须明确选择；立项冻结来源后不能把同合同全部订单自动加入项目。预算／预计营收未明确、成本未知的新项目保存 `null`，明确输入零仍保存零；只去除这三个项目字段的默认零，保留原有真实零值、类型、精度和财务算法。

当前事项事实以总仓 `canonicalJobScope` 所冻结的员工、组织、业务记录及来源为入口；Forge不信任模型的事实摘要。本人接口用服务端持久 context、当前声明、完整 recordVersion、新消息意图及持久 op 重新核验。recordVersion覆盖项目、实际关联、成员和原合同／订单／报价行；版本、操作键、摘要与确认均不属于模型业务参数。立项回执只带准确 `forge_project` 引用，不说明已启动或已交付。`project_start` 是第八种业务事项，由持久业务事实派生，游标绑定员工／组织／来源版本；无权读取的来源仍报告partial或拒绝，不能当作事项零。

原生对象读与记录范围分别核验。销售既有合法父订单读取不会自动补足child admission：本批只为销售合同办理补订单行的own read，并用已有 `IRlsMembershipResolver`、本人owned合同的同客户准确订单及 `ISharingService.buildReadFilter` 收窄新增child原生RLS。经理新增来源对象仅own read，由链接事务的原生只读Sharing取得确切来源。`forge-project-delivery` provenance绑定准确关联、订单版本及有效成员／经理；成员、经理与关联删除hook撤本来源，其他manual／review／team来源不覆盖、不误撤。不同team provenance冲突使关联整体回滚。项目本体及计划原RLS保留；两个结构子表link／member的SELECT按下述原生精确父项目边界修补，更新／删除岗位策略保留。

原生 `project_read_delivery_scope` 与启动在同一共享helper中使用现有body-runner的唯一读取算法。公开结果只有业务名称、完整设备／服务范围及FLS允许值；内部关联与源摘要只留在helper返回和锁内比较，不能进入普通页面、模型参数或工具公共输出。启动仍重新核来源对象admission/RLS、完整原行、服务端冻结摘要、经理身份和条件CAS，不凭公共工具摘要授予写权限。

### FLS复审与当前安全投影

独立复审在源码 `52fe45cf`／文档 `6d8e78a7` 后发现上述绿色门禁尚不足以证明FLS安全：项目helper将 `getReadableFields` 的null／undefined当作全部可读，公共header仍来自system body且只裁部分line字段。已安装ObjectStack17.5 `ISecurityService`接口明确undefined表示“无法回答，使用自身安全投影”，不是授权；system／app body-runner的字段不能作为该fallback。此旧问题和旧组件结果保留，不追改为安全通过。

当前补丁保留唯一原生body读取算法，仅使用其内部准确关联／原行引用和一致性结论。公开sources及lines完全由同actor原生get／query的实际parent及原行值重新投影，不复制system数据、快照编号或模型summary。对象admission必须明确boolean，字段答案必须明确数组；null／undefined／异常／非法字段答案返回503。任一必需header编号／状态／引用或原行名称、类型、数量、价税折扣、小计等字段被拒、真实值缺失或范围不完整，整项返回403；不会补成零或用旧快照补全。optional字段只有原生字段集允许且实际可见时才返回。内部绑定和摘要不进入普通页面、工具公共输出或模型参数。

本人ready与原生GUI startup共用该actor读取检查，资格／字段无法可靠取得时不提供启动；GUI仍在原事务中再次核同一合法范围，失败保持pending且不写actual_start_on。既有PS／RLS、原动作、同记录锁／CAS、可信op绑定、并发与unknown只查原结果边界均不变。

此前真实HTTP／NativePG验证18类缺答／拒值／缺值：4个实际来源对象各自undefined／null／异常，原生订单编号／单价FLS拒绝，以及实际原生投影缺code／quantity／taxed_subtotal／quantity_limit，公开范围和GUI启动均拒、本人员工nonready、项目仍pending且开始日期空。合法两行原值、授权只读task元数据及三写四处拒绝、原并发／分享／unknown／同库重启和完整本人桥回归2/2通过；14项对应内存门禁及typecheck／validate／build通过。这份夹具使用直接合同来源，未覆盖报价→合同→订单完整原行和销售创建者的范围读取；该限制保留，不作为下述修补的证据。
