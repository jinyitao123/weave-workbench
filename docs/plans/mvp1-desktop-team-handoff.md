# MVP1 桌面助手与团队接入方案

日期：2026-09-21。状态：产品方案已确定，实施与验收进度见[项目状态](../project-status.md)。

## 产品定位

员工与桌面助手共同构成工作发起方。Pi 等桌面助手负责陪伴员工完成本地工作，并在员工表达“提交工作”或工作已经具备交接条件时，主动建议交给企业团队继续处理。

Weave 负责团队发现、接单、编排、等待补充和结果交付；团队内的智能体默认由 Loom 执行。桌面 Pi 或其他 CLI 不作为某个固定团队成员，而是所有获授权团队都能回到的“员工与桌面助手协作入口”。Forge 继续负责正式业务动作及权限判断。

## 一次工作怎样流转

1. 员工和桌面助手在本地整理材料并形成阶段成果。
2. 员工明确要求提交，或助手发现工作适合继续交接并征得员工确认。
3. 桌面只查询当前账号可使用的团队能力，助手结合当前工作匹配合适团队；唯一明确时直接建议，多个候选时让员工选择。
4. 桌面读取目标团队发布的接单要求，从当前会话、成果和员工授权的文件中整理已有内容，只询问缺项。
5. 员工确认本次目标、材料版本和授权范围后，桌面向 Weave 提交并取得接单回执。
6. Weave 使用 Loom 团队执行。需要补充、确认或人工参与时，任务回到原员工和原桌面会话；员工与助手补齐后继续同一项工作。
7. 团队成果和待执行业务动作回到原会话和工作卡片；Workbench Host 用当前员工会话调用 Forge，Forge 再做业务权限判断并保存正式结果。

## 业务完成后怎样找到下一位员工

团队完成智能体工作后，由 Forge 根据正式业务状态决定下一步事项、目标岗位和具体处理人，Weave 不通过模型猜测人员。处理顺序为：优先使用业务记录中已经明确的负责人；需要按岗位流转时，结合所属组织、业务单元和岗位解析可处理账号；多人时使用业务负责人或明确的认领规则；无人时进入“待分配”，不能静默完成。

这部分复用 ObjectStack 默认系统能力，包括组织、业务单元、岗位、用户任职、直属经理、原生审批和消息收件箱。Forge 自建员工档案中的部门、岗位文本不能另成一套人员路由依据；需要使用时，应与 ObjectStack 系统账号和任职关系建立明确关联。

业务完成通知与下一步待办是两件事：前者告诉原员工结果，后者把可办理事项持久分配给具体账号。桌面按当前登录账号读取待办与通知，员工打开事项后，Pi 才取得该事项授权范围内的业务上下文。桌面或 Pi 离线不能造成任务丢失。

## 团队发布什么

每个团队发布一份简明的“团队能力卡”，至少包含：

- 能处理什么；
- 需要哪些信息和文件，哪些是必需项；
- 会返回什么成果；
- 哪些账号或业务角色可以使用；
- 哪些情况需要回到员工补充或确认。

MVP1 不建设通用表单设计器。接单要求使用有限的字段与文件要求表达，复杂判断继续放在团队指令、技能和 Forge 业务规则中。

## 团队如何找到

账号权限先限定可触达范围，桌面助手只在该范围内做语义匹配。Weave 在接单时再次校验团队使用权限，Forge 在每次业务动作时再次校验业务权限。

Forge 权限集决定账号能否开发或管理团队；具体能调用哪些业务团队，由组织、岗位或业务授权决定。Weave 只使用 Forge 已验证的结果保护接口。内部团队编号、流程版本和成员结构不暴露给普通员工。

## 桌面需要的固定接入层

GooeyPi 内增加统一的企业工作接入层，供 Pi 和后续其他 CLI 调用。它不创建新的智能体循环，只负责：

- 查询当前账号可用的团队能力与接单要求；
- 将当前会话、员工确认的材料和成果版本组成交接包；
- 提交工作、补充材料、回复确认；
- 将真实进度、待办和成果关联回原会话与工作卡片。

助手判断员工意图并决定何时建议交接；接入层负责可靠执行、身份、材料边界、幂等和状态同步。Forge 与 Weave 会话只由 Workbench Host 使用系统安全存储保管，不进入 Pi、团队定义、Weave 运行输入或交接包。

## 多运行时边界

- 团队内部智能体默认由 Weave 调度 Loom 执行。
- Pi 等桌面运行时只在员工主动工作的过程中参与，并通过统一接入层与团队交接。
- Weave 可以向原员工提出补充、确认和返工，但不把桌面助手当作长期在线的固定执行节点。
- 后续接入其他 CLI 时复用同一套团队发现和交接协议，只新增桌面适配。

## MVP1 实施范围

先完成一条合同交接闭环：Pi 识别提交意图，发现获授权的合同团队，按团队要求检查材料，员工确认后提交；Loom 团队处理，缺项回到原会话，最终成果回到工作卡片，并由 Forge 保存、由浏览器独立读回业务结果。

合同业务结果形成后，继续验证 ObjectStack 原生衔接：Forge 触发下一业务步骤，按组织与岗位关系解析具体员工，生成该账号可见的待办和通知，处理员工在桌面登录后能够接收、打开并继续办理。本阶段先验证和复用原生能力；只有验证确认存在缺口时，才补充最小连接能力。

MVP1 通过标准是上述路径能在桌面实际操作完成，重开后仍可继续，重复提交不产生重复工作，缺项与失败原因可读；同时能够证明岗位解析得到真实账号，待办不会因桌面离线丢失，并由处理员工在桌面办理、在 Forge 浏览器页面独立读回业务结果。自动推荐更多团队、复杂路由和团队能力市场放到后续版本。
