# MVP1 桌面助手与团队接入方案

日期：2026-09-22。状态：产品方案已确定，实施与验收进度见[项目状态](../project-status.md)。

## 产品定位

员工与桌面助手共同构成工作发起方。Pi 等桌面助手负责陪伴员工完成本地工作，并在员工表达“提交工作”或工作已经具备交接条件时，主动建议交给企业团队继续处理。

Weave 负责团队发现、接单、编排和运行状态；团队内的智能体默认由 Loom 执行。桌面 Pi 在员工打开工作或事项后协助办理。运行反馈由系统自动提供，业务退回与续办通过 Forge 的受控 MCP 动作完成；完整职责规则只维护在[统一产品架构](../architecture/product-architecture.md#运行反馈业务动作与员工续办)。

## 一次工作怎样流转

1. 员工和桌面助手在本地整理材料并形成阶段成果。
2. 员工明确要求提交，或助手发现工作适合继续交接并征得员工确认。
3. 桌面只查询当前账号可使用的团队能力，助手结合当前工作匹配合适团队；唯一明确时直接建议，多个候选时让员工选择。
4. 桌面读取目标团队发布的接单要求，从当前会话、成果和员工授权的文件中整理已有内容，只询问缺项。
5. Pi 依据员工实际授权确定本次目标、材料版本和范围，桌面提交并取得接单回执；已有明确授权不再重复确认。接单后 Pi 结束等待。
6. Weave 独立运行团队。系统自动提供运行成功或失败反馈；成员判断需要员工修改时调用 Forge MCP 业务动作，Forge 建立责任员工事项并通知。
7. 员工打开事项后，桌面读取 Forge 最新状态和材料再交给 Pi。修改后提交新版本，Forge 决定原位置复核或调用 Weave 检查。团队可在任务授权范围内直接调用 Forge 业务动作；只有评阅授权时，不得直接提交正式审批。

## 业务完成后怎样找到下一位员工

团队完成智能体工作后，由 Forge 根据正式业务状态决定下一步事项、目标岗位和具体处理人，Weave 不通过模型猜测人员。处理顺序为：优先使用业务记录中已经明确的负责人；需要按岗位流转时，结合所属组织、业务单元和岗位解析可处理账号；多人时使用业务负责人或明确的认领规则；无人时进入“待分配”，不能静默完成。

这部分复用 ObjectStack 默认系统能力，包括组织、业务单元、岗位、用户任职、直属经理、原生审批和消息收件箱。Forge 自建员工档案中的部门、岗位文本不能另成一套人员路由依据；需要使用时，应与 ObjectStack 系统账号和任职关系建立明确关联。

业务完成通知与下一步待办是两件事：前者告诉原员工结果，后者把可办理事项持久分配给具体账号。桌面按当前登录账号读取待办与通知，员工打开事项后，Pi 才取得该事项授权范围内的业务上下文。桌面或 Pi 离线不能造成任务丢失。

## 团队发布什么

每个团队发布一份简明的“团队能力卡”，至少包含：

- 能处理什么；
- 需要哪些信息和文件，哪些是必需项；
- 会返回什么成果；
- 哪些账号或业务角色可以使用；
- 哪些情况需要回到员工补充或确认。

MVP1 先复用现有团队目标和流程说明，由开发者写清接什么、需要什么、交付什么，不强制新增结构化表单。只有实际调试证明现有说明不足，再增加必要的最小字段；复杂判断继续放在团队指令、技能和 Forge 业务规则中。

## 团队如何找到

账号权限先限定可触达范围，桌面助手只在该范围内做语义匹配。Weave 在接单时再次校验团队使用权限，Forge 在每次业务动作时再次校验业务权限。

Forge 权限集决定账号能否开发或管理团队；具体能调用哪些业务团队，由组织、岗位或业务授权决定。Weave 只使用 Forge 已验证的结果保护接口。内部团队编号、流程版本和成员结构不暴露给普通员工。

## 桌面需要的固定接入层

GooeyPi 内增加统一的企业工作接入层，供 Pi 和后续其他 CLI 调用。它不创建新的智能体循环，只负责：

- 查询当前账号可用的团队能力与接单要求；
- 将当前会话、员工确认的材料和成果版本组成交接包；
- 提交工作、补充材料、回复确认；
- 将真实进度、待办和成果关联回原会话与工作卡片。

助手判断员工意图并决定何时建议交接；接入层负责可靠执行、身份、材料边界、幂等和状态同步。Forge 与 Weave 的桌面会话由 Workbench Host 使用系统安全存储保管，不进入模型、团队定义或交接包。远端成员调用 Forge MCP 使用服务端认可的受限任务委托；此委托与桌面长期登录会话分开，具体机制在实施前经契约和真实权限验证确定。

## 多运行时边界

- 团队内部智能体默认由 Weave 调度 Loom 执行。
- Pi 等桌面运行时只在员工主动工作的过程中参与，并通过统一接入层与团队交接。
- Weave 成员经 Forge 能力请求员工补充或返工；事项属于账号与原工作，不把原桌面会话当成必须在线的节点。
- 后续接入其他 CLI 时复用同一套团队发现和交接协议，只新增桌面适配。

## MVP1 实施范围

先交付[MVP1 首个完整业务流](mvp1.md#当前先交付第一条完整业务流)：开发者在桌面绑定真实能力，销售递交冻结材料，团队退回后销售修改，正式提交给交付与商务，人工退回后再修改，最终双方通过并由独立身份在 Forge 页面核验。执行顺序与后置项见[落地步骤](mvp1-delivery.md)。

先验证原生组织、任务、审批与收件箱能力，再决定最小补充。没有落库的正式业务结果、真实跨员工办理和文件读回，不能用接单或运行成功代替验收。
