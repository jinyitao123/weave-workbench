# 销售费用与优惠申请

## 当前范围

2026-10-10 用户要求补齐销售附加费用完整表单、销售优惠页面，并修复收款流水布局。费用采用一个费用单头和多条费用明细；来源记录确定客户、项目与负责人。优惠只申请、原生审批和保留决定，批准后由人工调整订单，不自动改订单、合同、发票、应收或回款金额。

## 保存与提交

员工通过受控草稿保存动作提交来源、费用明细或优惠方式、数值和原因。身份来自原生员工会话；组织、申请人、来源金额和价税汇总由服务端确定。请求键在当前组织唯一，重复请求必须保持相同内容；同键异参拒绝，更新草稿核对版本。写入同一事务完成，失败不留下部分明细。

费用保存时核对来源可读且属于当前组织，按每行不含税金额和税率计算税额、含税金额和单头汇总。费用单采用统一承担类型。费用审批复用原生财务复核岗位；费用生效不自动产生收付款。

优惠记录冻结来源订单、客户、申请金额及申请人。提交前再次核对来源金额、申请版本及真实在任销售订单复核人，禁止申请人自审。原生审批记录、办理人和意见是审批证据；页面不另建审批队列。通过只改变优惠申请状态，保留人工调整订单的后续边界。

## 取消与审计

草稿可以修改或作废；审批中从原生审批中心办理，不在页面直接覆盖审批状态。动作返回记录引用、业务编号、状态、版本与是否重放；内部引用只供调用，页面展示业务编号与名称。组织、所有者、来源、请求键、版本及原生审批均保留审计关系。读取失败不得显示成零记录。

## 实施与验证边界

本轮源码和本地只读预览供用户检查。按用户要求不执行自动检查、不代办业务写入；当前联调环境未发布新增对象和动作，不将页面预览写成保存或原生审批闭环通过。当前产品状态由总仓项目状态维护。
