# Forge 页面精修基线

2026-09-23 起，RISEMAP 为可选参考，视觉不再以双侧像素相似为验收门槛。任务、证据版本和验收规则见[交付标准](forge-page-delivery-standard.md)。本文维护 Forge 自身可用、清楚、一致的视觉和交互要求。

## 页面原型与设计基线

每页选择 workbench、task_workspace、timesheet_composite、analysis、configuration 中适合岗位任务的主原型，写清首屏顺序、主动作、筛选范围、数据口径、主工作区、结果和下一步。不同任务不能只换标题套整页模板。

可参考 `workbench.page.ts`、`project-task-workspace.page.ts`、`project-timesheet-cost.page.ts`，公共控件按实际依赖使用 `product-ui.ts`。样例代码不是该页已被验收的证明。优先复用平台组件，构建产物不因公共源码整包重复内嵌而无控制膨胀。

每页固定可审查的 Forge 基线版本、视口、数据状态和截图。外部参考注明来源和采用理由，允许根据本产品目标调整。变更基线须解释对用户任务的改善并重新审查，不能为掩盖缺陷而临时改基线。

## 可用性硬门槛

- 页面内容适应 Console 外壳，统一组件、文字层级、主题变量和状态语义；不自建第二套导航外壳。
- 至少检查标准桌面、侧栏展开的实际内容宽度、窄屏，以及长单号、长客户名、长选项和多操作按钮状态。
- 不允许按钮/控件非设计性重叠、主要文字裁切、竖排挤压、越界；表格横向滚动限制在内容卡中，不拖动整页。
- 加载、空数据、错误、未授权、提交中、成功和关键弹窗各有合理表达。读取失败不显示为零或空列表。
- 所有可见控件真实可用，统一日期/选择/确认组件，具有键盘路径、焦点、标签和可访问名称。字段与状态联动遵循 Forge 业务合同。
- 操作成功后能读回正式结果；Toast、handler、静态截图不能代替提交与结果。
- 页面不能展示内部 UUID/运行编号，也不以宣传标语和装饰指标占据业务工作区。

## 视觉证据与回归

保存 Forge 桌面、窄屏、有数据、空态、错误、关键表单/弹窗截图，以及控件几何和交互步骤。可对经确认的 Forge 基线做像素回归，阈值由页面合同定义；0.005 像素差和 2px 双侧差不再是统一强制门槛，RISEMAP 图片不是必需证据。

对比时记录视口、缩放、DPR、滚动和数据，动态区域有原因，不能遮罩主要布局/控件来制造通过。既有外部对照证据保留原义，不修改历史结果。新机器证据版本尚待实现，见交付标准；当前 review_required 不自动变更。

## 具体布局与控件指南

下列尺寸用于统一风格的起点，最终以本页任务和已审查基线为准；任何数值不能覆盖上面的可用性门槛。

### 1. 首屏构图

- 桌面内容区的宽度、内边距和留白由本页任务、内容密度和经确认的 Forge 设计基线决定；下文尺寸是统一设计的起点，特殊页面在合同中说明，不以外部产品像素值作为放行条件。
- 首屏区块按“标题与动作 → 范围或关键筛选 → 判断指标 → 主图表或主任务 → 状态页签与明细”排列。若某类页面没有对应区块，直接省略，不能用空卡补高度。
- 在常见 `1280×720` 至 `1440×900` 视口内，用户应至少看到标题、范围区、完整指标行和主工作区的标题或上半部分。首屏不能被超高指标卡、装饰性留白或说明文字占满。
- 相邻大区块的垂直间距以 `14px` 至 `16px` 为主；同组卡片的间距为 `10px` 至 `12px`。除弹窗和空态外，不使用大于 `32px` 的无业务含义留白。

### 2. 标题区与页面动作

- 公共动作使用 `ForgeButton`，尺寸、字重、图文间距、圆角、状态颜色统一由 `forgeButtonUiCss` 与 `--ui-control-*`／`--ui-button-*` 参数控制。公共按钮不再参与页面基础 `font: inherit` 重置；页面不得另写固定高度、图标尺寸或最小高度覆盖公共参数。当前紧凑配置采用28px高度、500字重、12.25px字号、5.25px图文间距和3.5px圆角；文字按钮图标14px，工具按钮图标16px，线宽2。常规、主动作、危险、无边框和浅色动作分别使用明确的公共变体，键盘焦点、禁用与处理中状态保留。
- `ForgeToolbar` 将办理按钮与辅助工具分为两个可换行组。办理按钮间距10.5px，刷新／列设置等工具间距3.5px并靠右；窄容器换行，不压缩文字或让整页横向滚动。价格策略、销售订单、销售发货单与收款流水已接入，原页面工具栏和列设置按钮的固定尺寸覆盖已移除。
- 本轮实际浏览器核对覆盖855px价格页及1280px订单、发货和收款页，上述尺寸／字重／图标与边框均生效，列设置正常打开；150份业务页面源码已使用同一公共按钮，不等于150页已逐页验收。ObjectUI公共 `Button` 同步提供公共控制标记与可选图标尺寸参数，保持原生props、ref与调用方样式覆盖；旧Console实物未重新构建，本地Forge呈现由页面公共运行时样式生效。无远端部署或业务写入。

- 面包屑或业务阶段说明使用 `12px` 辅助文字，位于标题上方，和标题间距约 `5px`。页面标题使用约 `24px/1.35`、中高字重；说明在标题下方 `5px`，只写一句当前职责。
- 页面级动作与标题顶部对齐并靠右。当前最重要的办理动作只能有一个蓝色主按钮；导出、刷新、设置和辅助入口使用白底次按钮。
- 同类次要动作可组成相连按钮组，例如“导出工时 / 导出任务”。按钮组与主按钮之间保留约 `12px`，按钮高度由公共配置统一；当前紧凑配置为 `28px`，不在页面另加最小高度。
- 新建、填报、发起、提交等主动作不得落在状态页签下方、列表底部或与“刷新”“导出”混在不明分组中。动作应出现在用户开始办理时自然寻找的位置。
- 标题区可选两种形态，同一页面只用一种：**纯文字标题区**（默认，标题 + 一句说明）或**品牌标识区（hero）**。hero 使用整块品牌渐变或品牌底色，左上角图标徽章 + 业务面包屑，主标题和一句职责说明，右侧可放线稿装饰图；高度约 `150px` 至 `200px`，文字反白或使用高对比色。
- hero 只承担页面标识，不放业务数据、指标、表单或操作按钮；页面级动作统一放在 hero 下方的一行工具栏右侧，仍遵循本节主/次按钮规则。一页只允许一个 hero。
- 装饰图只出现在 hero 右侧背景，不得遮挡标题或说明，不得溢入主工作区；hero 之外的卡片、表格、图表区域不使用渐变、插画或装饰图。

### 3. 范围与筛选区

- 公共 `ForgeSearchInput` 提供白底细边框28px搜索与灰底变体；列表默认280px，页面只决定占位宽度。`ForgeSelect` 的可搜索模式过滤真实选项，支持方向键、Enter与Escape；不把搜索输入放到每张页面自行维护。`ForgeSegmentedFilter` 使用互斥单选语义和键盘选择。`ForgeCompactMetrics` 使用明确的语义色参数，紧凑卡59.5px，不按中文标签猜颜色；默认四列、窄容器两列。

- 成对的起止日期统一使用公共 `ForgeDateRange`。 月份导航使用标准 `ChevronLeft/Right`，年份导航使用单枚 `ChevronsLeft/Right` SVG，不拼接两个单箭头。单框内为日历图标、可输入的开始日期、`~` 和结束日期；弹层为双月范围选择，包含悬停预览、年月切换、今天／最近 7 天／最近 30 天、清除及 Enter／Esc。页面通过成对回调一次更新起止值，保留原日期字段、权限及筛选口径。源码对照来自浏览器加载的 [RISEMAP DateRangePicker](https://risemap.cn/assets/DateRangePicker-i6CymfDX.js)，不是截图推测；本轮迁移 34 个页面源文件中的 44 处范围；55 个页面导出的源码语法，以及双月选择、反向选择、手输 Enter、快捷范围、清空和日期边界的组件交互检查通过，实际 Forge 页面呈现待人工检查。日期输入失焦问题已在公共组件修复：日历采用受控弹层，开关不强制移走输入焦点，未变更的值不触发回调；独立浏览器组件已确认点击后焦点保留、连续输入起止日期及 Enter 转移／提交正常，主预览服务未由本次修复重启。总仓文档检查被既有环境文档引用未跟踪的 OAuth 探针 README 阻断；未为本次控件修改处理该独立事项。

- 决定整页统计口径的日期、组织、项目或期间选择放在独立轻卡中，紧接标题区；卡片内边距约 `14px 16px`，控件高度统一。
- 筛选标签使用 `11px` 至 `12px` 中高字重和弱化颜色；输入框、选择器、日期控件保持 `34px` 至 `36px` 高度，圆角约 `8px`。
- 只影响列表的搜索、状态、项目等条件放在列表卡内部，位于页签下方或表格上方。不能把局部筛选放到页面顶部造成作用范围不明。
- 周、月、季、年等快捷范围使用紧凑按钮或页签。选中态必须同时有文字颜色和边框/下划线反馈，不能只靠浅色背景区分。
- 所有筛选必须立即影响对应指标、图表或列表，并保留明确的清除/重置路径。没有实际过滤结果的控件不得出现。

### 4. 指标卡

- 桌面优先一行四张；业务确实需要时可为三张或六张，但同一行宽度与高度一致。工时页基线为 `4 × 1`，卡片间距约 `11px`，在约 `980px` 以下变成两列，在约 `680px` 以下变成一列。
- 指标卡内边距约 `15px 16px`，最小高度由内容决定，禁止用大面积留白制造“高级感”。指标名称使用 `11px` 至 `12px` 弱化文字；主数值使用约 `22px`、紧凑行高；口径说明在数值下方 `2px` 至 `4px`。
- 数值、单位和币种必须在一眼可读的同一视觉层级中。单位不能被放大到与数值竞争，辅助口径不能比指标名称更醒目。
- 颜色用于业务语义和可扫读性：默认主数值以深色为主，可用蓝色、橙色等轻度区分业务方向；禁止每张卡使用不同高饱和背景。
- 指标必须帮助用户判断下一步，并能追溯到当前范围内的数据。仅用于凑数、没有口径或与当前页面任务无关的指标应删除。

### 5. 图表与分析区

- 图表放在带边框的白色卡片中，内边距约 `16px`。标题使用约 `14px`，范围、单位或图例放在同一标题行右侧或标题下方的紧凑位置。
- 图表高度根据比较任务确定。周分布类约 `150px`；月度趋势可为 `180px` 至 `240px`。禁止在零数据时留下占据半屏的空白画布。
- 图例颜色必须与图形一致；坐标、月份、日期和单位要能读懂。柱形、折线或环图必须按真实数值计算比例，不得使用固定装饰高度冒充数据。
- 零数据时保留轴、周期和图例可以帮助理解口径，但同时应显示简短空态或零值，不得让用户误以为图表加载失败。
- 两个并列分析卡应有明确主次。主趋势区可占约 `2/3`，构成或摘要区占约 `1/3`；内容较少时应收紧卡片，而不是放大空白。

### 6. 页签、列表与表格

- 公共表格分台账与简表呈现。台账保留35px表头、显式列宽和横向滚动；简表可选择49px表头和 `layout="fit"`，按容器与列最小宽度分配空间，仅在容器不足或用户明确增宽后出现横条。简表默认不固定操作列，不显示台账阴影；已有列显隐、顺序、调宽和重置仍有效。`data-fp-table-scope` 只关联工具与数据表，不改造该范围的祖先为表格。只有实际工具内容时才渲染工具行，列设置可进入已有筛选栏。

- 自定义 React 工作区统一使用公共 `ForgeTable`、`ForgeTableViewport`、`ForgeRecordTable` 与 `ForgeTablePagination`；不在每张页面复制表头、勾选、滚动条、固定操作列和空状态样式。数据表继续由 ObjectUI `RecordTable` 处理原有查询、排序、选择和分页契约。
- 公共表格与 ObjectUI 原生表格共用 `--ui-table-*` 主题变量。按 RiseMap 浏览器 DOM 与计算样式读取，当前主题统一采用 35px 表头、10.5px 表头字、12.25px 正文字及 10.5px 内边距；行高随内容增加，编辑控件和多行内容不强行裁切。 表头不按是否带勾选框强制加高；复杂控件仍可自然撑开。
- 空表格保留列头，空状态按可视容器居中；横向滚动留在表格视口内，工具栏与分页不跟着宽表移动。固定操作列保留真实处理动作，不添加没有回调的数据操作或装饰性排序按钮。
- `ForgeTableViewport` 显式提供数据区的滚动边界；`ForgeTable` 不读取、标记或改造祖先容器。标题、页签、工具栏、筛选与分页均在数据视口之外。列配置提供宽度、对齐与调宽入口；表头使用 0.04em 字距、统一灰色文字与单根短分隔线，标签自己省略、单元格不裁切调宽手柄；排序只在提供真实回调的列上出现，左侧勾选列与右侧操作列各自固定。
- 公共列设置入口使用标准 Settings 齿轮和无外框图标按钮；按真实表头或 `RecordTable` 列元数据生成，在工具栏提供显示列、必显标记、拖动排列、键盘上／下移与重置默认。选择列、业务标识首列和操作列保留；设置仅控制本页列呈现，偏好保存在浏览器，不改写业务记录。分组表头允许显隐但不跨组乱序。
- 横向滚动使用公共常驻拖动条，放在数据视口外侧底部，与实际 `scrollLeft` 双向同步；支持拖动、点击轨道与键盘，不依赖系统自动隐藏的滚动条。 该控制显式取得实际数据视口的横向滚动所有权，视口使用 `overflow-x: hidden` 消除第二条原生横条；触控板横向滚动、Shift 滚轮与方向键由公共层继续转发，原生纵向滚动保留。空状态保留在数据视口内，工具栏和分页不随宽表移动。原生数据表格由公共控件同步实现，宿主控制只通过 React 运行时入口交接，不新增元数据协议字段。
- 销售订单列表和明细使用明确列配置，表头与正文在同一个数据视口内，最大高度 500px。分页实际切换结果与每页条数，空状态保留在数据区，删除额外横向翻列按钮。浏览器参考读取仅覆盖 RiseMap，Forge 本轮按用户要求不自动检查。
- 树状分组使用公共 `ForgeGroupTree`：独立标题、节点滚动区、层级缩进、展开箭头、数量、选中态、键盘导航和底部操作。价格策略页已接入；现有分类字典为平面数据，保留真实分类与数量，不伪造父子关系。
- 状态页签放在列表卡顶部，页签栏高度约 `44px`，页签间距约 `22px`。选中态使用主色文字和 `2px` 下划线；右侧可放记录数量或当前口径。
- 列表筛选位于页签下方，使用 `13px 16px` 内边距，并用底部分隔线与表格连接，形成一个连续工作区。
- 表头、正文、状态标签和行操作保持紧凑。表格过宽时在卡片内部横向滚动，不压缩文字和按钮到不可读宽度。
- 行操作只保留当前状态真实可执行的动作；一个主要行动作可使用小型主按钮，危险动作使用小型危险按钮。动作按钮高度约 `30px`。
- 空表格仍保留真实列头，空态行高度通常为 `140px` 至 `180px`。空态文案说明“当前条件为何无数据”或“下一步如何产生数据”，不放伪按钮。
- 分页属于列表卡底部，左右分别呈现记录数/每页数量与页码。分页不能脱离列表卡悬浮在页面空白中。

### 7. 表单、弹窗与结果反馈

- 公共 `ForgeFormSection` 统一白底分区、内侧标题与分隔线、内容留白及头部动作；业务表单分别声明字段，特价和框架协议不能共用一份默认字段清单。`ForgeAttachmentPicker` 只负责文件选择、拖拽、粘贴、移除及待保存展示；保存通过原生存储和受控业务动作绑定，不能模拟上传进度或将选择写成上传成功。

- 批量迁移保留业务表单的字段、原始事件、上传调用及权限判断。公共 `ForgeFileInput` 承接原生文件入口，保留 `accept`、单选／多选、文件夹属性、输入引用和原生 change 事件；隐藏的导入入口仍由原按钮触发，标签上传区补键盘与拖放，不能套用特价辅助材料的20MB／20份规则。BOM／项目计划的层级表格保持业务表格；侧栏分组树的组织及图纸目录已接公共树，受控展开、选择与键盘语义统一。
- 公共表单分区可接旧标题与内容结构；标题区和内容区分别统一留白，旧订单／合同内层留白合并，避免贴边或双层内边距。多段生成模板的局部匹配和基础标签同步迁移，不能只替换最终表面。纯按钮入口使用 `forgeButtonUiRuntime`，避免整包内嵌表格与工作区代码。
- 当前本机源码审查未发现业务页面直接声明原生按钮、表格、选择器和文件／日期输入；本次17处按钮与14份源码中的23处文件入口迁移，6份表单源码及其生成引用接公共分区。215份导出页面的JSX编译和绑定语法检查通过，13个受影响导出页的字段约束、点击、提交与变化回调保留（图纸目录只新增分组选择回调）。本机React19 DOM验证文件引用／事件、类型与单选限制、文件夹、禁用／提交、表单输入保持及受控树键盘路径；13项既有客户原子保存／项目成本／附件回归通过。

- 页面内展开表单必须与触发动作相邻，并使用同一内容宽度。桌面表单通常为四列，长文本占两列；约 `980px` 以下两列，约 `680px` 以下单列。
- 字段标签、必填标记、控件高度和错误文案必须统一。提交按钮放在表单阅读顺序末尾并靠右，不能孤立在页面顶部。
- 弹窗标题说明动作，副标题说明对象，正文说明字段或业务影响；按钮顺序、禁用态、提交中状态和错误反馈保持一致。
- 成功后必须回读页面真实状态；失败时在当前办理上下文内显示原因。Toast 只作为补充，不能替代列表、状态或详情的变化。

### 8. 业务入口与下一步动作

- 业务入口不是宣传卡。入口卡只用于承接明确的下一岗位或下一单据，内容包括短标签、具体任务名称、一句结果说明和一个真实可达动作。
- 三个并列入口在桌面可为三列，但卡片内边距和高度应紧凑，并与前面的分析结果形成因果关系。按钮放在对应任务描述之后或卡片右侧，不能把所有按钮集中成一排而失去上下文。
- 如果下一步只是列表切换，可使用文本按钮或次按钮；如果是当前页面的核心办理动作，才使用主按钮。页面中不能同时出现多个视觉权重相同的蓝色主按钮。

### 9. 色彩、边框、圆角与阴影

- 页面背景、卡片、边框、文字和状态色统一使用 `--fp-*` 变量。常规卡片为白底、`1px` 轻边框、约 `10px` 至 `11px` 圆角和极轻阴影。
- 阴影只用于从背景中分离卡片，不制造浮层感。普通卡片、表格与图表区禁止使用浓重阴影、发光、玻璃拟态和大渐变；品牌渐变只出现在页面 hero 标识区（见第 2 节）。
- 主色用于选中、当前进度和主动作；成功、警告、危险色只表达对应状态。大面积业务内容以中性色为主，避免“每个模块一种主题色”。品牌渐变与品牌底色也只用于页面 hero，进入主工作区后回到中性色加主按钮。
- 图标统一为线性图标，尺寸通常 `14px` 至 `16px`；图标必须帮助识别含义，不能作为大面积装饰。

### 9.1 图标按钮逐项验收门禁

- 图标用于识别动作、状态、来源、返回、上传、设置、编辑、删除、预览、保存和提交；同语义使用统一图标与可访问名称，不用随机 emoji 或不可辨认符号替代真实操作语义。
- 每个图标记录来源、业务语义、外框尺寸、实际图形尺寸、描边粗细、颜色、与文字间距、与按钮边缘间距、点击区域和垂直对齐。无文字图标按钮还必须记录 `aria-label`、最小点击区域和焦点顺序。
- 每个按钮分别记录高度、最小宽度、左右内边距、圆角、边框、底色、文字字号/字重、图标尺寸、图文间距和同组按钮间距；同一工具栏不得混用无法解释的高度、图标体系或描边粗细。
- 必须分别截图并操作默认、悬停、按下、键盘聚焦、选中、禁用、加载和失败恢复状态。主按钮、次按钮、危险按钮、文本按钮、图标按钮和组合按钮按各自角色验收，不能只检查静态默认态。
- 使用长文案、系统字号缩放、侧栏展开宽度和窄屏检查图标与文字不得重叠、错位、被裁切、异常换行或挤压相邻输入框；工具栏空间不足时按本页已确认设计换行或在业务卡片内部滚动，不得压缩成竖排文字。
- 图标存在但动作不可办理、点击无反馈、仅显示成功提示却没有状态变化或下一步入口，仍判交互失败。尚无真实业务能力的入口不得制作成可点击或灰色假按钮，应在页面合同中记录为能力缺口。
- 页面证据包含图标按钮清单、Forge 基线与当前截图、关键按钮边界框、关键状态和实际点击读回。可见关键操作缺证据时保持 review_required。

### 10. 响应式与窄屏

- 在约 `980px` 以下，标题动作允许换到标题下方，指标改为两列，四列表单改为两列；工具栏必须换行，不能把按钮压成竖排文字。
- 在约 `680px` 至 `760px` 以下，内容左右内边距缩至约 `12px`，标题约 `21px`，指标与表单改为单列，图表图例和页签允许横向滚动或合理换行。
- 日期范围、按钮组和筛选在窄屏下按办理顺序排列。主按钮保持完整文案和可点击宽度，不得与次要动作重叠。
- 表格在卡片内横向滚动；固定最小列宽，不通过缩小字号、隐藏关键列或挤压行操作解决空间问题。
- 长文本列应定义可审查的列宽，并用单行省略配合完整值提示；需要展示多行正文的列必须单独记录换行规则。长单号不得把一行数据拉成多倍行高，横向空间不足时滚动表格而不是压扁控件。

### 11. 明确拒绝的页面效果

出现任一情况，页面保持 `review_required`，不得称为精修完成：

- 只复用 `fp-shell`、标题、圆角、按钮和颜色，但页面仍是通用指标、页签、表格生成器。
- 指标卡高度过大、信息过少，首屏大部分是无业务含义的白色区域。
- 图表是固定高度的装饰块、零数据大空白或与真实数据无比例关系。
- 主动作放在列表页签下方、表格末尾或远离当前办理步骤。
- 导出、刷新、新建、提交等不同层级动作使用相同主按钮样式。
- 三个“业务入口”做成高大的宣传卡，或把多个失去上下文的按钮堆在同一工具栏。
- 窄屏时按钮文字竖排、筛选溢出、卡片错位、表格压缩不可读或页面出现横向整体滚动。
- 任意按钮与输入框、相邻选择器、页签、行操作或弹窗动作发生重叠；按钮文案被裁切或竖排；输入框被压缩到无法辨认当前值；表格长文本通过无约束换行把行高异常拉大；右侧操作被推出卡片且没有卡片内滚动。

### 12. 截图与交互验收判据

- 桌面截图至少覆盖标题区、范围/筛选、完整指标行、主图表或主任务区，以及列表页签或下一步入口的起始位置。
- 窄屏截图至少覆盖标题与动作换行、指标重排、筛选顺序和主工作区，不得只截页面顶部。
- 验收人员必须实际操作主按钮、一个次要动作、范围或筛选、状态页签、关键弹窗和下一步入口，并确认操作后页面回读。
- 截图检查除“元素是否存在”外，还必须逐项判断：主动作是否易找、信息是否紧凑、卡片是否过高、按钮是否有上下文、图表是否真实、空态是否可理解、首屏是否形成连续办理路径；并逐项核对控件边界框是否重叠、挤压、异常换行、截断、错位或越界。
- 页面只有在桌面与窄屏都达到上述效果、关键交互可用，并完成 Forge 需求逐项验证与独立复核后，才允许在 `tests/page-polish.manifest.json` 中从 `review_required` 改为 `accepted`。

## 控件与反馈

- 页面读取失败、权限错误和办理结果统一使用公共 `ForgeMessage` 顶部消息；`ForgeNotice` 的 error／success 变体及指定为 toast 的读取警告已路由到该消息入口，旧 `fp-toast` 已在 52 个源文件、63 处接入同一组件。独立的页面报错与日期校验报错也复用该入口，不把错误横幅插到数据行或分页之间。
- 顶部消息保留原文、重试按钮、关闭和无障碍语义；同文去重，自动消失并支持悬停暂停。自动消失只收起消息，不调用页面清错回调，也不把读取失败或不可用计数变成成功、零条。
- ObjectUI 提供原生 `PageMessage` React 运行时组件，复用现有 Sonner 提示宿主；尚未包含该组件的本地 Console 组合由 Forge 的共用兼容消息宿主承接，仍只处理瞬时 UI 反馈，不形成业务通知或待办系统。

- 主按钮代表用户当前最可能完成的动作。导出、切换视图、辅助设置等使用次要按钮，不与主任务争夺视觉优先级。
- 选择器和日期使用 `ForgeSelectControl`、`ForgeDateInput` 等共享控件；确认和破坏性操作使用 `ForgeDialog`。不得调用浏览器原生选择器、日期控件或确认框。
- 行操作只显示当前状态下真实可执行的动作。动作不可办理时，使用说明、状态或空态解释原因，不保留点击无结果的按钮。
- 提交前校验必填、范围、状态和来源关系；提交中防止重复操作；提交后显示结果，并回读更新后的页面状态。
- 删除、终止、作废、撤销和清空必须二次确认，弹窗写清对象、业务影响和不可恢复结果。
- 状态使用统一标签和语义色；同一业务状态在不同页面保持相同中文名称和颜色含义。

## 页面类型

- 工作台：先展示岗位需要处理的事项，再展示经营指标和模块入口；指标必须能追溯到业务数据或明确标注口径。
- 执行页：标题区给出主动作，随后是当前范围、状态筛选、任务列表和下一步；编辑表单应在用户当前上下文内完成。
- 分析页：先写口径和时间范围，再显示指标、趋势和明细；图表必须有对应明细或可解释来源。
- 配置页：突出配置对象、影响范围和保存结果；低频说明可以保留，但不能伪装成尚未实现的业务操作。
