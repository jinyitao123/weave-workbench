日期：2026-09-23。结论：**未通过** `scenarios/sales-contract-handoff/合同场景设计.md` 的真人闭环验收。本记录区分已发生的桌面操作、服务端诊断和仍未完成的业务结果；不以源码构建或接口结果替代验收。

## 已经发生的真实操作

- 销售小王在桌面 Pi 中递交合同正文、技术协议和报价单。初次提交进入 Forge 正式审批；交付负责人小李在本人桌面打开待办、读取当时实际可见的正文并退回，Forge 浏览器独立读回审批为“已退回修改”。当时审批没有绑定两份附件，因此小李的退回有真实业务依据。
- 团队开发者小周在桌面开发中心调整“合同提交员”的业务能力和指令，点击“更新团队”，重新进入后看到两项能力。那次不回写调试使用的是合成文本，并非场景中的同一份合同材料。
- 销售小王在桌面打开退回事项交给 Pi，Pi 读取三份本地文件，以自然语言发起补附件工作。Weave 返回接单回执，但真实运行 `run-5478201b-8eb1-5a29-8aa3-682202873f29` 随后失败；Forge 两次拒绝“绑定合同修订附件”，没有完成绑定或重新提交审批。接单不能记作团队完成。

## 对照场景，尚未走通

1. 场景要求先由团队检查得出一次“需要补充”，销售离线后从原生收件箱接回，再决定正式提交。当前没有这段完整实测；初次正式审批已经发生，不能倒记为团队退回。
2. 小李的退回通过桌面待办完成，但他的 Pi 未完成同事项阅读、辅助检查及意见提交。切换账号后发现前一账号的 Pi 会话仍可见，账号隔离不合格；在修复前不能继续声称跨员工 Pi 已验收。
3. 小陈尚未以本人账号完成商务复核；修订版本尚未重新进入双岗位审批，合同未评审通过；交付物使用者及独立审计者也尚未完成最终读回。
4. 桌面“我发起的工作”未显示刚接单的真实团队运行。当前桌面用 `workbench-<用户>` 过滤运行，而该运行保存的 `project_id` 是另一种标识；需要核对 Weave 的账号归属查询契约。
5. Weave 本次运行以 `team_run_execution_unrecoverable: unreported token dimension must be zero-valued` 结束。工具调用错误和用量记账错误需分别解决；不能把任一代码修补当作业务重试成功。
