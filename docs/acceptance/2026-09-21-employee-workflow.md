# 员工工作流阶段验收

日期：2026-09-21。范围：FLOW-01 的 Weave 工作提交与跨员工待办切片。

## 已确认

- 开发环境已建立“合同交接团队”，包含合同交接负责人和合同复核员。
- “合同人工复核”工作流 v1 已通过服务端校验并发布，节点为“处理员工复核 → 形成交付回执”。
- 发起员工的原始说明先登记为固定输入版本，再以同一回执派发；服务端返回唯一运行和任务编号。
- 真实运行已进入 `parked / human`，待办标题、受众和工作流 v1 可从第二个账号读回。
- 管理员创建了第二个 Forge 开发测试账号；首次登录后 Weave 自动绑定为 `member`，无需第二套密码。
- 原生 GooeyPi 的“我的待办”已显示已发布合同流程和同一条真实人工待办。

## 发现并修复

第二个员工最初能读取待办，但恢复运行时报“execution subject does not match”。原因是任务队列同时合并了处理员工的请求身份和发起员工冻结在运行快照中的执行身份。本地修复后，人工转换记录处理员工为 actor，继续执行仍继承原运行快照主体；跨员工定向 PostgreSQL 测试通过。

## 尚未完成

- 上述身份修复仍需部署联调服务器，并由第二账号重新完成待办、读回运行终态。
- 当前流程尚未上传合同文件、调用 Forge 业务动作、创建 Forge 业务待办或由独立身份读回业务状态，因此 FLOW-01 和 MVP1 均未完成。
