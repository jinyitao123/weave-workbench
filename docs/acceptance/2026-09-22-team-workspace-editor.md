# DEV-02 团队工作台编辑与能力边界

## 实现与来源

总仓分支为 `codex/reliable-team-handoff`。Weave 来源与总仓组件一致为 `9e6b19d681a560ac18958a79701ea1d3665a0ac2`；线上健康读回同一提交，容器为 `weave-platform:mvp1-9e6b19d6`，Forge 保持 `5aed3c2f8be23421c61599e9e0b58576ad779263`。接口约定见 [team-workspace](../../contracts/v1/team-workspace.md)。

Weave 已有整团队远端草稿、CAS 保存、成员候选版本、冻结试跑请求、同修订成功试跑门槛和原子激活。桌面恢复团队分工与流程图、只读详情与局部编辑，修改仅保留在页面，明确点击保存才提交远端；调试位于当前流程，更新位于有修改时的差异面板。没有顶部保存/试跑/发布阶段导航。

成员可编辑职责、指令、模型、技能正文、运行资源及 Loom 工具循环轮次。流程支持添加串行步骤、增加并行分支、调整汇合条件、改回依次执行、选择任务输入和前序结果；成员和步骤移除检查引用，草稿删除可撤销，可恢复生效配置（均须显式保存）。插入末步骤会同步最终交付来源。菜单支持外点关闭与 Escape。

## 通用性边界

合同团队来自远端，桌面没有写死合同团队、成员或合同金额等业务内容。但当前实现仍偏向文本任务：新流程为简单负责人/成员/交付骨架，调试仅接收文本；不能据此宣称任意类型工作流编辑器完成。

合同只作为一个验收样例。后续须从同一个桌面入口完成非合同团队的新建、成员配置、流程调整和调试，不能用专用代码或后台写数据建立第二条验收路径。当前桌面文案已改为任务输入、步骤输入；这只是消除场景措辞，并不代表结构化输入、工具隔离等能力已完成。

仍缺：结构化输入及字段路径编辑；任意外部 MCP 工具的隔离调试；工具服务绑定的完整桌面交互；Loom 实际编译图的展示（现有成员执行链为静态示意，不是实际拓扑）；更广泛的流程节点编辑。Forge 业务动作已有服务端校验的模拟调试目录，不访问 Forge、不写业务数据；其他外部工具、命名技能及非 Loom 的试跑仍被明确拒绝，不能算完整能力编辑发布已通过。

## 第一批交互验证：显式保存

用户最新决定覆盖先前自动保存方案：查看与编辑在原位完成，字段不再逐项点“完成”，失焦恢复阅读状态；保存整份本地修改才写入远端。离开团队/应用页面提供继续编辑、放弃修改并离开、保存并离开；调试遇到未保存修改会提示先保存，不替用户保存。保存期间的新编辑不会随已发出的请求一起落库。

恢复 Git 基线中的紧凑流程图节点、间距及连线；默认原尺寸，提供全图缩放和拖动。新增节点从已选步骤上的“下一步/并行分支”进入，明确选择执行人、名称和任务，不自动选首位成员后直接落库。

本轮实际桌面已完成：

- 创建非合同团队“产品反馈分类”，填写目标。
- 原位编辑负责人职责和交付要求，看到未保存状态，点击保存后状态消失。
- 新增“分类复核员”，只填写名称和职责，加入页面草稿后显式保存。
- 创建“反馈整理与复核”流程，从执行成员节点添加“复核分类结果”，选择分类复核员；新节点接收原始输入和前一步结果，最终交付来源跟随新末步骤。
- 未保存时切换应用开发显示明确提示；选择继续编辑后保留修改。保存后离开，再进入团队页面，从远端读回负责人修改和新增成员。

最新类型检查、构建、修改范围 lint 通过；3 个相关测试文件共 8 项通过，包括“不保存时等待、导航及卸载均不提交”和“保存期间新编辑不随前一请求提交”。一次从总仓误运行全局 npx 测试因缺少 jsdom 失败，不作为验证；已在桌面目录使用项目固定 Vitest 重跑上述结果。

仍未完成第一批全部验收：团队/成员/流程/步骤删除与撤销的桌面验证、流程重开读回。最后切换流程时再次遇到用户正在改变窗口的工具提示，未继续抢占。结构化输入、真实 Loom 图、任意外部 MCP 工具隔离以及完整运行生效闭环继续属于后续项，不在此记录为通过。

## 合同团队能力分工与隔离调试

开发者从同一桌面团队页面新增“合同提交员”，把“提交指定合同版本”从负责人移交给该成员，并在并行复核与负责人汇总后插入“提交冻结合同版本”步骤。新步骤同时接收固定任务输入和汇总结果，负责人和两名复核成员不再持有写业务能力。

首次试跑真实暴露 `workflow_provider_revision_required`：候选流程已冻结新增草稿成员，但模型凭据授权仍只检查已发布成员。Weave `9e6b19d6` 将精确流程及版本加入候选凭据范围，并仅接受同一开发候选中冻结的启用成员；真实 PostgreSQL 回归覆盖“新增成员 + 组织模型 + 候选接单”，相关包测试及三项依赖边界检查通过。部署后在桌面重试原请求即成功接单。

当前修订 16 共完成两次桌面试跑。第一次如实因材料缺项未调用模拟动作；第二次明确测试隔离能力路径，运行 `run-3aca7e8e-0233-4be7-81b1-cad1229ecc6f` 成功，活动记录仅有同一提交节点的一次 `tool_started` 和一次 `tool_completed`。桌面随后增加同步提交锁，防止快速重复点击创建两个试跑；工具状态 `tool_started/tool_completed/tool_failed` 显示为“执行中/已完成/失败”。定向前端 6 项和完整类型检查通过。

Mac 在试跑结束后锁屏，尚未从桌面点击“更新团队”，因此修订 16 仍是已验证草稿，不能记为正式生效；销售真实提交、双岗位办理和 Forge 独立读回继续待验收。
