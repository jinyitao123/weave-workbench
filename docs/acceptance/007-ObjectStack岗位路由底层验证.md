# ObjectStack 岗位路由底层验证

> 冻结评审记录。编号 007，原记录日期 2026-09-21。下文保留当时观察与证据，不代表当前版本状态。当前工作见[项目状态](../项目状态.md)，开放问题见[问题清单](../plans/问题清单.md)。整理仅调整文件位置与引用，不改变验收结论。

日期：2026-09-21。范围：Forge 线上联调环境的组织、岗位、员工任职与消息基础能力。

## 结果

- Forge 已部署源码版本 `7cf8a5a`，运行镜像固定为 `inoforge-app:sha-7cf8a5aaf84b`；服务重启后健康检查通过，仍运行同一源码版本。
- 通过 ObjectStack 原生系统设置创建“合同复核岗”和“合同交付部”，并将“MVP1 处理员工”任职到该岗位和业务单元。
- 服务重启后，员工详情页仍显示 1 项岗位任职；数据库中的岗位、员工和业务单元关系保持不变。
- Forge 正式数据接口按岗位标识 `contract_reviewer` 查询返回 1 条有效任职，再按员工标识读取到“MVP1 处理员工”。这证明 Forge 已具备“目标岗位 → 真实员工账号”的底层解析数据与读取路径。
- 当前数据层包含站内信、通知、通知投递、通知回执和审批任务等原生对象，可作为后续业务待办与结果通知的基础，不另建一套组织和消息模型。

## 当前边界

本轮只确认底层组织关系、持久化和读取能力，不代表合同业务已经自动生成下一步待办，也不代表处理员工已经在桌面收到并办理事项。下一步由 Forge 在真实业务动作完成后解析目标岗位和员工，创建持久待办与完成通知，再由桌面按当前登录账号读取。

ObjectStack 原生岗位详情页的“任职人员”反向列表仍显示 0 条，而同一条任职在员工详情页和数据接口中均可读。原生“分配用户”弹窗还存在候选人不可选、底层表单暴露 ADR 和时间区间术语的问题。以上属于原生管理界面的显示与交互缺陷，不影响本轮底层读取结论，后续统一修补。

平台内置岗位名称仍为英文，平台托管记录不允许在普通编辑入口直接修改。本轮自定义的业务岗位、业务单元和员工名称均使用中文；内置名称中文化随 ObjectStack 管理界面修补处理。
