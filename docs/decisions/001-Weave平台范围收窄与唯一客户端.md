## 背景

Weave 在 2026-08 至 09-13 按独立的智能体团队平台设计：自带网页 Workbench，提供团队模板、自动建队与评测、元团队、人工等待和多运行时成员，并计划拆成 kernel、builder、runtime、server、workbench 五个独立仓。2026-09-20 起，本总仓以 GooeyPi 改造桌面产品，Weave 承担 MVP1 的企业团队执行后台。

同日代码核对确认：桌面创建、编辑、试跑、发布团队以及员工交接，只调用智能体、团队、成员配置草稿、团队开发工作区、流程草稿/校验/发布、交接登记与派发、运行、交付物和人工等待接口，**没有调用团队模板、建队运行、评测、元团队，也不经过网页 Workbench**。三者仍在同一份 `weave-next` 中叠加：Weave 仓 AGENTS.md 规定网页 Workbench 是唯一业务界面、迁移期间不新增功能，而 MVP1 持续在 Weave 中增加功能；分仓计划未提及 `weave-next`。

## 决定

1. **Weave 的保留范围。** Weave 是智能体团队平台，保留团队与成员定义、流程编排（顺序、并行、条件、循环、汇合、等待）、发布冻结、执行调度、租约、额度、取消与恢复、用量，以及开放的客户端契约。**多运行时保留**：Loom、Codex、Claude、OpenCode 等都可以担任成员执行器，各执行器分别声明恢复能力。
2. **唯一客户端。** 本总仓的 GooeyPi 桌面加 Forge 是 Weave 当前唯一客户端。以后出现新入口时，按客户端契约接入，不为某个入口在 Weave 中另建业务流程。
3. **下线能力。** 团队模板、建队运行与评测（含裁判）、元团队、网页 Workbench 下线。按“先关、后删”执行：
   - 先关：部署设 `WEAVE_METATEAM_ENABLED=false`，不再部署网页 Workbench 及其网关容器，不再注册上述能力的接口。
   - 后删：运行一个版本周期、确认没有调用后删除代码。
   - 删除前先完成两项解耦：把 `teamconstruction` 中被流程发布使用的产品发布代码移到发布相关的包；去掉智能体接口对元团队成员名的引用。
   - 124 `default` 工作空间中已写入的元团队数据先保留；删除元团队代码时一并处理，实际清理前再确认一次。
4. **权威边界。** 团队运行状态以 Weave 为准。业务记录、审批、处理人与最终业务状态以 Forge 为准。Weave 交付物只是团队交付，不能表示业务已完成；网页 Workbench 下线后，Weave 的“成果采纳”不再面向员工呈现。
5. **身份。** Forge 身份交换是唯一的员工与开发者登录方式。Weave 本地密码登录与首用户注册关闭；运维所需的管理员 API Key 仍由 `weave bootstrap` 等运维入口签发，不作为员工登录方式。
6. **源码主干与分仓顺序。** `weave-next` 是 Weave 唯一源码主干。MVP1 验收前暂停分仓迁移，已形成的独立仓不再接收功能变更。MVP1 验收后以 `weave-next` 为起点重新切分：不再需要独立的 `weave-workbench` 仓，`weave-builder` 按保留的编排与恢复策略重新界定范围。
7. **Loom 职责。** 长任务、等待与中断恢复是平台核心能力，Loom 的持久恢复保留并做稳，不以“成员从头重跑”替代。模型与工具调用的重放契约归 Loom（`stdlib.ExecutionJournal`），Weave 只提供存储、租约和围栏；按模型提供方录制真实调用记录的恢复回归用例放在 Loom 仓。
8. **客户端契约归属。** 本总仓 [contracts/v1](../../contracts/README.md) 中由 Weave 实现的部分（账号绑定、交接登记、任务委托、团队运行事件与结果、续办上下文、团队与流程管理、开发观察、业务能力目录）是 Weave 的正式客户端契约。Weave 仓承认并对其承担兼容与回归责任；契约正文在总仓维护，不在 Weave 仓复制。

## 未在本决定范围

以下同样未被 MVP1 使用，但本次没有决定去留，另行确认：对外投递目标、掼蛋演示（2026-09-10 已批准的服务密钥例外）、Weave 人工等待节点在本产品中的定位（正式人工复核已走 Forge 审批）。
