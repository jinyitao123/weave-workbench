## 背景

[决策 001](001-Weave平台范围收窄与唯一客户端.md) 规定 GooeyPi 桌面加 Forge 是 Weave 唯一客户端，网页 Workbench 下线，员工和开发者只经 Forge 身份交换登录，Weave 源码不再引入独立控制台。用户此后提出：Weave 与 Loom 是独立产品，Workbench 与 Forge 是可选集成；需要一个独立部署的网页管理端，用页面完成运行时接入、团队配置、任务执行、结果查看和异常处理，并能区分节点在线、可接任务、执行完成与验证通过。

2026-10-06 对 Weave 与桌面代码只读核对（未运行测试、未访问 124），结论：团队、调度、节点注册与心跳、运行状态和确定性核验已有接口可复用；没有代码仓库与提交版本的概念，没有由节点执行、与提交绑定的验证证据，运行过程靠轮询且公开事件每任务最多 512 条，节点没有统一的可接任务判定。详见主文档[现有能力与缺口](../architecture/Weave管理端设计.md#现有能力与缺口)。

## 决定

1. **增设 Weave 管理端。** 面向开发者与运维，独立部署，可脱离 Workbench 与 Forge 使用。它负责节点、环境、团队、任务及其证据，不承载业务记录、审批、员工待办和组织管理。本条替代决策 001 第 2 条中"唯一客户端"的范围：GooeyPi 桌面加 Forge 仍是员工业务的唯一入口，管理端是 Weave 自身的开发与运维入口。
2. **下线范围不变。** 已删除的网页 Workbench 代码不恢复；团队模板、建队运行与评测、元团队继续下线。管理端按新设计实现，不沿用旧网页 Workbench 的页面与协议。
3. **身份只做最基本的接入。** 沿用 Weave 现有外部身份交换：Forge 是第一个验证器实现，以后的产品实现同一验证接口并返回稳定身份来源、用户、组织与角色。不接 Forge 时，运维使用 `weave bootstrap` 签发的 API Key。本地密码登录与首用户注册继续关闭（决策 001 第 5 条不变）。不新增通用 OIDC、身份源管理、只读或审计角色、按团队授权；沿用现有 member、developer、admin 三档。
4. **桌面团队开发界面被吸纳。** 成员配置、流程画布、试跑与发布门禁、草稿修订进入管理端并升级。桌面保留 Pi 对话修改团队及其右侧栏、"我的工作"、会话中的团队运行卡片与业务动作回执；两边共用同一份远端草稿修订。第一阶段先共享接口契约，管理端稳定后再把组件抽成共享包。
5. **四个状态独立判定。** 在线、可接任务、执行完成、验证通过分别由服务端事实判定，页面分别显示。智能体自述只显示为"智能体声称"，不点亮验证通过；被验证的提交必须等于交付的提交。
6. **体验细则。**
   - 新建团队时预填"编码 + 验证"两名成员的初始草稿，与桌面现有的初始流程同性质；不提供模板库，不属于第 2 条下线的团队模板。
   - 交付方式第一版为推送到 `weave/` 前缀的分支并提供补丁下载；代码托管平台的合并请求后置。
   - 跟进指同一任务内的新一轮团队运行，从上次产出的提交开始；不改为单个成员续聊。
7. **部署形态与源码位置。** 管理端编译后的静态资源打包进 Weave 服务端二进制，与 Weave 接口同源提供，一次部署即可使用；源码放在 Weave 源码主仓 `weave-next`，随 Weave 版本发布，总仓 `platform/weave` 按版本锁同步。

## 后续工作

- Weave 源码主仓的 `AGENTS.md` 与 `make productguard` 中"不引入独立控制台"的规则，在准备阶段于源码主仓修订，不直接改总仓 `platform/` 副本。
- 管理端需要的新接口先在契约中写清调用者、身份、幂等、输入输出、错误、取消与审计，再分别实现。
- 分期与验收见主文档[分期实施](../architecture/Weave管理端设计.md#分期实施)；进展只在[项目状态](../项目状态.md)维护。

## 限制

本决定依据只读代码核对与会话讨论作出，没有运行 Weave、Loom、桌面测试，也没有访问部署环境。它不改变任何已有验收结论。完整 MVP1 尚未通过；管理端工作与 MVP1 剩余验收并行，不以管理端进展替代桌面业务闭环验收。
