## 背景

架构已规定“写入调试只进入沙箱环境”，但沙箱是什么、客户现场怎样修改 Forge 功能、改动怎样从沙箱到正式环境，都没有设计。当前只有一套联调环境；Forge 的对象、动作和流程是编进镜像的源码，客户无法自行修改。

约束来自私有化交付：客户开发人员不能审查代码；员工与开发者的电脑不安装 Docker、不构建、不运行服务；客户内网可能访问不到发行方的仓库和流水线；员工从桌面发起、团队真实调用扩展动作、Forge 写回的完整链路必须能在上正式前真实跑通。

## 决定

1. **标准版本加客户扩展包。** 客户定制放进独立命名空间的扩展包，随标准版本加载；不提供在产品页面中在线修改对象和动作。扩展包只能新增，不能修改或删除标准对象、动作与流程，不能直接写标准业务表，改动标准数据只经标准业务动作。扩展包新增的动作默认不对团队开放，由管理员确认后才可绑定。
2. **沙箱是服务器上的第二套完整安装，全体开发者共用一套。** 用同一份服务端包安装，与正式环境各有组织、账号、密钥和数据库；Forge、Weave 与 PostgreSQL 都是真实的。多个扩展包靠命名空间并存，同一扩展项目以最后一次上传为准。不为每个开发者建沙箱，不在开发者电脑运行 Forge、Weave 或数据库。
3. **源码放开发者本地，服务器构建。** 桌面把源码上传，服务器编译并保存编译产物。正式环境只安装服务器编译出的产物，不接受本地构建的产物。版本只认扩展包清单里的版本号，必须高于已装版本。
4. **把关靠机器检查和沙箱行为验收，不靠代码审查。** 只有三关：编译时的检查（平台自带规则加我们的越界检查）、沙箱中用演示账号办理并在 Forge 页面独立读回、正式安装前备份。出问题时重装上一版编译产物。
5. **联调环境不是产品层级。** 124 只属于发行方的研发链路；客户现场是正式环境加沙箱，检查与升级预检都在客户现场执行，不依赖发行方流水线。
6. **先加后删。** 新增时扩展包先装进正式环境，团队后发布；删除时团队先发布不再引用的版本，再卸载扩展内容。删除对象或字段分两次发布，清理前须实际演练过备份恢复。
7. **扩展对象使用 `forge_ext_` 保留前缀。** 扩展包的命名空间和对象名以 `forge_ext_` 加客户简称开头，标准版本不使用该前缀。任务委托契约与 Forge 的范围校验因此不用修改。
8. **扩展开发单独设权限。** Forge 增设“业务扩展开发”权限集，不并入“智能体团队开发”。持有者可在桌面新建扩展项目并上传到沙箱；装入正式环境只由管理员在服务器侧办理，不放进桌面。桌面按登录会话带回的权限显示入口，服务端每次调用重新校验；普通员工的桌面不出现任何扩展开发内容。
9. **沙箱的机制从简。** 沙箱就是同一份服务端包的第二次安装，不新增运行组件。每次上传固定三步：服务器编译、调用平台自带的装包入口、重启沙箱 Forge；全部上传排一个队，不区分是否含流程。装入正式环境用同一份编译产物和同一个装包入口。团队沿用现有草稿接口在沙箱和正式环境之间复制，正式环境仍走自己的试跑与发布。第一期不做：装包前的一次性容器预启动、正式环境配置自动导入沙箱、每人一套或临时沙箱、与已装版本的自动变更对比、脚本型动作。

## 已核实的平台事实

2026-10-10 分两步核实。先阅读 Forge 依赖树中 ObjectStack 17.5.0 的源码与本仓安装器源码；再在 Mac 开发机的独立目录导出 Forge 来源 `b80dcba5`，以开发模式和独立端口启动一个实例，先用独立 SQLite 文件、后用本机 PostgreSQL 16 的独立数据库，装入一个最小扩展包（一个自有对象、一个脚本动作、一个流程和指向它的流程型动作）。没有 Weave、没有使用生产镜像，以管理员会话经接口调用，不构成业务验收。验证后实例、数据库和目录均已清除。

实际运行读回：

- **离线装包入口已挂载。** Forge 当前配置启动后即提供该入口，无需云端控制台。
- **扩展包是纯数据。** 编译产物是约 5KB 的清单，动作脚本作为受限脚本体包含在内；编译阶段先后拦下三处错误：动作的 AI 说明过短、未知的键、关联字段指向包外对象。
- **安装不用重启。** 安装后对象立即可查、数据表已建、可读写；重启后自动恢复，数据保留。
- **升级不用重启。** 从 0.1.0 升到 0.1.1 增加一个字段，新字段立即可写，原有数据保留。
- **卸载要重启，且不删数据。** 卸载后重启前对象和目录条目仍在；重启后消失，但数据表和其中的记录留在数据库里。
- **扩展动作立即进入业务动作目录，且默认可交给团队。** 目录读回为写入类、团队可委托、可用。这与决定第 1 条“默认不对团队开放”相反，Forge 的动作策略须改成对扩展命名空间默认拒绝。
- **脚本型扩展动作不能执行。** 动作路由能找到定义，但没有已登记的执行器，重启后相同。源码显示脚本执行器只在启动时为本地代码包登记。
- **流程型扩展动作重启后可以执行。** 扩展包自带一个流程和一个指向它的动作，经动作路由调用后由流程写入扩展对象，数据接口读回该记录。流程在安装或升级后不会热生效，调用报流程不存在或仍按旧定义执行；重启后才登记。本次开发模式实例从启动到流程登记完成约 7 秒。
- **流程能读标准对象并分支。** 在 PostgreSQL 上，流程按输入读取一条标准对象记录，存在则把其名称写入扩展对象记录，不存在则不写；两种情况均按预期读回。
- **其他命名空间的扩展动作拿不到任务委托。** 对象名不以 `forge_` 开头时，请求返回范围无效；同样结构换成标准动作则通过范围校验、停在员工权限检查。原因是[任务委托契约](../../contracts/v1/task-delegation.schema.json)与 Forge 的范围校验都把动作和业务记录限定为 `forge_` 开头的对象。
- **用 `forge_ext_` 保留前缀后，任务委托下可以调用扩展动作。** 命名空间和对象改用该前缀后安装无冲突；配置身份来源后 Forge 签发了只含该扩展动作的任务委托；经团队成员使用的同一委托入口，动作清单只列出这一个动作，调用后流程写入，管理员会话独立读回该记录；同一委托调用员工本人动作、读取标准对象均被拒绝。契约和 Forge 源码均未改动。
- **Forge 开发模式实例常驻内存约 821MB，依赖目录 752MB。** 这是 Mac 上刚启动空闲时的读数，不代表容器内的生产模式。

阅读源码得出、未单独运行验证：

- 动作脚本在 QuickJS 沙箱内运行并受声明的接口能力限制，但数据访问是系统提权，绕过行级和字段级权限。平台不会阻止扩展脚本读写标准业务表，决定第 1 条的这一限制须由我们自己的检查实现。
- 平台自带运行时在线编写钩子和动作的能力，可用环境变量关闭；按决定第 1 条，正式环境应关闭。
- 流程节点有读取、新建、更新、删除记录、条件、循环、并行、子流程、通知、等待和连接器调用，没有“调用另一个业务动作”的节点。流程可以直接更新或删除标准对象的记录，决定第 1 条“改动标准数据只经标准业务动作”在流程里无法表达，须由我们的检查禁止流程写入扩展命名空间以外的对象。
- 命令行有代码插件的打包和签名命令，规范包中有其格式定义，但在 runtime、core 与包服务中没有找到对应的加载器。
- 本仓安装器每次安装生成独立的项目名、密钥和数据卷，可指定状态目录与端口。

## 未验证项

1. **由 Weave 团队真实调用，并从桌面发起。** Forge 一侧在任务委托下调用扩展动作已读回，但调用方是手工请求，不是 Weave 的团队运行，也没有桌面和 Forge 页面。本次的 Mac 没有运行 Docker，本机 PostgreSQL 没有向量扩展，未启动 Weave。
2. 流程的审批、循环和子流程节点；脚本型动作要可用，须在 Forge 一侧为已安装的包补登记脚本执行器，未做。
3. 扩展包给标准对象追加字段，以及关联标准对象的字段怎样通过编译。
4. 生产镜像下的表现。本次只用了开发模式。
5. 完整一套安装（含 Weave 与两个数据库）的内存与磁盘占用。本次没有取得联调主机的访问途径。
6. 卸载后残留数据表的清理方式。
7. 客户内网可用的模型编写扩展包的质量。

按本次结果，扩展包第一期可做对象、流程和流程型动作；流程和动作须重启 Forge 才生效，所以决定第 9 条规定每次上传都重启并排队。需要脚本的动作仍由标准版本承载。

## 放弃的方案

| 方案 | 放弃原因 |
| --- | --- |
| 同一实例内的沙箱组织 | 扩展包与数据库结构为整个实例共用，写坏的包会影响正式业务，升级也无法先试 |
| 每个开发者本机一整套 | 需要 Docker，与电脑要求不能高冲突 |
| Forge 沙箱在本地、Weave 在服务器 | 本地 Forge 的账号不能登录服务器的 Weave，团队一侧只能模拟，完整链路不成立 |
| Forge 与 Weave 都在本地且不用 Docker | Weave 只支持 PostgreSQL 并使用向量扩展，两个服务端组件目前只有 Linux 镜像；需要长期维护 Windows 与 macOS 的本地运行版 |
| 服务器上每人一套沙箱 | 服务器开销随开发人数增长 |

## 后续工作

- 完整链路验证：在一套带 Weave 的沙箱中，由演示员工从桌面发起、团队调用扩展动作、Forge 页面读回；同时量出一套安装的资源占用。
- 契约先行：扩展源码上传与编译、会话中的扩展开发权限、沙箱标识，写清调用者、身份、幂等、输入输出、错误与审计后再实现。
- Forge：增设“业务扩展开发”权限集；动作策略对 `forge_ext_` 对象默认不交给团队；正式环境关闭平台的在线编写；编译时增加越界检查（只用保留前缀、流程不写扩展以外的对象）。
- 安装器：沙箱标记，升级、备份与回退命令；离线镜像导入仍未实现。
- 桌面：扩展项目列表、新建、上传到沙箱并显示结果、切换到沙箱连接；不含装入正式环境。
- 验证通过后把当前规则写入上表三份主文档；在此之前主文档只指向本记录。

## 限制

- 本记录只是决定，不代表上述能力已实现或已验证；进展见[项目状态](../项目状态.md)。
- 团队仍在沙箱 Weave 的管理端共用草稿，沿用[决策 004](004-团队配置集中到Weave管理端.md)与[决策 005](005-管理端不按Forge权限隔离试跑与可用人群.md)；团队在沙箱与正式环境之间按决定第 9 条用现有草稿接口复制，页面入口尚未实现。
- 共用沙箱中，有问题的扩展包仍可能影响所有开发者；第一期只有声明式内容并由编译检查把关，出问题时重装上一版并重启，这一恢复办法未验证。
