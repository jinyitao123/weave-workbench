## 背景

2026-10-01 对三端衔接做只读代码核对，发现以下实现与目标设计不一致（代码位置按上述来源版本核对）：

1. **委托不受限。** Weave 登记固定输入时，把员工桌面登录用的 Forge Bearer 原样加密保存（`platform/weave/internal/app/api/business_delegation.go`），成员运行时解密后直接调用 Forge MCP。Forge 无法区分员工本人与团队代办，“本次允许范围”只由 Weave 执行。委托表有 `revoked_at` 但无任何写入路径；桌面退出登录只清本地，不注销 Forge 会话。
2. **委托期限与离线推进冲突。** `forgeDelegationTTL` 固定 30 分钟，排队或运行更久的团队无法完成业务写入，续期依赖桌面重新登记，违背“关闭会话不等于取消已递交工作”。
3. **身份来源绑定网络地址。** Weave 以配置的 Forge 地址（协议＋主机）作为 `issuer` 建立账号绑定，并复用它拼接材料读取与 MCP 地址。更换访问地址会生成新的员工映射，违背架构“更换访问地址不能创建新的员工账号映射”。
4. **桌面在合成状态。** 桌面工作总览按通知类型子串推断种类、自行判断“需要补充”消息是否被取代、逐条读取来源与审批意见，并以固定上限（审批 50、通知 200）读取且不分页。
5. **两套员工待办入口。** 桌面同时读取 Weave `/v1/human-tasks` 与 Forge 原生审批。
6. **团队使用无范围。** 所有登录账号都获得 `teams:use`，没有按团队限定使用人群。
7. **事件幂等偏差。** Forge 团队运行事件入口只按幂等键去重，同键不同内容不报冲突。

## 决定

1. **任务委托由 Forge 签发。** 桌面 Host 用员工本人会话向 Forge 申请一次任务委托，Forge 校验动作、记录与文件后签发独立于员工桌面会话的任务凭据，并保存其范围。Weave 只保存该任务凭据的加密引用，不再接收员工桌面会话。Forge 在执行入口识别任务凭据并强制本次动作、记录与文件范围；Weave 继续做调用前收窄，二者同时成立才执行。
2. **委托期限跟随运行。** 委托有效期等于该次运行期限，并受部署上限约束（默认 24 小时）。运行进入终态、员工取消工作或账号停用时撤销。员工退出桌面登录注销其桌面会话，但不撤销已递交工作的任务委托。
3. **身份来源使用稳定标识。** Forge 返回部署级稳定身份来源标识，Weave 以它建立账号绑定；Forge 网络地址仅用于连接。桌面会话中的身份来源采用 Weave 交换结果，不由桌面地址拼接。
4. **员工人工事项唯一入口。** 员工可见的人工事项只经 Forge 原生审批与收件箱。Weave 团队流程中的人工节点如保留，由 Weave 以 `human_review` 系统事件进入原生收件箱；桌面不再直接读取 Weave 人工任务列表。
5. **团队可用范围由 Forge 权限集决定。** 团队开发文档声明可用人群（Forge 权限集名称列表），随发布冻结；为空表示全组织可用。Weave 在团队列表与固定输入登记时校验当前会话的 Forge 权限集。
6. **状态推导回到服务端。** 团队运行的当前性与业务结果由 Weave 批量投影；Forge 提供本人审批事项的只读投影（含最新退回意见与分页）；消息种类只按准确 topic 识别。桌面只读取、映射和展示，读不完时明确提示。
7. **写入范围由 Host 展示。** Pi 选定本次业务动作后，桌面 Host 在对话中展示不经模型生成的范围卡片，并可直接取消该工作；不增加固定确认弹窗。
8. **事件同键同内容。** Forge 保存事件内容摘要，同一幂等键内容不同返回 `409`，Weave 将其视为永久失败。

## 原生能力验证（2026-10-01）

在本机隔离 PostgreSQL 16 上以 Forge `eb90f556` 原生运行时（ObjectStack 17.3.0、better-auth 1.7.2）执行一次性探针，结论如下。探针只用于验证，不进入代码库。

| 问题 | 结果 |
| --- | --- |
| 插件能否为同一员工签发独立会话 | 能。认证服务 `getAuthInstance()` 的 `$context.internalAdapter.createSession(userId, false, { activeOrganizationId, expiresAt })` 返回与桌面会话不同的令牌，组织随之设置 |
| 该令牌能否通过身份核对与 MCP | 能。`/api/v1/auth/me/permissions` 返回同一员工与权限集；MCP `list_actions` 正常 |
| 能否按令牌在 MCP 前拦截 | 能。ObjectStack `server.use('/api/v1/mcp', …)` 在 kernel:ready 注册后仍先于 MCP 执行，可对任务令牌返回 403 而不影响桌面令牌。**但该中间件拿不到请求体**，无法按 JSON-RPC 工具名或动作参数判断；直接在底层 Hono 应用上追加的中间件不会生效 |
| 原生撤销 | 能。`internalAdapter.deleteSession(token)` 后该令牌在身份核对处为未认证，桌面会话不受影响 |
| 任务令牌可见的 MCP 工具 | 与桌面会话相同，含 `create_record`、`update_record`、`delete_record`、`query_records` 等 11 个工具。这也是当前 Weave 直接持有桌面会话时已存在的暴露面 |
| 能否在数据层拦截任务令牌的写入 | 能。不限对象的 ObjectQL `beforeInsert` 钩子收到 `session.accessToken`，对任务令牌抛错后 MCP `create_record` 被拒 |
| 能否在读取层拦截 | 未证实。`beforeFind` 钩子在 MCP `query_records` 中未观察到会话令牌 |
| ObjectStack 原生 OAuth 代理主体（ADR-0090） | 存在：OAuth 访问令牌以“代表员工”的代理身份运行，MCP 工具按 `actions:execute` 等粗粒度范围收窄。但令牌须经员工交互式 PKCE 登录与同意签发，范围不能细到单个动作或记录，不适合按任务非交互签发；本批不采用 |

据此确定第 1 项的实现：Forge 插件签发独立会话作为任务凭据，并由三道守卫共同强制范围——

1. **入口守卫**（`server.use`）：任务令牌只能访问身份核对、MCP、对象元数据、Workbench 材料读取与本委托撤销路径，其余一律 403。
2. **动作守卫**：插件在全部动作注册完成后，以 ObjectQL 公开的 `registerAction` 为每个动作重新登记包装处理器；调用方为任务令牌时，核对对象、动作与记录在委托范围内，并在异步上下文中标记“处于获准动作内”。
3. **数据守卫**：不限对象的 `beforeInsert`、`beforeUpdate`、`beforeDelete` 钩子拒绝任务令牌在获准动作之外的一切写入，从而封住 MCP 通用增删改。

**已知限制：** 任务令牌仍可经 MCP 通用读取工具读取员工本人可见的数据。Weave 已只向成员暴露 `list_actions`、`run_action`，此项不扩大员工自身权限，但 Forge 侧暂不能强制；后续若 ObjectStack 提供会话级工具收窄或读取钩子可见会话，再补读取守卫。流程型（flow）动作不经 ObjectQL 动作处理器，实施时须先盘点当前开放给智能体的动作中是否存在流程型动作，存在则在入口拒绝任务令牌调用。动作守卫的重新登记与异步上下文标记未在探针中验证，须在实施测试中先行证明。

## 实施与限制

- 第 1、2 项的实现按上节验证结论；实施时以真实 PostgreSQL 原生运行时测试覆盖签发、三道守卫、撤销与桌面会话不受影响。
- 124 为开发联调环境，数据可清空重建；本批不写旧账号绑定、旧委托或旧通知的迁移与兼容。清空后既有场景验收现场作废，合同续办须在新版本上重新从桌面发起验证。
- 本记录只确定方向，不表示已实现。各项实现与验收进展见[项目状态](../项目状态.md)与[问题清单](../plans/问题清单.md)。

## 本轮实施修订

2026-10-01用户在整合会话明确选择“退出不影响已交接工作”，本批按24小时部署上限、运行终态与员工取消撤销推进。上方原生会话探针及其读取范围限制保留为当时事实；当前实施基于后续真实ObjectStack17.3/PostgreSQL验证，改用同一原生server-only签名/JWKS、稳定身份来源和purpose audience的任务JWT，结合SDK原生受限MCP bridge。任务令牌不成为员工会话，不进入通用MCP/CRUD或范围外记录、材料读取；没有第二份授权对象或账号体系。

当前真实PG回归证明：桌面会话过期/退出后任务仍有效，当前账号和组织资格每次核验；并发员工取消/任务自撤销以原生条件更新保留首次原因，重复撤销返回原结果。准确接口、机器字段与有效期以[契约v1](../../contracts/v1/README.md#受限任务授权与原输入续办)为当前主文档。此证据是组件验证，部署与员工闭环仍待完成。本轮保留124已有场景现场，不把上文历史的可重建环境描述当作本次清空操作已执行。
