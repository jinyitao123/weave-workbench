## 背景

2026-10-01 对三端衔接做只读代码核对，发现以下实现与目标设计不一致（代码位置按上述来源版本核对）：

1. **委托不受限。** Weave 登记固定输入时，把员工桌面登录用的 Forge Bearer 原样加密保存（`platform/weave/internal/app/api/business_delegation.go`），成员运行时解密后直接调用 Forge MCP。Forge 无法区分员工本人与团队代办，“本次允许范围”只由 Weave 执行。委托表有 `revoked_at` 但无任何写入路径；桌面退出登录只清本地，不注销 Forge 会话。
2. **委托期限与离线推进冲突。** `forgeDelegationTTL` 固定 30 分钟，排队或运行更久的团队无法完成业务写入，续期依赖桌面重新登记，违背“关闭会话不等于取消已递交工作”。
3. **身份来源绑定网络地址。** Weave 以配置的 Forge 地址（协议＋主机）作为 `issuer` 建立账号绑定，并复用它拼接材料读取与 MCP 地址。更换访问地址会生成新的员工映射，违背架构“更换访问地址不能创建新的员工账号映射”。
4. **桌面在合成状态。** 桌面工作总览按通知类型子串推断种类、自行判断“需要补充”消息是否被取代、逐条读取来源与审批意见，并以固定上限（审批 50、通知 200）读取且不分页。
5. **两套员工待办入口。** 桌面同时读取 Weave `/v1/human-tasks` 与 Forge 原生审批。
6. **团队使用无范围。** 所有登录账号都获得 `teams:use`，没有按团队限定使用人群。
7. **事件幂等偏差。** Forge 团队运行事件入口只按幂等键去重，同键不同内容不报冲突。

## 决定

1. **任务委托由 Forge 签发。** 桌面 Host 用员工本人会话向 Forge 申请一次任务委托，Forge 校验动作、记录与文件后签发独立于员工桌面会话的任务凭据，并保存其范围。Weave 只保存该任务凭据的加密引用，不再接收员工桌面会话。Forge 在执行入口识别任务凭据并强制本次动作、记录与文件范围；Weave 继续做调用前收窄，二者同时成立才执行。
2. **委托期限跟随运行。** 委托有效期等于该次运行期限，并受部署上限约束（默认 24 小时）。运行进入终态、员工取消工作或账号停用时撤销。员工退出桌面登录注销其桌面会话，但不撤销已递交工作的任务委托。
3. **身份来源使用稳定标识。** Forge 返回部署级稳定身份来源标识，Weave 以它建立账号绑定；Forge 网络地址仅用于连接。桌面会话中的身份来源采用 Weave 交换结果，不由桌面地址拼接。
4. **员工人工事项唯一入口。** 员工可见的人工事项只经 Forge 原生审批与收件箱。Weave 团队流程中的人工节点如保留，由 Weave 以 `human_review` 系统事件进入原生收件箱；桌面不再直接读取 Weave 人工任务列表。
5. **团队可用范围由 Forge 权限集决定。** 团队开发文档声明可用人群（Forge 权限集名称列表），随发布冻结；为空表示全组织可用。Weave 在团队列表与固定输入登记时校验当前会话的 Forge 权限集。
6. **状态推导回到服务端。** 团队运行的当前性与业务结果由 Weave 批量投影；Forge 提供本人审批事项的只读投影（含最新退回意见与分页）；消息种类只按准确 topic 识别。桌面只读取、映射和展示，读不完时明确提示。
7. **写入范围由 Host 展示。** Pi 选定本次业务动作后，桌面 Host 在对话中展示不经模型生成的范围卡片，并可直接取消该工作；不增加固定确认弹窗。
8. **事件同键同内容。** Forge 保存事件内容摘要，同一幂等键内容不同返回 `409`，Weave 将其视为永久失败。

## 实施与限制

- 第 1、2 项依赖 ObjectStack 17.3 是否允许插件为员工签发独立会话、MCP 入口是否接受该会话、动作上下文能否取得会话标识。实施前先验证并把结论补入本记录；原生能力不成立时，先回到本记录修订机制，不以共享管理员凭据或长期在线桌面代替。
- 124 为开发联调环境，数据可清空重建；本批不写旧账号绑定、旧委托或旧通知的迁移与兼容。清空后既有场景验收现场作废，合同续办须在新版本上重新从桌面发起验证。
- 本记录只确定方向，不表示已实现。各项实现与验收进展见[项目状态](../项目状态.md)与[问题清单](../plans/问题清单.md)。
