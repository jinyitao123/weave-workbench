# 项目管理配置页面合同

- RISEMAP 入口：`https://risemap.cn/settings/business/project`
- Forge 入口：`/_console/apps/forge/page/page_project_business_config`
- 岗位：项目管理员、项目经理、系统业务管理员
- 主数据：项目类型、项目角色、任务类型、闲置类别、工时类型、日志类型、日志标签、计划模板分类
- 主原型：配置型；顶部业务设置分类、左侧项目配置分类、右侧当前配置面板
- RISEMAP 当前事实：2026-09-21 在已登录内置浏览器实时核对八个分类。项目类型包含名称、颜色、启停、编辑、删除和拖拽排序；项目角色包含角色列表、系统角色标识及十二个项目模块的不可见/仅查看/可编辑权限矩阵；任务类型和日志标签带标签颜色；闲置类别、工时类型、日志类型为可排序启停字典；计划模板分类包含不可删除的默认分类。
- Forge 原表现：业务设置导航仅进入 `forge_project_type` 标准对象表，只有项目类型，缺少其余七类配置和角色权限矩阵。
- Forge 实现：新增统一项目管理配置页；项目类型继续使用 `forge_project_type` 并增加排序字段，其余七类使用 `forge_business_setting_option` 的 `project` 范围。所有列表支持新增、编辑、启停、拖拽排序和标准删除确认；系统预设项不可删除；角色权限矩阵保存到角色配置并可回读。
- 种子边界：仅写入 RISEMAP 当前已观察的项目角色、任务类型、闲置类别、工时类型、日志类型和默认模板分类；使用 `ignore` 模式，重启不会覆盖管理员修改或重新创建已删除配置。
- Forge 页面核对：完整重启同一 `.objectstack/data/objectstack.db` 后，八个分类及当前默认项均可回读；项目角色显示 13 个角色与十二模块权限矩阵。内置浏览器将“项目经理 / 概览”从可编辑改为仅查看并保存，出现“角色权限已保存”，随后恢复为可编辑并再次保存；任务类型新增弹窗空提交被“请填写名称和编码”阻断。
- 工程验证：`pnpm typecheck`、`pnpm validate`、`pnpm build` 与 `git diff --check` 通过；页面控件静态检查对本页无发现，当前全仓检查仍被七个既有页面控件问题阻断，未归入本页缺陷。
- 当前状态：实现与本轮页面交互已完成；结构化双视口像素证据尚未补齐，因此清单保持 `review_required`，不冒充仓库级 `accepted`。
