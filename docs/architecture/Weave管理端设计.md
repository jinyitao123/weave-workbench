# Weave 管理端设计

状态：2026-10-06 按[决策 003](../decisions/003-Weave独立管理端与身份接入.md)建立。本文是管理端的唯一主文档，回答目标、页面、状态规则、体验指标、接口缺口与分期；实施进展见[项目状态](../项目状态.md)。代码事实按当时 [components.lock.json](../../components.lock.json) 锁定的 Weave 版本核对。

## 目标与边界

管理端让开发者在一个网页里完成闭环：接入执行节点，配置环境与团队，提交真实开发任务，看清交接、实时输出、被验证的准确代码版本、执行证据和最终结论，并处理异常。典型团队是"Claude 分析、设计和写代码，Codex 验证测试"。

- 管理端只管 Weave 自己的事实：节点、环境、团队、任务、证据。业务记录、审批、员工待办与组织管理仍归接入的业务系统。
- 管理端可脱离 Workbench 与 Forge 使用；Forge 是可选集成，接入时才出现业务动作绑定与权限集选项。
- 体验以 Codex 云端任务为对标：一句话提交、提交后离开、回来先看改动与证据、一句话跟进、一键交付。

## 部署与源码

- 管理端编译后的静态资源打包进 Weave 服务端二进制，由 Weave 与接口同源提供；部署 Weave 即可使用，不另设网关或前端服务。
- 源码放在 Weave 源码主仓 `weave-next`，随 Weave 版本发布；总仓 `platform/weave` 按[版本锁](../../components.lock.json)同步，不在副本中直接修改。
- 构建先编译前端再编译服务端，镜像与发布产物同时包含两者；服务端只提供已打包的静态资源，不在运行时拉取前端。
- 当前已合实现入口是Weave API同源的`/admin`，默认端口8080；不依赖额外3080服务。源码合入／资源构建与线上实际部署分开核，当前联调环境尚未升级到这份管理端源码。

## 身份与权限

只做最基本的接入，不另建权限体系。

| 方式 | 适用 | 实现 |
| --- | --- | --- |
| 外部身份交换 | 正常使用 | 登录页先在 Forge 登录，再调用现有 `POST /v1/auth/external/exchange`。新产品实现同一个外部身份验证接口，返回稳定身份来源、用户、组织与角色 |
| 运维 API Key | 未接 Forge，或运维 | 使用 `weave bootstrap` 签发的管理员 API Key |

角色沿用现有三档：admin 管节点、模型供应方与全局配置；developer 配环境与团队、提交并查看任务；member 不作为第一阶段使用对象。本地密码登录与首用户注册保持关闭。因与接口同源，网页会话保存在 HttpOnly Cookie 中并做跨站请求校验，不放入页面脚本可读的存储。页面显示当前连接方式（HTTP 或 HTTPS）。

## 四个状态

四个状态分别判定、分别显示，任何页面都不合并为单一"成功"。

| 状态 | 判定依据 | 样式 |
| --- | --- | --- |
| 在线 | 最近 90 秒内有心跳 | 圆点 |
| 可接任务 | 在线、已启用、未吊销、未隔离、所需引擎可用、认证方式符合、有空闲槽位、协议版本受支持；不可接时给出原因 | 对勾，悬停显示原因 |
| 执行完成 | 运行或阶段为成功终态，节点回执与领取批次一致 | 中性蓝 |
| 验证通过 | 必需检查全部通过，且被验证的提交等于交付的提交；证据由节点执行或确定性比对产生 | 唯一使用绿色的状态 |

- 智能体在输出中声称测试通过，只显示为灰色虚线的"智能体声称"。
- 验证对象与交付提交不一致时，判为"验证对象不一致"，不通过。
- 证据缺失、截断或超出处理边界时，显示"无法确认"，不推断为通过。

## 页面体系

```
导航：任务（首页） · 环境 · 团队 · 节点          右上角：命令面板 · 通知 · 头像菜单（设置）
```

通用规则：

- 实时更新，不需要手动刷新；每个任务、阶段、日志行、提交对比都有可直达的链接。
- 空状态指向下一步。首次使用时首页显示引导清单：接入节点、建环境、建团队、提交第一个任务。
- 遵守本仓页面规则：不显示内部编号；选择器等控件使用产品统一组件，保留键盘操作与无障碍语义；只放完成任务所需的文字。提交 SHA、分支名是用户可读的代码版本，可以显示。
- 桌面宽屏为主；手机宽度可阅读任务进度与结论。

### 任务（首页）

- 顶部是输入框：写目标，选择环境、分支与团队（各环境记住默认值），可加附件，`⌘↵` 提交。没有节点能接所需引擎时，在输入框下直接说明缺什么并链接到节点页。
- 下方是任务列表，分为进行中、需要我看、已完成、已归档。每行显示标题、环境与分支、团队与版本、四态徽标、增删行数、耗时；排队中的任务显示排队位置与等待原因。
- "需要我看"包括：阶段失败、验证失败或无法确认、人工等待、节点异常导致的停滞。不再单独设置"待处理"页面。

### 任务详情

- 顶部：标题、环境与"基线提交 → 产出提交"、四态徽标；操作为跟进修复、推送分支、下载补丁、停止、重试、归档。
- 左栏是任务对话：
  - 你的要求与后续跟进；
  - 团队交接链：每一步写清交出方、接收方、交接的提交、文件与说明，可展开该阶段的实时输出；
  - 结论卡：被验证的提交、必需检查、未验证项和最终判断，由规则推出，每一条都能点到日志行或改动；
  - 底部是跟进输入框。
- 右栏四个标签：
  - 变更：文件树加 diff，可在基线与各阶段产出提交之间切换对比；
  - 日志：每个阶段的完整终端输出，可搜索，行可链接；
  - 证据：检查项、节点执行的命令、退出码、测试报告，以及它们绑定的提交；
  - 详情：节点、引擎及版本、用量、耗时、恢复与重试记录。
- 试跑与正式任务共用此页，试跑在标题上标注草稿修订号。

### 环境

环境对应 Codex 的"环境"概念，配置一次后退到幕后。

- 内容：仓库地址、可选的服务端访问令牌、默认分支、启动脚本、验证命令（测试、构建、检查）、是否推送结果分支、默认团队。环境变量与密钥、可用节点池、缓存状态尚未提供。
- 访问令牌只写不读：用服务端凭据密钥加密保存，页面只显示是否已保存；修改仓库地址而不重新填写时自动清除。保存令牌后，节点只能经服务端的任务级 git 代理拉取和推送这个任务冻结的仓库：仅在节点持有该运行中任务时可用，推送只能更新本任务的结果分支，上游重定向与认证失败不转给节点，节点拿不到令牌。不保存令牌时节点使用自己的 git 登录。仅支持 https 地址。
- "试一次环境"：在指定节点上执行一次启动脚本并显示日志。
- 团队的验证步骤引用环境声明的验证命令，同一团队可服务多个仓库。

### 团队

- 列表：名称、成员数、已发布版本、能否运行。
- 详情三个标签：
  - 成员：左侧列表，右侧配置，分区为职责、引擎与模型、节点池、技能、MCP、业务动作（仅接入 Forge 时出现）。选择引擎时实时显示可接该引擎的节点数。
  - 流程：宽画布，从左到右布局；步骤包括负责人、成员执行、并行、汇合、验证；"验证失败回到编码"的回路画在图上并显示最大轮数。当前以按顺序排列的步骤列表编辑串行流程，含并行或条件的流程只读并提示到桌面调整。
  - 验证退回：两步流程可打开"验证未通过时退回第一步"，并选择最多 1～5 轮。它直接使用工作流状态机已有的有界循环节点，不另建重试循环：验证步骤按固定结构输出"是否通过＋说明"，未通过且未到轮数时，说明作为下一轮编码的输入，编码从上一轮的提交继续。后续阶段的提示里写明平台在接手提交上实际运行的验证命令与退出码。是否退回由验证成员判断；页面的"验证通过"仍只由交付提交上的节点证据按规则推出，两者不一致时以规则结论为准。新建团队默认打开，3 轮。
  - CLI 成员（Claude、Codex、OpenCode）必须绑定一个提供该引擎的节点，不需要选择模型，使用节点自己的引擎登录；负责人可用不带模型的内置引擎。冻结的节点绑定以"节点＋版本"为身份但含引擎，所以同一次发布中一个节点只承担一种引擎，页面在保存前提示。
  - 试跑与发布：试跑进入任务详情页；发布门禁沿用桌面规则（当前草稿修订的每个流程都试跑成功才能发布），被拒时说明原因。
- 顶部常驻就绪检查，例如"验证步骤没有可执行的检查命令""编码成员的引擎没有可接节点"。
- 新建团队时预填"编码 + 验证"两名成员的初始草稿；不提供模板库。

### 节点

- 列表：名称、各引擎可用状态、槽位、版本、最近心跳。
- 接入：生成一次性安装命令；页面实时等待首次心跳，随后自动探测并报告各引擎结论。
- 详情（右侧抽屉）：
  - 引擎表：二进制版本、认证方式、可用性与原因；
  - 正在执行的任务；
  - 操作：改名、暂停与恢复接任务（暂停后不领新任务，已领取的继续完成，调度给出"已暂停"原因）、重新检测引擎（请求随下一次心跳到达节点，节点重新自检后重新上报）、轮换令牌（旧令牌立即失效）、删除；现有"停用"不可恢复，不在管理端提供；
  - Loom 诊断：Loom 二进制版本与事件格式契约版本；阶段级的检查点、恢复点、停止原因与预算在任务详情的"详情"标签显示。

### 设置（头像菜单）

模型供应方、MCP 服务、API Key、登录来源状态、集成（Forge 或其他产品，可选）。

## 主要流程

1. **部署与登录**：部署管理端，配置外部身份验证器；未接 Forge 时用 bootstrap 签发的 API Key 登录。
2. **接入节点**：新建节点，复制安装命令，在目标机器运行 `weave runtime`；页面依次显示在线、探测结果、可接任务。
3. **建环境**：填写仓库与凭据引用、默认分支、启动脚本与验证命令，"试一次环境"确认可用。
4. **配团队**：在预填草稿上调整成员引擎与模型、流程与回路、验证步骤；试跑成功后发布冻结版本。
5. **提交与观察**：首页一句话提交；详情页看交接、实时输出与改动。
6. **验收与交付**：结论卡按四态规则得出结果；推送到 `weave/` 前缀的分支或下载补丁。
7. **跟进与异常**：在同一任务内跟进，新一轮团队运行从上次产出的提交开始；阶段失败可在同一提交上重试或改派节点；节点异常可隔离、排空或停用；停止区分"已请求停止"与"已确认停止"。

## 桌面界面的去留

| 桌面现有部分 | 去向 |
| --- | --- |
| 团队分工：成员列表与成员配置 | 吸纳并升级为"团队·成员" |
| 工作流：窄画布、步骤检查器、流程图编辑 | 吸纳并升级为"团队·流程"，改宽画布并增加验证步骤 |
| 试跑面板与发布门禁 | 吸纳；试跑结果改用任务详情页，轮询改为流式 |
| 草稿修订与冲突处理 | 共用同一远端修订，管理端与桌面 Pi 修改互不覆盖 |
| 可用人群编辑 | 吸纳到团队设置，仅接入 Forge 时显示权限集 |
| 开发概览中的运行时与模型 | 运行时并入"节点"，模型并入"设置" |
| Pi 对话修改团队与修改提案 | 留在桌面 |
| "我的工作"：待办、审批、业务退回、消息 | 留在桌面，员工待办归 Forge 原生收件箱 |
| 会话中的团队运行卡片、取消、业务动作回执 | 留在桌面；回执"声称与证据分开"的规则推广到管理端证据面板 |
| 账号与登录设置 | 留在桌面 |

第一阶段管理端按同一技术栈（React、Vite、TypeScript、同一套产品控件）实现，与桌面共享接口契约类型；管理端稳定后再把画布、成员配置、试跑组件抽成共享包，桌面右侧栏改用共享包。共享包的发布方式（weave-next 发布包由桌面锁定版本引用，或桌面按版本锁同步一份副本）跨两个仓库，尚待决定；决定前管理端的流程编辑逻辑由 weave-next 中的工作流状态机校验样例约束，桌面保持现状。

## 体验指标

| 体验 | 目标 | Weave 现状 | 需要补的 |
| --- | --- | --- | --- |
| 提交到第一行输出 | 中位数不超过 10 秒 | 团队运行工作者每 2 秒轮询；节点领取后建临时目录并冷启动 CLI；没有代码检出 | 节点本地仓库镜像与预热工作树；提交后立即推流 |
| 输出延迟 | 不超过 1 秒 | 页面轮询活动接口；节点批量上报公开事件 | 服务端事件流；节点按秒小批量上报 |
| 日志 | 全量、可搜索、行可链接 | 每任务最多 512 条，只收文本与工具调用；只有 Codex、Claude 上报 | 全量日志作为带摘要的产物，分页读取；Loom、OpenCode 也上报 |
| 审阅 | 进入详情先看到改动 | 没有代码版本 | 记录基线与各阶段产出提交，按阶段对比 |
| 结论可信 | 每条结论能点到证据 | 只有确定性数据断言 | 节点执行验证命令，证据绑定提交，结论引用证据 |
| 跟进 | 一句话继续，沿用上次代码 | 只有桌面的输入替代与更正 | 任务内跟进，从上次产出提交起新一轮团队运行；CLI 会话可续接 |
| 交付 | 一键推送分支或下载补丁 | 没有 | 推送到 `weave/` 前缀的分支；合并请求后置 |
| 并行 | 同时多个任务，排队可见 | 有槽位，无排队展示 | 排队位置与等待原因 |
| 上手 | 15 分钟内跑通第一个任务 | 需命令行初始化，团队在桌面配置 | 引导清单与节点接入实时等待 |
| 手机 | 可读进度与结论 | 没有 | 响应式只读布局 |

在 Codex 体验之外，管理端保留四项差异：不同模型交叉验证；验证在用户自己的节点上执行且绑定提交；节点可直接使用本机已登录的 Claude 与 Codex 订阅；任务全过程可导出审计。

## 现有能力与缺口

| 领域 | 已有 | 缺口 |
| --- | --- | --- |
| 身份 | 外部身份交换（Forge 验证器）、API Key 与权限范围、三档角色 | 第二个验证器的配置选择；Cookie 会话与跨站请求校验 |
| 节点 | 一次性令牌注册与安装脚本、`weave runtime` 守护进程、引擎能力上报、90 秒在线窗口、健康与隔离、槽位与资源池；单节点详情、令牌轮换、与调度一致的可接任务结论、可恢复的暂停、主动重新检测（已补） | 节点上的任务列表 |
| 团队与流程 | 成员与引擎配置、顺序／并行／条件／循环／汇合／等待／交接节点、草稿校验试跑发布、准入；用循环节点实现的验证退回、JSON 节点结构约束下发到 CLI 成员（已补） | 画布编辑；节点绑定身份不含引擎（一个节点在一次发布中只能承担一种引擎）；脱离 Forge 时的可用范围说明 |
| 任务 | 仅凭任务文本即可提交、幂等请求号、停止、阶段重试、更正、人工等待；冻结的代码上下文、跟进、排队位置与等待原因（已补） | 运行中改派节点（见下） |
| 过程 | 阶段活动、成员输入来源、用量、检查点与轨迹读取；变更事件流、完整日志分页与搜索、Claude／Codex／OpenCode 实时公开事件、节点上 Loom 阶段的模型回复与工具调用日志（已补） | 节点上 Loom 阶段的逐字流式输出 |
| 结果 | 交付核验状态与运行状态已分开、确定性断言、业务回执核对、复查与历史版本；代码版本、节点执行的命令证据与代码结论、服务端托管令牌与任务级 git 代理、证据导出、GitHub 合并请求（已补） | 超过单文件 256 KB 的改动交接；GitHub 以外的合并请求 |

成员当前在节点的每任务临时目录执行，输入只能是不超过 8 MiB 的文件，产物从 `outputs/` 收集，见 [daemon.go](../../platform/weave/internal/app/daemon/daemon.go)；确定性核验按设计不执行代码，见[交付可计算核验契约](../../platform/weave/docs/架构/2026-09-13-交付可计算核验契约.md)。

## 需要补充的接口

接口先写入契约，写清调用者、身份、幂等、输入输出、错误、取消与审计，再实现。

- **节点**：单节点详情（含按引擎的可接任务结论与原因）；探测、启用、停用、排空、轮换令牌；节点上的任务列表。
- **环境**：环境的增删改查，凭据只存服务端；分支解析为提交；"试一次环境"。
- **代码版本**：任务提交时带环境与分支，按运行编号冻结代码上下文，节点领取 CLI 任务时随执行请求下发。环境未保存令牌时节点用自己的 git 登录拉取与推送；保存令牌后经任务级 git 代理（见"环境"）。每个阶段的提交是"基线提交＋该阶段的完整文件树"，作者、时间与说明固定，下一个节点用一份累计补丁精确还原并核对同一提交后才开始执行；补丁经现有阶段文件通道交接（单文件 256 KB），超出时明确失败而不截断。
- **验证与结论**：验证命令声明在环境中，每个阶段结束后由节点在该阶段的确切提交上直接执行（提交未变则沿用上游证据），记录命令、退出码、耗时、完整输出摘要与输出末尾；版本、补丁与证据文件由节点写入，成员不能覆盖。结论由服务端按规则推出：只有交付提交上的全部声明命令都通过才判为验证通过；成员在输出里的结论不计入。
- **过程**：任务变更事件流；阶段完整日志分页读取与搜索；Claude、Codex、OpenCode 上报公开事件，节点上的 Loom 阶段从它经过的模型与工具端口写日志。
- **跟进与交付**：任务内跟进，从上次产出提交起新一轮团队运行；推送到 `weave/` 前缀的分支；补丁下载。
- **交付扩展**：结束的任务导出只读证据文件（任务、各阶段确切提交、节点证据、规则结论与内容摘要，不含凭据与成员提示）；结果分支已推送且环境保存了令牌时，可在 GitHub 创建合并请求，每个结果分支一个，跟进复用。
- **异常**：排队位置与等待原因（已补）。运行中把某个阶段改派到其他节点与冻结发布冲突：节点绑定是发布的一部分，改动必须形成新发布。改派的做法是在团队里换节点、试跑并发布，再在原任务上跟进，新一轮从上次产出的提交继续；不在运行中改写冻结绑定。
