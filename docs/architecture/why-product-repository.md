# 为什么建立产品总仓

## 现在的问题

桌面助手、Weave 和 Forge 已经分别具备大量能力，但完整工作发生在三者之间。继续在三个仓库中独立推进，会让同一个业务概念出现多套定义，例如用户身份、任务状态、材料引用、取消结果和最终交付。组件各自通过测试，也可能无法完成一次真实业务。

之前 Workbench 的页面、Weave 的执行机制和 Forge 的业务能力多次交叉调整，已经说明仅靠文档约定无法长期保证一致。先有总仓，可以让一个产品改动以同一次审查覆盖桌面体验、平台契约、业务动作和验收场景。

## 总仓负责什么

总仓是产品组合和发布边界，负责：

1. 用户从桌面开始到业务结果完成的完整体验。
2. 三个组件共用的契约和版本组合。
3. 本地开发、远程 Forge 联调和桌面打包。
4. 跨员工、跨运行时、跨环境的验收场景。
5. 将来拆仓时可独立发布的目录边界。

## 总仓不改变什么

Weave 仍是通用智能体协作和执行平台，Forge 仍是通用业务平台，桌面仍可选择 Pi、Loom、Codex 等运行时。总仓不会把销售流程写进 Weave 内核，也不会把智能体调度写进 Forge。

## 为什么现在做

当前没有旧数据兼容负担，Forge 已先收束，桌面改造尚未产生功能提交。此时建立边界，迁移成本最低，也能避免后续 AI 修改继续把产品界面、执行内核和业务模块揉在一起。
