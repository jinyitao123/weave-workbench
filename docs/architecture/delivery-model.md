# 开发和发布方式

## 当前阶段

先在总仓中完成组合开发，目录边界直接采用未来分仓边界。三个来源版本写入 `components.lock.json`，任何联调和验收都以锁定组合为准。

## 开发环境

- 桌面应用在本地运行，macOS 先完成真人验证，Windows 持续保持构建能力。
- Weave 默认在本地启动，以便观察团队创建、执行、恢复和用量。
- Forge 可连接已经收束的远程开发环境。该环境启用 HTTPS 前，只允许健康检查和不含身份、令牌、材料的基础联通验证。
- Forge 功能开发在总仓的 `platform/forge` 中进行，写入验证使用本地或专用沙箱。

## 版本与发布

每次可验收版本都锁定桌面、Weave、Forge 和运行时适配版本。发布顺序是契约、Forge 动作、Weave 调用、桌面体验、跨组件验收。任一组件回滚时使用完整版本组合，不把未知的新旧版本混用。

## 未来分仓

当目录能够独立构建、独立发布，并且跨目录只通过 `contracts` 定义通信时，再把 `desktop`、`platform/weave` 和 `platform/forge` 分成独立仓库。总仓保留为产品组合、版本锁定和端到端验收仓。
