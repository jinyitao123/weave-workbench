# Forge 工作台与 RISEMAP 页面对照（2026-09-15）

## 范围与口径

本轮使用已登录的内置浏览器读取 RISEMAP 当前页面，并使用同一浏览器逐页检查 Forge。页面信息结构和交互事实以当前页面为准；Forge 继续使用 ObjectStack Console 与工作台既有的蓝绿色标题区、白色业务卡片、紧凑表格和标准弹窗，不追求平台外壳的像素级一致。

## 本轮内置浏览器证据

- RISEMAP：`https://risemap.cn/`、`https://risemap.cn/ai`、`https://risemap.cn/onboarding`、`https://risemap.cn/todos`。
- Forge：`page_workbench`、`page_workspace_ai`、`page_onboarding_center`、`page_todo_management`。
- RISEMAP 待办页打开了“新建待办”弹窗，仅用于读取字段，没有提交或修改线上数据。
- Forge 创建“工作台页面对照验收”待办，依次进入进行中和已完成；“完善公司主体信息”标记完成。两项均使用独立 SQLite 验收库保存，并在完整停服重启后通过页面与 API 回读。

## 响应式复核（独立分支）

本轮在内置浏览器中重新打开 RISEMAP `/`、`/ai`、`/onboarding`、`/todos`，并对 Forge 四个对应页面检查 `1440`、`768`、`390` 三档。RISEMAP 当前工作台域保持桌面最小宽度，窄视口依赖横向内容；Forge 作为 ObjectStack Console 页面采用适应内容区的响应式布局，这一呈现差异记录为 Forge 产品决策。

- `page_workbench`：员工服务在 `390` 下保持两列已接入入口，未接入的员工自助说明独占一行并完整换行；初始化、快捷操作和业务待办顺序不变。
- `page_workspace_ai`：`1440` 三列、`768` 两列、`390` 单列；搜索与清空动作换行，分类保持可横向访问，未开放场景仍无伪操作按钮。
- `page_onboarding_center`：`768` 以下搜索独占一行，四个状态筛选在 `390` 下完整显示；阶段导航可横向访问，步骤动作在窄屏移到正文下方，避免压缩标题和说明。
- `page_todo_management`：`1440` 保留八列表格；`768` 与 `390` 改为带字段名的记录卡片，快速访问改为横向导航。已实测空表单阻断、新建、开始、完成、重新打开入口、搜索与状态筛选。

四页仍保持 `review_required`。原因是 RISEMAP 缺少同一组材料的完整办理结果，且工作台资料管理、AI 执行能力、引导中心若干配置入口、待办清单/标签/附件/关注人编辑/动态流仍未实现；响应式通过不能替代这些业务证据。

## 风格决策

补齐页面与工作台共用一套设计语言：蓝绿色渐变标题区、相同的内容宽度与留白、白色业务卡片、低噪声状态色、紧凑表格、Console 标准选择器/日期控件/确认弹窗。RISEMAP 的业务结构和交互语义是对照基线，ObjectStack 工作台视觉是 Forge 的统一呈现基线。

## 剩余缺口与停止规则

以上缺口不计入完成能力。补充对应对象、权限和业务结果前，不新增可点击入口；发现当前 RISEMAP 页面变化时，先更新本页合同，再改 Forge。工作台四个入口之外的 RISEMAP 全站页面不属于本轮“工作台所有页面”的范围。
