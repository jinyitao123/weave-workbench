# Forge 采购发票与应付切片

## 结果

Forge 已把采购入库继续衔接到应付与进项发票。采购订单设置为“按入库产生应付”时，合格数量入库过账后自动生成一笔未付款应付。本轮验收的采购入库数量为 1，含税金额 6800，因此应付原值和余额均为 6800。随后登记同额进项发票，发票关联原应付，不重复生成账款。

RISEMAP 当前证据确认采购发票、应付账款和付款任务页面存在，也明确应付余额按“应付发生额减已付款核销额减调整核销额”计算，但尚未成功观察同一采购入库在何时生成应付、发票如何分摊以及付款如何核销。因此本切片保持待 RISEMAP 同输入复核状态。

## 已实现规则

- `payable_trigger=inbound` 的采购订单在合格数量入库时生成一笔应付账款。
- 应付原值取采购入库库存金额，初始已付款和已冲抵均为 0，应付余额等于原值。
- 每张采购入库单只允许登记一张有效进项发票。
- 进项发票数量、含税单价和价税合计取采购入库结果，避免调用方另填金额形成差异。
- 发票应付日期不得早于开票日期；登记后关联已有入库来源应付并补齐到期日期。

## 验收证据

API 验收覆盖入库自动确认应付、非法日期阻断、同额发票登记和重复发票阻断。完整停服并从同一 SQLite 文件重启后，进项发票、发票明细、采购入库与应付账款均以原 ID 回读，金额保持 6800。

页面检查确认 [进项发票](references/risemap-capture/deep/supply-chain/purchasing/rm-017/809-forge-purchase-invoice-list.png) 和 [应付账款](references/risemap-capture/deep/finance/funds/rm133/810-forge-accounts-payable-list.png) 均显示供应商、采购订单、来源单据、金额和状态。

## 保留边界

当前只支持每张采购入库单一张有效进项发票。发票查验、抵扣、红冲、作废、合并分摊、付款任务、资金账户、实际付款与核销尚未实现。ObjectStack 17.3.0 的动作事务受审计持久化超时影响，应付、发票及关联回写采用顺序写入，尚无原子回滚保证。
