# Forge 销售报价、合同与订单工作流切片

## 结果

Forge 已把 `报价草稿 → 报价审批 → 发送客户 → 客户接受 → 一键生成合同与明细 → 合同审批 → 一键生成订单与明细 → 订单审批 → 合同额度回写` 做成可调用、可持久保存的记录动作。该切片使用与 RISEMAP 相同的客户、成品、数量、价格、税率和折扣完成对照：2 台控制柜、含税单价 128000、税率 13%、折扣 5%、含税总额 243200。

这是一条可运行的销售主链，不是完整销售闭环。分批发货计划已在后续切片实现；仓库实际出库、开票、收款、收入确认和会计台账仍未实现。审批目前也没有岗位路由、意见、驳回、撤回和重提记录。

## RISEMAP 实测契约

| 环节 | 实测结果 | Forge 对照 |
| --- | --- | --- |
| 报价金额 | 明细 2 × 128000，整体折扣 5%，含税总额 243200，税额 27978.76 | `重新计算金额` 从明细回写折前金额、折扣、税额、含税总额和成本 |
| 报价生命周期 | 草稿、待审批、已审批、已发送、已接受；接受后同时显示已成交 | 四个受状态约束的记录动作依次推进到 `accepted` |
| 合同门槛 | 仅审批报价仍不能保存合同；实际提示要求报价“已审批且客户已接受” | `合同提交审批` 检查来源报价必须为 `accepted` |
| 折扣转换 | 报价整体 5% 折扣没有自动进入合同明细，合同初始为 256000；补录行折扣后为 243200 | Forge 报价明细本身保存 5% 折扣，一键转换按明细复制后合同直接为 243200；差异已显式记录 |
| 合同审批 | 提交并同意后为执行中 | 提交后为待审批，同意后为 `active`，界面标签为执行中 |
| 合同订单约束 | 合同声明总额和单品数量上限；订单审批后合同显示已下单 243200、剩余 0、100%、关联订单 1 | 提交订单时校验合同执行状态、金额额度、物料归属和数量上限 |
| 订单审批和回写 | SO-2026-0001 审批后为执行中，并回写合同执行额 | 同意订单在一个事务内把订单置为 `active`，再重算合同订单数、金额和行累计数量 |
| 付款条件 | 可配置订单生效后 30 天到期、提前 3 天提醒；订单详情仍显示付款方式未配置 | 仅保存订单付款字段，尚未实现付款条件对象、继承、提醒或应收生成 |

RISEMAP 终态证据位于 `2094` 至 `2097`：报价 `QT-OEM-20260909-001`、合同 `SC-OEM-20260909-001`、订单 `SO-2026-0001`。Forge 对照使用隔离夹具 `OEM-RM-20260909-A-sales-workflow-v0.2`，不会改变销售基础夹具。

## Forge 动作契约

| 对象 | 动作 | 前置状态或规则 | 结果 |
| --- | --- | --- | --- |
| 销售报价 | 重新计算金额 | 草稿且至少一条明细 | 从明细重算头部金额 |
| 销售报价 | 提交审批 | 草稿 | 待审批 |
| 销售报价 | 同意 | 待审批 | 已审批 |
| 销售报价 | 发送给客户 | 已审批 | 已发送 |
| 销售报价 | 标记客户接受 | 已发送 | 已接受 |
| 销售报价 | 转为合同 | 已接受；尚无来源合同；填写合同类型、编号、名称和日期 | 在同一事务创建合同及全部报价明细，额度等于报价总额 |
| 框架销售合同 | 提交审批 | 草稿；来源报价已接受；至少一条合同明细 | 重算合同总额并进入待审批 |
| 框架销售合同 | 同意 | 待审批 | 执行中 |
| 销售订单 | 提交审批 | 草稿；至少一条订单明细；合同执行中；未超金额和单品数量 | 重算订单总额并进入待审批 |
| 销售订单 | 同意 | 待审批 | 在同一事务内进入执行中并回写合同累计 |
| 框架销售合同 | 创建销售订单 | 执行中；尚无未取消订单；存在剩余数量 | 在同一事务按全部剩余数量创建订单与明细 |

动作只在允许的记录状态显示，并在服务端再次校验状态。匿名调用被拒绝。超出合同数量或金额的订单保持草稿，不产生合同累计。

## 验证与边界

`sales-workflow.integration.mjs` 已覆盖 7 项：隔离数据建立、未接受报价阻断合同、报价金额与完整顺序、合同审批、超限订单阻断、等额订单审批及事务回写、匿名动作拒绝。`sales-conversion.integration.mjs` 另覆盖 5 项：创建并接受转换报价、生成合同与复制明细、重复报价转换阻断、生成订单与复制剩余明细、重复订单转换阻断并审批回写。验收报告分别保存于 `.objectstack/acceptance/sales-workflow-report.json` 和 `.objectstack/acceptance/sales-conversion-report.json`。完整停服并从同一 SQLite 文件重启后，API 重新读取基础、工作流和转换三套记录，确认报价、合同、订单、来源关系、243200 金额和数量 2 累计仍存在；控制台页面也重新显示相同结果。页面证据包括 [报价转合同表单](references/risemap-capture/deep/sales/orders/rm-060/777-forge-quote-convert-dialog.png)、[合同转订单表单](references/risemap-capture/deep/sales/orders/rm-060/778-forge-contract-order-dialog.png)、[Forge 合同重启回读](references/risemap-capture/deep/sales/orders/rm-060/775-forge-contract-active-rollup.png) 和 [Forge 订单重启回读](references/risemap-capture/deep/sales/orders/rm-060/776-forge-order-active.png)。

当前转换边界是报价转框架合同，以及合同按全部剩余数量生成唯一一张未取消订单。分批释放、取消后重建、并发双击的数据库级幂等和报价直接转订单仍需补齐。后续优先进入审批岗位和意见轨迹，再进入发货、开票、收款及应收余额链。额度检查目前发生在订单提交阶段，真正的并发写入竞争仍需数据库约束或带锁事务验证。
