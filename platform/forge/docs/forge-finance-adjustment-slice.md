# Forge 发票部分红冲与冲抵撤回切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-finance-adjustments`，验收端口 `4374`，数据库 `.objectstack/otc-finance-adjustments.sqlite`。该库承接阶段 20 已停服的发票红冲验收快照；SQLite 完整性检查为 `ok`。

## 证据边界

RISEMAP 的 RM-145、RM-146 和 DR-1071 证明进销项发票有正常、作废、红冲状态，并明确销项发票承担红冲管理。公开更新记录进一步说明红冲会释放可开票额度、更新订单开票状态。现有证据没有成功部分红冲记录，也没有证明按数量还是按金额、审批、关账期间、抵扣、税务和总账规则。

本切片先实现可以由现有单明细发票和往来账严谨支撑的数量更正。预收预付冲抵撤回是 Forge 为恢复部分红冲前置账目而补齐的逆向能力，RISEMAP 同材料入口和行为仍待复核。

## 已实现行为

- 单明细蓝字销项发票可按未红冲数量分次生成红字发票与明细；原发票、应收、订单明细、订单、合同和项目已开票累计按比例回退。
- 单明细蓝字进项发票可按未红冲数量分次生成红字发票与明细；原发票和应付的已红冲金额与有效余额同步更新。
- 部分冲销保留 `partially_red_reversed`，累计冲完后进入 `red_reversed`。原明细记录累计红冲数量，审计记录保存本次金额和剩余有效金额。
- 销项侧存在有效回款、预收冲抵、收入确认或项目结算时阻断；进项侧存在付款、预付冲抵或有效付款任务时阻断。
- 客户预收冲抵撤回恢复预收余额、应收、发票、订单、合同和项目回款累计；供应商预付冲抵撤回恢复预付款与应付。两者不重复移动资金，并保留撤回人、时间和原因。
- 财务冲销页集中展示原额、已红冲、有效余额、冲抵状态与审计记录，可直接办理数量红冲和冲抵撤回。

## 验证结果

定向 API 验收 5 组全部通过。客户预收 `3000` 先冲抵 `1000` 再撤回，应收与发票恢复 `121600`；供应商预付 `3000` 先冲抵 `1200` 再撤回，应付恢复 `6800`，资金账户保持 `20000`。随后销项按数量红冲 `30400`、进项红冲 `1700`，并验证匿名、零数量、超量、有效冲抵和重复撤回阻断。

Chrome 隔离会话在同一财务冲销页再次办理两个方向的数量红冲，并撤回客户 `300`、供应商 `200` 冲抵。最终销项原额 `121600`、累计红冲 `60800`、有效余额 `60800`；进项原额 `6800`、累计红冲 `3400`、有效余额 `3400`。四笔冲抵均为已撤回，预收和预付款余额各为 `3000`，账户仍为 `20000`。

服务完整停止后以同一 SQLite 文件重启，原发票、四张部分红字发票、应收应付、四笔已撤回冲抵和四条部分红冲日志均按原记录回读；浏览器刷新金额与状态一致。合入同期项目计划工作台后的元数据门禁为 108 个对象、1731 个字段、26 个页面、133 个动作；`typecheck`、`validate` 和 `build` 均通过。

## 未证明范围

- RISEMAP 同材料部分红冲和冲抵撤回尚未实际办理，Forge 行为待对照。
- 当前部分红冲只支持单明细按数量，不支持多明细选择、按金额分摊、跨订单发票或红字信息表。
- 不含采购进项抵扣撤回、开票任务、作废、红冲审批、关账期间、总账凭证、税务申报和真实岗位权限。
- 多对象写入仍为顺序调用，没有数据库事务级原子回滚；并发更正和失败补偿尚未证明。
