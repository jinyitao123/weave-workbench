**前端资源抽查说明了什么**

工时页面样本中可直接读到“闲置时长”输入的前端最小值 0.5、最大值 24 和步进 0.5。这个发现只针对该字段的前端行为，不能推广为所有工时记录、每日累计工时或服务端约束。

项目配置脚本包含角色费率、薪资折算和管理加成的界面说明；税价计算帮助脚本也可读取。这些线索足以减少通过反复点击才能获取字段、选项和计算方式的工作。已下载脚本仍为压缩编译产物，需要结合调用位置理解。

本轮抽查的入口与业务样本中没有 `sourceMappingURL` 引用，不能据此声称整个网站完全没有 source map。没有取得原始源码仓库、数据库结构、服务端实现或部署配置。

下载这些构建产物可以保留前端证据，但不能直接得到独立运行的完整应用。前端仍调用原服务，原服务承担持久数据、权限、审批和跨单据处理。若试图复用整个编译前端，需要实现其全部后端接口约定，长期修改也缺少原始源码；这未必比在 ObjectStack 上重建更省工。

**建议替换原先取证工作的重心**

1. 先整理现有公开资料，按模块将流程、角色、单据、关键校验和更新日志关联到 RM 功能编号。生成规格初稿、明确未知项，证据足够的功能立即进入实现。
2. 按模块静态分析已经公开引用的前端资源，提取字段、选项、默认值、前端校验、请求结构和页面组织。优先基础资料、报价订单、项目、工时与成本。需要其他分块时沿已发现引用取得，不探测未公开接口或后台路径。
3. 使用浏览器集中核验状态变更、审批、跨单据联动、数量金额、分批退货冲销、角色权限、真实导出及配置影响。每次实际操作继续保留步骤证据，不为生成截图重复操作已经明确且无新问题的内容。
4. 文档、前端实现和当前页面冲突时建立差异记录。以选定目标版本、租户配置与实际运行结果确定复刻行为，不能静默覆盖另一来源。若实际行为有缺陷，原样记录，修复作为显式差异决定。
5. 用同输入对照持续反推补证问题。通用控件和共享规则按可证明的共用实现复用结论，特殊分支单独验证；完整功能清单保留覆盖责任。

规格建议至少区分 `published_guide`、`published_example`、`release_note`、`frontend_static`、`runtime_observed`、`forge_verified`。一个字段可以有多个来源，不用单一“已验证”掩盖静态声明与运行事实之间的区别。
