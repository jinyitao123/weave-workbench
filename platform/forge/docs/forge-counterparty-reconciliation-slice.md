# Forge 往来对账单切片

更新于 2026-09-10，当前实现位于隔离分支 `codex/otc-counterparty-reconciliation`。

## 证据与范围

RISEMAP 的 RM-143 对账中心已有只读证据。DR-1062 至 DR-1068 证明它分为客户应收和供应商应付，状态包含草稿、已发送待确认、已确认、有差异和已关闭，并核对期初、本期应收或应付、本期收款或付款、期末余额。生成表单还展示客户/供应商、六种汇总维度、期间、四种生成依据和预收预付等高级口径。

本切片只实现已有账务对象能够严谨支撑的“往来单位余额口径”。它从已生效应收应付、已审核收付款核销以及可选预收预付冲抵生成不可变期间快照；其他维度、发货收货口径、合同执行口径和对外真实发送渠道继续保留为待实现边界。

## 实现

- `forge_counterparty_statement` 保存往来方向、期间、口径、期初、本期发生、本期收付、期末、状态和差异结果。
- `forge_counterparty_statement_line` 按日期保存应收应付、收付款核销与预收预付冲抵明细及逐行余额。
- `forge_counterparty_statement_log` 保存生成、发送、确认一致、反馈差异和关闭的操作人、时间与说明。
- 客户和供应商分别提供生成动作；对账单提供登记发送、登记确认和关闭差异动作。
- 生成后快照不随底层账目变化，避免后续收付款改写已经发出的对账依据。
- `page_counterparty_reconciliation` 在同一页面办理客户与供应商对账，并显示余额、差异和审计数量。

## 验证结果

隔离地址为 `http://localhost:4373`，数据库为 `.objectstack/otc-counterparty-reconciliation.sqlite`。

API 验收 5 组通过：匿名访问、无效期间和未实现口径被阻断；客户对账为期初 `243200`、本期收款及预收冲抵 `1500`、期末 `241700`；供应商对账为期初 `6800`、本期付款及预付冲抵 `2500`、期末 `4300`；一致确认与 `100` 差异关闭均形成审计；底账新增 `900` 收款后原快照仍保持 `241700`。

Chrome 隔离会话实际办理第二套记录。客户对账纳入后续 `900` 收款，期末为 `240800` 并确认一致；供应商对账期末 `4300`，以对方确认 `4200` 形成 `100` 差异后关闭。最终保存 4 张对账单、9 条冻结明细和 14 条操作记录。

服务完整停止后以同一 SQLite 重启，四张对账单状态、9 条明细和 14 条日志均按原记录回读；浏览器刷新金额与状态一致，SQLite 完整性检查为 `ok`。最终 `typecheck`、`validate` 和 `build` 均通过。

## 未覆盖

- RISEMAP 同材料对账单仍未实际生成、发送或确认，Forge 行为待对照。
- 合同、订单、发货/收货、发票等维度和按发货、开票、余额、合同执行四种依据尚未实现。
- 当前“发送”只登记接收对象和时间，没有真实邮件、下载文件、打印版式或客户/供应商门户回执。
- 不含红字与退货专项展示、未开票业务、税额拆分、币种换算、差异调账、关账期间、角色权限和事务级原子回滚。
- 银行流水导入与逐笔勾兑不属于当前 RISEMAP RM-143 证据所示对账单范围，仍未实现。
