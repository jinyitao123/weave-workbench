# RISEMAP 完整复刻与采集标准

更新于 2026-09-09。发起人明确要求完整复刻 RISEMAP。此前八个页面、柜机优先和缩小首版范围的建议停止作为当前复刻范围依据。完成复刻后，再结合 OEM 企业运营现状、内部业务方法和更多客户材料讨论适配。

## 完成目标

以厂商提供的 https://risemap.cn 为参照，覆盖该产品全部模块、页面、交互、业务规则、状态变化、角色权限、配置、报表及可使用的集成能力。执行方式改为按业务块滚动开展“取证、实现、同输入对照、定向补证”。全量目标和逐步截图要求保留，不能因先做某条业务路径、某个实现批次或某次对照通过而删减完整复刻范围。

完整覆盖必须以可核查清单为依据。试用版未开放的模块、其他角色入口、厂商后台及外部集成列为待取得证据的缺口。当前账号能够访问的部分不自动等于产品全集。根据页面只能重建可观察行为，不能据此声称取得或还原厂商内部源码与部署实现。未知项不能默认为原系统事实，也不能被占位行为冒充完成。

Forge 仍须达到真实客户使用要求，包括持久保存、客户隔离、备份恢复、持续部署和维护。页面相似、菜单齐全或单条流程跑通都不构成完整复刻验收。原三到四周只保留历史目标，完整盘点后重新估算工作量，不通过暗中裁剪模块兑现旧时间。

## 每个功能怎样采集

| 层次 | 必须记录的内容 | 证据及验收方式 |
| --- | --- | --- |
| 全量导航 | 模块、菜单、子页、弹窗、抽屉、页签、配置入口及角色可见性 | 功能编号与导航清单，逐个标记已发现、已采集或缺口 |
| 页面外观 | 布局、尺寸、颜色、字体、图标、间距、表格、表单、反馈和响应式状态 | 记录视口、角色、数据条件和截图，相同条件下对照 |
| 字段与表单 | 类型、必填、默认值、选项来源、关联选择、联动、精度、唯一性和校验提示 | 字段字典，正常值及边界输入的实际结果 |
| 操作行为 | 搜索、筛选、排序、分页、批量操作、新增编辑、复制、导入导出、打印、附件 | 操作前提、输入、步骤、结果及产物样本 |
| 业务流程 | 发起、提交、审核、驳回、撤回、重提、变更、完成及作废等实际存在的动作 | 状态转换表与逐步操作记录，记录下游单据和通知变化 |
| 数据关联 | 客户、报价、合同、订单、采购、库存、项目、资金等实际对象关系 | 同一测试业务贯穿多模块，核对来源、数量、金额和版本 |
| 角色权限 | 菜单、记录、字段、动作、审批分工、数据范围和导出附件权限 | 用不同身份实际查看和办理，管理员结果不能代替其他角色结果 |
| 异常及恢复 | 空数据、非法输入、重复操作、取消、权限不足、驳回、并发编辑和失败后续办 | 记录系统真实反馈，不把未观察行为自行补成原系统事实 |
| 配置与集成 | 初始化、组织岗位、编号字典、自定义字段、流程、通知、财务规则及实际集成 | 配置前后行为对照，外部依赖未具备时保留未验证状态 |

发起人明确要求逐步截图。每次业务操作都保存截图并编号，记录操作前后关系；弹窗、校验、加载、成功或失败及不同角色状态各自留证。重复画面也保持步骤编号，不因去重丢失操作过程。截图与结构化操作记录共同承担复现和验收依据。采集目录为 `docs/references/risemap-capture/`。

每条证据保存采集时间、账号角色、页面位置、前置数据、输入动作、预期或待探明问题、实际结果、关联记录和截图编号。凭据、会话令牌不进入文档或证据包。

## 执行顺序

1. 保留全量目标、试用空间逐步操作和截图留证要求；试用期优先采集到期后难以补齐的业务行为证据。
2. 建立并持续维护 [RISEMAP 滚动复刻交接表](risemap-rolling-handoff.md)，每个业务块记录 RM 编号、证据状态、共享对象依赖、已确认规则、未知项、同输入测试案例、实现状态和对照结果。
3. 第一批实现从公共模型和已有有效操作证据的基础资料开始，统一客户、供应商、物料、单据明细、金额精度、附件、身份与业务关联，公共定义由一处维护。
4. 一个业务块在核心字段、关系、正常路径明确，至少有效保存并核对结果，具备可重复输入与预期结果时即可开工；尚未确认的状态、权限或下游影响列入补证项，并限制完成声明。
5. 报价与订单、采购到入库、发货到开票应收收款、审批通过/驳回/撤回、分批/退货/冲销/变更、岗位权限、项目计划/工时/成本/交付包/验收、导入导出和打印产物优先补证。
6. 实现结果必须是实际可运行、可持久保存、能够通过页面办理的功能。首屏、状态枚举、空表单校验或说明文字只证明可观察界面，不证明业务链通过。
7. 用同一版本测试数据持续对照 RISEMAP 与 Forge。遇到规格空白时，在试用期内定向返回原系统核验，并维护差异与补证清单。
8. 同步进行有明确边界的 ObjectStack 技术初筛，固定准确版本及依赖，验证持久化、服务端规则、审批等待重启、重复订单转换、版本保护、岗位权限和正式编译运行；若核心阻塞，记录复现和影响。
9. 全量功能清单、跨模块流程、角色权限、配置、报表、可用集成和正式运行条件全部通过后，才声明完成复刻；OEM 适配另行建表、决策和验收。

## 当前已观察结果

已完成初始化、全量导航首轮采集和大量深度操作证据。当前页面契约已登记到 RM-181，覆盖工作台、供应链、销售、生产、项目、行政、财务、报表和系统入口；其中许多条目仍只是首屏或空表单证据，不能视为业务能力验收通过。

2026-09-09 证据纠错：2085 的 BOM 保存失败；2089 重试保存后，经 2090 列表、2091 详情及 2092 结构重新核对，BOM 草稿持久保存才得到证明。详见滚动交接表。
