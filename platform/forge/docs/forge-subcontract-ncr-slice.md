# Forge 委外 NCR 四类处置切片

更新于 2026-09-12。本切片承接委外回厂验收：任一回厂明细出现不合格数量，提交时自动生成独立 NCR，并保存来源回厂单、订单、供应商、物料、仓库和不合格数量。NCR 经过处置方案、提交审批、审核和执行后，回写来源回厂单与委外订单。

当前实现四种物理处置。退货、报废和返工只登记处置数量，不进入正式库存；特采生成独立的委外特采入库单，以零值增加正式库存并形成 `subcontract_ncr_concession` 库存流水。零值只表示本切片尚未建立不良品计价依据，后续财务调整不能从当前实现外推。

API 验收从同一包工包料订单建立四张全不良回厂单，分别完成退货、特采、报废和返工。验收覆盖匿名访问、处置数量不完整、越级执行、重复执行和来源状态门槛。最终订单四类处置累计均为 `1`；只有特采增加正式库存 `1`，库存金额和流水金额均为 `0`；四张 NCR 共保存 `20` 条操作记录。

Codex 内置浏览器另从受控回厂动作生成 `SR-NCR-BROWSER-001`，在委外不合格处理页面填写返工方案、提交审批、审核通过并执行。页面最终显示 `5` 张 NCR 全部已执行、特采入库 `1` 件和操作记录 `25` 条。服务完整停止并从同一 `.objectstack/otc-subcontract-ncr.sqlite` 重启后，API 按原 ID 回读五张 NCR、五张来源回厂单、零值特采入库、库存余额、库存流水和全部操作记录。

RISEMAP 实时只读证据确认 `/inventory/ncr` 的状态筛选为待提交、审批中、已通过、已驳回、已执行；处置筛选包含退货、特采、拒收、报废、复检、返工和供应商赔偿。当前有可见详情操作证据的只有让步接收，其余三类仅取得列表枚举，因此 Forge 四类处置仍需 RISEMAP 同材料复核。拒收、复检、供应商赔偿、财务赔扣、退料、对账、应付、岗位权限、并发事务和撤销不属于本切片。
