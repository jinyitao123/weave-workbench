# Forge 复刻作业顺序基线

日期：2026-09-13  
状态：实施顺序已冻结，按功能逐块推进。  
适用范围：RISEMAP 公开流程与教程证据、汇川 OTC 业务链、Forge 页面复刻。

## 结论

Forge 后续不再按对象数量、接口数量或孤立页面推进。每个功能块必须放回以下三层顺序中：

1. **系统配置顺序**：回答“系统怎样准备好”。
2. **业务办理顺序**：回答“岗位怎样连续完成工作”。
3. **OTC 交付顺序**：回答“项目怎样从客户需求走到结项”。

三层顺序不能互相替代。RISEMAP 教程目录是配置参考，RISEMAP 业务流程是岗位和单据承接参考，汇川 OTC 是跨模块产品闭环参考。

## 三层基线

### 1. RISEMAP 系统配置顺序

根据已保存教程目录，配置顺序为：

1. 个人中心与组织基础配置
2. 流程中心
3. 基础资料
4. 字段管理
5. 业务设置
6. 期初入库、应收、应付
7. 采购管理
8. CRM 与销售
9. 库存管理
10. 组装管理
11. 销售回款与采购付款流程

该顺序只用于判断配置依赖，不作为业务菜单或用户办理路径。证据：`docs/references/risemap-public/20260909T015246Z/community/tutorials.txt`。

### 2. RISEMAP 业务办理顺序

RISEMAP 公开流程不是一条单线，而是按业务域拆成多个可穿透流程：

- **销售与项目**：价格策略 → 销售合同/订单 → 项目创建 → 项目计划与执行 → 交付/验收 → 收入确认 → 应收与收款。
- **采购与供应链**：采购申请 → 采购订单 → 供应商发货 → 到货登记 → 检验或免检 → 合格入库/不合格处置 → 应付 → 付款核销。
- **项目成本**：项目配置 → 工时填报 → 工时成本 → 归集到项目/订单/合同 → 项目分析。
- **仓储质量**：采购或委外到货 → 待检库存 → 检验 → 合格入库、不合格处理、拒收退回或让步接收。
- **财务闭环**：收入/应收来源或采购/应付来源 → 发票、收付款 → 认款/付款 → 核销 → 经营分析。

其中“销售到收款”和“费用报销”在公开页面被标为示例，不能单独作为强制规则；其他公开流程也必须在 RISEMAP 当前租户中继续复核。证据：`docs/references/risemap-public/20260909T015246Z/flows.json` 和 `docs/risemap-public-reference-findings.md`。

### 3. 汇川 OTC 交付顺序

作为跨模块产品主线，Forge 保留以下九阶段：

1. 客户需求与立项
2. 报价、合同与订单
3. 项目计划与方案设计
4. 采购与物料齐套
5. 制造与装配
6. 发运与现场交付
7. 集成调试与验收
8. 开票与回款
9. 结项与经营复盘

公共主数据、权限、审批、编号、字段、集成、导入导出和打印是全流程支撑能力，不插入主导航阶段。证据：`docs/forge-otc-information-architecture.md`。

## 当前先做什么

**下一块先做“项目计划与任务”，不是采购、行政或委外。**

理由有三点：

1. RISEMAP 的“项目创建与管理”流程在项目创建完成后明确进入“项目计划管理”，随后才进入项目执行。
2. 汇川 OTC 的第三阶段是“计划与方案设计”，它承接项目立项和销售订单，也是采购、制造、委外和交付的上游依据。
3. 当前 Forge 已有项目计划对象、阶段/里程碑/任务和部分进度能力，最适合先把已有能力收敛成岗位可连续办理的页面，避免继续产生孤立对象。

## 项目计划块的最小交付范围

第一轮只做以下连续路径：

```text
项目中心
  → 打开项目详情
  → 进入项目计划
  → 新建或套用计划
  → 新建阶段 / 里程碑 / 任务
  → 指定负责人、日期和前置任务
  → 更新任务状态与进度
  → 填写并回读日报
  → 在项目详情看到计划进度和下一步
```

必须覆盖：

- 项目上下文保持一致，不默认选第一条项目；
- 计划树、任务列表和甘特视图使用同一数据；
- 任务状态、进度、负责人、计划日期和实际日期可回读；
- 至少一个前置任务未完成时的阻断或提示；
- 操作成功后返回当前项目上下文，而不是跳到原始对象列表；
- 同一 SQLite 完整停服重启后，计划、任务、进度和日报仍可读取；
- RISEMAP 页面证据、Forge 页面操作、API 结果和重启结果分别记录。

第一轮不加入尚未有证据的自动排程、关键路径计算、复杂基线、客户门户和新的计划对象模型。

## 每个功能块的固定作业步骤

1. 建立页面合同：入口、岗位、主单据、字段、状态、动作、阻断、来源、下一步和证据分类。
2. 对照 RISEMAP 当前页面和已保存公开流程，区分观察事实、Forge 工程推断、待复核行为和未执行实验。
3. 盘点可复用对象、服务和动作，先确认语义边界，再设计页面。
4. 在独立分支和 worktree 实现，导航、共享 barrel、`package.json` 等冲突回主线处理。
5. 用真实业务材料完成正常路径和至少一个关键异常路径。
6. 验证 API、内置浏览器、同一 SQLite 停服重启回读和页面上下文连续性。
7. 与 RISEMAP 做并排结构和行为对照，记录差异，不把 Forge 独立实现写成 RISEMAP 已证明行为。
8. 通过本块门禁后，才进入队列中的下一块。

## 停止规则

出现以下任一情况，停止扩展新页面，先修当前功能块：

- 页面只能从技术对象列表进入，不能从岗位任务或当前单据进入下一步；
- 状态、金额、数量、来源或责任人不能在详情和重启后回读；
- 正常路径需要 API 预制数据才能在浏览器办理；
- 异常路径没有明确阻断、原因和下一步；
- RISEMAP 对照证据不足，却准备把工程推断写成产品规则；
- 构建或健康检查通过，但真实业务结果尚未形成闭环。
