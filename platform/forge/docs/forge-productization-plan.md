## 页面架构

1. 统一业务壳层。承接九阶段导航，提供清晰的当前项目/当前单据、面包屑和返回路径。项目选择只过滤有真实关联的记录；缺少关联时要求用户选择，不能用默认第一条记录冒充上下文。
2. 三种稳定页面模板。列表页负责筛选与选择；单据详情页负责状态、摘要、明细、关联单据和审批历史；工作台负责 BOM 树、项目甘特等组合视图。新建和阶段性动作在独立表单、抽屉或对话框中办理。
3. 统一组件。统一标题状态区、工具栏、页签、紧凑字段组、可编辑明细表、金额数量显示、记录选择器、空态、加载、错误与成功反馈。样式和组件统一维护，逐页嵌入源码不再各自复制整套视觉规则。
4. 业务访问适配。保留现有同源会话和 `/api/v1`，读取对象和调用既有业务动作。金额、库存、进度回算和状态转换继续由业务层决定。显示层可以格式化数值，不能另建一套计算口径。
5. 生产界面与开发控制台分开定位。当前控制台继续承担检查元数据和原始对象的用途，产品入口不直接展示明细表/审批日志对象清单。第一批必须验证现有自定义 React 渲染入口能否稳定承载业务壳层、路由、样式隔离与共享组件；若只能通过隐藏宿主 DOM 实现，则改用同仓独立前端入口承载同一组件及 API 适配，保留 ObjectStack 业务运行时。此项是短小的运行验证，不预先宣称框架能力已满足。

## 具体改造规则

- 导航只保留用户办理业务的入口。订单明细、BOM 节点、审批日志、到货行等从对应单据的页签或子表进入。
- 列表是进入业务的默认起点，创建表单不常驻列表顶部。保留搜索、必要状态筛选、清晰空态、分页和记录打开路径。
- 主操作跟随单据当前状态；其他操作放入次级区。真实权限尚未提供时，不把前端隐藏按钮称为权限控制。
- 去掉浏览器验收单号、固定数量、固定理由、默认第一条供应商/仓库等测试用预填。只保留可解释且不会误选业务记录的默认值。
- 将浏览器原生 prompt/alert 换成一致的业务对话框和就地错误反馈。提交失败保留输入；提交中防重复；成功后回读当前记录及关联结果。
- 空数据、无权限、请求失败和能力未实现分别处理。不能把失败显示成“暂无数据”，也不能以说明文字代替已实现动作。
- 宽表允许容器内横向滚动，保留关键识别列；页面整体不得横向溢出。金额右对齐，数量和金额分别遵守业务精度，状态用文字和适量颜色共同表达。
- 控制台元数据、调试标识、RISEMAP 对照说明留在开发和验收材料，不进入正式业务文案。

## 完成标准

每页单独记录四个状态：业务能力已交付、页面已实现、Forge 页面验收通过、RISEMAP 对照通过。不得用一个“完成”覆盖四者。

1. 页面契约有对应 RISEMAP 截图/操作证据，标明已知差异、未实现功能和布局参考来源。
2. 以同一窗口尺寸核对标题、操作、页签、字段、明细、密度和反馈；桌面至少检查 1440×900 与 1280×800。
3. 用内置浏览器完成一次真实办理，从选择记录开始，到提交、看到结果及重新进入同一单据结束；拒绝路径也要有适当证据。
4. 对照 API 验证记录 ID、关联、数量、金额、状态；涉及持久状态，完整停服并从同库重启后再从页面读取。
5. 元数据修改执行 typecheck、validate、build，并运行对应业务链已有验收；共享组件改动检查受影响代表页面，不写只复述组件实现的测试。
6. 保存页面截图、输入场景、API 回读摘要、数据库路径和提交版本。没有 RISEMAP 成功对照的流程继续标记待复核。
