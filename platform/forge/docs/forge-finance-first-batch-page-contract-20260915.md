## 客户预收款 `page_customer_prepayment`

- RISEMAP 入口：财务 → 收款管理 → 预收款管理（`/finance/payment-collections`）。
- RISEMAP 当前事实：维度为待确认、全部、按客户、订单预收；展示预收款余额、已冲抵、客户数、订单预收笔数，以及客户和订单 Top 汇总；当前无记录。
- 岗位与主单据：财务收款岗；客户预收款及关联销售订单、收款流水、应收款。
- 页面职责：先判断预收余额和待确认任务，再登记订单预收；到账后确认，随后按同订单应收冲抵，未使用余额可申请退款。
- 首屏结构：业务标题与主动作 → 业务说明 → 四项指标 → 业务维度 → 明细或客户/订单汇总。
- 动作与阻断：主动作是“登记订单预收”；登记、到账确认、冲抵和退款均在上下文弹窗办理。缺少订单、账户、流水号、金额或日期时阻断提交；金额和状态继续由既有 Action 校验。
- 来源与下一步：销售订单 → 收款流水/预收款 → 到账确认 → 应收冲抵或客户退款。
- Forge 产品扩展：将后续办理动作放入行上下文弹窗，并给出下一步文案；不把未实现能力显示成按钮。
- 未决项：RISEMAP 同材料登记、确认、冲抵与退款路径待复核；删除和逆向处理不在本批事实范围。

## 采购付款 `page_purchase_payment`

- RISEMAP 入口：财务 → 付款管理（`/finance/payment-writeoffs`）。
- RISEMAP 当前事实：付款任务、预付款管理两个页签；支持批量登记付款和导出；按状态、来源筛选；付款任务表当前无记录。
- 岗位与主单据：业务申请人、付款审批人、财务出纳、核销复核人；付款任务、实际付款、应付核销、供应商预付款。
- 页面职责：业务提交付款申请，审批后由财务登记实际出账并核销；合同预付进入独立预付款余额，后续冲抵应付或申请供应商退款。
- 首屏结构：业务标题与当前页签主动作 → 页签 → 办理说明 → 四项指标 → 任务/付款视图 → 搜索及状态、来源筛选 → 明细。
- 动作与阻断：申请、审批/驳回、实际付款、核销审批/撤销/冲回、预付冲抵/退款均在上下文弹窗办理。空必填项、超额申请、账户不可用、余额不足和状态不匹配由页面必填校验及既有 Action 阻断。
- 来源与下一步：应付或采购订单 → 付款任务 → 审批 → 实际出账 → 核销；采购订单 → 预付款 → 应付冲抵或供应商退款。
- Forge 产品扩展：保留单笔登记作为当前可办理主路径；RISEMAP 的“批量登记付款”仅作为已观察事实，未实现前不放置假入口。
- 未决项：RISEMAP 同材料成功付款、预付、冲抵和退款待复核；批量付款的字段和阻断证据不足。

## 供应商退款 `page_supplier_refund`

- RISEMAP 入口：财务 → 退款申请（`/finance/refunds`）。
- RISEMAP 当前事实：客户退款、供应商退款两个页签及数量；支持导出、状态筛选；列表展示退款单、关联合同/订单、往来单位、实退金额、方式、单据状态、收付款状态、核销状态、申请日期；当前无记录。
- 岗位与主单据：业务申请人、财务审批人、出纳、核销复核人；供应商退款申请及关联采购订单/合同、预付款、到账流水。
- 页面职责：统一查看客户和供应商退款；供应商退款按申请、审批、实际到账、核销顺序办理。
- 首屏结构：业务标题与导出/刷新 → 客户/供应商页签 → 搜索和状态筛选 → 十二列退款列表 → 分页。
- 动作与阻断：选中待办行后在上下文弹窗审批/驳回、登记到账或核销。审批意见、账户、实收金额、银行流水和核销意见按步骤校验；状态和金额由既有 Action 再次阻断。
- 来源与下一步：供应商预付款 → 退款申请 → 财务审批 → 实际到账 → 核销完成。
- Forge 产品扩展：客户退款与供应商退款在同一页面分栏查看；供应商办理动作只在符合状态的行出现。
- 未决项：RISEMAP 同材料供应商退款成功路径待复核；当前账号空数据无法核对动作出现条件和弹窗字段。
