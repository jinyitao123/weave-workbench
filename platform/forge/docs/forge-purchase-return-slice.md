# Forge 采购退货退款切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-purchase-return`，验收端口 `4367`，数据库 `.objectstack/otc-purchase-return.sqlite`。该库承接已停服的采购付款与供应商预付款数据，通过非破坏性同步加入采购退换货、明细、审批记录和退款流水；SQLite 完整性检查为 `ok`。

## 证据边界

RISEMAP 的采购退换货列表和表单证明退货退款与换货补货共享来源采购订单，记录供应商、处理方式、预计补货日、退货原因和退款或参考货值；采购退换货出库由退货单驱动，没有手工新建入口。依据来自 RM-022、RM-044、DR-0055 至 DR-0058、DR-0163。当前未在 RISEMAP 保存同材料采购退货，因此状态和结果仍属于待复核实现。

## 已实现行为

- 已审核且已有入库数量的采购订单可按原订单明细发起退货退款。系统按原含税单价计算参考货值，并同时校验已入库未退数量、未驳回申请占用和所选仓库可用库存。
- 草稿提交后由财务审批。驳回会释放申请占用；审批通过后，仓库再次核对实物和可用库存，再进入退货出库。
- 出库按库存当前平均成本减少在手、可用数量和库存价值，写采购退货出库流水，并累计采购订单及明细的已退数量。出库前不改库存。
- 供应商退款只接受与审批参考货值完全一致的金额。到账生成独立退款流水，增加指定资金账户，并把退货单置为已完成。
- 采购退换货页面可完成草稿、提交、审批、仓库确认、出库和退款到账，并显示财务、仓库、出库和退款状态。

## 验证结果

定向 API 验收共 6 组。驳回 `0.7` 件申请后释放占用；随后为原采购明细退货 `0.4` 件，参考货值与库存成本均为 `2720`。出库后库存由 `1` 降至 `0.6`、库存价值由 `6800` 降至 `4080`，采购明细累计已退 `0.4`；供应商退款使 API 账户由 `5000` 增至 `7720`。匿名、超量、重复提交、重复出库、退款金额不一致和重复退款均被阻断。

浏览器独立办理 `PR-BROWSER-20260910-001 → PRR-BROWSER-20260910-001`，完整点击六步流程。退货 `0.2` 件、退款 `1360` 后，页面显示已完成、仓库已确认、已出库和已收款；库存降至 `0.4`、价值降至 `2720`，浏览器账户由 `2100` 增至 `3460`。

完整停服后从同一 SQLite 文件重启，API 按原 ID 回读两笔已完成退货、两条库存流水、两条退款流水、采购明细累计 `0.6`、库存 `0.4 / 2720` 和两个资金账户余额。元数据门禁通过：100 个对象、1527 个字段、22 个页面、109 个动作；`typecheck`、`validate` 和 `build` 均通过。

## 未证明范围

连续多对象写入仍依赖顺序调用，没有数据库事务包裹；库存、流水、订单累计或资金余额中途失败时仍可能不一致。当前每张退货单只支持一条订单明细，退款必须一次足额到账。换货补货的供应商到货、检验和再入库将在下一阶段实现。采购申请、待办池、询价、不合格处置、部分退款、撤销、反核销、红冲、批次与 SN、岗位权限和 RISEMAP 同材料成功记录仍待后续实现或复核。
