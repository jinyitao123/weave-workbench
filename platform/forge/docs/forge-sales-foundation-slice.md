# Forge 销售报价、合同与订单基础切片

## 业务边界

本切片建立 `客户 → 报价 → 框架合同 → 销售订单` 的可追溯数据链。报价承载正式对客价格与有效期；框架合同承载允许下单的商品、价格、数量与额度约束；销售订单是后续发货、开票、收款和项目交付的执行来源。

基础切片先建立可持久化单据、从属明细、受控状态和关键引用。其后的销售工作流切片已经补上报价金额重算、提交、同意、发送、客户接受、合同提交与同意、订单提交与同意，以及订单审批后对合同累计的事务回写。信用占用、库存扣减、收入确认和应收核销仍需后续动作与下游台账共同验证。

## 信息架构

“客户与销售”下新增“销售业务”，只展示销售报价、框架销售合同和销售订单。报价明细、合同物料明细与订单明细是从属数据对象，不进入一级导航；报价类型、报价主体和合同类型放在“客户配置”。

## 证据到模型

| Forge 对象 | 运行态观察 | 公开资料 | 当前落地 |
| --- | --- | --- | --- |
| 销售报价 | RM-059、DR-0279 至 DR-0311：客户、类型、主体、有效期、负责人、明细、税率、折扣、状态与最小完整性 | 销售业财闭环第 2 步描述报价模板、价格策略、税率、有效期和付款条件 | 报价头、报价行、六种观察到的状态、付款方式、金额与条款字段 |
| 框架销售合同 | RM-046、DR-0165 至 DR-0177：合同类型、客户、物料、累计下单额度、例外审批策略、五类收入触发 | “销售合同与销售订单”说明合同约束一对多订单且合同不直接执行 | 合同头、合同物料行、订单额度与审批策略字段、五类观察到的收入触发 |
| 销售订单 | RM-047、DR-0178 至 DR-0183：直接新建/关联合同、客户、交期、负责人、付款结算、明细、金额和履约进度 | 同一公开流程说明直接订单与合同订单汇入唯一执行单据 | 订单头、订单行、两种来源、报价/合同追溯、付款、收入触发和发货/开票/回款累计字段 |

证据类别保持独立：`runtime_observed` 证明当前租户界面呈现与校验；`published_guide` 仅提供目标流程语义；`forge_verified` 只在本地 API 和重启后回读成功后成立。

## 当前验收界线

同输入测试需创建完整报价头和明细、由报价建立框架合同与合同明细、再由合同建立销售订单与订单明细，逐段核对客户、SKU、来源引用、数量、税率、单价与总额。还需验证缺必填引用、无效外键、负数量、非法状态和重启持久化。

基础数据验收仍由 `OEM-RM-20260909-A-sales-v0.1` 承担；工作流能力与同输入对照见 [Forge 销售报价、合同与订单工作流切片](forge-sales-workflow-slice.md)。

报价转框架合同、合同按全部剩余数量转销售订单及重复转换保护已在后续工作流切片实现。以下仍未实现：报价直接转订单，合同分批释放订单与取消后重建，审批岗位路由、意见、驳回、撤回和重提，合同额度的并发数据库约束，订单信用占用，发货、开票、收款、收入确认与财务过账，以及将从属明细嵌入单据详情页的专用交互。
