# Forge 多物料到货登记切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-multiline-arrival`，承接汇川 OTC 缺料采购订单生成的订单级到货通知。

## RISEMAP 对照结果

- 从 `ANO-2026-0001` 的“到货登记”进入采购到货表单，流程条依次为“到货登记 → 待检库存 → 检验单 → 入库单”。
- 选择供应商和 `PO-2026-0001` 后，一次带出 4 条物料，数量 `1 / 1 / 2 / 1`，合计 5；未税金额 `14442.48`，含税金额 `16320.00`。
- 到货日期、供应商、采购订单、每行到货数量和仓库必填。联系人、电话、承运方、物流单号、批次、库位、行备注和总备注可填。
- 页面提供“保存草稿”和“提交待检”。本阶段仅观察到完整表单和字段联动，尚未在 RISEMAP 提交该到货登记，因此后续待检记录的生成粒度仍以已保存的页面证据为待复核契约。

## Forge 已证明行为

1. 一张订单级通知可生成一张到货登记头和多条到货明细；每条明细保留通知行、订单行、SKU、仓库、库位、批次、价格和数量来源。
2. 草稿不占用通知与订单的到货数量；草稿提交待检后一次性回写通知行、通知头、订单行和订单头。整张通知到齐后状态进入已到货。
3. 数量不能为负，不能超过通知行剩余可到量；重复通知行、无效通知行、缺仓库和空物料均被拒绝。
4. 提交待检后按每条到货物料生成独立待检记录，不虚构检验单、检验结论、库存增加、入库单或应付。
5. 专用到货工作台呈现 RISEMAP 的基础资料、4 行物料表、数量与金额汇总、备注和四步流程，并可从采购订单到货通知直接进入。
6. 金额按采购订单行的四位含税单价计算，每行金额先取两位再汇总；RISEMAP 的 1 台基准仍为 `16320.00`，计划数量 3 的独立页面夹具为 `33260.02`。

## 验证结果

- 全新 `.objectstack/otc-multiline-arrival-final-v2.sqlite` 从基础资料开始顺序通过销售基础、销售流转、项目立项、正式 BOM、缺料分析、缺料采购和本阶段验收。
- 本阶段 API 验收 6 项全部通过，包含非法输入、草稿不占量、草稿提交、4 行累计、重复提交和满额后继续到货阻断。
- 内置浏览器提交 `ARR-2026-0002`，4 种、8 件、含税 `33260.02`，物流单号 `FORGE-UI-ARR-20260910`；到货登记状态为待检验，来源通知和采购订单均累计 8 并进入已到货。
- 完整停服后使用同一 SQLite 文件重启，API 按原 ID 回读两张到货登记、各 4 条明细、通知及订单累计量；浏览器刷新仍显示 `ARR-2026-0002`、待检验、4 行和 8 件。
- `pnpm typecheck`、`pnpm validate`、`pnpm build` 为本分支最终门禁。

## 当前边界

本阶段闭合到多物料提交待检；逐物料待检和检验已经在 `docs/forge-multiline-inspection-slice.md` 继续实现。检验规则、抽检与免检、不合格处置、采购入库、库存流水和应付仍待后续阶段。当前动作包含多对象顺序写入，尚未证明并发提交下的原子回滚。
