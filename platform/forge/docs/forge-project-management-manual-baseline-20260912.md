# 项目管理复刻基线与预审记录

日期：2026-09-12  
分支：`codex/project-management-manual-baseline`  
范围：先完成项目管理菜单与信息架构基线，再按页面合同逐个修补。

## RISEMAP 已观察事实

项目组当前保存证据包含五个入口，顺序为：项目中心、项目分析中心、任务管理、工时管理、项目配置中心。

- 项目中心：表格/甘特图、项目状态筛选、负责人/进度/客户筛选、项目主数据列和查看详情。
- 项目分析中心：全部项目/单个项目、营收与成本对比、成本构成、费用流向、利润率排名和日期范围。
- 任务管理：任务状态、项目/人员/优先级筛选、列表/人员/甘特图、新建任务和导出。
- 工时管理：填报、工时记录、闲置工时统计、项目筛选、工时单号/日期/人员/项目/内容/工时/类型/费率/成本/状态。
- 项目配置中心：计划模板、交付包模板、工时成本配置、新建模板、分类筛选和搜索。

证据来源：`docs/risemap-page-contracts.md` 的 RM-094 至 RM-098，以及 `docs/references/risemap-capture/deep/project` 下的已保存页面材料。上述材料证明首屏和部分交互，不等同于 RISEMAP 全流程已验证。

## Forge 工程现状

现有能力包括项目主数据、项目计划树、阶段/里程碑/任务、进度更新、日报、工时审核与人工成本、费用与成本归集、交付验收、整改复验和项目经营分析。现有页面可复用，但此前导航把交付验收和费用成本直接混入项目管理主组，分析入口放在报表，配置入口缺失。

## 决策

1. 项目管理主组先对齐 RISEMAP 五个入口。
2. 交付验收和费用成本不删除，移入“项目执行与成本”分组，保留原页面和能力。
3. 项目分析中心复用现有 `page_project_operating_analysis`，导航名称改为 RISEMAP 业务名称；报表下既有入口暂时保留，后续决定是否改为跨域报表入口。
4. 新增项目配置中心承载页；计划模板已完成本地对象和保存、读取、空计划套用，交付包模板与工时成本配置继续按 RISEMAP 证据补齐。
5. 项目计划页面内部名称保留“项目计划与执行”，菜单名称使用“任务管理”，避免工程实现名覆盖用户任务语义。

## 三方预审

### 产品审查

通过本轮 IA 预审。五个入口能覆盖项目负责人、项目成员、工时审核人和管理者的主要入口；交付、成本等下游任务仍可达，但尚未完成 RISEMAP 页面合同和岗位连续任务复核。

待决策：项目详情是否需要承载任务、工时、交付、成本和分析的上下文页签；RISEMAP 的甘特图、导出、模板新建和日期范围的具体行为仍需逐页复核。

### 工程审查

通过本轮导航与承载审查。复用现有项目对象、计划对象、工时/成本对象和分析页面，不改写历史记录，不引入第二套项目数据模型。配置中心已落地计划模板对象和业务写入动作，交付包模板与费率配置仍保持事实承载边界。

边界：导航配置是共享文件，后续并行分支不得直接改写；项目模板、权限、导入导出和甘特交互不能由当前导航改动推断完成。

### 质量审查

通过进入 IA 实施，未通过业务闭环验收。必须在独立 SQLite 中验证五个入口可见、页面首屏加载、项目列表/分析/任务/工时/配置之间可达，并对已有项目工时和计划做停服重启回读。页面可打开、构建通过和 API 成功不能替代岗位业务验收。

## 下一轮页面修补顺序

本节顺序受 `docs/forge-replication-work-order-20260913.md` 约束；项目中心之后优先补齐项目计划与任务的岗位连续办理，不先跳到采购或行政。

1. 项目中心：对齐列、状态筛选、项目详情上下文和新建项目。
2. 任务管理：把计划树、任务列表和甘特视图收敛为岗位任务入口。
3. 工时管理：对齐工时记录和审核反馈，并保持成本归集可追溯。
4. 项目分析中心：补日期范围、排名、成本流向和项目穿透。
5. 项目配置中心：计划模板保存、读取和空计划套用已完成；继续复核交付包模板与工时成本配置行为。

## 停止规则

若页面无法从项目上下文进入下一任务、状态和来源无法回读、或只能依赖 API 预制记录完成浏览器操作，则停止扩展项目管理页面，先修复当前页面合同和任务连续性。
