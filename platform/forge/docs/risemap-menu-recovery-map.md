# RISEMAP 菜单复刻挽回台账

更新于 2026-09-13。基线为 Forge `main` 提交 `0fef9d6` 及已保存的 RISEMAP 181 个菜单入口清单。本轮只整理 Forge 主导航与信息架构，不删除已有对象、Action、页面或数据，不修改线上 RISEMAP 数据，也不把入口可见写成业务闭环通过。当前主线冻结审计见 `docs/forge-main-product-audit-20260912.md`。

## 事实

- RISEMAP 当前保存证据中的一级菜单顺序为：工作台、供应链、销售、生产、项目、行政、财务、报表、系统。
- 九类菜单分别包含 4、41、19、29、5、32、18、11、22 个入口，完整编号见 `docs/risemap-feature-inventory.md`。
- Forge 已有采购、库存、销售、生产、委外、项目和财务的部分对象、Action 与专用页面；这些能力此前按 OTC 阶段组织，现已按 RISEMAP 菜单重新归位，但仍需按页面和岗位任务逐项审查。
- 财务的“对账单”在 RISEMAP 的“业务确认”分组内；Forge 已将对账中心和银行余额对账移回该分组，避免把对账误读成独立一级业务域。
- 系统在 RISEMAP 下分为“系统设置”和“业务设置”；Forge 已保留一个明确的系统设置状态入口，并将现有商品、客户、采购销售、库存和项目配置收纳到业务设置下，保留原有配置页面。
- 当前委外已形成订单、发料、供应商签收、回厂、良品入库、NCR、退料、委外对账和应付生成的受控样板；供应商外部确认、部分结算和岗位待办仍缺或待 RISEMAP 复核。
- 2026-09-13 已按 RISEMAP 入口清单补齐供应链、销售、生产、行政、财务、报表和系统的缺失导航项。没有真实实现的入口统一进入区域待复刻承载页，不能据此宣称功能完成。

## 决策

1. Forge 一级菜单及顺序固定对齐 RISEMAP 九类入口。
2. 二级分组优先使用 RISEMAP 已观察名称；只有存在真实可达页面或对象时才挂三级入口。
3. 现有底层对象、Action、库存与财务台账全部保留。明细、日志、审批记录等内部对象从常规导航收回，后续放入主单据详情页。
4. OTC 九阶段保留为跨菜单任务旅程，不再承担主导航。
5. 每个功能以后独立经历页面合同、岗位任务、状态动作、上下游、异常阻断、同库重启和浏览器验收，不按对象数量计算进度。
6. 菜单广度与功能深度分级推进：A 类主链深走查，B 类常用能力先完成入口和首屏合同，C 类低频能力先保留准确结构和缺口，不让低频菜单阻塞主链。

## 加速分级与复用

| 等级 | 入口范围 | 交付要求 | 进度含义 |
| --- | --- | --- | --- |
| A 类主链 | 委外、采购、销售、生产、财务订单/资金主链 | RISEMAP 页面合同、岗位连续任务、正常/关键异常、上下游、API、同库重启、浏览器和独立验收 | 可进入下一功能，但不能外推为整个业务域完成 |
| B 类常用能力 | 客户、供应商、物料、BOM、库存、报表、常用设置 | 菜单归位、入口可达、首屏字段/动作、事实与缺口记录 | 只代表结构和首屏，不代表业务闭环 |
| C 类低频能力 | 行政、人事、低频系统设置和集成 | 保留 RISEMAP 菜单事实、占位入口或缺口状态 | 不阻塞 A 类，不计入已实现功能 |

所有 A 类功能复用统一页面合同：入口、职责、岗位、主单据、字段/列、状态、动作、阻断、来源、结果、下一步和验收材料。RISEMAP 证据只在发现新事实或差异时增量更新；Forge 浏览器操作和验收脚本复用同一合同。

## 假设

- ObjectStack Console 的区域、分组和标准页面足以承载 RISEMAP 的一级、二级导航语义；若实际浏览器验证发现空区域不可见或页面上下文不足，再扩展平台元数据或共享组件。
- 同一业务能力在主菜单只保留一个权威入口，跨业务查阅通过主单据关联和上下游跳转完成，而不是复制多个语义不同的菜单项。
- RISEMAP 现有试用空间的菜单结构可作为当前复刻基线；厂商版本差异仍需后续复核。

## 本轮结构纠正

- 新增统一区域待复刻承载页：`page_supply_chain_gap`、`page_sales_gap`、`page_production_gap`、`page_administration_gap`、`page_finance_gap`、`page_reports_gap`、`page_system_gap`。
- 这些页面只列出 RISEMAP 已观察入口和“待复刻”状态，不写入业务数据、不生成伪造记录、不提供未经证实的业务动作。
- 删除或收回技术对象入口仍需在对应主链页面完成后逐项处理，当前不删除 `ObjectStack` 对象、Action 或数据。

## 本轮验证

- `pnpm typecheck`、`pnpm validate`、`pnpm build` 均通过；当前验证统计为 159 个对象、45 个页面和 194 个 Action。该统计只作工程盘点，不作为产品完成度。
- 在端口 `4398` 使用独立 `.objectstack/menu-ia-20260912.sqlite` 启动 Console，登录后侧栏按顺序显示九类一级菜单。
- 首次浏览器检查发现空区域会被 Console 隐藏；加入明确标注“待复刻”的状态页后，完整停服并从同一 SQLite 重启，工作台和行政均可见。
- 浏览器已展开生产下的组装业务管理、图纸管理、委外管理；委外看板与委外订单分别可加载，订单页列表职责独立可见。
- 在独立 worktree 端口 `4452` 完成配置重载验证：财务侧栏将“对账中心”和“银行余额对账”显示在“业务确认”下；系统的“系统设置 / 业务设置”结构通过配置校验，原有业务配置仍保留在“业务设置”下。系统区域的完整浏览器展开仍列为待复核。
- 本轮只证明菜单结构、入口路由和状态页承载，不证明任何业务功能新增或业务闭环。

## 逐功能修补队列

首个业务修补单元为“生产 / 委外管理”，按页面和岗位连续任务推进，不再并行堆孤立对象：

1. 委外看板与订单上下文，明确来源、当前状态、结果、异常和下一步；两个入口已在导航层拆开。
2. 委外发料与供应商签收，补批次来源、岗位阻断和状态反馈。
3. 委外回厂、良品入库和不良处置，统一物理、质量和订单状态。
4. 委外对账单、应付生成和付款关联；退料已进入独立功能验收，仍需 RISEMAP 写入语义复核。
5. 同一 SQLite 全链停服重启、真实浏览器操作及独立业务验收；当前已证明回厂批次到应付的页面闭环，但订单整体仍可能因计划数量未完成而保持进行中。

在第 5 项通过前，不把委外称为业务闭环，也不自动迁移到采购、生产、销售或财务的其他功能。

后续执行采用“一个页面合同、一个纵向功能、一次完整门禁”的节奏。取证、页面实现和脚本准备可以在独立 worktree 并行；共享导航、barrel 和包配置由主线统一合并。
