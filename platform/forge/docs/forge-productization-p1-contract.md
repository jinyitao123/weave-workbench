# 采购连续办理产品化契约

日期：2026-09-10。状态：实施中。分支：`codex/forge-productization-p1`。本阶段承接 P0 提交 `05a1916`，并已合入 `main` 的 `76df859`。

## 用户任务

采购人员从缺料快照创建采购订单，审核后沿同一订单进入到货登记；仓库按物料接收到货，质检逐项给出结论，仓库只把检验合格且尚未入库的数量办理入库。每一步都能返回来源订单、看到当前进度、打开已产生的下游单据，并在重新进入页面后保持同一记录。

## 页面合同

| 页面 | 默认入口 | 详情与动作 | 连续办理边界 |
| --- | --- | --- | --- |
| 采购订单 | 可搜索、按状态筛选的订单列表；新建必须显式进入 | 显示供应商、金额、到货与入库进度、明细、审批和到货通知；使用正式审核对话框 | 当前只支持已经完成的 BOM 缺料分析转换，不显示库存补充、项目采购、以销定采或采购申请为可用入口 |
| 到货登记 | 到货记录列表；从已审核订单的到货通知进入新建 | 一张登记承接通知的多条物料，逐行填写数量、仓库、批次和库位；草稿与提交待检分开 | 到货数量不得超过通知行剩余量；提交后才生成逐物料待检记录 |
| 待检与检验 | 待检列表和检验单列表均可搜索；从待检记录显式创建检验单 | 一条物料一张检验单，填写检验日期、合格数量和结论 | 当前支持全检与抽检显示；不把检验项目、附件、免检或不合格处置伪装成已实现 |
| 采购入库 | 入库单列表；从已完成检验的订单进入新建 | 一张入库单可承接同订单多条剩余合格物料，提交、审核、执行入库依次办理 | 只有执行入库后才改变库存；当前不会自动生成应付 |

## 共同交互规则

- 四页使用 P0 的共享页面壳层、状态、空态、加载、提示和对话框，不再隐藏或重排 ObjectStack 宿主 DOM。
- 默认列表不自动打开第一条记录，不常驻测试表单。记录通过 URL `id` 明确打开，新建通过 `new=1` 或上游来源参数明确进入。
- 去除 RISEMAP、汇川 OTC、测试夹具和实现边界的页面标语；必要边界通过动作可用性、状态提示和验收材料表达。
- 不预填测试单号、固定审批意见、固定备注或默认首个供应商/仓库。必填缺失就地提示，接口失败保留输入，处理中防重复。
- 操作成功后回读当前记录；产生下游记录时直接打开结果或给出明确入口。页面显示值不重新发明服务端金额、数量和状态规则。

## 验收

1. 以独立端口和独立 SQLite，从订单列表开始办理一条订单到入库的真实链路，并记录订单、通知、到货、待检、检验、入库、库存和流水 ID。
2. API 对照页面显示的数量、金额、状态和关联。失败路径至少覆盖必填、超量或重复动作之一，并验证输入或上下文仍保留。
3. 完整停服后从同一 SQLite 重启，重新打开订单和最终入库单；API 回读全部来源关联与库存结果。
4. 运行 `pnpm typecheck`、`pnpm validate`、`pnpm build`，以及采购订单、到货、检验、入库对应的已有验收与重启回读。
5. 1280×800 和 1440×900 检查列表、详情、表单和宽表。RISEMAP 同材料尚未成功提交的到货、检验、入库继续标记待复核。
