# 销售直接出库页面合同

日期：2026-09-15

## RISEMAP 当前事实

- 入口：供应链 → 出库管理 → 销售直接出库，当前地址 `/inventory/outbound/sales-direct`。
- 页面职责：管理所有出库单和待出库发货单。
- 工具栏只有刷新，没有独立新建入口。
- 搜索范围提示为直接出库单号、订单号、客户单号和客户。
- 状态筛选为待出库、部分出库、已完成。
- 列为直接出库单号、客户单号、客户、出库进度、状态、创建时间、操作，默认每页 20 条。
- 当前 RISEMAP 租户没有销售直接出库数据，因此有数据行的具体操作名称和详情层级待同材料复核。

证据：`docs/references/risemap-capture/deep/supply-chain/outbound/rm-042/616-rm-042-sales-direct-list.dom.txt`、`617-rm-042-sales-direct-status.dom.txt`，并于本轮在内置浏览器实时复核。

## Forge 当前实现

- 入口：`/_console/apps/forge/page/page_sales_direct_outbounds`。
- 以销售发货单为聚合主单据，将同一发货单的分批销售出库单汇总成一行进度。
- 列、搜索提示、三种进度状态和 20 条分页与 RISEMAP 当前页面对齐。
- 待出库和部分出库行进入待出库发货单办理页；已完成行进入最近一张真实销售出库单详情。
- 出库由销售发货单承接，不在聚合列表虚构独立新建按钮。
- 服务动作校验发货剩余数量和真实库存，成功后扣减余额、生成库存流水，并回写发货单及销售订单进度。

## 差异与结论

- RISEMAP 当前没有可办理数据，Forge 将既有 `forge_sales_shipment` 映射为销售直接出库任务、`forge_sales_outbound` 映射为分批执行结果；这是 Forge 工程映射，待 RISEMAP 同材料验证后再确认字段级语义。
- Forge 行内额外展示来源发货单和销售订单，便于追溯，不改变 RISEMAP 主列结构。
- 当前销售出库执行只支持单物料发货单；多物料发货与同材料 RISEMAP 行动作仍是后续缺口。

## 本轮验收材料

- 浏览器正常路径：`DN-CONVERT-20260915112205-001` → 选择 `WH-RM-01` → 二次确认 → `OUT-FORGE-20260915-001`。
- 页面结果：出库进度 `1 / 1`、`100%`、状态“已完成”，来源发货单和销售订单可见。
- API：出库单、来源发货单、发货明细、销售订单、客户与 `sales_outbound` 库存流水关系一致。
- 同一 SQLite 完整停服重启后，API 和内置浏览器均回读相同结果。
