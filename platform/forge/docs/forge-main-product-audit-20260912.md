## 审计结论

当前 `main` 已完成 RISEMAP 九类一级导航的结构重排，并形成委外订单到回厂、入库、不良处置、退料、对账和应付的受控样板。它仍不是 RISEMAP 全量产品复刻，也不是完整委外订单完工证明。当前证据由同库 API 连续链、分阶段内置浏览器办理和停服重启回读组成，不能改写成一次全程浏览器办理。订单整体仍可能因计划数量未完成而保持“进行中”。

工程统计只作为盘点索引，不作为产品完成度指标：`pnpm validate` 当前基线为 159 Objects、2,587 Fields、45 Pages、194 Actions。源码盘点为 21 个对象模块、30 个 Action 模块、36 个页面模块；一个模块可声明多个平台对象、动作或页面，不能用文件数替代产品能力。

## 状态与来源不变量

已证明或已编码的关键不变量：

1. 未完成入库或未完成 NCR 的回厂批次不得进入可对账池，并且页面必须显示阻断原因和下一步。
2. 同一回厂明细不得被多个有效委外对账单重复占用。
3. 对账单生成后保存来源、金额和订单关系；确认前不回写已确认金额，生成应付必须幂等。
4. 回厂提交阶段只产生待入库结果；确认入库阶段才执行材料倒冲和正式库存计价。
5. 订单上下文的下一步优先反映未完成异常，再反映入库、发料、回厂和结算任务；异常存在时不能仍给出结算入口。

尚未证明为 RISEMAP 事实的实现：顺序写入的原子性、供应商外部确认、部分结算/重开/拆分、赔偿和扣款分配、付款关联、权限分工以及历史数据迁移规则。

## 下一修补单元

继续只处理委外链，顺序固定为：

1. 补齐同一 SQLite 上由真实页面完成的连续岗位验收记录，明确业务员、仓库、质量、财务四个岗位的入口和交接；现有材料覆盖各阶段，但尚未形成一次全程浏览器办理记录，真实多角色账号仍未证明。
2. 对照 RISEMAP 复核委外订单、发料、回厂、NCR、RM-087、RM-093 的页面结构和状态动作。
3. 在未决行为获得 RISEMAP 同材料证据前，保持“Forge 工程实现 / 待复核”标记，不推广到采购、生产、销售或财务其他模块。

停止条件：出现来源丢失、状态可绕过、金额重复、异常仍可错误结算、重启回读不一致或页面无法从当前单据进入下一岗位任务时，停止继续添加功能并先修正语义或持久化边界。
