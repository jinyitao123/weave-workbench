更新于 2026-09-10。实现位于隔离分支 `codex/otc-prepayment-refund`，验收端口 `4365`，数据库 `.objectstack/otc-prepayment-refund.sqlite`。该库从已停服的 `procurement-finance-20260909.sqlite` 复制，保留采购订单 `PO-RM-202609-001` 和应付 `AP-PIN-RM-20260909-001`。为允许预付款任务不关联应付，已通过非破坏性迁移把付款任务和付款流水的 `payable_id` 调整为可空；迁移前后 SQLite 完整性检查均为 `ok`。

## 证据边界

RISEMAP 付款管理的预付款页签证明预付款可按供应商和付款单汇总，显示预付总额、已冲抵和余额；观察到的合同预付款可以高于当前应付余额。退款申请的供应商退款页签展示关联订单/合同、供应商、币种、实退金额、退款方式、单据状态、财务审批、收款状态、核销状态和申请日期。以上依据来自 DR-1020、DR-1025、DR-1026、DR-1476、DR-1481 和 DR-1482。当前没有在 RISEMAP 保存同材料预付款或供应商退款记录，因此这些页面行为是实现依据，不能记作同输入结果一致。

## 已实现行为

- 已审核采购订单可发起预付款任务。申请额度按订单总额减去未驳回预付款任务累计值计算，不受当前应付余额限制；任务仍需审批，实际出账后才生成逐笔供应商预付款余额。
- 预付款出账复用付款任务和付款流水，扣减真实资金账户，但不生成应付核销。预付款保留订单、供应商、付款任务和付款流水来源。
- 预付款可直接冲抵同一供应商的未结应付。冲抵减少应付余额和预付款余额，不产生第二笔现金收付；待审批、已审批或待核销退款会先占用可用余额。
- 供应商退款依次经过申请、财务审批、实际到账和核销审核。到账增加资金账户余额，只有核销通过后才减少预付款余额；驳回会释放占用，实退金额必须等于审批金额，重复核销被阻断。
- 付款管理页已提供可办理的预付款页签；退款申请页按 RISEMAP 的供应商退款列展示审批、到账和核销状态。

## 验证结果

定向 API 验收共 6 组。订单总额为 `13600`、当前应付为 `6800` 时，成功申请并支付 `8000` 预付款；资金账户从 `12000` 降至 `4000`。随后用 `1500` 冲抵应付，使应付余额变为 `5300`、预付款余额变为 `6500`，资金账户不变。`500` 退款申请被驳回后释放占用；另一笔 `1000` 退款经过审批、到账和核销，资金账户增至 `5000`，预付款余额降至 `5500`。超订单预付、超可用退款、金额不一致到账和重复核销均被阻断。

浏览器独立办理 `PT-PRE-BROWSER-20260910-001 → PAY-PRE-BROWSER-20260910-001 → SR-BROWSER-20260910-001`。先从浏览器资金账户支付 `1200`，再完成 `300` 供应商退款的申请、审批、到账和核销，最终预付款余额为 `900`，账户余额为 `2100`。新开页面显示三张供应商退款，浏览器记录为已完成、已审批、已收款和已核销。

完整停服后从同一 SQLite 文件重启，API 按原 ID 回读 API 与浏览器两套预付款、退款、冲抵、应付和资金账户；新开浏览器页仍显示相同状态与金额。验收报告位于运行时目录 `.objectstack/acceptance/prepayment-refund-report.json`，不提交数据库或运行时产物。元数据门禁通过：93 个对象、1387 个字段、20 个页面、94 个动作；`typecheck`、`validate` 和 `build` 均通过。

## 未证明范围
