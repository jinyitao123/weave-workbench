# Forge 页面精修基线

任务范围、逐页合同、标准样例取证、四维验收和版本失效规则见 [默认交付标准](forge-page-delivery-standard.md)。本文件是视觉和交互细则的唯一来源；参考页面是设计样例，不代表其全部业务已经验收通过。

## 适用范围

本基线约束 Forge 自定义页面的视觉层级、控件形态和交互反馈，供后续功能页持续复用。它不定义业务事实：菜单、字段、状态、动作、阻断、来源关系和下一步仍以 RISEMAP 当前页面及对应页面合同为准。

参考实现：

- `apps/forge-objectstack/src/pages/workbench.page.ts`：跨模块工作台与经营概览。
- `apps/forge-objectstack/src/pages/project-task-workspace.page.ts`：任务型执行工作区。
- `apps/forge-objectstack/src/pages/project-timesheet-cost.page.ts`：指标、筛选、填报、审核和成本承接组合页。
- `apps/forge-objectstack/src/pages/product-ui.ts`：页面共享样式、状态、空态、选择、日期和弹窗能力。

## 逐页原型合同

共享视觉变量不能替代逐页设计。每个页面在实现前必须选择一个主原型，并把选择写入页面合同和 `tests/page-polish.manifest.json`：

- `workbench`：岗位工作台。参考 `workbench.page.ts`，先呈现待处理事项和岗位焦点，再呈现指标、业务入口和辅助信息。
- `task_workspace`：任务执行页。参考 `project-task-workspace.page.ts`，围绕当前任务提供范围、状态、筛选、任务区、办理动作和下一步。
- `timesheet_composite`：指标与办理组合页。参考 `project-timesheet-cost.page.ts`，把时间或业务范围、判断指标、状态页签、主列表和关联结果组织成连续工作区。
- `analysis`：分析页。借鉴 `workbench.page.ts` 的决策层级和 `project-timesheet-cost.page.ts` 的指标到明细关系，先说明口径和范围，再呈现指标、趋势、异常和可追溯明细。
- `configuration`：配置页。沿用共享表单、列表和反馈控件，突出配置对象、影响范围、保存结果及返回入口。

页面合同必须逐页写清：参考原型、首屏区块顺序、当前主动作、筛选作用对象、指标如何帮助判断、主工作区、结果反馈和下一步入口。即使多个页面读取相似对象，也只有在岗位、主任务和区块顺序一致时才能复用整页结构。只替换标题、指标、页签和表格列的批量生成页面保持 `review_required`，不能计入已精修页面。

`tests/page-polish.manifest.json` 是页面设计状态清单。`review_required` 表示入口或功能可以存在，但设计仍需逐页复核；`accepted` 只用于已经完成双侧页面对照、主原型核对、关键交互、空态和响应式检查，并在清单中记录证据文件的单个页面。

## 页面结构

页面按用户办理顺序组织，而不是按代码模块堆放组件：

1. 标题区说明业务位置、页面名称和当前职责。
2. 标题右侧只放跨页面或页面级动作。一个当前主任务使用主按钮；并列次要动作使用普通按钮，含义相近时组合展示。
3. 筛选区紧贴其作用的数据区域。筛选必须真实生效；暂未实现的条件不做成占位控件。
4. 指标区只展示能帮助用户判断下一步的数据，优先控制在一行内，并保持数字、单位和口径清楚。
5. 主工作区承载列表、表单、看板、图表或任务执行；关联结果和下一步入口放在主结果之后。
6. 加载、失败、空数据、受限能力和成功反馈都必须有可理解的页面状态。

## 视觉语言

- 自定义页面优先复用 `product-ui.ts` 中的 `forgeProductUiCss` 和 `forgeProductUiRuntime`，避免每页复制按钮、表格、状态、弹窗和表单样式。
- 页面使用 Console 内容区，不另建独立导航外壳。内容宽度通常为 `1380px` 到 `1520px`，大屏居中，小屏自然收缩。
- 使用 `--fp-*` 变量统一背景、文字、边框、主色和业务状态颜色。卡片使用轻边框、轻阴影和约 `9px` 到 `11px` 圆角；控件保持约 `34px` 到 `36px` 高度。
- 标题、说明、指标、表头、正文和辅助文字形成清楚层级。常规页面保持紧凑密度，避免大面积装饰和无业务含义的留白。
- 页面必须覆盖约 `1050px`、`760px` 等窄屏断点；工具栏、指标和表单在空间不足时换行或改为单列。

## 工时管理设计语言的页面效果要求

`page_project_timesheet_cost` 是 Forge 自定义业务页的首要页面效果基线。这里的“保持一致”指相同的信息密度、空间节奏、控件质感和任务层级，不要求所有页面复制工时页的区块数量或业务内容。每页仍需根据岗位任务选择自己的主原型。

### 1. 首屏构图

- 桌面内容区使用 `width:min(1380px,100%)`，左右内边距 `22px`，顶部内边距 `20px`，底部至少 `42px`。内容在宽屏中居中，不贴边，也不在中等屏幕人为缩成窄栏。
- 首屏区块按“标题与动作 → 范围或关键筛选 → 判断指标 → 主图表或主任务 → 状态页签与明细”排列。若某类页面没有对应区块，直接省略，不能用空卡补高度。
- 在常见 `1280×720` 至 `1440×900` 视口内，用户应至少看到标题、范围区、完整指标行和主工作区的标题或上半部分。首屏不能被超高指标卡、装饰性留白或说明文字占满。
- 相邻大区块的垂直间距以 `14px` 至 `16px` 为主；同组卡片的间距为 `10px` 至 `12px`。除弹窗和空态外，不使用大于 `32px` 的无业务含义留白。

### 2. 标题区与页面动作

- 面包屑或业务阶段说明使用 `12px` 辅助文字，位于标题上方，和标题间距约 `5px`。页面标题使用约 `24px/1.35`、中高字重；说明在标题下方 `5px`，只写一句当前职责。
- 页面级动作与标题顶部对齐并靠右。当前最重要的办理动作只能有一个蓝色主按钮；导出、刷新、设置和辅助入口使用白底次按钮。
- 同类次要动作可组成相连按钮组，例如“导出工时 / 导出任务”。按钮组与主按钮之间保留约 `12px`，按钮高度统一为 `34px` 至 `36px`。
- 新建、填报、发起、提交等主动作不得落在状态页签下方、列表底部或与“刷新”“导出”混在不明分组中。动作应出现在用户开始办理时自然寻找的位置。
- 标题区可选两种形态，同一页面只用一种：**纯文字标题区**（默认，标题 + 一句说明）或**品牌标识区（hero）**。hero 使用整块品牌渐变或品牌底色，左上角图标徽章 + 业务面包屑，主标题和一句职责说明，右侧可放线稿装饰图；高度约 `150px` 至 `200px`，文字反白或使用高对比色。
- hero 只承担页面标识，不放业务数据、指标、表单或操作按钮；页面级动作统一放在 hero 下方的一行工具栏右侧，仍遵循本节主/次按钮规则。一页只允许一个 hero。
- 装饰图只出现在 hero 右侧背景，不得遮挡标题或说明，不得溢入主工作区；hero 之外的卡片、表格、图表区域不使用渐变、插画或装饰图。

### 3. 范围与筛选区

- 决定整页统计口径的日期、组织、项目或期间选择放在独立轻卡中，紧接标题区；卡片内边距约 `14px 16px`，控件高度统一。
- 筛选标签使用 `11px` 至 `12px` 中高字重和弱化颜色；输入框、选择器、日期控件保持 `34px` 至 `36px` 高度，圆角约 `8px`。
- 只影响列表的搜索、状态、项目等条件放在列表卡内部，位于页签下方或表格上方。不能把局部筛选放到页面顶部造成作用范围不明。
- 周、月、季、年等快捷范围使用紧凑按钮或页签。选中态必须同时有文字颜色和边框/下划线反馈，不能只靠浅色背景区分。
- 所有筛选必须立即影响对应指标、图表或列表，并保留明确的清除/重置路径。没有实际过滤结果的控件不得出现。

### 4. 指标卡

- 桌面优先一行四张；业务确实需要时可为三张或六张，但同一行宽度与高度一致。工时页基线为 `4 × 1`，卡片间距约 `11px`，在约 `980px` 以下变成两列，在约 `680px` 以下变成一列。
- 指标卡内边距约 `15px 16px`，最小高度由内容决定，禁止用大面积留白制造“高级感”。指标名称使用 `11px` 至 `12px` 弱化文字；主数值使用约 `22px`、紧凑行高；口径说明在数值下方 `2px` 至 `4px`。
- 数值、单位和币种必须在一眼可读的同一视觉层级中。单位不能被放大到与数值竞争，辅助口径不能比指标名称更醒目。
- 颜色用于业务语义和可扫读性：默认主数值以深色为主，可用蓝色、橙色等轻度区分业务方向；禁止每张卡使用不同高饱和背景。
- 指标必须帮助用户判断下一步，并能追溯到当前范围内的数据。仅用于凑数、没有口径或与当前页面任务无关的指标应删除。

### 5. 图表与分析区

- 图表放在带边框的白色卡片中，内边距约 `16px`。标题使用约 `14px`，范围、单位或图例放在同一标题行右侧或标题下方的紧凑位置。
- 图表高度根据比较任务确定。周分布类约 `150px`；月度趋势可为 `180px` 至 `240px`。禁止在零数据时留下占据半屏的空白画布。
- 图例颜色必须与图形一致；坐标、月份、日期和单位要能读懂。柱形、折线或环图必须按真实数值计算比例，不得使用固定装饰高度冒充数据。
- 零数据时保留轴、周期和图例可以帮助理解口径，但同时应显示简短空态或零值，不得让用户误以为图表加载失败。
- 两个并列分析卡应有明确主次。主趋势区可占约 `2/3`，构成或摘要区占约 `1/3`；内容较少时应收紧卡片，而不是放大空白。

### 6. 页签、列表与表格

- 状态页签放在列表卡顶部，页签栏高度约 `44px`，页签间距约 `22px`。选中态使用主色文字和 `2px` 下划线；右侧可放记录数量或当前口径。
- 列表筛选位于页签下方，使用 `13px 16px` 内边距，并用底部分隔线与表格连接，形成一个连续工作区。
- 表头、正文、状态标签和行操作保持紧凑。表格过宽时在卡片内部横向滚动，不压缩文字和按钮到不可读宽度。
- 行操作只保留当前状态真实可执行的动作；一个主要行动作可使用小型主按钮，危险动作使用小型危险按钮。动作按钮高度约 `30px`。
- 空表格仍保留真实列头，空态行高度通常为 `140px` 至 `180px`。空态文案说明“当前条件为何无数据”或“下一步如何产生数据”，不放伪按钮。
- 分页属于列表卡底部，左右分别呈现记录数/每页数量与页码。分页不能脱离列表卡悬浮在页面空白中。

### 7. 表单、弹窗与结果反馈

- 页面内展开表单必须与触发动作相邻，并使用同一内容宽度。桌面表单通常为四列，长文本占两列；约 `980px` 以下两列，约 `680px` 以下单列。
- 字段标签、必填标记、控件高度和错误文案必须统一。提交按钮放在表单阅读顺序末尾并靠右，不能孤立在页面顶部。
- 弹窗标题说明动作，副标题说明对象，正文说明字段或业务影响；按钮顺序、禁用态、提交中状态和错误反馈保持一致。
- 成功后必须回读页面真实状态；失败时在当前办理上下文内显示原因。Toast 只作为补充，不能替代列表、状态或详情的变化。

### 8. 业务入口与下一步动作

- 业务入口不是宣传卡。入口卡只用于承接明确的下一岗位或下一单据，内容包括短标签、具体任务名称、一句结果说明和一个真实可达动作。
- 三个并列入口在桌面可为三列，但卡片内边距和高度应紧凑，并与前面的分析结果形成因果关系。按钮放在对应任务描述之后或卡片右侧，不能把所有按钮集中成一排而失去上下文。
- 如果下一步只是列表切换，可使用文本按钮或次按钮；如果是当前页面的核心办理动作，才使用主按钮。页面中不能同时出现多个视觉权重相同的蓝色主按钮。

### 9. 色彩、边框、圆角与阴影

- 页面背景、卡片、边框、文字和状态色统一使用 `--fp-*` 变量。常规卡片为白底、`1px` 轻边框、约 `10px` 至 `11px` 圆角和极轻阴影。
- 阴影只用于从背景中分离卡片，不制造浮层感。普通卡片、表格与图表区禁止使用浓重阴影、发光、玻璃拟态和大渐变；品牌渐变只出现在页面 hero 标识区（见第 2 节）。
- 主色用于选中、当前进度和主动作；成功、警告、危险色只表达对应状态。大面积业务内容以中性色为主，避免“每个模块一种主题色”。品牌渐变与品牌底色也只用于页面 hero，进入主工作区后回到中性色加主按钮。
- 图标统一为线性图标，尺寸通常 `14px` 至 `16px`；图标必须帮助识别含义，不能作为大面积装饰。

### 10. 响应式与窄屏

- 在约 `980px` 以下，标题动作允许换到标题下方，指标改为两列，四列表单改为两列；工具栏必须换行，不能把按钮压成竖排文字。
- 在约 `680px` 至 `760px` 以下，内容左右内边距缩至约 `12px`，标题约 `21px`，指标与表单改为单列，图表图例和页签允许横向滚动或合理换行。
- 日期范围、按钮组和筛选在窄屏下按办理顺序排列。主按钮保持完整文案和可点击宽度，不得与次要动作重叠。
- 表格在卡片内横向滚动；固定最小列宽，不通过缩小字号、隐藏关键列或挤压行操作解决空间问题。

### 11. 明确拒绝的页面效果

出现任一情况，页面保持 `review_required`，不得称为精修完成：

- 只复用 `fp-shell`、标题、圆角、按钮和颜色，但页面仍是通用指标、页签、表格生成器。
- 指标卡高度过大、信息过少，首屏大部分是无业务含义的白色区域。
- 图表是固定高度的装饰块、零数据大空白或与真实数据无比例关系。
- 主动作放在列表页签下方、表格末尾或远离当前办理步骤。
- 导出、刷新、新建、提交等不同层级动作使用相同主按钮样式。
- 三个“业务入口”做成高大的宣传卡，或把多个失去上下文的按钮堆在同一工具栏。
- 窄屏时按钮文字竖排、筛选溢出、卡片错位、表格压缩不可读或页面出现横向整体滚动。

### 12. 截图与交互验收判据

- 桌面截图至少覆盖标题区、范围/筛选、完整指标行、主图表或主任务区，以及列表页签或下一步入口的起始位置。
- 窄屏截图至少覆盖标题与动作换行、指标重排、筛选顺序和主工作区，不得只截页面顶部。
- 验收人员必须实际操作主按钮、一个次要动作、范围或筛选、状态页签、关键弹窗和下一步入口，并确认操作后页面回读。
- 截图检查除“元素是否存在”外，还必须逐项判断：主动作是否易找、信息是否紧凑、卡片是否过高、按钮是否有上下文、图表是否真实、空态是否可理解、首屏是否形成连续办理路径。
- 页面只有在桌面与窄屏都达到上述效果、关键交互可用，并完成 RISEMAP 同页事实对照后，才允许在 `tests/page-polish.manifest.json` 中从 `review_required` 改为 `accepted`。

## 控件与反馈

- 主按钮代表用户当前最可能完成的动作。导出、切换视图、辅助设置等使用次要按钮，不与主任务争夺视觉优先级。
- 选择器和日期使用 `ForgeSelectControl`、`ForgeDateInput` 等共享控件；确认和破坏性操作使用 `ForgeDialog`。不得调用浏览器原生选择器、日期控件或确认框。
- 行操作只显示当前状态下真实可执行的动作。动作不可办理时，使用说明、状态或空态解释原因，不保留点击无结果的按钮。
- 提交前校验必填、范围、状态和来源关系；提交中防止重复操作；提交后显示结果，并回读更新后的页面状态。
- 删除、终止、作废、撤销和清空必须二次确认，弹窗写清对象、业务影响和不可恢复结果。
- 状态使用统一标签和语义色；同一业务状态在不同页面保持相同中文名称和颜色含义。

## 页面类型

- 工作台：先展示岗位需要处理的事项，再展示经营指标和模块入口；指标必须能追溯到业务数据或明确标注口径。
- 执行页：标题区给出主动作，随后是当前范围、状态筛选、任务列表和下一步；编辑表单应在用户当前上下文内完成。
- 分析页：先写口径和时间范围，再显示指标、趋势和明细；图表必须有对应明细或可解释来源。
- 配置页：突出配置对象、影响范围和保存结果；低频说明可以保留，但不能伪装成尚未实现的业务操作。

## 实施与验收清单

每个新页面或页面精修至少检查以下项目：

- 页面合同已记录 RISEMAP 当前入口、字段、状态、动作、阻断和下一步。
- 页面合同和精修清单已记录逐页主原型、参考页面及证据状态；批量套用共享样式没有被计作精修完成。
- 页面层级符合标题、动作、筛选、指标、主工作区、结果与下一步的办理顺序。
- 已复用共享控件和视觉变量；新增通用模式先扩展 `product-ui.ts`，仅页面特有布局留在页面内。
- 所有可见按钮、选择、日期、页签、弹窗和行操作都已在内置浏览器真实操作并回读结果。
- 已检查加载、失败、空态、权限或能力受限、成功反馈和窄屏布局。
- 已分别记录 RISEMAP 页面事实与 Forge 页面表现；外观差异、Forge 产品决策和待复核项没有混写成复刻事实。
- 已运行 `pnpm typecheck`、`pnpm validate`、`pnpm build` 及对应业务验收；涉及持久状态时从同一 SQLite 停服重启后回读。
