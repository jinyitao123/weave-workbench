# Forge 银行对账与财务期间切片

更新于 2026-09-10。实现分支 `codex/forge-productization-p5`，验收端口 `4375`，持久库 `.objectstack/p5-bank-period.sqlite`。

## 产品边界

- 银行流水是银行侧证据。登记、勾兑、取消、审核、反审核和作废均不改变资金账户余额，也不回写应收、应付、发票、订单或项目累计。
- 首批按一条银行流水对一条现有账面收付款。收入只能选择同账户有效 `forge_cash_receipt`，支出只能选择同账户有效 `forge_cash_payment`；账面记录同时只能有一条有效勾兑。
- 银行金额与账面金额一致才进入待审核并可审核为已勾兑。金额不一致进入差异状态，取消后才能重新匹配。
- 资金账户可以建立互不重叠的财务期间。建立首个期间后，标准收款、订单预收、付款及其可用撤销动作，以及银行流水登记、反审核和作废，只能发生在开放期间。
- 期间内所有非作废银行流水完成勾兑后才可锁定；关闭必须从锁定进入；锁定或关闭期间可以带原因重新开放。全部状态变化保留日志。

RISEMAP 现有证据只证明资金流水字段、统计、筛选与状态。相同材料下的成功勾兑、撤回及关账结果仍待复核，因此当前规则标为 Forge 的待对照实现。

## 验证结果

定向 API 5 组通过，覆盖重叠期间、匿名访问、期间外登记、重复银行参考号、收入和支出等额勾兑、差异阻断、取消、作废、锁定、关闭、重开与反审核。全过程验证银行动作不修改账面资金余额。

服务完整停止后从同一 SQLite 重启，回读得到两条已勾兑流水、一条已作废差异流水、两条当前有效审核记录、一条历史反审核、一条取消记录和六条期间状态日志；数据库完整性检查为 `ok`。

内置浏览器使用独立账户登记 `400` 元银行收入，关联已入账 `400` 元收款并审核。页面显示银行流水、账面金额和差额均正确，账户账面余额未因银行动作再次变化；空白表单、差异提示和财务期间页均已检查。

## 未包含范围

银行文件导入、来源批次去重、自动匹配、批量审核、手续费拆分、账户划转双边记账、总账凭证、全组织统一期间、退款及采购退货退款的实际收付日期字段和期间控制、发票红冲期间控制、岗位权限、数据库事务与并发锁不在本批。上述余额变动路径在补齐实际收付日期前不能宣称受财务期间完整覆盖。
