# Forge 客户预收款与退款切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-customer-prepayment-refund`，验收端口 `4366`，数据库 `.objectstack/otc-customer-prepayment-refund.sqlite`。该库承接已停服的收款结算数据，并通过非破坏性同步加入客户预收、预收冲抵和客户退款表；SQLite 完整性检查为 `ok`。

## 证据边界

RISEMAP 收款管理展示待确认、全部、客户和订单预收款视图，并汇总预收金额、已冲抵和余额；客户退款页展示关联合同、客户、币种、实退金额、退款方式、单据、财务审批、付款、核销和申请日期。依据来自 DR-1015 至 DR-1018、DR-1025。当前没有在 RISEMAP 保存同材料预收款或客户退款，因此这些页面只作为字段和流程依据。

## 已实现行为

- 已审核或执行中的销售订单可登记实际预收到账。到账立即增加资金账户，形成待确认预收款；累计预收不得超过订单总额减已回款与现有预收余额。
- 财务确认后预收款进入可分配状态，可直接冲抵同一客户、同一订单的未结应收。冲抵同步更新应收、发票、订单及已有项目销售关联的回款累计，不产生第二笔现金流。
- 客户退款依次经过申请、财务审批、实际付款和核销审核。待审批、已审批和待核销退款占用可用预收余额；驳回释放占用。实际付款扣减资金账户，核销审核后才减少预收余额。
- 收款管理页可办理订单预收、财务确认、应收冲抵和退款申请；退款申请页在客户与供应商页签间展示各自审批、实际收付与核销状态。

## 验证结果

定向 API 验收共 6 组。订单总额 `10000`、当前应收 `6000` 时登记并确认 `8000` 预收，资金账户从 `1000` 增至 `9000`；再冲抵应收 `1500`，应收余额降至 `4500`、预收余额降至 `6500`，账户余额不变。`500` 退款申请被驳回后释放占用；另一笔 `1000` 退款完成审批、付款和核销，资金账户降至 `8000`，预收余额降至 `5500`。匿名登记、超订单预收、超可用退款、金额不一致付款和重复核销均被阻断。

浏览器独立办理 `CR-PRE-BROWSER-20260910-001 → OFF-CR-BROWSER-20260910-001 → CRF-BROWSER-20260910-001`。`1200` 预收确认后冲抵 `200` 应收，再完成 `300` 客户退款，最终预收余额 `700`、应收余额 `2800`、资金账户余额 `1900`。退款页显示记录已完成、财务已审批、已付款和已核销。

完整停服后从同一 SQLite 文件重启，API 按原 ID 回读 API 与浏览器两套预收款、冲抵、应收、退款和资金账户；新开浏览器页仍显示相同金额与状态。验收报告位于运行时目录 `.objectstack/acceptance/customer-prepayment-refund-report.json`，不提交数据库或运行时产物。元数据门禁通过：96 个对象、1446 个字段、21 个页面、102 个动作；`typecheck`、`validate` 和 `build` 均通过。

## 未证明范围

连续多对象写入仍依赖顺序调用，没有数据库事务包裹；到账、冲抵、退款付款或余额更新中途失败时仍可能不一致。当前一笔到账对应一条客户预收款，只允许冲抵同一订单应收。销售退货、贷项通知、收款撤销、反核销、红冲、银行对账、收入确认、岗位权限和 RISEMAP 同材料成功记录仍待后续阶段。
