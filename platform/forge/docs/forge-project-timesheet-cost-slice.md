# Forge 项目工时与人工成本切片

更新于 2026-09-10。该切片把项目工时从草稿、提交、审核带入可追溯的人工成本池，并同步项目累计成本。工时记录和成本记录分别持久保存，驳回不会形成成本，已结算、已终止或已归档项目不能继续填报或增加人工成本。

## 业务规则

- 工时记录包含项目、员工、可选任务、日期、内容、类型、工时、费率和成本；专用页面从当前项目团队选择人员。单条工时限制为 `0.25` 至 `24` 小时，费率不得小于零。
- 保存只产生草稿；提交后进入待审核。只有待审核记录可以通过或驳回，审核意见必填。
- 审核通过后按 `工时 × 费率` 生成一条已归集人工成本，来源固定指向原工时，并把金额加到项目累计成本。重复审核被阻断。
- 审核与驳回记录当前登录操作人的账号 ID。驳回只保存结论和意见，不生成成本。
- 项目经营分析对未结算项目读取当前累计成本，因此已审核人工成本会进入活动项目的经营口径；已结算项目继续读取结算快照，避免事后改变历史结算结果。

## 验证结果

- API 独立项目保存并提交 `TS-API-20260910-001`，`6.5h × 200 = 1300`；审批后生成 `COST-TS-API-20260910-001`，人工成本已归集 `1300`，项目累计成本为 `1300`。
- 另一条 `2h × 300` 工时被驳回，未生成成本。匿名调用、`25h` 非法工时、已结算项目填报和重复审核均被阻断。
- 浏览器独立办理 `TS-BROWSER-20260910-001`，完成保存草稿、提交审核和审核通过；页面回读 `8.00h`、`¥1,760.00`，并显示同来源的人工成本记录和项目累计成本。
- 验收使用独立端口 `4361` 和 `.objectstack/otc-project-timesheet-cost.sqlite`。完整停服、SQLite 完整性检查和同库重启后，API 与浏览器记录、审核状态、成本来源和项目累计仍一致。
- 元数据门禁通过：85 个对象、1246 个字段、17 个页面、77 个动作。

## RISEMAP 对照与边界

RISEMAP 已观察到项目工时页面的单号、日期、人员、项目、内容、工时、类型、费率、成本和状态字段，以及待审核、已通过、已驳回状态；帮助与项目分析说明显示工时连接项目执行、人员利用率和人工成本，审批后的业务记录进入成本归集。当前没有在 RISEMAP 建立同材料工时并完成审核，因此 Forge 的费率来源、审批岗位和成本生成时点仍待同输入复核。

当前费率由填报时输入，尚未接入岗位费率、人员薪资或加班规则；批量填报、非项目与闲置工时、撤回重提、反审核、成本冲销、结算后调整、制造费用、差旅、委外、报销和其他外部项目成本仍未实现。工时、成本和项目累计采用顺序写入，尚无数据库事务级原子回滚保证。
