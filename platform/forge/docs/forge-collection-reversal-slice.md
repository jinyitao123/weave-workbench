# Forge 收款反核销与到账撤销切片

更新于 2026-09-10。本切片承接已停服的分批履约数据，只证明销售收款链的逆向更正；RISEMAP 尚未取得同材料成功撤销记录，因此当前行为仍待复核。

## 已实现行为

- 已审核核销可按原因反核销，恢复应收、发票、订单、合同和项目的已回款累计，并把金额退回原收款流水的未分配余额。
- 同一收款流水存在待审核或已审核核销时不能撤销；全部分配均已取消或反核销后，才可撤销原到账。
- 撤销到账按原账户冲减余额，余额不足时阻断；核销和到账都保存撤销人、时间、原因及独立日志。
- 已结算项目禁止反核销；同一收款存在更晚的已审核核销时，必须按逆序撤销，避免重算口径跨越后续账务。
- 页面提供“反核销”和“撤销到账”，并要求填写撤销原因。

## 验证结果

定向 API 验收共 4 组通过。基准应收 `121600`，登记到账 `60000` 后完成分配与审核，再依次反核销、撤销到账；最终应收恢复为 `121600`，资金账户恢复为 `0`，并保存两条撤销日志。匿名访问、空原因、越过有效核销和重复撤销门槛一并覆盖；余额不足阻断已实现，本轮未单独构造动态样本。

浏览器办理 `CR-REV-BROWSER-20260910-001 → CA-REV-BROWSER-20260910-001`，金额 `40000`。审核核销后从页面反核销，再撤销原到账；页面最终显示两笔收款和两笔核销均为已撤销，应收恢复为未收款，账户余额为 `0`。

`.objectstack/otc-collection-reversal.sqlite` 完整停服后使用同一文件重启，API 回读原 ID、状态、金额、撤销原因和日志；浏览器重新加载后结果保持一致。SQLite 完整性检查为 `ok`。元数据门禁通过：103 个对象、1627 个字段、23 个页面、119 个动作；`typecheck`、`validate` 和 `build` 均通过。

## 边界

本切片没有实现采购付款撤销、进销项发票红冲、预收预付冲抵撤销、银行流水对账、总账凭证、财务关账期间、岗位权限和事务级原子回滚。已结算项目阻断与逆序撤销规则已在动作层实现，本轮没有独立构造已结算样本进行动态验收。RISEMAP 的实际撤销入口、审批要求、期间控制和凭证影响仍需同材料补证。
