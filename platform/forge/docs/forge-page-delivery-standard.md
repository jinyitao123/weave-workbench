# Forge 默认页面交付标准

适用于所有新增页面、页面精修及功能修复。任务只需描述业务目标和范围，默认继承本标准、项目 AGENTS.md 和[页面精修基线](forge-page-polish-baseline.md)。本标准不改变 RISEMAP 实时对照、同材料办理、API、持久化回读和工程门禁的要求。

## 范围与任务合同

- 联合核对实际导航、注册页面、内部跳转、列表/新建/详情/表单/弹窗及已有页面合同；manifest 不是全量范围的唯一依据。
- 一条完整业务链作为一个批次，通常涉及 2–5 个关联页面；复杂单页可单独成批，不按数量切断岗位和单据承接。全量目标不随批次缩小。
- 使用[逐页交付模板](templates/forge-page-delivery.md)，每页开工前说明岗位、任务、主原型及理由、参考页、首屏顺序、主动作、筛选作用对象、数据口径、状态、阻断、来源和下一步。
- 每项要求都有稳定编号，关联“当前 RISEMAP 事实或明确的 Forge 决策 → 页面区域/控件 → 实现位置 → 操作步骤 → 预期与实际结果 → 证据”。能力说明不等于能力实现；隐藏假按钮后，原业务缺口仍保留。
- 分别维护未实现、功能已有但页面交互欠缺、RISEMAP 证据不足三类清单。不得通过删除需求或把待复核项改成不适用来获得通过。

## 标准样例与逐页结构

| 主原型 | 参考源文件（均位于 apps/forge-objectstack/src/pages） | 主要学习内容 |
| --- | --- | --- |
| workbench | workbench.page.ts | 岗位焦点、待办优先级、业务入口和下一步 |
| task_workspace | project-task-workspace.page.ts | 当前任务、办理依据、状态、动作和承接 |
| timesheet_composite | project-timesheet-cost.page.ts | 范围、判断指标、填报/审核、明细和结果 |
| analysis | workbench.page.ts 或 project-timesheet-cost.page.ts | 口径、趋势、异常和可追溯明细 |
| configuration | project-timesheet-cost.page.ts | 控件、表单及保存反馈；结构按配置任务组织 |

共享控件来自 product-ui.ts。禁止为了模仿样例给配置页强加指标卡，或把不同职责页面做成只替换标题和列的同一个整页模板。

每批首次使用原型时保存标准样例包：源文件版本、视口尺寸、数据条件、桌面与窄屏截图，以及为何采用该结构。页面自身还需保存有数据、空态、错误反馈和关键表单/弹窗证据。已有样例证据在版本、视口、数据和适用条件匹配时可复用；历史截图不能替代项目规定的当前 RISEMAP 对照。缺少样例截图时如实记录待采集，不能把源码路径当成截图。本次规则引入不将任何参考页自动标成已验收。

实施过程中必须在 Codex 内置浏览器持续打开当前 Forge 页面供用户查看；切换页面时同步更新可见页面，修改前、修改后和关键交互状态都要刷新展示。后台浏览器中的 RISEMAP 取证不能替代这一可见实施窗口。

## 四维验收与返修

| 维度 | 必须检查的结果 |
| --- | --- |
| replication | 双侧同材料操作；入口、字段、状态、阻断、来源和下一步对照；差异已有明确结论 |
| visual | RISEMAP 与 Forge 在相同视口、缩放和数据状态下完成业务内容区像素对照；原图、叠图/差异图、元素几何测量和量化阈值全部通过；标准桌面、侧栏占宽后的实际内容宽度、窄屏以及有数据/空态、表单/弹窗/错误反馈分别取证；长文本和多动作压力状态下不存在控件重叠、挤压、异常换行、截断、错位或越界 |
| interaction | 所有可见按钮、筛选、选择、日期、页签、弹窗及行操作实际使用，覆盖提交中、防重复、失败反馈和成功后回读 |
| business | 正常链、关键异常、页面/API 一致性、关联单据和下一岗位；同一 SQLite 停服重启后回读 |

每项单独记录 pending/pass/blocked/fail。部分通过可保留证据及结果，页面总状态仍为 review_required；待 RISEMAP 复核、待独立验收不得称为 accepted。当前功能块没过项目门禁就不能进入下一功能块。

由实施者之外的复核者复现关键操作，并查看同视口的样例与页面、完整主工作区、窄屏及关键状态。复核者可以是用户或实际参与的独立审查者，不要求为每页另开会话；没有独立复核就记录未发生，不能由实施者换一个名字签字。缺陷带页面、复现步骤、预期、实际和证据退回实施者；修复后验证影响范围。

## 机器检查与证据版本

现有 `pnpm build` 的 prebuild 和 `pnpm acceptance:page-polish` 均执行 `tests/page-polish.static.mjs`。它继续检查原型、参考页、共享控件、原生弹框等，并通过 `tests/page-delivery-gate.mjs` 检查 accepted 记录。新标准下 accepted 必须使用 schemaVersion 2，并包含桌面和窄屏两组同视口像素对照；旧 schemaVersion 1 记录只能作为 review_required 的历史或部分证据。

- manifest 每个 accepted 条目只能包含一个页面，填写仓库相对路径 `contract`（逐页合同）、`evidence`（验收报告）、`acceptance`（结构化 JSON 记录）。全部文件必须真实存在且非空。
- acceptance 采用[模板](templates/forge-page-delivery.md)中的字段。记录页面、原型、已提交的被验收版本、实际环境、四维结果、独立复核、逐要求步骤与结果，以及桌面、窄屏、数据、空态、表单、错误反馈、样例对照等证据。
- 每组像素对照必须记录 RISEMAP 与 Forge 相同的视口宽高和缩放、业务内容裁剪框、原图、差异图、使用工具、不同像素比例和主要元素最大几何偏差。不同像素比例不得超过 `0.005`，主要元素最大几何偏差不得超过 `2px`；任何遮罩或排除区域必须逐项说明动态原因，不能遮掉业务内容、布局或控件。
- accepted 记录的每组原图必须各提供一张与记录视口尺寸完全一致的 PNG，差异图必须提供一张与业务内容裁剪框尺寸一致的 PNG。门禁固定用 `pixelmatch 7.2.0`、阈值 `0.1` 重新裁剪并计算，动态排除区只从分母和对照像素中剔除；记录的不同像素比例和提交的差异图必须与重算结果一致，不能依赖人工填写的合格数字。动态排除区最多 10 个，去重后的总面积不得超过业务裁剪区的 `1%`。每侧还必须提供一份同视口、同裁剪框的几何测量 JSON，至少包含 5 个同名主要元素及其 `x/y/width/height`；门禁重新计算最大几何偏差，不接受自报数字。
- 几何体检必须发生在交互验收之前，并用真实长单号、长客户名、长选择项和多按钮状态覆盖最坏宽度。逐个记录按钮、输入框、选择器、日期控件、页签、表格列、行操作及弹窗底部动作的边界框和结果；任何两项非设计性相交、主按钮文字被压缩、输入控件低于可用宽度、表格靠换行拉高行高、操作区被推出卡片或页面整体横向滚动都判为 visual fail，修复并重新截图后才能继续下一页。
- `subjectFiles` 用 SHA-256 固定页面源码、共享 product-ui.ts、参考页、视觉基线及本页依赖的对象、Action、服务、导航/配置等文件。四个默认文件由脚本强制要求；业务依赖的完整性由合同和独立审查负责。
- 脚本检查每个 subjectFile 在 reviewedRevision 的内容和当前内容均匹配记录。相关代码改变后旧证据失效：恢复 review_required，重验受影响维度，未受影响部分记录复用依据，再更新验收记录。仅合并或 cherry-pick 导致提交号变化，但受验文件内容完全一致时，可以沿用原验收版本。
- review_required 可填写 `acceptance` 保存部分证明，不填写代表总体通过的 `evidence`。旧的 review_required 条目暂不强制回填；首次触及页面时补合同和记录。历史债务不伪装成通过，也不迫使无关批次重做全站。
- 机器只证明结构、文件和版本条件满足，不能判断截图是否美观、证据是否充分、操作是否真的正确。禁止用脚本 PASS 反向宣称页面已通过人工或业务验收。

建议在 apps/forge-objectstack 目录验证：

```sh
node --test tests/page-delivery-gate.test.mjs
pnpm acceptance:page-polish
```

元数据修改继续执行 typecheck、validate、build 和对应业务门禁。纯规则/检查脚本维护使用相称验证，不启动业务页面或写入业务数据。

## 持续执行与效率

更新任务要求、形成合同、阶段汇报都不自动暂停已有执行；遵守用户明确的暂停与恢复指令。真实阻塞说明缺失条件与最小解阻动作，不原样无限重试。

同一失败连续两次且无新证据就换定位方法。代码、环境和依赖未变且没有未决疑点时，不重复相同验证。完整 DOM、日志和截图留在证据文件中，交接只带版本、范围、事实、决策、未决项、验证结果和下一步；按需加载，避免每轮重新扫描全部资料。

每批记录实现/精修类型、页面与业务链、首次验收结果、返工原因及实际可取得的耗时/调用/费用。拿不到的数据标未知；成本包含失败、复核和集成，不为收集成本先建监控平台，不凭模型占比自行换模型。

阶段报告固定给出本批范围、四维结果、实际打开的双侧页面、代码版本、证据、缺口和下一步。无缺口且达到本批门禁后，在已有授权内继续既定队列，不新增启动审批。
