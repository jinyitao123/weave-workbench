# Forge 项目费用与全成本结算切片

更新于 2026-09-10。该切片承接项目工时成本，把制造、差旅、委外和其他外部项目费用从报销草稿、提交、审核带入可追溯成本池，并将材料、人工和外部费用共同冻结到项目结算快照与经营分析。

## 业务规则

- 费用单固定归属一个项目，保存申请人、报销人、供应商、预计付款日、说明和多条费用明细。明细保存类别、业务日期、金额、发票引用和成本类型。
- 首条明细随费用单保存，草稿可继续追加。提交后锁定明细；只有待审核记录可以通过或驳回，审核意见必填。
- 审核通过后每条费用明细生成一条唯一来源成本记录。制造、差旅和委外分别进入对应成本类型，检验、软件、办公及其他类别进入其他项目成本。驳回不生成成本，重复审核被阻断。
- 已结算、已终止或已归档项目不能新增、提交或审核费用。活动项目实时累计已审核费用；最终结算按已分配成本逐类汇总并冻结材料、人工、制造、差旅、委外、其他和总成本。

## 验证结果

- API 在已有人工成本 `1300` 的活动项目上审批四条费用：制造 `800.25`、差旅 `320.75`、委外 `1500`、其他 `180`，费用合计 `2801`，项目累计成本变为 `4101`。另一笔 `500` 费用被驳回且没有生成成本。
- 匿名调用、零金额、已结算项目、提交后追加和重复审核均被阻断；审核人使用当前登录账号，不使用固定夹具身份。
- 浏览器办理 `EXP-BROWSER-20260910-001`，先保存制造费用 `900`，再追加差旅 `380`，完成提交和审核。活动项目从人工成本 `1760` 增至总成本 `3040`，经营分析显示营收 `48000`、成本 `3040`、利润 `44960`，成本构成为人工 `1760`、制造 `900`、差旅 `380`。
- 独立全成本结算案例在已交付、已全额开票回款项目上审批人工 `200`、制造 `400`、差旅 `200`、委外 `300`、其他 `50`。结算快照保存生产材料 `32640.0066`、总成本 `33790.0066`、毛利 `209409.9934`。
- 费用链使用端口 `4362` 和 `.objectstack/otc-project-expense-cost.sqlite`；全成本结算使用端口 `4363` 和 `.objectstack/otc-project-full-cost-settlement.sqlite`。两库均完成停服、SQLite 完整性检查和同库重启回读；费用页面与经营分析页重启后也按原记录回读。
- 元数据门禁通过：87 个对象、1283 个字段、18 个页面、82 个动作。

## RISEMAP 对照与边界

RISEMAP 已观察到费用报销的标题、本人或代他人报销、项目/合同/订单/期间归属、项目分摊、供应商、预计付款、借款抵扣、备注，以及费用类别、金额、说明、日期和附件字段；状态包含草稿、待审核、审核中、已通过、已驳回、已支付和已作废。成本中心说明已审批采购入库、生产领料和费用报销会形成成本记录。当前没有在 RISEMAP 用同材料完成费用审核、支付及全成本结算，因此 Forge 的分类映射和入账时点仍待同输入复核。

当前只实现项目归属和审核入成本。合同、订单、财务期间、多项目分摊、借款抵扣、真实附件上传、付款联动、撤回重提、反审核、成本冲销和结算后调整尚未实现。多对象和多明细写入仍为顺序操作，没有数据库事务级原子回滚保证。
