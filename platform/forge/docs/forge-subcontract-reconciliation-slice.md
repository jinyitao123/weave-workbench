# Forge 委外对账切片审查与实施边界

版本：2026-09-12  
基线：`codex/subcontract-product-sample`，基于主线 `d3ef2bc` 后的委外样板链。

## 目标

把 RISEMAP 的“委外对账”从订单上下文中的待复刻占位，恢复为按岗位办理的生产侧结算入口。财务或委外业务人员无需理解底层对象，就能按供应商看到可对账订单、回厂批次、待对账金额和阻断原因，并从当前上下文生成、确认或处理差异。

本切片只处理委外业务结算，不改线上 RISEMAP 数据，不把普通供应商余额对账改造成委外对账，也不删除现有 `forge_counterparty_statement` 能力。

## 证据分层

### RISEMAP 已观察事实

- RM-087“委外对账”是生产 / 委外管理下的独立入口。
- 页面显示待对账池、对账单、供应商、委外订单、回厂批次等汇总指标。
- 待对账池按供应商聚合，展示供应商、订单数、涉及委外订单、回厂单数、待对账金额和操作入口。
- RM-093“委外对账单”展示对账单号、供应商、账期、行数、加工费、补料、扣款、应付、关联应付和状态。
- 已保存的委外页面与指南证据已经证明：待对账池按“已入库且尚未对账”的回厂批次组织；多个回厂批次可以合并生成一张对账单；对账单状态至少包括待确认、已确认、已生成应付和已作废；应付金额口径为“加工费 + 补料 − 扣款”；已审批赔偿可以进入对账扣减；来源被其他对账使用后不可重复纳入。
- 当前证据仍未证明 RISEMAP 的内部审核、供应商确认、部分结算和应付生成是否由同一页面动作完成；Forge 对这些未观察行为保留“工程实现 / 待 RISEMAP 复核”标识。

### Forge 已有工程能力

- `forge_subcontract_order` 保存加工费总额、已对账金额、供应商和订单执行进度。
- `forge_subcontract_receipt` 与 `forge_subcontract_receipt_line` 保存回厂数量、良品/不良、可结算加工费和来源订单。
- `forge_subcontract_inbound` 保存良品入库结果；`forge_subcontract_ncr` 保存不良处置结果。
- `forge_counterparty_statement` 是按已审核应收/应付余额生成的通用往来快照，已有发送、确认、差异关闭动作，但不含委外订单、回厂批次和生产结算口径。
- RM-087 委外对账页负责从待办池生成、确认和生成应付；RM-093 委外对账单已拆为独立结果报表页，避免把待办入口和结果报表混成同一页面。
- `forge_accounts_payable` 现已增加委外对账来源和 `reconciliation_id` 关系；付款任务与付款核销仍未接入本切片。

### 工程推断

- 委外对账应以生产侧单据为主入口，以供应商为第一聚合维度，并可穿透到订单、回厂单、入库单和 NCR。
- 已完成回厂入库且不良处置已结束的回厂批次，才可进入待对账候选；存在待入库或未处置 NCR 时必须显示阻断原因。
- 对账单应冻结来源金额与来源单据，底层后续变化不能静默改写已发送或已确认的对账依据。
- 订单的 `reconciled_amount` 只能在委外对账状态达到明确的确认/关闭门槛后回写，不能在“生成草稿”时回写。

### 本轮工程边界决策

- 委外对账必须使用独立业务对象和页面，不复用通用往来对账页面的生成逻辑。
- 对账单行必须保存供应商、订单、回厂单、回厂明细和金额快照；生成后不可通过重新计算改变原行金额。
- 未完成入库、未处置 NCR、已进入其他有效委外对账单的回厂批次不得再次进入待对账池。
- 通用供应商余额对账继续保持原语义，不得通过改名或备注承载委外结算。
- 按 RISEMAP 已观察公式实现首版金额组成：加工费、补料费用、损耗赔偿/扣款、退款，并将未实现的费用来源保持为零值或明确阻断，不从备注推导。
- 首版支持多个已入库回厂批次合并生成一张对账单；同一回厂明细只能被一个未作废对账单占用。
- 对账单先进入待确认，确认后才允许生成应付；生成应付必须幂等。
- `reconciled_amount` 在对账确认时累计已确认分摊金额；只有订单剩余可对账金额为零时才标记为已对账。

### 待决策 / 待 RISEMAP 复核

- RISEMAP 是否由内部审核锁定和供应商确认拆成两个动作；当前 Forge 首版合并为“确认并锁定”并保留待复核标识。
- 补料、退料、超耗、扣款、赔偿、税额和运费的具体来源对象及分配算法仍待复核；当前只接入已有可结算加工费和已审批扣款候选。
- 差异对账单是否允许部分确认、重开或拆分；当前不实现这些行为。
- 委外对账是否需要供应商账号确认，还是由内部人员登记外部确认结果。
- 同一回厂批次多次返工回厂时，是否按批次独立对账，还是按订单合并。

## 三方互审结论

### 产品审查

产品审查结论：不能把通用“供应商余额对账”扩展成委外对账。RM-087 是按供应商聚合的待对账业务入口，RM-093 是结果报表。当前样板已形成“供应商待办 → 回厂来源 → 金额口径 → 对账动作 → 结果与下一步”的连续路径；订单上下文在存在未完成 NCR 或待入库时明确显示阻断原因，不再直接提供对账入口。内部审核、供应商确认和差异关闭仍需 RISEMAP 复核。

### 工程审查

工程审查结论：现有委外订单、回厂、入库、NCR 和库存能力已复用；通用往来对账未复用其生成逻辑。样板新增委外对账头、明细和操作日志，使用稳定来源 ID、重复占用阻断和幂等应付生成。当前动作仍是顺序写入，未建立事务或补偿机制；历史订单不自动迁移。

### 质量审查

质量审查结论：已使用真实订单 `OS-SAMPLE-001` 的回厂、入库和 NCR 结果完成 API 正常链路、重复生成幂等、内置浏览器逐步提交、同一 SQLite 停服重启回读，以及重启后内置浏览器结果页回读。未入库阻断、NCR 未处置阻断已分别在独立本地副本中完成 API 与内置浏览器证据：页面保留异常批次、显示具体阻断原因和下一步，正常批次仍可继续办理。构建、健康检查、单独 API 成功均不构成完整业务闭环。

三方结论：**委外对账可以进入受控实现，但只能实现已被 RISEMAP 证据支持的来源、状态和公式；未被同材料操作证明的行为必须在页面和报告中标记为 Forge 实现 / 待 RISEMAP 复核。**

## 停止规则

- 无法证明回厂、入库、NCR 与对账行的来源关系，停止金额回写。
- 对账单生成后底层变化可以改写已发送/已确认结果，停止继续实现。
- 页面只能从技术对象入口办理，不能从岗位入口连续完成，停止扩展。
- 订单上下文显示未完成异常却仍提供对账入口，停止扩展；必须先展示阻断原因和对应岗位入口。
- 重复生成会重复计入订单，或停服重启后来源关系丢失，停止样板验收。
- RISEMAP 未观察到的计价、扣款、赔偿、应付规则不得以“已复刻”名义发布。
- 产品金额口径和结算资格未确认时，停止编码，不以工程默认值推进。
