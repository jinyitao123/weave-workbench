## 判定

**当前样板在 Forge 本地受控范围内条件通过，不构成 RISEMAP 等价复刻或独立业务验收通过。**

条件是：本轮订单和期初库存准备也通过内置浏览器完成，随后从发料页面提交开始，经审核、出库、供应商签收、回厂验收、入库、对账、确认锁定和生成应付，形成一次连续的内置浏览器办理链；同一 SQLite 停服重启后 API 和页面均回读成功。仍没有真实多角色权限、RISEMAP 同材料写入、质量异常路径和独立业务负责人签字。该结论只覆盖已实际办理的批次和动作，不代表整张订单完成，也不代表 RISEMAP 尚未成功办理的行为已经复刻。样板只能作为后续 RISEMAP 复核和委外剩余功能修补的基线，暂不推广到采购、生产其他功能、销售或财务其他功能。

本轮新增的完整浏览器链证据：在隔离端口 `4463`、同一 SQLite `/tmp/forge-subcontract-full-browser-20260912.sqlite` 上，内置浏览器先完成 `SC-BROWSER-001` 建单审核，再通过“供应链 → 入库管理 → 期初入库”建立 `IN-BROWSER-SC-001` 的 `30` 件冷轧钢板可用库存；随后连续办理 `SI-BROWSER-FULL-001` 审核、出库、供应商签收，`SR-BROWSER-FULL-001` 回厂登记、良品入库，最后生成并确认 `REC-BROWSER-FULL-001`、生成 `AP-REC-BROWSER-FULL-001`。同一 SQLite 停服重启后 API 回读仍为订单 `reconciled`、发料 `signed`、回厂 `stocked`、对账 `payable_generated`、应付 `unpaid`，原料库存 `26` 件、成品库存 `2` 件、应付未结 `¥177.00`；新建浏览器页显示对账单 `1` 张和累计确认 `¥177.00`。

## RM-086 三方互审增补

产品审查：RM-086 是“委外退料”独立岗位入口，不应直接暴露库存余额对象；页面必须显示关联订单、供应商、退料原因、退料结果和下一步。确认退料与仓库入库是两个业务节点，不能合并成一次立即扣账。

工程审查：复用 `forge_subcontract_stock_balance` 和 `forge_subcontract_stock_ledger` 作为执行底座，新增退料头、明细、待入库单和日志保持来源可追溯；退料仅允许甲供料订单，数量按当前在外余量校验。当前顺序写入未升级为事务或补偿，供应商外部账号确认未实现。

质量审查：已覆盖草稿不动库存、超量阻断、确认后待入库、入库后余额/累计/流水、同一 SQLite 停服重启回读，以及内置浏览器列表和新建表单。尚未覆盖 RISEMAP 线上成功写入、真实多角色账号和赔偿扣款联动。

三方结论：**RM-086 可作为 Forge 受控本地样板纳入委外基线，但不能宣称 RISEMAP 行为已完全复刻，也不能单独触发向其他业务域推广。**

## RM-0481 供应商签收上下文修补

产品审查：已发出但尚未签收的发料单是委外订单的当前岗位任务，订单上下文必须把它排在回厂验收之前，并显示当前单据、状态、结果和下一步。入口不能只带订单而重新打开“新建发料单”，否则用户会丢失当前办理对象。

工程审查：复用现有 `subcontract_issue_sign` Action 和 `issued → signed` 状态；订单上下文增加 `issued` 派生阻断与具体 `issue_id` 跳转，发料页按该 ID 聚焦当前发料单。没有新增对象、库存写入或线上数据迁移。

质量审查：已覆盖订单上下文、具体发料单列表、签收对话框、真实浏览器提交、API 状态回读及同一 SQLite 停服重启回读。RISEMAP 当前线上签收写入、真实外部供应商账号和多角色权限仍未证明。

三方结论：**该修补通过本地产品连续性门禁，可合并到委外样板；供应商签收的 RISEMAP 对齐仍保持待复核，不得扩展为权限或跨域推广结论。**

## RM-0472 / RM-0481 回厂入库上下文修补

产品审查：订单上下文中的“确认良品入库”是仓库岗位对既有待入库单的办理，不应重新进入回厂登记。待入库和不良处置可以并行存在，确认良品入库不能隐式关闭 NCR。

工程审查：回厂页复用现有 `subcontract_inbound_confirm` Action；当 `order_id` 上下文存在 `pending_inbound` 回厂记录时，直接打开该记录的确认对话框，只有不存在待入库记录时才保留原有“登记回厂”建单逻辑。未新增对象、Action 或数据迁移。

质量审查：已覆盖回厂 API 正常/异常材料、订单上下文、入库确认对话框、内置浏览器提交、KPI 与列表结果、API 状态回读、同一 SQLite 停服重启回读，以及 NCR 未被误关闭的边界。RISEMAP 当前线上入库写入、混合批次、拒收/复检和真实多角色权限仍未证明。

三方结论：**该修补通过本地回厂到入库的岗位连续性门禁，可纳入委外样板；不良处置和 RISEMAP 行为复核仍保持独立待办。**

| 目标域 | 当前结论 |
