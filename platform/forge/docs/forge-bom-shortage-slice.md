# Forge BOM 缺料分析切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-shortage-analysis`，以汇川 OTC 固定材料中已生效的项目 BOM 为输入。

## RISEMAP 对照证据

- 未保存 BOM 进入缺料分析时，RISEMAP 阻断并提示“请先保存 BOM”。
- 已保存并生效的同材料 BOM，计划生产数量为 `1`、库存为零时，RISEMAP 显示齐套率 `0%`、采购件 `4`、缺口项 `4`、最大可生产数 `0`、预计采购金额 `14442.48`。
- 明细列为物料编码、名称、规格、型号、单位、单机用量、总需求、库存、锁定、可用、缺口、供应商、单价和小计。
- 本次观察页面没有生成采购申请或采购订单的动作，因此 Forge 不从缺料分析自动创建采购单据。

## Forge 已证明行为

1. 仅已生效 BOM 可分析，计划生产数量必须大于零，匿名调用被拒绝。
2. 按 BOM 子项和计划数量计算总需求，跨仓汇总真实库存余额的现存、锁定和可用数量。
3. 保存不可变的分析摘要与逐项快照，包括齐套率、缺口项、最大可生产数和预计采购金额。
4. 零库存时精确得到 RISEMAP 对照结果 `0% / 4 / 4 / 0 / 14442.48`。
5. 通过已审批期初入库加入真实库存后，计划数量为 `2` 得到齐套率 `60%`、缺口项 `3`；浏览器把计划数量改为 `1` 并重新分析后得到 `80%`、缺口项 `1`、预计采购金额 `2831.86`，仅 `RM-HMI-700` 缺 `1`。
6. 专用 BOM 工作台实现缺料分析页签、数量输入、重新分析、五项汇总指标和与 RISEMAP 对齐的明细列。

## 验证结果

- 定向 API 验收：6 项通过。
- 浏览器办理：从专用 BOM 工作台改数量并重新分析，页面结果与持久记录一致。
- 同库重启：完整停服后使用 `.objectstack/otc-shortage-analysis-final.sqlite` 重启，回读 3 份分析摘要、12 条快照明细和 3 条来源库存余额；浏览器刷新后仍显示最后一次 `80%` 结果。
- Forge 门禁：`pnpm typecheck`、`pnpm validate`、`pnpm build` 通过。

## 边界

本切片只证明当前库存下的 BOM 缺料计算和历史快照。采购申请或采购订单生成、库存预留、并发订单分配、供应商自动选择、生产缺料待办和补料闭环仍未实现。后续采购阶段必须独立建立 RISEMAP 行为证据，不从本切片外推。
