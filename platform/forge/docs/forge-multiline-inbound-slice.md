# Forge 多物料采购入库切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-multiline-inbound`，承接逐物料检验的合格数量。

## RISEMAP 对照结果

- 采购入库是检验后的独立业务动作。新建页先选择供应商和未完成采购订单，再带入订单物料；入库单状态按草稿、待审批、已审批、已入库推进。
- 已保存页面证据确认入库日期、入库单号、入库类型、仓库、往来单位、制单人、物料、规格型号、单位、数量、含税与不含税单价、税率、含税金额、库位、批次和状态等字段。
- RISEMAP 当前同材料到货尚未提交，因此没有同材料采购入库成功记录。Forge 实现采用已完成检验的剩余合格数量作为可入库上限，仍标为待远端提交复核。

## Forge 已证明行为

1. 一张采购入库单可承接同一采购订单的多张逐物料检验单；零合格数量不进入候选行。
2. 入库单号在保存时自动生成。草稿、待审批和已审批状态均不改库存余额，也不写库存流水。
3. 草稿开始占用检验合格剩余数量，防止两张未完成入库单重复认领同一数量；超过剩余合格量会被拒绝。
4. 审批意见必填。执行入库只处理已审批明细，逐行更新仓库与 SKU 库存余额、移动平均成本和库存价值，并生成来源可追溯的入库流水。
5. 入库数量逐行回写采购订单明细，汇总回写采购订单。到货登记中零合格的已检物料视为已处置，不阻止其余合格物料完成入库。
6. 本阶段不自动生成应付。旧实验曾按入库确认应付，但 RISEMAP 实际应付触发时点未证实，因而从当前主线中收窄。

## 验证结果

- 全新 `.objectstack/otc-multiline-inbound-final.sqlite` 在端口 `4355` 顺序跑完基础资料、销售、立项、计划、正式 BOM、缺料、采购、到货、检验和本阶段验收。
- API 基准入库为 3 种、3 件、未税 `9610.62`、含税 `10860.00`，排除零合格柜体；7 项验收覆盖匿名与格式错误、超量、自动编号、草稿占用、提交、审批、执行、重复执行、库存与应付边界；另验证合格数量分两次入库时，第一半不会提前关闭到货行。
- 内置浏览器使用独立订单办理 `PIN-2026-0002`，页面带出 4 种、合格数量 7、含税 `24120.01`，依次提交审批、填写意见、审批通过并执行入库；API 回读 4 条已入库明细和 4 条库存流水。
- 完整停服后使用同一 SQLite 文件重启，四张入库单、9 条明细、审批日志、库存余额和流水均按原 ID 回读，浏览器刷新后 `PIN-2026-0002` 仍显示已入库。
- `pnpm typecheck`、`pnpm validate`、`pnpm build` 是本分支最终门禁。

## 当前边界

RISEMAP 的同材料提交、检验完成和采购入库仍待用户明确确认后执行，因此自动候选规则、零合格处置和应付触发时点没有取得远端同材料结论。取消草稿、驳回重提、采购退货、批次与序列号级库存、附件、角色审批和并发事务仍未实现。多对象写入继续顺序执行，尚无数据库事务级原子回滚。
