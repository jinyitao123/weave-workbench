# Forge 供应链页面对照与实操记录（2026-09-17）

本轮使用内置浏览器实时打开 RISEMAP 与 Forge 两侧页面；Forge 侧运行独立实例（端口 4487 / 4488，各自独立 SQLite），未复用主线 4310。

## 一、采购申请（RISEMAP `/purchase/requests` ↔ Forge `page_purchase_request_pool`）

### RISEMAP 当前事实（实时）

- 标题 `采购申请`；表格列（含前置勾选列）：勾选、申请编号、申请标题、优先级、关联项目、关联客户、负责人、物料数、总数量、预估含税金额、币种、期望到货日期、建议供应商、采购原因、备注、状态、申请日期、操作。
- 筛选：搜索框（`搜索申请编号、标题...`）、`开始日期`、`结束日期`；当前列表 0 条，空态文案 `暂无采购申请`。
- 左侧导航 `采购管理` 下依次为采购发票、采购申请、采购待办池、询价管理、采购订单、采购退换货、供应商价格本。

### Forge 当前表现（实时，独立实例 4487）

- 标题 `采购申请`、说明 `发起采购申请、审批流转、转询价或订单全流程跟踪`；页内仅一条路径 `供应链 / 采购管理 / 采购申请`（自绘重复面包屑已移除）。
- 工具栏：下一步操作 采购待办池 ›、导出、批量导入、刷新、新建申请。
- 页签：申请列表 / 物料明细。筛选：搜索采购申请、采购状态（共享 picker）、`申请日期 起 ~ 止`（共享日期控件）、清空筛选。
- 列表 17 列与 RISEMAP 的业务列顺序完全一致；分页文案 `共 0 条记录 · 每页 20 条`；空态 `暂无采购申请` 并带新建入口。

### 明确差异与处理结论

| 项 | RISEMAP | Forge | 结论 |
| --- | --- | --- | --- |
| 行选择 | 列表首列为勾选 | 无勾选列 | 缺口：批量选择能力未复刻，记录待办，不隐藏 |
| 导入导出 | 单个 `导入/导出` 入口 | `批量导入` + `导出` 两个入口 | Forge 决策：拆分为两个独立动作，均可执行 |
| 日期筛选 | `开始日期` / `结束日期` | `申请日期 起 ~ 止` | Forge 决策：明确起止语义（用户整改要求） |

### 页面实操（Forge 独立实例）

- 新建申请：打开弹窗，字段含采购申请单号、申请标题、优先级、关联项目、关联客户、币种、申请日期、期望到货日期、负责人、建议供应商等，底部为「取消 / 保存并提交审批」；随后关闭。
- 物料明细页签：切换后列变为申请编号、明细来源、物料编码、物料名称、型号、规格、物料分类、数量、单位、含税单价、税率、含税小计、期望到货日期。
- 状态筛选：共享 picker 列出 全部状态 / 草稿 / 审批中 / 已通过 / 已驳回 / 已转采购 / 已取消；选择「草稿」后触发器显示草稿并进入空态。
- 日期筛选：日历打开（2026 年 9 月），选择日期后范围显示 `2026-09-09 ~ 请选择日期`。
- 清空筛选：状态恢复「全部状态」，日期范围清空。
- 控制台：无 error / warn。

### 窄屏（390×844）与本次修复

- 页面无横向溢出（`documentElement.scrollWidth` = `innerWidth` = 390）；工具栏换行后按钮宽度均 ≥56px、无裁切；筛选区收敛为单列；表格 `申请编号` 固定在左、`操作` 固定在右。
- 发现缺陷：空态位于 1540px 宽表内部并居中，窄屏时被推到可视区外，用户只看到空白表格。
- 修复：为空态单元内容增加 `position:sticky;right:0`（分支 `codex/supply-narrow-empty-state`）。修复后 390px 下空态与「新建申请」按钮可见（x=25..365），桌面 1280px 下仍居中，控制台无错误。
- 用户反馈「都挤在一起」：1280px 下搜索框、状态、日期范围与清空筛选挤在一行，两个日期控件被压到约 120px。
- 修复：筛选栅格改为 `minmax(200px,1fr) 190px minmax(380px,auto) auto`，日期范围最小宽度 380px；≤1280px 时搜索与状态占一行、日期范围与「清空筛选」占下一行（清空筛选右对齐）；≤1050px 时全部单列堆叠。
- 复核结果：1280px 下两个日期控件各 405px、清空筛选 79px 右对齐，无横向溢出；390px 下四个控件各 308px 单列堆叠，两个日期控件各 150px，无裁切、无溢出，空态与 CTA 可见。
- 回归修复：上一版插入 ≤1280 媒体查询时吞掉了 ≤1050 的 `@media` 前缀，导致 ≤1050 与 ≤760 规则整体失效（窄屏筛选不再堆叠）；已恢复三个独立媒体查询并重新验证。

## 二、边界与未决

- RISEMAP 采购申请列表当前 0 条数据，未做同材料的提交 / 审批 / 转询价页面级对照；Forge 独立实例为全新库，也尚无业务数据。
- 因此本页「业务正确性」仍为待复核：采购申请 → 审批 → 待办 → 询价 / 订单的承接此前只用 API 验收脚本证明，未在两侧页面用同一材料办理。
- 视觉精修未判定通过（缺完整桌面 / 窄屏对照截图集与独立复核），`designStatus` 保持 `review_required`。
- 附带记录：本轮为核对本页打开了 RISEMAP「其他入库」入口（`/inventory/inbound/new?type=4`），其行为是直接进入「新建其他入库」表单（含基本信息 / 入库物料明细 / 备注与附件，明细区提供 添加物料、Excel 导入、下载模板、导入任务），与 Forge 用列表承载、再由「新建其他入库」进入表单的做法不同，已记录为信息架构差异，待该页单独对照时处理。
