# Forge 制造装配与交付验收产品化验证

日期：2026-09-10。分支：`codex/forge-productization-p3`。消费基线：`d3e3740`。

## 实现边界

本阶段收敛两个既有工作台，没有修改生产、库存、调试、交付包、客户验收和项目完工的业务动作。

- 组装单新建页不再自动选择第一条 BOM 和仓库，也不再预填数量、业务备注、补退料数量、入库数量、批次和完工说明。保存、下达、入库和完工只在当前必填内容完整时开放。
- 组装单列表把成品 ID 转为可读名称；详情仍连续显示四行 BOM 需求、齐套、领补退、成本、分批入库和完工状态。
- 调试、交付包和客户验收不再自动选择第一条项目或组装单，不再预填设备、地点、版本、客户代表、检查结果、现场记录、证据、验收意见和签署引用。
- 每个调试或验收项目都要求操作者明确填写现场记录、证据并选择结果。调试结论、交付提交说明、整改截止日、客户意见、签署引用、整改措施、关闭证据、复验记录和复验证据均由当前操作显式提交。
- 导航保留连续办理工作台及仍需独立办理的领补退、拆解和换件页面；工作台已经覆盖的生产入库日志、调试记录、交付包、验收、整改、项目和日报原始对象不再重复出现在对应业务区。

## 连续业务门禁

服务运行于 `http://localhost:4394`，数据库为 `apps/forge-objectstack/.objectstack/productization-p3-full-chain.sqlite`。数据库以 P1 当前结构的完整采购入库材料为底，恢复经 P1 验收的生产前四项库存数量，并接入 P2 已验收的活动计划及工作项；接入时把项目和组织身份映射到同一项目。该组合只用于 P3 独立验收，没有修改来源数据库。

在同一数据库依次运行：

- `acceptance:production-assembly`：6 组通过，覆盖两台主单、计划优先分配、四行领料、补 `1`、退 `1`、两批入库和独立完工。
- `acceptance:delivery-acceptance`：7 组通过，覆盖调试失败与复测、交付资料缺失阻断与补齐、四项客户验收、一项整改关闭与复验、计划未完成阻断、客户确认和项目完工。
- 完整停止服务、以同一 SQLite 重启后，`acceptance:production-assembly-restart` 与 `acceptance:delivery-acceptance-restart` 均通过。

最终 API 回读到 `ASM-2026-0001` 已完工、四行物料和两批生产入库；`COM-2026-0001` 为五项通过，`DP-2026-0001` 为四项齐套并已接收，`ACC-2026-0001` 为四项通过、整改数为零，项目进度为 `100%` 且状态为已完工。

## 内置浏览器检查

内置浏览器在服务重启后检查了组装新建页、组装列表、客户验收新建页、交付控制台和客户验收详情。1280 像素视口下页面宽度均为 1280，没有页面级横向溢出。组装新建页的 BOM、仓库和数量为空，客户验收新建页的客户代表、四项现场记录和四项证据均为空，保存按钮保持禁用。验收详情显示 `ACC-2026-0001`、四项通过、零项未关闭整改及已关闭整改记录。
