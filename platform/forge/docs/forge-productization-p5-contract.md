# Forge 产品化 P5：银行勾兑与财务期间契约

日期：2026-09-10。实现基线：`main@8e035a4`。目标是把外部银行流水与 Forge 已有收付款账做可追溯勾兑，并用账户级财务期间阻止已锁定日期继续登记或撤销资金业务。

## 已知事实

- `forge_cash_receipt`、`forge_cash_payment`、客户退款、供应商退款和采购退货退款已经在各自业务动作中更新资金账户；应收应付在核销动作中更新。
- 基线提交 `8e035a4` 新增的银行流水登记会再次更新资金账户，审核分配又直接更新应收应付。这会形成一条与既有收付款账并行的资金过账路径，无法判断账户余额来自业务流水还是银行流水。
- RISEMAP 证据证明资金流水存在待分配、部分分配、待审核和已分配状态，并提供收支方向与流水类型筛选；同材料成功勾兑、撤回及关账结果尚未取得。

## 产品决策

1. 银行流水是银行侧证据，不是第二套资金账。登记、勾兑、取消和反审核都不修改资金账户、应收、应付、发票、订单或项目累计。
2. 首批只支持一条银行流水与一条现有账面收款或付款的一对一勾兑。收入只能匹配同账户的有效 `forge_cash_receipt`，支出只能匹配同账户的有效 `forge_cash_payment`。
3. 银行金额与账面金额一致时进入待审核；不一致时形成差异记录，不能审核为已勾兑。取消后才能重新选择账面记录。
4. 同一银行流水、收款或付款同时只能有一条有效勾兑记录。同一账户的非空银行参考号不可重复。来源批次与来源行键随文件导入能力后续实现。
5. 银行流水登记后保持原金额、方向、账户、交易时间和来源身份。录入错误只能在未勾兑且期间开放时作废，并保留操作日志。
6. 财务期间首批按资金账户建立。账户未建立任何期间时保持既有行为；建立首个期间后，银行流水登记、反审核和作废，以及标准收款、订单预收、付款和现有收付款撤销必须落在开放期间。
7. 锁定期间前，期间内银行流水必须全部完成勾兑，不允许待审核、差异或未匹配记录。关闭只能从锁定状态进入；锁定或关闭期间可以带原因重新开放，并保留日志。

## 页面契约

- “银行勾兑”页包含银行流水、勾兑记录和财务期间三个区域。
- 新建表单不预填账户、单号、金额、银行参考号、往来单位、审核意见或撤销原因；业务日期可以默认当天。
- 用户先选择一条银行流水，再从同账户、同方向且尚未勾兑的账面收付款中选择目标。页面显示银行金额、账面金额和差额。
- 期间页显示账户、起止日期、状态、期间内流水数和未完成数，并提供创建、锁定、关闭和重新开放动作。

## 工程复核

- 勾兑动作只写 `forge_bank_transaction`、`forge_bank_transaction_match` 及其日志，避免重复影响正式资金账。
- 服务端重新读取账户、银行流水、账面记录和有效勾兑记录；页面筛选不作为授权或唯一性保证。
- 期间边界按业务日期比较。启用期间控制后，找不到覆盖日期的开放期间同样阻断，避免绕过锁定区间补录。
- 当前 ObjectStack 动作由多个对象写入组成，尚无数据库事务级原子回滚或行级并发锁；首批通过重复身份和状态重读收窄风险，但不把它描述为并发安全。

## 质量复核与验收

- API 覆盖收入和支出各一条完整勾兑、金额差异、重复银行身份、重复账面目标、取消、反审核、作废和匿名访问。
- 财务期间覆盖重叠阻断、未勾兑锁定阻断、锁定/关闭后的登记与反审核阻断，以及带原因重新开放。
- 验收确认勾兑前后资金账户、应收应付和既有收付款金额均不变化。
- 使用独立端口和独立 SQLite，从同一文件完整停服重启后回读银行流水、勾兑、期间和日志；再从内置浏览器重新进入同一记录。

## 暂不执行

Excel/银行文件解析、银行直连、自动匹配、批量审核、手续费拆分、账户间划转双边记账、总账凭证、全组织统一会计期间、退款及采购退货退款的实际收付日期字段和期间控制、发票红冲期间控制、岗位权限和数据库事务级并发控制不属于本批。后续扩展必须沿用本契约中“银行证据不重复过账”的边界。
