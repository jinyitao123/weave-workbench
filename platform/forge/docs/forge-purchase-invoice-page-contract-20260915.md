# Forge 采购发票页面合同（2026-09-15）

## 页面与岗位

- RISEMAP：`https://risemap.cn/purchase/invoices`
- Forge：`http://localhost:4386/_console/apps/forge/page/page_purchase_invoice_entry`
- 岗位：采购经办、应付会计。
- 职责：查看采购进项发票，回溯采购入库、采购订单、供应商及应付账款。

## RISEMAP 当前事实

- 标题“采购发票”，说明“进项发票（收票登记）全记录，票可分摊至采购订单，登记后自动联动应付”。
- 状态页签为全部、正常、已作废、已红冲；工具栏有邮件收票、导出和刷新。
- 搜索区支持采购发票搜索和抵扣状态筛选。
- 表格列为发票号/类型、开票日期、供应商、价税合计、税率、分摊订单、状态、抵扣状态、登记时间、登记人、操作。
- 当前 RISEMAP 账号无采购发票；未观察到列表新建入口或有数据时的行操作。

## Forge 实现与业务链

- 独立列表页直接读取进项发票、明细、供应商、采购订单、采购入库、应付和登记人。
- 页签、搜索、抵扣状态筛选、导出、刷新、表格列及空态按 RISEMAP 当前页面实现。
- Forge 增加“待登记入库单”作为明确产品入口，从已入库且尚未登记有效发票的采购入库单进入登记；这属于 Forge 产品决策，不冒充 RISEMAP 当前行为。
- 浏览器已从 `PIN-2026-0001` 登记 `PI-PIN-2026-0001`，生成一条发票明细，并将原应付关联到该发票；列表回读金额 6,800 元、正常、待抵扣。
- 邮件收票尚未配置企业邮箱。页面使用业务说明弹窗明确缺口，并引导到待登记入库单，不提供无结果的假入口。

## 阻断与下一步

- 只有已入库采购单可以登记进项发票；同一入库单已有有效正常发票时不能重复登记。
- 应付日期不得早于开票日期；金额和数量必须来自已入库业务数据。
- 红冲能力由发票记录动作与红冲中心承载，付款或冲抵后会阻断；RISEMAP 当前空列表下的行操作仍待同材料复核。

## 验收材料

- RISEMAP/Forge 内置浏览器对照首屏、页签、筛选、邮件收票反馈、待登记入口、登记表单和登记后列表结果。
- `pnpm acceptance:purchase-invoice-page-readback`
- 同一 SQLite 完整停服重启后页面与 API 回读。
- `pnpm typecheck`、`pnpm validate`、`pnpm build` 及页面控件门禁。
