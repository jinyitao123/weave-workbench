# Forge 逐物料待检与检验切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-multiline-inspection`，承接订单级多物料到货登记。

## RISEMAP 对照结果

- “待检验库存”按物料记录，列出待检单号、物料编码和名称、规格型号、到货数量、单位、批次、供应商或客户、采购合同、状态和操作。
- “检验单”同样按物料记录，列出检验单、到货单号、物料、供应商或客户、方式、总数量、合格数量、不合格数量、结果、状态和检验员；下一步是采购入库。
- 已保存证据确认一张检验单对应一种物料，并要求总数量等于合格与不合格之和。当前 RISEMAP 租户尚无同材料提交后的待检和检验记录，本阶段实现继续标为待远端提交复核。

## Forge 已证明行为

1. 多物料到货提交后，每条非零到货行生成一条独立待检记录；草稿不生成待检记录。
2. 每条待检记录只能生成一张检验单，检验单保留到货头、到货行、采购订单、订单行、供应商、仓库、SKU、批次和数量来源。
3. 支持全检和抽检两种办理方式；免检、抽样规则与检验方案尚未接入，因此不能从当前结果外推。
4. 完成检验时录入检验日期、合格数量和结论，不合格数量自动按总量扣减；结果自动判定为合格、部分合格或不合格。
5. 单条完成后，到货登记保持检验中；只有全部到货物料完成检验，整张到货登记才进入已检验。
6. 检验只回写物料、待检记录、到货登记和采购订单明细的检验累计，不自动创建入库单、增加库存或确认应付。

## 验证结果

- 全新 `.objectstack/otc-multiline-inspection-final-v2.sqlite` 在端口 `4354` 顺序通过基础资料、销售、立项、正式 BOM、缺料、采购、到货和本阶段验收。
- 本阶段 API 验收 8 项全部通过，覆盖 4 条待检记录、逐物料建单、重复阻断、数量与结论边界、三种结果、整单状态聚合、匿名访问和不生成入库单。
- 内置浏览器从待检列表为 `RM-HMI-700` 生成 `IQC-2026-0005`，录入总数 3、合格 2、不合格 1，结果回读为部分合格；其余三条经 API 完成后，到货登记进入已检验。
- 完整停服后使用同一 SQLite 文件重启，API 按原 ID 回读两组各 4 条待检记录和 4 张检验单；浏览器刷新仍显示触摸屏检验结果及结论。
- `pnpm typecheck`、`pnpm validate`、`pnpm build` 为本分支最终门禁。

## 当前边界

RISEMAP 的真实到货提交仍需用户确认，因此待检和检验的自动生成时机尚未得到同材料远端记录证明。检验项目库、检验方案、抽样数量、免检分流、附件证据、不合格处置、让步接收和采购入库继续待后续阶段。多对象写入仍为顺序执行，尚未证明并发提交下的原子回滚。
