# RISEMAP 产品结构复刻挽回方案

> 历史阶段方案（2026-09-16 标记）：下文队列、分支、环境、已完成声明和取证方式保留为当时记录，不作为当前执行指令。现行要求以[项目规则](../AGENTS.md)、[交付标准](forge-page-delivery-standard.md)和用户当前目标为准；不得据本方案跳过实时页面对照。保留原路径以维护页面合同及历史证据引用。

版本：2026-09-12  
基线：Forge `main`，提交 `ae6b5d4`；RISEMAP 依据已保存的当前菜单、页面合同和只读行为证据。

## 目标与边界

目标是让 Forge 按 RISEMAP 的产品结构承载真实岗位任务，并逐功能证明页面、动作、状态、上下游关系和持久化结果。对象、字段和 Action 数量只用于工程盘点，不用于判断产品完成度。

本方案只改变 Forge 的承载和实现方式，不删除既有对象、Action、记录、台账或验收材料，不迁移或改写线上 RISEMAP 数据。未在 RISEMAP 成功办理的行为继续标为“待 RISEMAP 复核”。

## 加速执行方法

工作量按“菜单广度”和“业务深度”分开管理，不要求 181 个入口同时达到同一深度：

| 等级 | 范围 | 本轮要求 | 不得外推 |
| --- | --- | --- | --- |
| A 类主链 | 订单、采购、销售、生产、委外、财务 | 当前页面、页面合同、岗位任务、正常/异常路径、上下游和持久化验收 | 不能因为某一条主链通过而宣布整个业务域完成 |
| B 类常用能力 | 主数据、报表、常用配置 | 菜单归位、入口可达、首屏字段/动作和缺口记录 | 不能把首屏可见写成业务闭环 |
| C 类低频能力 | 行政、人事、低频系统配置 | 保留正确菜单、记录 RISEMAP 事实和未实现边界 | 不阻塞 A 类，也不提前实现未经取证的规则 |

每个 A 类功能使用同一张页面合同推进：`RISEMAP 入口 → Forge 入口 → 页面职责 → 岗位 → 主单据 → 字段/列表列 → 状态 → 动作 → 阻断 → 来源关系 → 结果 → 下一步 → 验收材料`。取证只在 RISEMAP 事实发生变化时增量更新；Forge 页面和验收脚本复用已有合同，不重复发明页面结构。

浏览器只承担用户可见行为证明，脚本承担批量数据断言和停服重启回读。实现、取证和验收可以在独立 worktree 并行，但共享导航、页面 barrel 和包配置统一由主线合并。这样减少重复劳动，不降低任何业务闭环门禁。

## 产品地图

Forge 一级导航固定对齐 RISEMAP：

`工作台 → 供应链 → 销售 → 生产 → 项目 → 行政 → 财务 → 报表 → 系统`

二级导航使用稳定任务簇。三级入口只暴露用户可办理的列表、看板、工作台或设置页；明细、日志、流水和审批记录进入主单据详情页或关联页签。OTC 九阶段保留为跨菜单任务旅程，不再作为一级导航。

当前完整映射与缺口见 `docs/risemap-menu-recovery-map.md`。其中工作台和行政的“复刻状态”入口只保留结构并显示未实现状态，不代表业务能力已经存在。

## 页面架构

每个业务功能按以下层次实现：

1. 岗位入口：显示该岗位当前可办理的待办、预警和筛选结果。
2. 主单据工作台：显示主单据身份、来源、当前状态、关键数量/金额、负责人和交期。
3. 任务动作区：只显示当前状态允许的动作，动作前明确影响和阻断条件。
4. 业务页签：明细、上下游单据、库存/财务结果、异常、审批和操作记录。
5. 下一步区：显示已完成结果、未完成原因、下一岗位和可直接进入的后续单据。
6. 审计与回读：记录操作者、时间、来源、状态变化和持久化标识，支持同库停服重启后回读。

技术对象可以继续作为服务层和数据层存在，但不得迫使用户理解 `source_object`、`source_id` 等内部命名才能办理业务。

## 核心任务旅程

首个样板为委外业务：

`委外订单 → 发料 → 供应商签收 → 回厂验收 → 良品入库 / 不良处置 → 对账结算`

岗位连续性要求：

- 委外业务员建立并提交订单，看到供应商、料权、加工件、交期和付款条件。
- 仓库人员从订单上下文办理发料、审核、出库和签收，看到库存变化和剩余可发数量。
- 质检/收货人员从来源上下文办理回厂，拆分良品/不良，看到批次、耗用、待入库和 NCR。
- 仓库人员确认良品入库，看到不可撤回影响、正式库存和材料倒冲结果。
- 质量岗位完成不良处置，状态回写回厂和订单，并显示仍然阻断的后续任务。
- 财务人员只从已满足结算条件的回厂、退料、补料、扣款和赔偿候选生成对账单，再生成可追溯应付。

## 现有能力处理策略

| 处理 | 范围 | 原则 |
| --- | --- | --- |
| 保留 | 现有对象 ID、Action 名称、库存余额、库存流水、审计日志、已验证 API 能力 | 作为兼容执行底座，不隐式重算历史账 |
| 改造 | 委外四个分离工作区、订单状态、回厂/NCR 状态、财务入口、来源跳转 | 增加业务上下文、岗位任务、状态语义和下一步；对账池与对账单已形成首个受控样板 |
| 新增 | 委外上下文读模型、批次来源、退料、岗位待办，以及后续补料/赔偿来源 | 已新增并验收对账单、对账行、应付关系和退料待入库链；其余按证据逐项实施 |
| 收回导航 | 明细、日志、流水、审批记录等技术对象入口 | 从常规菜单移入主单据详情，不删除底层能力 |
| 暂不开放 | 未经 RISEMAP 或真实业务材料证明的计价、赔偿、扣款、超耗、自动应付规则 | 标为工程推断或待复核，不固化为产品规则 |

## 数据与迁移策略

1. 历史对象、记录 ID、来源单号、库存和财务台账保持不变。
2. 新上下文先以只读投影或影子读模型聚合现有订单、发料、回厂、入库、NCR 和财务候选。
3. 历史数据不自动生成新的对账、赔偿或应付，除非规则经过产品确认并有显式迁移记录。
4. 新动作必须幂等，来源关系使用稳定 ID，复合库存/财务动作必须使用事务、版本校验或可验证补偿。
5. 每个样板使用独立 worktree、端口和 SQLite；合入主线前只带代码、文档和脱敏证据，不带运行时数据库、构建产物或登录态。

## 视觉与交互基线

- 保留 ObjectStack Console 统一外壳和页面承载方式。
- 以 RISEMAP 的信息层级、阅读密度、标题/状态区、工具栏、筛选、表单顺序、详情页签和反馈路径为基线。
- 页面标题、状态、主操作、结果和下一步必须处于同一任务上下文中。
- 不用浏览器原生弹框、原生下拉和原生日期控件；使用 Console 或项目共享组件。
- 样式差异可以接受，功能遗漏、错误状态、缺少来源、无法继续办理和错误阻断不能接受。

## 风险与三方互审结论

产品审查结论：RISEMAP 是按岗位和连续任务组织的委外产品，Forge 现有多个页面只能算工程切片；委外订单与发料、回厂、NCR、对账之间必须建立当前单据上下文。  
工程审查结论：现有订单、发料、签收、回厂、库存和 NCR 能力可复用；批次来源、委外对账/应付对象和状态拆分已在样板中落地，权限和复合动作原子性仍待补。
质量审查结论：委外对账样板已使用真实样本材料完成 API、正常/异常浏览器操作、同一 SQLite 停服重启和独立验收；随后将订单、发料、回厂和入库脚本改为可在同一 SQLite 中按原单据 ID 连续验收，四段连续运行和停服重启回读均通过。最近一次内置浏览器还从订单上下文连续办理 NCR 退货处置、对账单生成、确认锁定和应付生成，验证了异常阻断解除后可回到结算岗位。RM-086 另在发料签收后的同一 SQLite 上验证退料草稿、超量阻断、待入库生成、仓库入库和重启回读。该证据证明回厂批次结算与退料库存回写链，不证明订单整体完工；未观察行为仍保持待复核标识。

未决产品问题：

- 委外订单何时允许标记物理完成、质量完成、结算完成和业务关闭。
- 供应商签收由内部登记、供应商账号确认，还是两者并存。
- 良品与不良混合回厂时，NCR 未关闭是否阻断订单完工和对账。
- 加工费、补料、退料、扣款、赔偿、税额和应付的结算口径。
- 业务、仓库、质量和财务的角色、数据范围、审核与执行权限。

## 分阶段顺序

1. 菜单与信息架构基线：九类一级菜单、任务簇、A/B/C 分级、缺口台账和状态页；基线冻结后只做差异更新。
2. 委外订单上下文：订单、来源、状态、发料/回厂/异常/对账入口和岗位待办，先完成一张页面合同。
3. 委外执行链：发料、签收、回厂、入库、不良处置和精确来源关系，按一个连续任务逐功能通过。
4. 委外结算链：退料、补料、差异、对账单、供应商确认、应付和付款关系；未被 RISEMAP 证实的规则保持待复核。
5. 真实业务验收：同一 SQLite、真实浏览器、正常/异常路径、停服重启、RISEMAP 并排对照和独立业务验收。

只有第 5 阶段通过，才讨论其他业务域的迁移计划；在此之前不继续堆叠采购、生产、销售或财务孤立模块。

## 停止规则

- API、健康检查、构建、对象数量或单页可打开不得单独宣布业务闭环。
- 页面不能从当前单据连续进入下一任务，停止扩展。
- 关键来源、状态、数量、金额或库存结果无法回读，停止结算实现。
- 真实浏览器操作无法复现，或测试依赖 API 预制记录，停止样板验收。
- 各阶段不在同一 SQLite 中连续产生，停止“完整链”声明。
- RISEMAP 只有只读证据时，相关 Forge 行为必须保持“待 RISEMAP 复核”。
- 委外样板未完成独立业务验收前，不提出向其他业务模块推广的结论。
