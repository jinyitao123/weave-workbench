# Forge 销售收入确认切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-revenue-recognition`，验收端口 `4369`，数据库 `.objectstack/otc-revenue-recognition.sqlite`。该库承接已停服的销售分批履约快照；SQLite 完整性检查为 `ok`。

## 证据边界

RISEMAP 的销售收入确认页已观察到确认单号、来源订单、客户、确认方式、净确认金额、累计与订单金额、剩余金额、确认日期、财务期间、开票状态、状态、制单和审核信息。确认方式包含按发货、按开票、按里程碑、按验收、按周期和手动，状态包含待审核、已审核、已驳回和已作废。当前同材料销售合同配置为按发货出库，但 RISEMAP 尚无成功收入确认记录，因此 Forge 的生成、审核和金额规则属于待复核实现。

## 已实现行为

- 执行中、部分发货、已发货或已完成订单可从当前订单的已出库记录生成待审核收入确认单。单据保存来源键、订单、合同、客户、项目、确认方式、确认日期、财务期间、开票状态、制单人和完整金额快照。
- 每笔已出库来源只能存在一张未驳回、未作废的有效确认单。驳回后释放来源，可重新生成；匿名、错误期间、跨订单来源、错误来源状态、重复来源和累计超订单金额均被阻断。
- 发货确认金额读取销售订单明细的折后含税小计，按出库数量占订单数量的比例计算，避免使用历史未折扣发货金额。审核通过后更新订单累计确认收入和来源确认状态；驳回只保留审批轨迹，不计入累计确认收入。
- 按开票来源的生成逻辑已实现，但本阶段没有独立的按开票订单样本，因此不记为已验证。里程碑、验收、周期和手动确认会明确阻断，待对应来源计划建模后接入。
- 页面可选择可用订单和来源、生成确认单、填写审核意见、审核或驳回，并展示确认单、待审核、已审核收入、可用来源和 RISEMAP 对照字段。

## 验证结果

定向 API 验收共 4 组。订单 `SO-CONVERT-20260909-001` 总额为 `243200`，两笔出库各按折后订单金额确认 `121600`。API 先审核第一笔，第二笔生成后驳回并释放来源；页面随后从同一来源生成 `REV-BROWSER-20260910-001` 并审核。最终订单累计确认收入为 `243200`，剩余为 `0`，两笔出库来源均为已确认。

最终持久结果包含 3 张收入确认单，其中 2 张已审核、1 张已驳回，共 6 条生成与审核日志。原有 2 张销项发票和 2 条应收保持不变，原快照没有收款流水或资金账户余额，收入确认全程未生成或修改现金账。

完整停服后从同一 SQLite 文件重启，订单、三张确认单、两笔出库来源和六条日志均按原 ID 回读；浏览器重启后仍显示已审核收入 `243200`、待审核 `0`、可用来源 `0`。元数据门禁通过：102 个对象、1612 个字段、23 个页面、117 个动作；`typecheck`、`validate` 和 `build` 均通过。

## 未证明范围

RISEMAP 同材料成功确认仍待复核。按开票、里程碑、验收、周期、手动确认尚未完成对应样本或来源计划验收；批量审核、作废、撤销、反确认、跨期间调整、税务与总账凭证、角色权限和导出也未实现。多对象写入仍依赖顺序调用，没有数据库事务包裹；并发生成、审核中途失败和补偿恢复需另行加固。
