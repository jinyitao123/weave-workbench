## 判定口径

| 状态 | 判定 |
| --- | --- |
| 已证明 | 对应行为已实现，并完成定向 API 验收、同一 SQLite 停服重启回读和真实浏览器办理 |
| 部分证明 | 已实现一部分，或验证层级不全；缺失项在单元格内明确列出 |
| 未实现 | Forge 尚无可运行的对应业务对象或动作；导航占位不算实现 |
| 待 RISEMAP 复核 | Forge 可独立运行，但 RISEMAP 尚无同材料成功业务记录，不能声称行为一致 |

## 加速而不降门槛

功能按 A/B/C 分级推进：A 类订单与资金主链做完整纵向验收；B 类主数据、报表和常用配置先完成入口、首屏和页面合同；C 类低频行政、人事和系统能力先保留准确结构与缺口。分级只改变走查顺序，不改变 A 类功能的验收标准。

同一功能的证据分工固定为：内置浏览器证明入口、字段联动、弹窗、阻断、反馈、跳转和用户可见结果；API/验收脚本批量证明状态、来源、数量、金额、库存、幂等与同一 SQLite 停服重启回读。只有两类证据同时存在，才可从“已实现”进入“已证明”；RISEMAP 没有同材料成功记录时继续标为“待 RISEMAP 复核”。

页面合同是复用边界，至少记录 RISEMAP 入口、Forge 入口、岗位、主单据、字段/列表列、状态、动作、阻断、来源、结果、下一步、事实/推断/未决项和验收材料。新增功能不得绕过页面合同直接增加对象或 Action。

## 当前结论与执行顺序

Forge 目前不能称为完整覆盖 RISEMAP。当前顺序 OTC 主链已从项目立项推进到项目结算后的经营分析，并完成工时、多类费用、六类成本结算、采购应付付款、预收预付与退款、采购退换货、按发货收入确认、统一银行流水、期初往来建账与对冲以及受控 CSV 银行文件与余额对账；阶段 3 的图纸与工程变更已覆盖生命周期、五类版本冻结引用、多接收对象确认和客户图纸真实文件接收。委外已完成供应商能力开通、两种供料方式订单、正常发料签收、回厂确认入库、退货/特采/报废/返工四类 NCR 处置、甲供料退料、委外对账和应付生成；成品成本、零值特采计价、退料赔偿和结算细则仍待 RISEMAP 同材料复核。采购入库仍不自动生成应付，其余大块多数未实现。

后续以同一笔 OTC 项目为主线顺序推进：

1. 沿阶段 3 补客户图纸评审、采纳、归档和内部图号保存后关联，再补图纸导入导出和打印；真实文件、五类版本冻结和多人部分确认已经动态办理。
2. 在出现可验证的 RISEMAP 对应入口后补计划基线、修订和变更；甘特条与组合进度工作台需要独立前端视图能力。
3. 委外正常发料、签收、回厂确认入库、四类 NCR 处置、甲供料退料、对账和应付生成已经办理；继续按 RISEMAP 实时证据补拒收、复检、超耗补料、供应商赔偿、赔扣、部分结算/重开/拆分和追溯，并在取得远端可用订单时复核成品与特采计价。
4. 再扩展合同、订单、发货/收货与发票对账口径，补退款实际收付日期的证据、银行模板适配、自动匹配与未达账项、多明细及按金额红冲、采购抵扣撤回和其余收入确认来源。
5. 主链和委外完成后继续行政人事、报表、权限、集成、导入导出和打印等横向能力。
