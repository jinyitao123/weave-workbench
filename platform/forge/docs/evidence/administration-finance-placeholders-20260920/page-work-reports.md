# 工作汇报逐页对照记录

## 页面与状态

- RISEMAP 列表：`https://risemap.cn/ops/reports`
- RISEMAP 新建：`https://risemap.cn/ops/reports/new`
- Forge：`http://localhost:3001/_console/apps/forge/page/page_work_reports`
- 主原型：任务执行型
- 设计状态：`review_required`
- 本轮状态：已完成实时双侧取证、结构性实现、Forge 桌面/窄屏交互检查、本地草稿保存及同一 SQLite 完整停服重启回读；同材料双侧办理、附件实传、像素差异量化和独立复核仍未通过。

## RISEMAP 当前事实

- 列表使用“工作汇报 / 汇报规则”两个页签；标题区说明工作汇报用于周期性提交、审阅和复盘。
- 工具栏包含新建汇报、导出、刷新、密度或列表设置；筛选包含搜索、类型和状态。
- 列表列为选择框、汇报标题、提交人、汇报类型、汇报周期、状态、提交时间、审批评分和操作，当前无记录。
- 新建使用独立页面，顶部动作是“保存草稿”和“提交审批”。
- 工作内容可重复添加，每行包含工作内容、完成度和优先级。
- 正文依次包含工作总结、下期计划、问题与风险、项目进度说明、KPI 完成情况、商机跟进、客户拜访、技术问题、人员动态、次日计划和自评得分。
- 基本信息包含关联规则、汇报类型和汇报周期；附件支持多文件，并显示填写提示。

## Forge 修改前表现与明确差异

- 缺少 RISEMAP 的渐变标题区和“工作汇报 / 汇报规则”两页签，反而使用五个状态页签。
- 列表多出汇报编号、完成度、自评得分等结构，缺操作列，工具栏和分页也未按 RISEMAP 当前页面组织。
- 新建仍是小弹窗，不是独立任务页；只有标题、编号、类型、周期、单段工作内容、总结、计划、风险和评分。
- 缺重复工作内容、优先级、项目/KPI/商机/拜访/技术/人员/次日等正文区、关联规则和附件。
- “保存草稿”同时出现在列表标题动作和弹窗内，办理路径不自然。

## 本轮 Forge 实现

- 列表重做为渐变标题区、双页签、工具栏、三项筛选、RISEMAP 同序主要列、空态和分页信息。
- 新建改为页内完整任务页；顶部保留返回、保存草稿和提交审批，主内容按 RISEMAP 当前页面顺序呈现。
- 工作内容支持动态添加/删除，持久保存每条内容、完成度和优先级；列表完成度由有效工作项计算。
- 补齐工作总结、计划、风险、项目进度、KPI、商机、客户拜访、技术问题、人员动态、次日计划、自评、关联规则和多附件字段。
- 附件沿用 ObjectStack 存储上传链；没有选择真实文件前不把该能力判为通过。
- 必填校验覆盖标题、至少一条工作内容、总结和起止日期；日期倒置及 0–100 之外的完成度会被阻断。
- 汇报规则页只展示已证实的默认周报/自由汇报说明，并明确标注组织级规则发布和审批人配置待 RISEMAP 同材料复核，不伪造配置按钮。
