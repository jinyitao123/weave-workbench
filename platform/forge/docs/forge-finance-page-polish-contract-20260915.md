# 财务页面精修与 RISEMAP 对照合同（2026-09-15）

## 范围和判定

本轮覆盖财务导航下 21 个页面。RISEMAP 当前页面决定入口、标题、首屏信息结构、筛选、列、空态和已观察弹窗；Forge 继续使用 ObjectStack Console 与 `product-ui.ts`。RISEMAP 当前没有可办理数据的页面，本轮只确认首屏和空态，不据此推断审批、记账、撤销等后续规则。

## 已有财务页面统一处理

资金流水、银行余额对账、期初往来账与对冲、收款管理、付款管理、退款申请、销售收入确认、往来对账、财务冲销、开票收款与项目结算，均改用共享标题区并继续注入 `product-ui.ts`。原有真实按钮、筛选、状态变化、标准确认弹窗和持久业务动作保持不变。

本次二次精修以 `page_project_timesheet_cost` 的页面密度和信息层级为基准：所有注入 `product-ui.ts` 的产品页统一隐藏 Console 自动生成的重复标题，保留页面内标准标题区；财务列表页采用 1380px 内容宽度、20/22/42px 页面留白、四列指标卡、独立页签卡、筛选卡和数据表卡。标题区操作按钮统一为 36px，高频主次按钮统一为 34px 高和 8px 圆角，卡片统一为白底、细边框和 10px 圆角；原有渐变标题块收口为与工时管理一致的普通标题层级。该调整只改变页面承载和信息层级，不改变已验证的业务动作与持久数据。

## 明确差异和未决项

- RISEMAP 的员工借款已观察到提交后详情和待审批状态，但尚未执行“同意、驳回、转办、撤回”，因此这些动作的结果、阻断和后续放款核销仍待同材料复核。Forge 为完成岗位闭环保留审批、驳回、放款和还款能力，并将其标为产品扩展。
- RISEMAP 的成本、费用、报销和三类发票列表当前为空，因此首屏结构已有当前证据，未观察到的行级动作继续保持待对照。
- Forge 现在以独立开票申请承接“已发货未开票”销售订单，审批通过后才允许登记正式销项发票；登记时同步生成发票明细、应收账款并回写订单和合同开票金额。
- Forge 的财务账已经包含回款、付款、冲抵、退款、红冲和对账的可执行能力；这些能力继续保留。页面呈现采用 ObjectStack Console 的统一样式，视觉尺寸不做像素级复制。

## 页面结构门禁

`tests/page-polish.manifest.json` 收录本轮 21 个财务页面及此前已采用共享标题区的供应链页面。`tests/page-polish.static.mjs` 检查共享产品样式和运行时、产品根节点、标题区、真实按钮、原生控件、内部验收文案及财务占位入口。该检查接入 `prebuild`，结构不满足时 `pnpm build` 直接失败。
