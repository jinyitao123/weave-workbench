# Forge 银行文件导入与余额对账切片

更新于 2026-09-10。实现由隔离分支 `codex/otc-bank-statement-reconciliation` 验收后合入 `main`，验收端口 `4378`，数据库 `.objectstack/otc-bank-statement-reconciliation.sqlite`。原计划端口 `4377` 已被另一项独立主线验收占用，本分支未复用该端口或数据库。

## 证据边界

RISEMAP RM-131 证明资金账户包含账户余额和余额趋势；RM-132 与 DR-1005 至 DR-1008 证明资金流水存在流水总额、已分配、待分配、待审核、收支方向、流水类型、批量审核与导出。已保存的公开更新记录提到 Excel 导入、后台导入任务和自动识别往来单位，但现有账号未取得银行文件导入或银行余额对账的可办理页面与成功记录。

本切片实现一个受控 CSV 首版，业务结果仍标为待 RISEMAP 对照。它不把公开更新文字扩大解释为已验证的 Excel 模板、银行适配器或自动匹配规则。

## 已实现行为

- 启用的银行账户可暂存 CSV。表头至少包含交易时间、收支方向、金额和银行参考号，单批最多 200 行；暂存逐行保存校验结果，不改变账户余额。
- 导入按同一账户的银行参考号识别既有重复项，也识别文件内重复项。重复行保留并标为跳过，错误行和超出账期行进入需修正状态。
- 文件计算期末余额必须等于填报的银行期末余额，批次才可生成流水。生成前再次检查账面余额快照、重复参考号和账户财务期间，随后生成来源为 `import` 的银行侧证据。导入不会再次更新正式资金账。
- 生成流水时同步建立银行余额对账快照，分别保存银行期初/期末、文件计算期末、账面期初/期末和差额。零差额才可确认一致；非零差额只能登记原因，状态明确为“差异已记录”。
- 未勾兑且对账尚未确认的已生成批次可整批撤回，将导入流水作废并保留明细、对账与操作日志；账面资金始终不变。
- 专用页面展示待处理批次、已生成流水批次、有效导入流水和未解决差异，支持 CSV 暂存、明细展开、生成流水、取消、撤回、一致确认及差异登记。

## 验证结果

定向 API 验收 8 组全部通过。首批银行期初 `10000` 导入收入 `1200`、支出 `200`，文件计算期末、银行期末和既有账面余额均为 `11000` 并确认一致，导入前后账面余额不变。后续文件中的既有银行参考号被保留为重复行，只生成支出 `300` 的银行证据，再整批撤回且账面仍为 `11000`。两条错误行被阻断并取消。另用银行期初 `11400` 导入收入 `100`，银行期末 `11500` 与账面 `11000` 的差异 `500` 被登记但未标为对平。独立账户还证明锁定期间会阻断生成流水，带原因重开后才能继续。

内置浏览器在真实页面选择独立账户，暂存两行 CSV，页面显示可生成/重复/错误为 `2 / 0 / 0`、收入 `400`、支出 `100`。生成银行流水后账户既有账面余额保持 `5300`，银行期初 `5000` 加收入 `400`、减支出 `100` 后，银行期末、文件计算期末和账面余额均为 `5300`，差额为 `0`，随后在页面确认一致。浏览器刷新还同时回读 API 留存的 `500` 差异状态。

服务完整停止后使用同一 SQLite 文件重启，7 个批次、11 条导入明细、8 条来源为导入的银行流水、6 张余额对账和 20 条文件操作日志完整回读；API 账户为 `11000`，浏览器账户为 `5300`，两者在文件导入前后均未变化，SQLite 完整性检查为 `ok`。元数据为 120 个对象、1934 个字段、29 个页面和 157 个动作。

## 未证明范围

- RISEMAP 银行文件导入、逐行错误呈现、批次生成流水、撤回和余额对账仍未实际办理，字段、模板和状态均待对照。
- 当前仅接受粘贴的 UTF-8 CSV 内容，不含真实文件附件留存、Excel 二进制解析、银行专用模板、编码探测、超大文件后台任务、进度通知或下载错误清单。
- 内容签名是批次级快速重复保护，不是密码学文件校验。行去重只使用同账户银行参考号；不处理参考号缺失银行的组合指纹规则。
- 不含自动识别客户供应商、自动推荐收付款匹配、批量勾兑审核、手续费拆分、账户间双边划转、未达账项和总账凭证。账户级财务期间会阻断文件生成与撤回，但尚无统一组织期间。
- 生成前完成全批预检，但多对象写入仍由动作顺序执行，没有数据库事务级原子回滚。既有实际收付款保留为正式资金账，银行流水只作为外部证据，不迁移或重复过账。
