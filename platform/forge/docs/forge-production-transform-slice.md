# Forge 生产拆解与换件验证

更新于 2026-09-10。实现位于隔离分支 `codex/otc-production-transform`，运行端口 `4357`，验收数据库 `.objectstack/otc-production-transform.sqlite`。该数据库由上一阶段停服后的 `.objectstack/otc-production-assembly.sqlite` 通过 SQLite 在线备份形成独立快照，完整性检查为 `ok`。

## RISEMAP 已观察行为

- 拆解按成品、生效 BOM、版本和数量展开理论物料，逐项选择回收或报废，并统计成品数、回收价值与报废损失。
- 同材料只读预览中，一台控制柜会把成品库存从 `1` 降为 `0`，释放成本 `47787.61`，四项物料理论回收价值 `14442.48`；每项理论数量都必须完整分配为回收数量与报废数量。
- 换件要求在库成品和改制 BOM，整机不离库；新件领用出库，旧件可回收入库或报废，并单独计算新件成本、旧件价值和成本变化。
- 2026-09-14 实时复核确认生产配置分为拆解原因与改制原因，两类原因均包含名称、描述、标识颜色和启停状态；停用原因不进入新建单据下拉，已保存单据仍保留原原因。远端新增弹窗已填写同材料，但尚未点击最终添加，因此真实审批节点、库存成本口径、状态推进和批次追踪仍待同材料成功记录复核。

## Forge 已完成闭环

1. 生效 BOM 可创建拆解单，四项末级物料各自保存理论数量、回收数量和报废数量；每项两者之和不等于理论数量时拒绝创建。
2. 待确认拆解单不移动库存。确认时再次检查成品可用库存，按成品移动平均成本扣减整机，逐项把回收物料按 SKU 成本加入库存，并写一条成品出库与每个回收物料一条来源流水。
3. API 拆解单 `DIS-2026-0001` 全量回收四项物料，释放成品库存成本 `16320.0033`，回收价值 `16320.00`，舍入差额损失 `0.0033`。Forge 库存账使用含税移动平均成本，不能与 RISEMAP 只读预览的未税 BOM 价值直接等同。
4. 浏览器拆解单 `DIS-2026-0002` 将两件电源分为回收 `1`、报废 `1`；成品减少 `1`，回收价值 `15460.00`，报废损失约 `860.00`，详情页显示四条分配和已入库状态。
5. 生效 BOM 可创建多明细换件单。旧件数量不能超过所选 BOM 与改制数量对应的理论数量；同单新旧规格不能重复或交叉复用。
6. 待确认换件单不移动库存。确认时要求对应数量整机仍在库并逐项检查新件可用库存；新件出库，旧件按选择回收或报废，整机余额和价值均不变。
7. API 换件单 `REP-2026-0001` 同时覆盖一项旧件回收和一项旧件报废，产生两条新件领用和一条旧件回收流水，成本变化 `8200.00`。浏览器换件单 `REP-2026-0002` 回收 PLC、领用 HMI，整机库存保持 `1 → 1`，成本变化 `-3600.00`。

## 验证结果与边界

- `production-transform.integration.mjs` 八组业务验收通过，覆盖停用原因阻断、原因配置持久关联、匿名拒绝、无仓库草稿、拆解分配校验、确认前不动库存、成品扣减、回收入库、换件理论上限、回收/报废分支、整机不变和重复确认阻断。
- `production-transform-restart-readback.mjs` 与浏览器回读脚本在完整停服重启后合计回读四张单据、十一条明细、十条拆解流水、五条换件流水和最终成品余额。
- `production-transform-ui-readback.mjs --restart` 回读浏览器拆解、换件、逐项分配、来源流水及整机 `1 → 1`，两个详情页重启后仍可见。
- `pnpm typecheck`、`pnpm validate`、`pnpm build` 通过。保留项目既有页面 `className` 指导提示和当前 Node `25.6.1` 不满足包声明 `<25` 的引擎提示。

当前已建立可配置的拆解原因与改制原因字典，单据同时保存原因配置关联和名称快照，停用配置会阻断新建。提交确认和库存过账仍压缩为两个动作，尚未复刻 RISEMAP 的完整草稿、审批、待领料、拆解/换件中、完工与独立入库状态链。多行库存写入仍为顺序执行，不具备数据库事务级原子回滚；岗位权限、驳回/反审核、批次与 SN 谱系、成品成本层重估和报废处置单仍待后续实现。
