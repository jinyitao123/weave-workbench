# Forge 当前产品结构审计

更新于 2026-09-12。审计基线为 `main` 的 `12305fb`。本文件只评价当前产品结构和可见体验，不否定已经通过 API、SQLite 重启回读或浏览器办理验证的底层能力。

## 结论与影响

当前 Forge 已积累较多可复用业务对象、动作和 36 个自定义页面，但它还不是 RISEMAP 产品结构的复刻。根因不是缺少某几个字段，而是产品入口被改写成 OEM 项目履约的 10 个阶段区，并有 64 个原始对象入口与 36 个任务页面混排。用户要先理解 Forge 的内部对象和实现分层，才能找到工作；RISEMAP 则先按职能域、岗位任务、待办和业务单据组织产品。

这会造成四个直接后果：

1. 同一岗位的日常任务散落在多个生命周期阶段，用户无法形成稳定的工作区。
2. 明细、日志、流水和关联表成为一级可点击入口，主单据与结果被拆散。
3. 已实现的单点页面容易被误报为一个产品阶段已经完成。
4. RISEMAP 的工作台、审批、系统配置、报表和角色入口没有成为 Forge 的产品骨架，后续功能越多，碎片化越严重。

## 量化盘点

| 指标 | 当前结果 | 含义 |
| --- | ---: | --- |
| Forge 一级区域 | 10 | 按 OEM 项目生命周期组织，与 RISEMAP 的 9 个职能域不同 |
| Forge 二级分组 | 22 | 同时混合流程、配置、主数据和内部记录 |
| Forge 可见导航入口 | 100 | 其中 36 个自定义页面、64 个原始对象入口 |
| RISEMAP 已发现入口 | 181 | 覆盖工作台、供应链、销售、生产、项目、行政、财务、报表、系统 |
| 与 RISEMAP 标题完全同名的 Forge 入口 | 32 | 只能说明名称相交，不能说明字段、行为或闭环对齐 |
| Forge 中没有同名 RISEMAP 入口的可见入口 | 67 | 大部分是内部明细、日志、聚合页或 OEM 自定义工作台 |

以上数量由当前 `objectstack.config.ts` 和 `docs/risemap/verticals` 中的 RM 行直接统计。标题相同不作为完成证据。

## 能力处置原则

### 保留

- 已经验证的对象关系、状态动作、数量金额计算、库存流水和持久化能力。
- 36 个自定义页面中能承接 RISEMAP 任务入口的页面实现。
- Forge 的 OEM 特有能力，包括项目交付验收、工程变更影响、项目经营分析；它们作为明确扩展进入相关职能域或单据详情。
- 现有验收材料继续证明其限定范围，不降格也不扩大。

### 改造

- 所有业务主单据的原始对象页改造成任务页，至少具备标题与状态、指标或待办、筛选列表、主动作、详情上下文、结果和下一步。
- 合并页按 RISEMAP 入口拆开，例如“委外看板与订单”拆成看板与订单。
- 重新建立顶层职能域、二级功能组、角色工作台和统一待办。
- 把 Forge 扩展能力放入最接近的职能域，并显示“Forge 扩展”来源，避免伪装成 RISEMAP 已观察事实。

### 从业务导航隐藏

- 单据行、BOM 节点、审批日志、操作日志、库存流水明细、发放接收对象、关系表、影响表、银行账户等依附对象。
- 这些对象继续存在于数据层，通过主单据详情、受控页签、追溯视图或运维入口访问。

### 暂不删除

- 本轮不删除对象、动作、字段或既有数据。
- 旧 10 区导航在迁移期只作为可回退配置保留，不作为默认用户入口。
- 只有新结构完成数据回读、浏览器验收和角色验证后，才移除旧导航定义。

## 视觉与交互证据

RISEMAP 委外看板和订单页体现了稳定的四层结构：全局职能域、当前职能域侧栏、任务页签、业务内容。业务内容把标题与主动作、阶段指标、个人待办、在途记录和快捷入口放在一个连续视野中。Forge 现有产品化页已有更克制的表格和统一控件，但仍存在以下结构差距：

- Forge 顶层只显示生命周期区域，无法确认当前岗位和职能域。
- 页面上方留白较多，阶段编号对用户帮助有限；关键待办、异常和下一步密度不足。
- 左侧同时展开区域和对象列表，技术对象比任务入口更醒目。
- 详情、来源、结果和后续动作缺少统一位置，不同页面各自实现。
- RISEMAP 的渐变色不是复制重点；需要复制的是信息层级、任务密度、可达路径和状态反馈。

## 事实、假设、决策和未执行实验

| 类型 | 条目 |
| --- | --- |
| 已观察事实 | RISEMAP 已发现 181 个入口；委外域有 13 个入口和 4 类岗位视角；当前 Forge 有 10 区、22 组、100 个入口，其中 64 个为原始对象入口 |
| 已观察事实 | 已保存证据覆盖 RISEMAP 的页面首屏、部分深度交互和委外指南；并非 181 个入口都已走通业务闭环 |
| 工程事实 | Forge 已有委外供应商、订单、发料、签收、回厂、入库、NCR 与库存相关对象和动作；退料、赔偿、对账、应付、追溯仍缺 |
| 待验证假设 | RISEMAP 当前 9 个顶层职能域对普通目标用户仍是默认信息架构；不同租户与角色可能隐藏部分域 |
| 已作决策 | 恢复阶段以 RISEMAP 职能域为默认产品骨架，OEM 生命周期作为跨域视图或项目详情能力 |
| 已作决策 | 底层对象保留，依附对象退出业务导航；先完成委外样板，再决定是否扩展迁移 |
| 未执行实验 | 尚未让委外业务员、仓库、质检、财务四类真实用户在 Forge 新结构中独立完成任务 |
| 未执行实验 | 尚未用同一业务材料在 RISEMAP 与 Forge 并排完成整条委外闭环 |

## 审计门禁

本审计只证明当前结构与 RISEMAP 产品结构存在系统性偏离，并给出可回退的迁移方向。它不证明新结构已实现，也不改变现有功能的限定验收状态。
