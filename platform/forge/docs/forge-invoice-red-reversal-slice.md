# Forge 进销项发票红冲切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-invoice-red-reversal`，验收端口 `4372`，数据库 `.objectstack/otc-invoice-red-reversal.sqlite`。该库承接已停服的主线兼容快照，保留销项发票 `INV-CONVERT-20260909-001` 与进项发票 `PINV-RM-20260909-001`；SQLite 完整性检查为 `ok`。

## 证据边界

RISEMAP 的 RM-145/RM-146 发票列表均有正常、已作废和已红冲筛选。DR-1071 进一步说明销项发票用于管理开具、交付、作废与红冲。当前仍没有同材料成功红冲记录，也没有观察审批、关账期间、税务申报和总账凭证影响。因此 Forge 本切片实现受限更正链，不能声称与 RISEMAP 行为一致。

## 已实现行为

- 销项红冲生成独立红字发票与复制明细，原蓝字发票和应收标记已红冲，应收余额归零；订单明细已开票数量、订单和合同已开票金额同步回退。
- 订单关联未结算项目时，同步重算销售关联和项目已开票金额。项目已结算或已有结算快照时禁止红冲。
- 销项发票存在待审核/已审核收款核销、有效客户预收冲抵或有效收入确认时禁止红冲；必须先走对应逆向链恢复原值。
- 进项红冲只接受从未付款、从未预付冲抵且应付余额仍等于原值的发票；存在未驳回付款任务或未撤销付款流水时禁止执行。
- 进项红冲生成独立红字发票与明细，原蓝字发票和应付标记已红冲，应付余额归零。原入库单可重开发票，并恢复同一应付为未付款原值。
- 两个方向均保存原单、红字单据、金额、原因、操作人和时间的独立审计记录。红字单据不参与收付款或收入确认。

## 验证结果

定向 API 验收 5 组全部通过。销项侧先登记 `1000` 到账并分配，验证红冲被阻断；取消分配并撤销到账后，红冲 `121600`，应收、订单明细和订单已开票累计分别恢复为 `0`。进项侧先建立 `500` 付款任务验证阻断，驳回任务后红冲 `6800`，应付归零。两个方向随后重开发票，验证销项重新形成 `121600` 应收、进项恢复 `6800` 应付。

浏览器在发票红冲页对两张重开发票再次办理红冲。页面最终显示销项和进项各 2 张蓝字发票已红冲、4 张对应红字发票和 4 条审计记录；销项金额 `121600 × 2`，进项金额 `6800 × 2`。

完整停服后从同一 SQLite 文件重启，API 回读 4 条红冲记录、全部原单和红字单据、已红冲应收/应付及归零余额。元数据门禁通过：105 个对象、1663 个字段、24 个页面、124 个动作；`typecheck`、`validate` 和 `build` 均通过。

## 未证明范围

本切片没有实现部分红冲、跨多张订单分摊发票、增值税抵扣撤回、开票任务、作废流程、红冲审批、关账期间、总账凭证和税务申报。采购红冲的成功入口只由状态筛选间接证明，实际审批和下游联动尤其需要 RISEMAP 同材料复核。多对象连续写入仍依赖顺序调用，未提供数据库事务级原子回滚。
