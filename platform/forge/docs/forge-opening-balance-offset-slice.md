# Forge 期初往来建账与对冲切片

更新于 2026-09-10。实现位于隔离分支 `codex/otc-opening-balances-offset`，验收端口 `4376`，最终验收数据库 `.objectstack/otc-opening-balance-offset.sqlite`。该库从已停服的阶段 19 持久快照复制，经官方迁移命令放宽四个期初来源外键及五个既有元数据漂移列；迁移前保留备份。

## 证据边界

RISEMAP RM-134 的 DR-1009 至 DR-1014 证明系统启用日对应的期初单据日期固定为前一日；期初应收保留原到期日、原值、已收和余额，期初应付保留原到期日、原值、已付和余额。期初录入不产生销售出库、采购入库、收入或成本。建账可以完成或明确跳过，完成后仍可管理期初记录。往来对冲在同一往来单位的应收应付间发生，不产生现金，经历草稿、待审核、已审核、已驳回或已撤回状态。

本切片按上述可观察行为实现。RISEMAP 同材料尚未成功保存期初账或完成对冲，因此 Forge 的成功办理结果仍属于待对照实现。

## 已实现行为

- 期初建账记录保存系统启用日、固定前一日单据日，以及应收应付各自的待建账、完成或跳过进度。完成和跳过只记录过程，不阻断后续补录。
- 期初应收应付直接进入现有往来账，保留原到期日、历史合同编号、历史开票标记、原值、期初已收或已付及余额；不伪造订单、出入库和发票引用。
- 客户与供应商仅在统一社会信用代码一致，或规范化单位名称一致时允许建立对冲草稿；判定依据随对冲单固化。
- 对冲经提交和财务审核后同时减少应收应付余额，驳回后可重提，已审核对冲按审核时间逆序撤回；全过程不新增或修改银行流水。
- 专用页面提供应收、应付和往来对冲三个页签，展示建账进度、期初余额、已审核/待审核对冲金额及逐笔明细，并支持录入和审核动作。

## 验证结果

定向 API 验收 7 组全部通过。期初应收原值 `1000`、已收 `200`，期初应付原值 `900`、已付 `100`；先审核并撤回 `400`，再保留一笔已审核 `300` 对冲，最终两边余额均为 `500`。不同主体对冲被阻断，驳回重提、完成后补录、匿名访问、无现金对冲，以及期初应收银行分配与反审核均已覆盖。

内置浏览器打开真实“期初往来账与对冲”页面，三个页签均完成可见回读。页面显示启用日 `2026-01-01`、单据日 `2025-12-31`、期初应收余额 `500`、期初应付余额 `650`、已审核对冲 `300`、待审核对冲 `100`；应收与应付明细分别回读原值、已收/已付、已对冲和余额，对冲页回读主体依据和三种状态。

已有库迁移前后应收 `2` 条、应付 `1` 条均保持不变，迁移计划由 9 项归零。服务完整停止后使用同一 SQLite 文件重启，1 条建账记录、3 条对冲记录和 17 条操作日志完整回读；有效应收应付仍为 `500 / 500`，银行收款完成分配、反审核和整笔冲销后资金余额恢复，原流水保留为已冲销，SQLite 完整性检查为 `ok`。元数据门禁结果为 114 个对象、1836 个字段、28 个页面和 148 个动作。
