# Forge 考勤假期职责页合同（2026-09-16）

## 证据边界

- RISEMAP 实时入口：`/hr/overtime`、`/hr/leave`、`/hr/business-trip`。
- 实时页面均为 0 条业务记录，因此本轮证明列表、表单字段和可见入口；不能证明审批后的全部状态回写。
- RISEMAP 请假页明确显示“暂无可用假期类型，请联系管理员配置”，附件上传控件可见，但没有可办理材料验证上传、扣减和审批联动。
- Forge 不修改 RISEMAP 数据。测试材料仅写入独立 SQLite。

## 加班申请

- 主原型：`timesheet_composite`，参考 `project-timesheet-cost.page.ts`。
- 岗位与主任务：员工提交加班申请并回看状态。
- 首屏顺序：标题与主动作 → 搜索/状态筛选 → 加班列表 → 分页。
- RISEMAP 已观察字段：开始时间、结束时间、加班事由、补偿方式（调休/加班费）、关联客户、关联项目、关联合同。
- RISEMAP 已观察列：单号、申请人、部门、加班日期、时段、时长、补偿方式、状态、加班事由、操作。
- Forge 结果：写入 `forge_overtime_request`；提交时试算时长；取消使用标准破坏性确认弹窗。

## 请假管理

- 主原型：`timesheet_composite`，参考 `project-timesheet-cost.page.ts`。
- 岗位与主任务：员工查看额度并申请；审批人处理团队请假；管理员配置假期类型。
- 首屏顺序：标题与动作 → 四个职责页签 → 额度看板/阻断说明 → 对应工作区。
- RISEMAP 已观察页签：假期列表、审批管理、调休补假、假期配置。
- RISEMAP 已观察字段：假别、开始时间、结束时间、扣减明细、请假事由、附件。
- RISEMAP 已观察列：单号、申请人、部门、假别、开始时间、结束时间、请假时长、请假事由、当前状态、操作。
- Forge 结果：`forge_leave_type` 维护额度；`forge_leave_request` 保存申请；提交占用待审批额度，通过后转为已使用，驳回释放占用。
- 未决：附件存储和 RISEMAP 真实假别规则待有可用假期类型后复核，本轮不放置无结果上传控件。

## 出差申请

- 主原型：`timesheet_composite`，参考 `project-timesheet-cost.page.ts`，新建为独立全页。
- 岗位与主任务：员工登记基本信息、费用预估和至少一段行程，保存草稿或提交审批。
- 首屏顺序：标题与草稿/提交动作 → 基本信息 → 费用预估 → 行程安排。
- RISEMAP 已观察字段：出差事由、关联客户、出发日期、返回日期、交通方式、同行人员、备注；费用类别/说明/金额；行程出发到达时间、起点、终点。
- RISEMAP 已观察交通方式：飞机、高铁、火车、自驾、大巴、其他。
- RISEMAP 已观察列：单号、申请人、部门、目的地、交通方式、出差事由、出发日期、返回日期、出差天数、预计费用、状态、操作。
- Forge 结果：主单写入 `forge_business_trip_request`，费用与行程分别写入真实子对象；提交前阻断缺失日期、目的地、事由和行程。

## Forge 产品决策

- 取消已提交加班申请使用二次确认，即使 RISEMAP 当前空列表未能观察该动作。
- 请假额度按小时保存，以支持半天和跨日时间段；RISEMAP 实际工作日历与午休扣减规则尚未取得证据，因此当前仅按自然时间试算。
- 出差目的地作为明确字段保存；RISEMAP 新建页的行程终点可形成该值，但空列表列中也单独展示目的地。

## 验收材料

- 同一独立 SQLite 创建并回读加班、假期配置/申请/审批、出差主单/费用/行程。
- 内置浏览器分别检查三个 RISEMAP 页面和三个 Forge 页面，覆盖新建、阻断、提交反馈、列表回读及窄屏。
- 停服后从同一 SQLite 重启，回读三条业务链结果。
