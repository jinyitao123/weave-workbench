# Forge 项目关联、待对账池与财务逆向链路验收记录

## 本轮目标

使用同一套汇川型控制柜交付案例，补齐项目与销售合同、销售订单的关联，增加待对账来源池，并通过页面办理收款、付款、退款、银行流水和往来对账的异常及逆向路径。所有 Forge 页面使用同一 SQLite 文件 `.objectstack/ltc/ltc-hc-20260915-a.sqlite`。

## RISEMAP 当前页面事实

- 项目详情 `/project/2097679562137157634` 的“关联订单&合同”页签显示项目金额、已开票、已回款和应收摘要，并提供“添加关联订单&合同”。当前示例关联一组合同和订单。
- 往来对账 `/finance/reconciliations` 显示“待对账池”，规则为仅展示对账期间已结束、来源已审核生效且未被有效对账单占用的数据；页面提供按往来单位、合同、订单、发货、发票和收付款六个维度。当前客户列表为空，按订单指标显示 1。
- 本轮没有在 RISEMAP 修改数据，也没有用相同材料生成、确认或关闭对账单，因此状态动作仍属于待同材料复核。

### 待对账池

`page_counterparty_reconciliation` 增加“待对账池”和“对账单”两个视图，并提供六个维度。来源按业务日期早于今天、业务已审核生效、未被已有对账单来源键占用三个条件筛选；选择一组来源后可带入往来单位、期间和冻结来源键生成对账单。服务端重复校验期间和来源占用，防止页面选中后数据变化仍被生成。

本案例当前客户待对账池为 0。原因是现有来源已经进入有效对账单，或业务日期尚未结束。该结果与 RISEMAP 当前空列表一致，但不能据此宣称两侧同材料生成结果已通过。

## 当前结论与边界

本轮 Forge 页面已证明项目关联、待对账池、收付款逆向、退款超额阻断与驳回、银行差异处理、对账差异关闭和恢复可以连续办理。RISEMAP 本轮只完成项目关联页和待对账池的实时页面取证；退款、银行、付款和对账状态动作继续沿用此前保存的 RISEMAP 页面证据，未做同材料双边办理，因此这些功能应标为 Forge 已实现、待 RISEMAP 同材料复核。
