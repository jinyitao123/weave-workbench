# inoForge Agent Instructions

## 文档入口与维护

- 当前资料入口为 `docs/README.md`，根 README 仅说明目标和启动入口。按当前任务读取对应合同和证据，不默认加载全部历史资料。
- `docs/archive/` 和明确标为历史快照的计划、矩阵、交接记录不构成当前执行队列或验收通过证据。新报告写明被验收版本、范围和证据；旧记录不得因整理文档改写为当前通过。
- 项目规则只在本文件维护；应用 `AGENTS.md` 仅补充局部事实，兼容入口引用规则，不复制全文。归档必须保留原文、迁移记录并修复引用，不能删除仍被合同或验收记录依赖的证据。

## 默认交付与持续执行

- 新增页面、精修、功能修复默认采用 `docs/forge-page-delivery-standard.md`；逐页合同使用 `docs/templates/forge-page-delivery.md`。视觉细则只维护在 `docs/forge-page-polish-baseline.md`，不要在会话和其他规则文件复制整套正文。
- 用户更新目标、质量要求或实施步骤时，保持已有任务的执行状态；阶段汇报、完成盘点、形成合同或完成一个批次，不自动成为暂停点。已授权的实现持续推进，不额外增加“等待再次确认启动”。用户明确暂停仍须保持，真实阻塞须说明缺失条件；不得以持续推进绕过验收门禁或扩大授权。
- 先把用户目标转成可核查的全量范围和逐页合同；事实充分时自主确定常规实现方案并继续，只有影响业务方向的未决选择才向用户提问。盘点不能代替交付，隐藏未实现控件不能删去对应业务缺口。
- 以完整业务链分批交付，每页分别记录复刻一致性、结构视觉、交互完整性、业务正确性。验收退回的问题由实施任务修复；缺证据或未独立复核时保持待验收，不以页面数量、共享样式引用、截图存在或构建成功替代通过。
- 工程流程和规则文档本身的维护，若不改变业务页面、元数据或业务行为，按改动面验证脚本、文档及引用即可，不为无对应页面的规则修改制造双侧业务操作；不得据此宣称任何页面已复刻或验收通过。

## 目标与证据

- Forge 以 RISEMAP 的可观察业务行为为复制基线。页面、状态、字段和阻断规则应引用已保存证据；尚未在 RISEMAP 成功跑通的路径必须标为待复核实现。
- “完成”至少包含实现、相称的 API 验收、持久数据库停服重启回读，以及对用户可见关键页面的内置浏览器检查。单独的编译通过或接口健康不构成业务闭环。
- 不把测试夹具、调用方传入的库存数字或单进程状态描述成真实库存账、财务账或端到端验收。

## RISEMAP 复刻标准

- RISEMAP 复刻与汇川 OTC 产品化是两个不同层次：RISEMAP 决定页面、菜单、字段、步骤、状态和交互的复刻基线；汇川 OTC 只用于检查跨模块岗位连续性和完整交付闭环，不能替代 RISEMAP 的页面或行为证据。
- 实现前必须先核对已保存的 RISEMAP 当前页面、DOM、操作手册、公开流程和教程证据。当前页面优先于历史截图、公开说明和工程设想；不同来源冲突时记录差异，不静默选取方便实现的一方。
- 严格区分四类内容：RISEMAP 已观察事实、Forge 已有可复用服务能力、Forge 工程推断、尚未执行或尚未复核的实验。工程推断不得写成 RISEMAP 规则，公开流程或教程不得直接写成已成功运行的业务闭环。
- RISEMAP 的教程顺序只用于判断系统配置依赖，不得当作用户办理业务的单线顺序；RISEMAP 的业务流程用于确定岗位和单据承接；汇川 OTC 阶段用于跨模块实施排队。三者必须分别记录。
- 页面或功能未完成时，明确标记为“未实现”“Forge 已实现但页面/交互未复刻”或“RISEMAP 缺少可办理数据、待复核”，不得用“已接入”“接口成功”“页面可打开”合并为完成。
- 页面控件必须符合实际产品布局和人类使用习惯：主按钮放在用户完成当前任务后自然能找到的位置；列表行操作只放真实可执行动作；未验证、未实现或仅保留入口的能力应呈现为业务说明、状态提示或后续入口说明，不得做成灰色按钮、假按钮或点击无反馈的控件。
- 每个可见按钮、选择器、日期输入、弹窗确认和行操作都必须实际可用，至少经过一次页面级点击、输入、提交、反馈和状态回读；只在代码中存在 handler、只通过接口或只显示成功 toast，不构成控件可用。
- 复刻时必须把“用户是否真的能顺手完成业务”作为页面验收项：控件名称要说明业务动作，位置要贴合当前办理步骤，点击后必须进入可理解的表单、确认、状态变化或下一步；如果当前能力还不能办理，应展示业务说明或空态引导，不得包装成按钮、页签、筛选或行操作。
- 保留 ObjectStack Console 作为统一低代码页面载体，优先使用平台元数据、标准组件和扩展机制。Console 外壳可以保留，但外壳内的业务内容区必须按 RISEMAP 当前页面做像素级复刻；平台默认样式与 RISEMAP 冲突时，应通过共享主题、标准组件扩展或页面样式修正，不得以“平台统一语言”为理由降低复刻精度。只有平台外壳本身可作为明确裁剪区排除，不能排除业务内容。
- 复刻范围同时包含业务功能、信息架构、页面内容和交互反馈。后台对象或 Action 可调用，只能证明功能实现，不能证明页面已复刻。
- 每轮实施前按当前代码和 RISEMAP 实际页面维护三类清单：功能尚未实现；功能已实现但菜单、页面或交互未复刻；RISEMAP 缺少可办理数据、只能标为待复核。不得把三类状态合并为“已完成”。
- 菜单在 Console 导航能力内尽量对齐 RISEMAP 当前业务分类、分组、名称、顺序和入口；允许顶部与侧边栏等承载形式不同。列表、新建、详情、工作台和报表应保持清晰的业务职责及可达入口，不得因实现方便而合并后丢失内容或关键操作。
- 页面逐项核对标题区、指标卡、工具栏、搜索筛选、列表列与顺序、空状态、分页、表单字段与顺序、详情信息层级、状态文案和关联单据展示；面包屑、标签和控件呈现遵循 Console 规范。通用对象页能完整承载所需内容与交互时可以使用；不足时优先配置或扩展平台能力，仅为必要业务能力补充定制组件，并保持平台统一风格。
- 页面交互不得使用浏览器原生弹框、下拉选择器或日期选择器；使用 ObjectStack Console 标准组件或项目共享组件承载确认、选择和日期输入，并保留键盘操作、焦点管理与可访问语义。
- 复刻页面必须同时核对控件布局是否符合实际产品使用习惯、按钮是否放在用户办理该动作时自然会寻找的位置、动作是否真的可点击可提交可回读；不得保留看似按钮但没有业务结果的控件、仅用于占位的筛选项、点击无反馈的行操作，或与当前状态不匹配的主按钮。
- 交互至少逐项对齐入口条件、字段联动、按钮出现条件、弹窗内容、不可逆提示、提交阻断、成功或失败反馈、操作后跳转、状态变化及关联单据联动。只验证最终数据库结果，不算交互复刻完成。
- 视觉目标是对 RISEMAP 当前页面做可测量的像素级复刻。必须在相同视口、相同缩放、相同数据状态下逐项对齐内容区的坐标、尺寸、间距、字号、字重、行高、颜色、边框、圆角、阴影、图标、列宽、行高、滚动位置和响应式重排；保存 RISEMAP 原图、Forge 原图、叠图或像素差异图及量化结果。业务内容区任一未记录的视觉差异都属于验收阻断，不能以“纯样式”“平台语言”“信息结构已一致”或“用户仍可办理”放行。平台外壳只有在逐页证据中固定裁剪坐标并证明未侵入业务内容时才可排除。
- 每页必须在交互验收前先完成真实数据下的几何体检：至少覆盖标准桌面、侧栏展开后的实际内容宽度和窄屏三档；逐项检查按钮、输入框、选择器、日期控件、页签、表格列、行操作及弹窗底部动作是否发生重叠、互相挤压、异常收缩、文字竖排、非预期换行、截断、错位或越界。长单号、长客户名、长选项和多按钮状态必须作为压力数据检查；表格空间不足时使用明确列宽、单元格省略提示和卡片内横向滚动，不得依靠压缩控件或拉高行高勉强展示。任一此类缺陷存在时停止进入下一页，并保持 `review_required`。
- RISEMAP 当前线上页面是菜单、字段、状态和交互的首要证据；上手指南、社区更新说明和历史截图只作辅助。辅助材料与当前页面冲突时以当前页面为准，并记录差异。
- 页面验收必须使用内置浏览器分别办理关键路径并保存同视口对照证据，覆盖操作前、关键弹窗或表单、操作后状态和停服重启后的页面回读。验收报告分别说明功能一致性、页面内容、关键交互和像素差异；视觉差异与功能差异分栏记录，但两者都是验收项。未完成同视口截图、叠图/像素差异计算和主要元素几何测量时，visual 只能保持 pending 或 fail。
- 业务验收必须使用同一组真实业务数据，分别从 RISEMAP 页面和 Forge 页面完整走完对应岗位路径；入口、字段输入、页面反馈、状态变化、来源关系、结果和下一步预期应逐项对照，效果预期相同或差异已获得明确决策后才算通过。API、脚本、健康检查、构建成功或单独数据库结果只能作为辅助证据，不能替代 RISEMAP 与 Forge 的并排页面办理。

## 每次开发与调试的强制对照步骤

- 本节适用于项目域的每次开发、调试、缺陷修复、文案调整和验收，不得只在功能块开始或最终验收时执行一次。
- 第一步，在已登录的内置浏览器中打开 RISEMAP 当前对应页面，读取当前入口、页面结构、字段与列、状态、动作、弹窗、阻断和操作反馈；不得以历史截图、合同文档或 Forge 当前实现代替实时页面。
- 第二步，打开 Forge 对应页面，使用同一业务材料逐项对照，并在页面合同或验收记录中同时保存“RISEMAP 当前事实、Forge 当前表现、明确差异、处理结论”。`金一涛` 与 `Dev Admin` 按同一业务用户对照，不得将名称差异写成功能缺口或技术标识。
- 第三步，只修改已有 RISEMAP 当前证据或已明确标注为 Forge 产品决策的内容。修改过程中发现证据不足时，立即返回 RISEMAP 页面补证；不得依靠工程推断继续堆叠页面。
- 第四步，修改后必须再次使用内置浏览器检查 RISEMAP 与 Forge 两侧，覆盖操作前、关键弹窗或表单、提交阻断、成功或失败反馈、操作后状态和下一步入口。两侧实时证据缺少任一项时，只能标为“待对照”或“部分证明”。
- 复刻实施期间必须在 Codex 内置浏览器中持续打开当前正在处理的 Forge 页面供用户查看；切换处理页时同步切换可见页面，修改前后均刷新并展示当前结果。后台 Edge 可用于保留已登录的 RISEMAP 取证页，但不能替代面向用户可见的内置浏览器 Forge 页面。
- Forge 中的删除、终止、作废、撤销、清空等破坏性动作必须使用标准二次确认弹窗，明确显示操作对象、业务影响和不可恢复结果；不得因为 RISEMAP 当前页面缺少确认而省略。该差异记录为 Forge 产品安全决策。
- 第五步，页面对照通过后再运行相称的 API 验收、同一 SQLite 停服重启回读以及 `pnpm typecheck`、`pnpm validate`、`pnpm build`。这些工程证据不得反向替代页面对照。
- 每次阶段汇报必须列出本轮实际打开并核对的 RISEMAP 页面和 Forge 页面。若本轮没有实时打开 RISEMAP，不得使用“已复刻”“已对齐”“可验收闭环”或“完成”等表述，也不得进入下一功能。

## 复刻实施顺序

- 主导航先按 RISEMAP 当前业务分类、分组、名称和顺序整理，再逐个功能块修补；导航重排不得删除已有对象、动作、数据或服务能力。
- **RISEMAP 线上数据允许为双材料对照写入**（2026-09-19 起生效，用户授权范围内）：可以在 RISEMAP 新建并推进带「审计走查」「对照」等可识别前缀的测试单据，用于验证页面入口、字段、状态、动作、阻断与交互反馈。写入前说明将新增的材料，写入后记录页面、单据号、结果和清理情况，测试材料尽量在 RISEMAP 侧保留可追溯标识或清理干净。
- 禁止在 RISEMAP 删除、作废、撤销或改写既有历史单据与非测试数据；未获明确授权时，不得在 RISEMAP 执行真实资金收付、开票、红冲、结算入账等不可逆账务动作。
- 默认实施队列按“菜单与信息架构 → 项目中心 → 项目计划与任务 → 工时与项目成本 → 销售合同与销售订单 → 采购与物料齐套 → 制造/委外/交付 → 财务承接 → 报表与经营复盘”推进。队列是执行顺序，不代表后续功能已经完成。
- 当前项目管理块必须先严格复刻 RISEMAP 的五个项目入口：项目中心、项目分析中心、任务管理、工时管理、项目配置中心；再按项目创建、计划来源、阶段/里程碑/任务、进度和日报逐项实现。
- 项目计划实现必须先以 RISEMAP 已观察流程为准：项目创建完成后进入项目计划管理，呈现已证实的计划生成方式、阶段、里程碑、任务、负责人、日期、前置关系、进度和日报。没有对应 RISEMAP 证据的自动排程、关键路径、复杂基线、权限规则或阻断规则不得自行加入并宣称已复刻。
- 汇川 OTC 的阶段顺序“客户需求与立项 → 报价合同与订单 → 计划与方案设计 → 采购与物料齐套 → 制造与装配 → 发运与现场交付 → 集成调试与验收 → 开票回款 → 结项复盘”只作为跨模块连续性检查，不得为了 OTC 连续性擅自改变 RISEMAP 页面语义。
- 每个功能块先完成页面合同和产品、工程、质量预审，再开始扩展对象或 Action。页面合同至少引用 RISEMAP 入口与证据，并写清岗位、主单据、字段/列、状态、动作、阻断条件、来源关系、下一步、事实/推断/未决项和验收材料。
- 同一功能块未完成页面对照、正常路径、关键异常、API、内置浏览器操作和同一 SQLite 停服重启回读前，不得进入下一个功能块，也不得以健康检查、构建成功或单独接口成功作为业务闭环。
- RISEMAP 页面因数据、权限或环境无法完整办理时，先按上面的授权范围在 RISEMAP 补建对照材料后重跑；确实无法补建时，Forge 只能标为“待 RISEMAP 同材料复核”，不得用 Forge 自己的夹具结果冒充对照通过。对照验收必须保存两侧的操作步骤、关键页面和最终结果证据。
- 任何 Forge 自定义页面、上下文跳转、字段联动、状态阻断或产品优化，若不是 RISEMAP 已观察行为，必须在页面合同和验收记录中标为 Forge 决策或工程推断，不能混入复刻事实。

## Git 与并行开发

- `main` 是集成分支。独立业务链使用 `codex/<scope>` 分支和独立 worktree；不要让多个 Agent 同时修改同一 worktree。
- 每个并行分支使用独立端口和独立 `.objectstack/*.sqlite`。验收时显式设置 `FORGE_URL`，禁止复用主线 `4310` 后宣称分支通过。
- 分支提交必须包含明确的实现边界和验证结果。主线逐个审查提交，解决共享 barrel、导航和 `package.json` 冲突，再统一运行门禁。
- 提交运行时数据库、`node_modules`、构建产物、环境文件、登录态或临时缓存是禁止的；证据截图和脱敏文本可以提交。

## Forge 门禁

在 `apps/forge-objectstack` 的每次元数据修改后运行：

```bash
pnpm typecheck
pnpm validate
pnpm build
```

再运行与本次业务链对应的验收脚本。涉及持久状态时，必须完整停服并从同一 SQLite 文件重启后回读。

## Forge 页面精修基线

- 新增或精修 Forge 自定义页面前，先阅读 `docs/forge-page-polish-baseline.md`，并以 `apps/forge-objectstack/src/pages/product-ui.ts` 及文档列出的参考页面作为共享视觉和交互基线。
- 精修基线只约束 Forge 页面语言和办理体验；业务入口、字段、状态、动作、阻断和来源关系仍以 RISEMAP 实时证据和页面合同为准。
- 新的通用按钮、筛选、状态、空态、选择、日期或弹窗模式优先扩展共享 `product-ui.ts`；只有确属单页结构的布局才保留在页面文件中。
- 每个页面开始实现前必须在页面合同中指定一个主原型：工作台型、任务执行型、工时组合型、分析型或配置型，并写明参考页面、首屏区块顺序、主动作、筛选作用对象、结果反馈和下一步入口。缺少逐页原型映射时不得开始页面实现。
- 引用 `product-ui.ts`、统一宽度、按钮、圆角、标题或颜色只证明使用了共享控件，不能证明页面已经精修。页面必须按岗位职责形成自己的信息层级和办理路径；用户任务不同的页面不得仅替换标题、指标、页签和表格列后共用同一个整页生成器。
- `tests/page-polish.manifest.json` 中 `designStatus: "review_required"` 的页面属于待逐页精修债务，不得在阶段汇报、页面合同或合并说明中称为“已精修”“已对齐设计语言”或“页面验收通过”。只有完成 RISEMAP 与 Forge 双侧页面对照、主原型核对、关键交互、空态和响应式检查，并补充证据路径后，才能改为 `accepted`。
- 页面精修验收必须逐页进行；“页面可打开、标题可见、无控制台错误”只证明入口可用。内置浏览器至少核对桌面和窄屏首屏结构，并实际操作主按钮、筛选、页签或视图切换、关键弹窗、提交反馈和下一步入口。
- 后续功能分支在开始页面开发前从最新 `main` 建立独立 worktree，避免继续从已经合并的旧业务分支叠加共享页面和导航改动。
- 已经运行的并行会话在主线页面基线更新后，先完成当前工作的安全检查点，再同步最新 `main`、重新读取本文件和页面精修基线，然后继续页面开发；不得沿用旧 worktree 直接合入新的共享页面、导航、barrel 或 `package.json` 改动。

## 加速执行规则

- 加速只能减少重复分析、重复操作和无效等待，不能减少 RISEMAP 对照、岗位连续任务、异常阻断、持久化回读或独立验收证据。
- 菜单走查分三级：A 类为订单、采购、销售、生产、委外、财务主链，必须做页面合同和纵向业务走查；B 类为主数据、报表和常用配置，先核对入口、首屏、字段和主要动作；C 类为低频行政、人事和配置，先保留准确菜单、首屏事实和明确缺口。C 类不得阻塞 A 类主链，也不得被入口存在描述成已实现。
- 每个功能实施前先建立页面合同，至少包含 RISEMAP 入口、Forge 入口、页面职责、岗位、主单据、字段/列、状态、动作、阻断条件、来源关系、下一步、事实/推断/未决项和验收材料。页面合同未明确，不开始扩展对象或 Action。
- 以纵向业务链作为实施单元：主单据、岗位待办、当前动作、状态变化、结果、下一岗位和来源回溯必须一起设计。完成一个功能后再进入下一个，不以对象、字段、页面或测试数量计算进度。
- 可并行的工作仅限于真正独立的 RISEMAP 取证、Forge 页面实现和验收脚本准备；每条线使用独立 `codex/<scope>` 分支、worktree、端口和 SQLite。导航、共享组件、barrel 和 `package.json` 由主线统一处理，禁止并行修改同一 worktree。
- 浏览器操作用于证明用户可见入口、字段联动、弹窗、阻断、反馈、跳转和结果；API/脚本用于批量断言状态、来源、数量、金额、库存和停服重启回读。两者不能互相替代。
- 每个功能的最小通过条件是：页面合同有 RISEMAP 证据、正常路径可连续办理、至少一个关键异常路径有明确阻断、同一 SQLite 停服重启可回读、浏览器结果与 API 结果一致。任一项缺失都保持为部分证明或待 RISEMAP 复核。
- 出现来源丢失、状态绕过、异常可结算、重复金额、页面无法进入下一岗位、重启不一致或事实与实现冲突时，停止新增功能，先修正当前链和证据。

## RISEMAP 复刻推进方法（2026-09-13 固化）

- 完整复刻目标不因阶段性实现而缩小；每个业务块按“直接取证 → 页面合同 → 可运行实现 → 同输入对照 → 定向补证”滚动推进。
- RISEMAP 当前页面、DOM 和真实操作结果是页面、字段、入口、状态和交互的首要依据；历史截图、公开流程和教程只作辅助。来源冲突时记录差异，不静默选择方便实现的一方。
- 每条结论必须标明属于“RISEMAP 已观察事实”“Forge 已有能力”“Forge 工程推断”或“尚未执行/待复核实验”。不得把页面可打开、接口成功、构建通过或本地夹具结果写成业务闭环。
- 复刻范围同时覆盖全量导航、页面内容、字段表单、操作反馈、业务状态、数据关联、角色权限、异常恢复、配置、报表和可用集成；试用版未开放或当前账号无法办理的内容保留为证据缺口。
- RISEMAP 教程顺序只用于配置依赖，RISEMAP 业务流程用于岗位和单据承接，汇川 OTC 顺序用于跨模块连续性检查；三种顺序分开记录，不互相替代。
- 每个功能块必须先建立页面合同，写清入口、岗位、主单据、字段/列、状态、动作、阻断条件、来源关系、下一步、事实、推断、未决项和验收材料。
- 验收必须使用同一组业务材料分别办理 RISEMAP 和 Forge。内置浏览器证明入口、表单、弹窗、反馈、跳转和页面状态；API 证明数量、金额、来源、状态和持久化；同一 SQLite 停服重启证明状态可恢复。三类证据不能互相替代。
- RISEMAP 当前页面没有可办理数据时，Forge 必须将只读基线与可写执行扩展分层展示；本地扩展不得冒充线上 RISEMAP 事实，也不能因此删除已有执行能力。
- 一个业务块只有在页面对照、正常路径、关键异常、API、内置浏览器和停服重启都完成后，才允许进入下一个功能块。出现来源丢失、状态绕过、页面无法进入下一岗位、重启不一致或事实与实现冲突时，停止扩展并先修当前链。

## ObjectStack 项目级 Skill 使用规则

- 项目级 Skill 位于 `.agents/skills/`，只在 inoForge 范围内使用。开始修改前按实际改动面读取对应 `SKILL.md`，不得为了形式一次性加载全部 Skill。
- 页面、导航、列表、表单、弹窗、看板、仪表盘、报表或 Action 使用 `objectstack-ui`；涉及列表过滤、排序、分页、聚合和关联展开时同时使用 `objectstack-query`。
- 新增或修改对象、字段、主从关系、校验、权限、索引、生命周期钩子或种子数据使用 `objectstack-data`；涉及 CEL 公式、字段显隐、只读、必填、校验条件或动作条件时同时使用 `objectstack-formula`。
- 多步骤且存在条件分支的业务流程、审批、状态机、定时任务或 webhook 使用 `objectstack-automation`；单对象分步表单仍由 `objectstack-ui` 的 wizard 承载。
- 只有新增自定义端点、认证、实时通道或 API 契约时使用 `objectstack-api`；对象自动 CRUD 不额外设计自定义 API。
- 修改 `objectstack.config.ts`、运行时能力、插件、服务注册、迁移、CLI 或部署时使用 `objectstack-platform`；协议跨主版本升级或出现 `[REMOVED]` 迁移错误时使用 `objectstack-upgrade`。
- 翻译包和语言覆盖使用 `objectstack-i18n`；ObjectStack AI skill、tool、知识源或 MCP 能力使用 `objectstack-ai`。当前业务未涉及这些表面时不加载。
- Skill 约束负责 ObjectStack 元数据和运行时的正确实现；RISEMAP 实时页面仍是业务入口、字段、状态、动作和交互的首要证据。两者冲突时先区分业务事实与平台实现边界，再在页面合同记录处理结论。
- 每轮实施汇报写明实际使用的 Skill、修改表面和验证结果。元数据改动至少运行 `pnpm validate`；项目门禁继续执行 `pnpm typecheck`、`pnpm validate`、`pnpm build`，并叠加对应业务验收、内置浏览器对照和同一 SQLite 停服重启回读。
