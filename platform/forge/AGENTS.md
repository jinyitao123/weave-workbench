# inoForge Agent Instructions

## 当前产品决定

2026-09-23 用户明确将 RISEMAP 从复刻目标调整为参考，并确认 Forge 按供应链、销售、生产、项目、行政、财务、报表七个业务应用组织，每个应用有自己的业务设置。此前“全量复刻、逐像素一致、必须双侧同材料、缺 RISEMAP 证据不得继续”的规定停止作为新任务门禁；历史截图、合同与验收结果保留原义，不追改为新版本已通过。

- 用户确认的目标、客户业务规则和 Forge 场景/页面合同决定产品要求。RISEMAP 的流程、字段和布局用于参考；无法访问或未提供功能时，不阻断有明确 Forge 业务定义的实现。
- 七个应用共享原生账号、组织、岗位、审批、消息、附件与业务数据。每个正式对象或台账只有一个权威维护方，应用拆分不自动变成七套服务或七个数据库。
- 遵循 ObjectStack 单个应用包最多一个 App 的约束；第一阶段保持既有对象/记录标识与唯一注册，各应用独立导航、页面、设置与权限。不得复制库存账、财务账、主数据或员工待办。
- 用户已说明旧入口未对外发布：不做旧 `/forge/page/...` 地址兼容、旧页面镜像或第八个可见的 Forge 应用。共享 `forge_*` 能力保留唯一注册；先验证无 App 的共享能力包和七个业务 App 在实际运行时可用，再认定拆分完成。
- 详细应用/设置划分、功能缺口治理和性能方案由产品总仓 `weave-workbench/docs/architecture/Forge应用与性能设计.md` 维护；本仓负责实现和逐页证据。外部系统能力组合的主文档仍为 `docs/forge-customer-composable-architecture.md`。

## 文档入口与维护

- 从 `docs/README.md` 进入对应业务合同、交付标准和原始材料；不默认重读全部历史。
- 项目规则仅在本文件维护；应用 AGENTS 只补局部事实。新目标更新原主文档，修复引用，不生成重复规则或会话日志大全。
- 旧合同中 RISEMAP 专属差异是参考记录；已采纳的业务要求和未解决缺陷仍须逐项处理。不能因参考地位降低而删除功能、批量改 accepted 或追改历史失败。
- 当前实现、部署、设计与验收分开描述。源码、构建和健康检查不等于业务完成。

## 开发与持续执行

- 新增页面、功能修复和精修使用 `docs/forge-page-delivery-standard.md`、`docs/forge-page-polish-baseline.md` 与 `docs/templates/forge-page-delivery.md`。
- 按实际导航、页面、内部跳转、动作、设置消费者及跨应用链盘点，不能把 manifest 或菜单数量当成全部功能和完成度。
- 一批围绕一个可验证业务结果，通常 2–5 个相关页面；共享文件明确归属。持续推进已授权工作，真实阻塞留下复现与下一步，不原样无限重试。
- 需求不清、未实现、后端已有但入口缺、流程断、数据/权限错误、仅缺证据分别记录。数据/权限/丢失问题优先；缺失动作不能靠隐藏控件被删除。
- 当前链存在来源丢失、状态绕过、重复金额、错账号或下一岗位无法办理时，先修断点。没有依赖的其他工作可继续，不能因参考资料不足无限阻塞。
- 业务设置必须说明维护方、范围、权限、消费者和生效规则，并验证保存/重启读回及实际业务效果。平台设置仍复用原生 Setup。
- UI 首屏、字段、状态和动作使用产品语言，不展示内部 UUID 等技术编码，不放宣传标语、假按钮或装饰性统计。

## 页面质量与验收

- 页面原型围绕岗位任务选择，共享控件优先复用 ObjectStack 标准组件与 Forge 已有组件；不另建独立导航外壳。
- “页面”作为产品界面不等于 ObjectStack Page 元数据。标准列表/表单/详情优先用对象及视图，报表/仪表盘/平台能力走各自原生入口；仅组合或复杂界面才声明自定义 Page。业务设置可以是导航分组，不强制每功能或每应用包装一张 Page。
- 用户可见业务地址要求去除 `/page/`，按应用与业务入口组织；内部 Page 仍可作为实现类型。此路由改造尚待实现，须同时验证新地址的直接访问、刷新、SPA 跳转与登录返回，不能仅改菜单 URL 或地址栏宣称完成。
- 布局遵循经记录的 Forge 设计基线，参考来源可为 RISEMAP、已有 Forge 页面或明确产品设计。检查桌面、侧栏占宽和窄屏、长文本、多个操作、空态、错误、受限、加载中与弹窗；不得重叠、裁切、越界或压缩到不可用。
- 复杂筛选与表格按侧栏占位后的内容容器宽度布局；固定列宽不能把筛选、清空、主要操作和空态推到可视区域外。表格需要可发现的横向查看方式，弹框头尾可见且主体可滚动。
- 确认、选择、日期和弹窗使用统一产品组件，保留键盘操作、焦点、标签及无障碍语义。
- 表单子组件的类型在输入期间必须稳定，不在会随输入重渲染的组件内重新定义 React 组件；验证中文连续输入、取消重开与切记录。新建态只用已确定业务默认值，不写入演示姓名、公司、单号或日期；参考系统和待实现说明不进入员工表单。
- 自定义 Page 读写 ObjectStack 数据时使用宿主提供的认证 adapter（`useAdapter`、`getAuthHeaders` / `fetchImpl` 或已封装的 `ForgeApiRequest`），不直接对 `/api/v1` 调全局 `fetch` 并假定浏览器 Cookie 一定携带身份；401、403 和空结果分别显示。
- 每个可见主操作必须从正常产品入口实际点击、填写、提交并看到正式结果；不能用 handler、toast、接口或数据库结果替代页面操作。
- 验收依据为需求覆盖、视觉可用性、交互、业务、权限/角色、持久化和性能。Forge 自身可重复材料与预期结果是必需项，RISEMAP 双侧材料和像素相似不再是必需项。
- 涉及持久状态须完整停服并从同一持久数据库重启读回；部署使用 PostgreSQL 时验证同一 PostgreSQL，不以另一份 SQLite 代替。
- 跨员工链按实际业务的发起人、办理人和成果使用者走正常路径；关键结果在独立 Forge 页面由有权的实际业务角色读回。独立取证是验收方式，不新建核验员角色或为验收扩权；只有真实业务另有审计岗位时才以其授权账号复核。实施者的单次观察不能冒充第二名员工已经办理或独立复核。
- `review_required` 不自动转 accepted。schemaVersion 1/2 自动门禁保留历史规则；schemaVersion 3 按 requirements、Forge 视觉与真实交互/业务/权限/持久化/性能证据验收，RISEMAP 仅为可选参考。不得伪造证据、修改旧记录冒充新准则通过，或把旧门禁 PASS 当新业务验收。
- 保存被验收版本、环境、材料、步骤、预期/实际、错误与脱敏证据。参考不足与业务未知分开，重大业务口径未确定时明确待决。

## Git、验证与协作

- `main` 为集成分支，独立工作使用 `codex/<scope>` 分支；有并发时用独立 worktree、端口和数据库。先识别并保留其他任务未提交成果。
- 导航、公共组件、barrel 和 package 文件由明确负责人集成，只整合已知提交和证据。分支验证显式使用对应 `FORGE_URL`，不能复用别的服务冒充通过。
- 元数据改动在 `apps/forge-objectstack` 执行 `pnpm typecheck`、`pnpm validate`、`pnpm build`，再运行与变化对应的业务检查。纯文档/规则修改验证链接与相关工具，不为其制造业务写入。
- 工程通过、页面可用、业务闭环、正式部署分别记录。检查通过后，只有新变化、失败或未决疑点才扩大/重复测试。
- 不提交数据库、node_modules、构建产物、环境文件、口令或会话。截图/日志脱敏，清理本次无用临时文件。
- 只有真正独立且有明确输入、输出、完成条件的工作才委派；共享状态和连续决策由当前负责人处理，不能用委派替代最终复核。

## ObjectStack 项目级 Skill 使用规则

- 项目级 Skill 位于 `.agents/skills/`，只在 inoForge 范围内使用。开始修改前按实际改动面读取对应 `SKILL.md`，不得为了形式一次性加载全部 Skill。
- 页面、导航、列表、表单、弹窗、看板、仪表盘、报表或 Action 使用 `objectstack-ui`；涉及列表过滤、排序、分页、聚合和关联展开时同时使用 `objectstack-query`。
- 新增或修改对象、字段、主从关系、校验、权限、索引、生命周期钩子或种子数据使用 `objectstack-data`；涉及 CEL 公式、字段显隐、只读、必填、校验条件或动作条件时同时使用 `objectstack-formula`。
- 多步骤且存在条件分支的业务流程、审批、状态机、定时任务或 webhook 使用 `objectstack-automation`；单对象分步表单仍由 `objectstack-ui` 的 wizard 承载。
- 只有新增自定义端点、认证、实时通道或 API 契约时使用 `objectstack-api`；对象自动 CRUD 不额外设计自定义 API。
- 修改 `objectstack.config.ts`、运行时能力、插件、服务注册、迁移、CLI 或部署时使用 `objectstack-platform`；协议跨主版本升级或出现 `[REMOVED]` 迁移错误时使用 `objectstack-upgrade`。
- 翻译包和语言覆盖使用 `objectstack-i18n`；ObjectStack AI skill、tool、知识源或 MCP 能力使用 `objectstack-ai`。当前业务未涉及这些表面时不加载。
- Skill 约束负责 ObjectStack 元数据和运行时的正确实现；用户确认的 Forge 业务目标与页面合同是产品依据，RISEMAP 仅作参考。业务决定、平台能力和外部参考分别记录，不把参考行为当成平台事实。
- 每轮实施汇报写明实际使用的 Skill、修改表面和验证结果。元数据改动至少运行 `pnpm validate`；项目门禁继续执行 `pnpm typecheck`、`pnpm validate`、`pnpm build`，并叠加对应业务验收、内置浏览器对照和同一持久数据库停服重启回读。
