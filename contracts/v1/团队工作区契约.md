# DEV-02 团队工作台

桌面定义、试跑、发布共同编辑 Weave 中的一份团队草稿。成员配置、团队说明、流程及材料输入关系都属于该草稿，保存不会激活线上版本。

- 调用者：Forge 已授予 teams:develop 的当前 Weave 用户；服务端逐次验证组织与团队归属。
- GET /v1/teams/:id/development 读取 revision、document、prepared_revision、trials 和线上基线；trials 列出本团队最近的试跑，不限发起人，每条带发起人显示名。PUT 接收 expected_revision 与完整 document，使用 CAS；过期返回 409。只有开发者在界面点击保存，或明确要求本次 Pi 修改并调试且 Pi 显式调用保存工具，才提交 PUT；字段失焦、切换页面、退出组件和单纯提建议不得隐式提交。保存只提交该次确认的快照，之后的编辑保持未保存；CAS 不得覆盖并发修改。
- document 包含 name、objective、audience、members（现有成员标识或新成员临时标识、configuration、relationship）、workflows（标识、名称、用途、graph_definition、trigger_config）。删除仅从草稿移除；服务端发布时保留历史并归档。
- 谁能使用团队由 Forge 决定，不在团队草稿里配置（[决策 005](../../docs/decisions/005-管理端不按Forge权限隔离试跑与可用人群.md)）。Forge 配置管理页为团队选择“可使用人员名单”；没有配置名单的团队，组织内全部账号可用。名单生效后，`GET /v1/teams` 与团队检索只返回当前账号可用的团队，`POST /v1/workbench/dispatch-inputs` 和 `POST /v1/teams/:id/dispatch` 对不可用团队返回 `403 team_not_available`，不写入输入版本；该拒绝是业务拒绝，桌面不得据此退出登录。团队开发者编辑与试跑不受名单限制。名单的读取接口尚未定义：实现前须先在本节写清调用者、身份、输入、输出、错误与审计，再由 Forge 与 Weave 分别实现；在此之前 Weave 不过滤，已发布团队全员可用。document 里旧的 `audience` 字段兼容接收并原样保存，但不参与任何判断，Weave 管理端不显示也不编辑它，名单接口落地时删除。
- POST /v1/teams/:id/development/trials 接收 revision、workflow_id、request_id（UUID）、固定 input 文本，以及当前候选成员所引用 Forge 动作的冻结定义。服务端解析并冻结成员、流程和动作定义，不改变已发布配置；复用 Kernel AdmitCandidate、队列、取消和运行记录。重复请求必须复用原配置、材料和动作定义，改变任一内容返回冲突。
- Forge 业务动作在开发试跑中使用隔离调试分发器：工具名称、说明、必填字段和枚举与本次冻结目录一致，调用输入和模拟输出进入真实运行轨迹，但不携带 Forge 凭据、不访问 Forge、不写业务数据。只有服务端登记的开发试跑任务可使用该分发器；正式运行仍要求当前员工的任务委托。尚未隔离的通用 MCP、Skill 或其他外部权限继续明确拒绝，不移除能力后冒充完整试跑。input 支持开发者提供的文本样例；不借用另一员工身份。
- `business_actions` 的每份冻结定义增加 `simulation_authorized` 布尔值，缺省为false。动作目录不是授权；界面明确选择，或Pi在当前开发者明确要求的模拟试跑中通过受控请求提交该选择。服务端只接受当前候选绑定的动作，并将选择与定义共同纳入既有请求摘要；同一request_id改变选择返回冲突。测试输入、成员输出或模型声称调用不能激活授权。该范围仅允许隔离模拟，不创建真实员工委托、不授予Forge权限；未选中的模拟写工具不向成员开放。
- 实际模拟派发将开始与成功／失败／未知结果写入既有活动账本，来源为 `development_simulation`，绑定当前组织、开发者、run、snapshot、input、capability及operation。只有经已冻结试跑范围核实的实际调用回执进入模拟完成检查，模型文字和普通工具输出中的自称回执不能代替。试跑复用现有完成检查、工具选择、预算、取消和恢复；正式路径拒绝模拟来源，不增加第二套循环或终态。零调用声称完成须纠正或明确失败，失败／未知不得重新执行冒充成功；合法只读试跑仍允许零调用。
- 模拟校验的必办集合为当前冻结检查与显式模拟范围的交集，不能因没有真实员工委托而清空它；这份模拟范围不改写真实授权。选择由可信桌面或当前Pi host绑定开发者本轮明确试跑请求并审计，裸模型回复或输入文本不作为范围凭据。每个选中的必办能力须有同一逻辑操作的实际模拟开始及成功结果；失败／未知硬停不再派发。同request_id核对／重试复用原run和receipt，恢复保持原范围及操作身份；取消／终态后的迟到结果不能新增发布覆盖。
- GET 运行 activity/delivery 显示实际输入来源、版本和输出；摘要须标记为摘要。完整原始输入单独读取，本组织具备团队开发或管理权限的账号都可读取该团队的试跑输入。
- 侧栏与 Pi 对同一条工具活动使用一致的状态及证据解释。调用清单完整不等于实参和模拟回执完整，二者分别表达；缺失载荷保持未记录，不能从成员摘要补造。工具的节点归属只采用平台记录，不按成员名称、执行顺序或模型自述猜测。模拟工具完成仍不代表 Forge 业务已办理。
- 开发试跑的 activity 在确认当前账号具备团队开发或管理权限、且试跑属于本组织该团队后，可从已有持久工具日志投影实际输入与模拟回执，按父运行、运行快照、节点调用、成员及工具调用关联，不读取模型私有思考，不向普通运行活动扩散原文。工具增加可选 `input_state/output_state`（`recorded/missing/truncated`）及原始 `input_bytes/output_bytes`，区别合法空内容、未记录和有界截断；每值最多8 KiB，每运行最多200条。`member_tool_activity` 仍表示调用清单完整性，新增 `member_tool_payloads` 独立表示实参／回执完整性；查询失败、缺记录、截断或超过上限不能表示完整。旧记录缺少这些字段时按实际存在的载荷保守解释。
- POST /v1/teams/:id/development/publish 接收 revision，要求每个待发布流程存在相同草稿的成功试跑。固定 candidate 发布、可重复恢复；所有流程和成员一次激活。失败不部分切换线上目录。试跑后修改使原结果过期。
- 声明必办业务回执检查的流程还须有同修订、同冻结候选的实际成功模拟回执，覆盖该流程声明的全部必要能力；可合并同候选多个成功试跑的覆盖。只有技术状态succeeded、只读试跑、旧的无模拟范围／回执记录以及失败／未知调用都不提供写动作覆盖。GET development增加服务端派生的 `publication_readiness: {ready, workflows:[{workflow_id, required_capability_ids, covered_capability_ids, missing_capability_ids, passed}]}`；桌面与Pi按同一结果阻止发布，缺少结果时写动作流程不视为通过。覆盖从原账本计算，不另存状态。接口沿用当前身份、CAS、幂等、取消与审计；覆盖不足返回409业务拒绝，不退出登录。
- 试跑与发布不按开发者个人隔离（[决策 005](../../docs/decisions/005-管理端不按Forge权限隔离试跑与可用人群.md)）：本组织具备团队开发或管理权限的账号都可以试跑同一份已保存草稿，已由他人准备的冻结候选直接复用；发布覆盖按同一修订、同一冻结候选下任何账号的成功试跑合并计算，发布者不必是试跑者。每次试跑仍记录发起账号，准入回执与模拟回执按该账号核验，不把某试跑的回执用于其范围外的能力。
- Weave 管理端试跑时，动作的冻结定义取自工作区的业务能力目录快照（见[契约索引](README.md)“管理端读取业务能力目录”），界面逐项列出本流程用到的业务动作并由开发者选择是否模拟；快照里没有的动作不能补造定义，页面须说明原因。
- Weave 管理端维护业务回执检查的声明：流程实际用到的成员只要带业务动作，管理端在每次编辑时让该流程的 `delivery_contract` 带上 `weave.business-action-receipts` 检查，并启用 `workbench_result_v1` 结果分类；默认必办集合是其中会写入的动作，只有读取动作时为这些读取动作，开发者可在交付步骤调整但至少保留一个。成员不再带业务动作时撤回该检查。结构与桌面 `business_completion` 写入的一致，两端可互相读取。最终交付来源不是负责人或成员（例如并行汇合）时无法声明，页面须说明原因，不能写入不合法的声明。
- DELETE /v1/teams/:id/development/team 为可追溯退役，不抹除版本、运行或成果；正在执行的工作沿用冻结版本。
- 审计包含当前主体、组织、草稿修订、冻结候选摘要、试跑及发布回执；不保存长期凭据。

桌面只提供编辑与观察，不建立第二套运行队列。步骤输入支持原始材料与多个上游成果并存；执行绑定由 Weave 校验，不通过模型转抄。

成员绑定的业务能力随实际执行成员冻结；“理解”“只读”等步骤名称或指令本身不额外收窄工具权限。需要严格只读的前序步骤应绑定无写能力的成员，授权办理步骤再绑定获准执行该动作的成员，并核对冻结后的实际工具范围。复用有写能力的成员执行前后两步时，不能仅凭前一步写有“不调用”就认定能力已隔离。

## Pi 辅助开发工具

桌面 Pi 主会话是开发者以对话提出修改与调试要求的入口；同一份远端草稿、差异、实际试跑轨迹和发布状态在 Weave 管理端查看，桌面不再有团队开发侧栏。Pi 可列出/打开有权开发的团队、读取草稿与业务动作目录、预览受控修改、按开发者本轮明确要求把修改保存到同一草稿、发起隔离试跑并读取每步实际输入输出。开发者明确要求“更新团队”且同修订试跑成功后，Pi 才可调用现有发布接口；仅要求查看或提出建议时不得保存或发布。新团队在 Weave 管理端创建，Pi 不提供新建团队的工具，也不保留新建候选。

这些工具只面向已登录且具备 `teams:develop` 的当前账号，并绑定 Pi 运行会话及当前团队。每次保存、试跑和发布都重新核对账号、远端修订与团队权限；账号切换、会话结束或草稿修订变化后拒绝旧请求。一次试跑使用固定 UUID 请求标识，传输不确定时按原请求核对，不用新标识重复执行。错误时保留待修改内容和原试跑回执，Pi 说明卡在哪一步。普通员工的团队交接工具不提供草稿修改能力。

受控修改限定为团队名称与目标、成员新增或职责/指令调整、业务动作选择及声明参数的文件来源、流程说明、步骤新增或调整。成员、流程、步骤和动作引用必须来自当前草稿或目录；不能通过受控修改写任意 JSON 路径、增加未登记动作或执行 Forge 业务写入。

修改写法按需读取：会话开头只给每个工具一句用途；团队上下文列出可修改的类别，每类一行，并说明哪些配置只在 Weave 管理端办理；某一类修改的准确字段与例子由 Pi 在用到时单独读取。不在工具说明中一次给出全部写法，Pi 也不得凭猜测填写字段。

开发者只要方案时，Pi 预览修改并在对话中说明会带来的变化；预览不保存，也不留下待处理内容。开发者要求 Pi 直接修改时，Pi 使用同一受控操作和校验器生成变更，读取远端当前修订后显式保存；草稿已在别处变化时拒绝保存，不覆盖新内容。此时重新打开该团队即放弃这一项未保存的修改并读取最新草稿，Pi 说明放弃了什么，再按最新内容重新提交。试跑只针对已保存修订，发布要求同修订成功试跑；Pi 在对话中报告真实试跑结果及更新回执，开发者在 Weave 管理端读回。工具语义独立于 Pi 扩展传输，后续 MCP 适配复用同一验证与权限边界，不另建团队草稿接口或后台调度器。

## 受控修改接口

本节尚未实现。实现前，受控修改的写法、名称解析和校验在桌面开发桥内完成，Weave 管理端页面另有一套编辑逻辑；本节把“能改什么、怎么改、还差什么”收到 Weave 服务端，桌面 Pi、管理端和以后的其他入口读取同一份。管理端页面仍整份保存草稿（PUT），不要求逐项调用受控修改。

- **调用者与身份。** 桌面 Pi 开发桥和以后的智能体入口，以当前开发者的 Weave 会话调用；角色要求与 `PUT /v1/teams/:id/development` 相同（developer／admin／owner，限本工作区）。服务端不接收也不保存 Forge 令牌。
- **修改类别目录。** `GET /v1/development/operations` 返回 `{version, topics:[{topic,title,covers}], console_only}`，每类一行；`GET /v1/development/operations/:topic` 返回该类的 `{topic,title,operations:[{kind,summary,fields:[{name,type,required,description}],example}],rules}`。只读，不审计；未知类别 404。目录只列服务端实际接受的修改，新增修改能力时同一处更新。
- **提交受控修改。** `POST /v1/teams/:id/development/operations` 输入 `{expected_revision, request_id, dry_run, operations}`：`request_id` 为 UUID，`operations` 为 1 至 24 项。成员、流程、步骤和业务动作用草稿与工作区目录快照中的准确名称引用，由服务端解析；名称不存在或重复时拒绝，不猜测。输出 `{revision, saved, changes, issues}`：`changes` 是逐项的中文说明，`issues` 同下文待办。`dry_run=true` 只计算不写入，`saved=false`，修订不变。
- **幂等与结果不确定。** 同一团队内相同 `request_id` 且内容相同的重复提交，返回首次结果，不再次应用；相同 `request_id` 而内容不同返回 `409 request_conflict`。调用方在传输结果不确定时用原 `request_id` 重试来核对，不换新标识。接口同步完成，没有取消；连接中断不回滚已提交的保存。
- **错误。** `expected_revision` 过期返回 `409 development_revision_stale`，不写入；某项修改不合法返回 `422 operation_invalid` 与 `{index, message}`，整组不写入；团队不存在或不在本工作区 404；无开发角色 403。
- **草稿待办。** `GET /v1/teams/:id/development` 增加 `issues:[{scope,target,workflow,code,message,blocks}]`：`scope` 为 team／member／workflow／step，`target` 与 `workflow` 是名称，`blocks` 说明它挡住保存、试跑还是发布。待办由服务端按当前草稿与目录快照计算，包括成员带业务动作而流程未声明必须办成的动作、流程说明为空等；管理端页面与 Pi 显示同一份，不各自推断。
- **新建团队。** `POST /v1/development/teams` 输入 `{request_id, name, objective, kind}`，`kind` 为 business 或 code，创建带负责人、一位执行成员和基础流程的草稿，返回 `{team_id, name, revision}`。同一工作区内相同 `request_id` 返回同一团队，不重复创建；内容不同返回 `409 request_conflict`。管理端与 Pi 共用；Pi 只在开发者本轮明确要求新建时调用。
- **审计。** 保存与新建记录工作区、团队、操作人、`request_id`、修订前后、各类修改的数量和时间；不记录修改内容。预览与目录读取不记录。
- **不变的边界。** 受控修改不能写任意 JSON 路径、增加未登记动作或执行 Forge 业务写入；保存不改变已发布配置；试跑与发布仍走原接口和原条件。

## 场景与编辑器边界

团队、成员职责、流程及输入绑定由远端开发定义提供。桌面不得按合同、采购等场景写死成员、审批或模型。现有文本调试只是首版能力范围；结构化输入、外部工具隔离和实际 Loom 拓扑未接通时须明确保留为缺口，不能用场景专用指令或示意图宣称对应能力已开放。
