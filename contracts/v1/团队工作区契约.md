# DEV-02 团队工作台

桌面定义、试跑、发布共同编辑 Weave 中的一份团队草稿。成员配置、团队说明、流程及材料输入关系都属于该草稿，保存不会激活线上版本。

- 调用者：Forge 已授予 teams:develop 的当前 Weave 用户；服务端逐次验证组织与团队归属。
- GET /v1/teams/:id/development 读取 revision、document、prepared_revision、trials 和线上基线。PUT 接收 expected_revision 与完整 document，使用 CAS；过期返回 409。只有开发者在界面点击保存，或明确要求本次 Pi 修改并调试且 Pi 显式调用保存工具，才提交 PUT；字段失焦、切换页面、退出组件和单纯提建议不得隐式提交。保存只提交该次确认的快照，之后的编辑保持未保存；CAS 不得覆盖并发修改。
- document 包含 name、objective、audience、members（现有成员标识或新成员临时标识、configuration、relationship）、workflows（标识、名称、用途、graph_definition、trigger_config）。删除仅从草稿移除；服务端发布时保留历史并归档。
- audience 是可使用该团队的 Forge 权限集名称数组（每项 1–128 字符，至多 32 项，去重），随发布冻结；缺省或空数组表示组织内全部账号可用（[决策 002](../../docs/decisions/002-任务委托身份来源与员工入口收敛.md)）。Weave 以登录交换时 Forge 返回的权限集判断：`GET /v1/teams` 与团队检索只返回交集非空的团队；`POST /v1/workbench/dispatch-inputs` 和 `POST /v1/teams/:id/dispatch` 对不可用团队返回 `403 team_not_available`，不写入输入版本。团队开发者编辑与试跑不受 audience 限制：持有开发或管理权限的账号以 `GET /v1/teams?purpose=development` 读取完整团队列表，普通列表与派发仍按 audience 校验。`team_not_available` 是业务拒绝，桌面不得据此退出登录。桌面不展示权限集内部名称以外的技术标识。
- POST /v1/teams/:id/development/trials 接收 revision、workflow_id、request_id（UUID）、固定 input 文本，以及当前候选成员所引用 Forge 动作的冻结定义。服务端解析并冻结成员、流程和动作定义，不改变已发布配置；复用 Kernel AdmitCandidate、队列、取消和运行记录。重复请求必须复用原配置、材料和动作定义，改变任一内容返回冲突。
- Forge 业务动作在开发试跑中使用隔离调试分发器：工具名称、说明、必填字段和枚举与本次冻结目录一致，调用输入和模拟输出进入真实运行轨迹，但不携带 Forge 凭据、不访问 Forge、不写业务数据。只有服务端登记的开发试跑任务可使用该分发器；正式运行仍要求当前员工的任务委托。尚未隔离的通用 MCP、Skill 或其他外部权限继续明确拒绝，不移除能力后冒充完整试跑。input 支持开发者提供的文本样例；不借用另一员工身份。
- `business_actions` 的每份冻结定义增加 `simulation_authorized` 布尔值，缺省为false。动作目录不是授权；界面明确选择，或Pi在当前开发者明确要求的模拟试跑中通过受控请求提交该选择。服务端只接受当前候选绑定的动作，并将选择与定义共同纳入既有请求摘要；同一request_id改变选择返回冲突。测试输入、成员输出或模型声称调用不能激活授权。该范围仅允许隔离模拟，不创建真实员工委托、不授予Forge权限；未选中的模拟写工具不向成员开放。
- 实际模拟派发将开始与成功／失败／未知结果写入既有活动账本，来源为 `development_simulation`，绑定当前组织、开发者、run、snapshot、input、capability及operation。只有经已冻结试跑范围核实的实际调用回执进入模拟完成检查，模型文字和普通工具输出中的自称回执不能代替。试跑复用现有完成检查、工具选择、预算、取消和恢复；正式路径拒绝模拟来源，不增加第二套循环或终态。零调用声称完成须纠正或明确失败，失败／未知不得重新执行冒充成功；合法只读试跑仍允许零调用。
- 模拟校验的必办集合为当前冻结检查与显式模拟范围的交集，不能因没有真实员工委托而清空它；这份模拟范围不改写真实授权。选择由可信桌面或当前Pi host绑定开发者本轮明确试跑请求并审计，裸模型回复或输入文本不作为范围凭据。每个选中的必办能力须有同一逻辑操作的实际模拟开始及成功结果；失败／未知硬停不再派发。同request_id核对／重试复用原run和receipt，恢复保持原范围及操作身份；取消／终态后的迟到结果不能新增发布覆盖。
- GET 运行 activity/delivery 显示实际输入来源、版本和输出；摘要须标记为摘要。完整原始输入单独按当前试跑权限读取。
- 侧栏与 Pi 对同一条工具活动使用一致的状态及证据解释。调用清单完整不等于实参和模拟回执完整，二者分别表达；缺失载荷保持未记录，不能从成员摘要补造。工具的节点归属只采用平台记录，不按成员名称、执行顺序或模型自述猜测。模拟工具完成仍不代表 Forge 业务已办理。
- 开发试跑的 activity 在确认当前开发者及试跑归属后，可从已有持久工具日志投影实际输入与模拟回执，按父运行、运行快照、节点调用、成员及工具调用关联，不读取模型私有思考，不向普通运行活动扩散原文。工具增加可选 `input_state/output_state`（`recorded/missing/truncated`）及原始 `input_bytes/output_bytes`，区别合法空内容、未记录和有界截断；每值最多8 KiB，每运行最多200条。`member_tool_activity` 仍表示调用清单完整性，新增 `member_tool_payloads` 独立表示实参／回执完整性；查询失败、缺记录、截断或超过上限不能表示完整。旧记录缺少这些字段时按实际存在的载荷保守解释。
- POST /v1/teams/:id/development/publish 接收 revision，要求每个待发布流程存在相同草稿的成功试跑。固定 candidate 发布、可重复恢复；所有流程和成员一次激活。失败不部分切换线上目录。试跑后修改使原结果过期。
- 声明必办业务回执检查的流程还须有同修订、同冻结候选的实际成功模拟回执，覆盖该流程声明的全部必要能力；可合并同候选多个成功试跑的覆盖。只有技术状态succeeded、只读试跑、旧的无模拟范围／回执记录以及失败／未知调用都不提供写动作覆盖。GET development增加服务端派生的 `publication_readiness: {ready, workflows:[{workflow_id, required_capability_ids, covered_capability_ids, missing_capability_ids, passed}]}`；桌面与Pi按同一结果阻止发布，缺少结果时写动作流程不视为通过。覆盖从原账本计算，不另存状态。接口沿用当前身份、CAS、幂等、取消与审计；覆盖不足返回409业务拒绝，不退出登录。
- 发布覆盖还绑定当前发布者／prepared_actor，不能借用另一开发者的试跑；多试跑合并只合并同一主体、修订和冻结候选下各自经验证的模拟范围，不把某试跑的回执用于其范围外的能力。
- DELETE /v1/teams/:id/development/team 为可追溯退役，不抹除版本、运行或成果；正在执行的工作沿用冻结版本。
- 审计包含当前主体、组织、草稿修订、冻结候选摘要、试跑及发布回执；不保存长期凭据。

桌面只提供编辑与观察，不建立第二套运行队列。步骤输入支持原始材料与多个上游成果并存；执行绑定由 Weave 校验，不通过模型转抄。

成员绑定的业务能力随实际执行成员冻结；“理解”“只读”等步骤名称或指令本身不额外收窄工具权限。需要严格只读的前序步骤应绑定无写能力的成员，授权办理步骤再绑定获准执行该动作的成员，并核对冻结后的实际工具范围。复用有写能力的成员执行前后两步时，不能仅凭前一步写有“不调用”就认定能力已隔离。

## Pi 辅助开发工具

桌面 Pi 主会话是开发者以对话提出修改与调试要求的入口；同一份远端草稿、差异、实际试跑轨迹和发布状态在 Weave 管理端查看，桌面不再有团队开发侧栏。Pi 可列出/打开有权开发的团队、读取草稿与业务动作目录、生成受控修改、按开发者本轮明确要求把修改保存到同一草稿、发起隔离试跑并读取每步实际输入输出。开发者明确要求“更新团队”且同修订试跑成功后，Pi 才可调用现有发布接口；仅要求查看或提出建议时不得保存或发布。Pi 的新建团队提案在桌面没有确认入口，新团队在 Weave 管理端创建；不能把新建候选说成已生效。

这些工具只面向已登录且具备 `teams:develop` 的当前账号，并绑定 Pi 运行会话及当前团队。每次保存、试跑和发布都重新核对账号、远端修订与团队权限；账号切换、会话结束或草稿修订变化后拒绝旧请求。一次试跑使用固定 UUID 请求标识，传输不确定时按原请求核对，不用新标识重复执行。错误时保留待修改内容和原试跑回执，Pi 说明卡在哪一步。普通员工的团队交接工具不提供草稿修改能力。

提案操作限定为团队名称与目标、成员新增或职责/指令调整、业务动作选择及声明参数的文件来源、流程说明、步骤新增或调整。成员、流程、步骤和动作引用必须来自当前草稿或目录；不能通过提案写任意 JSON 路径、增加未登记动作或执行 Forge 业务写入。桌面将提案与发起时的本地草稿快照比较；开发者在 Pi 运行期间修改了草稿，旧提案必须重新生成，不能覆盖新编辑。

Pi 提案仍可只在桌面显示差异，供开发者选择手动应用。开发者要求 Pi 直接修改时，Pi 使用同一受控操作和校验器生成变更，读取远端当前修订后显式保存；不得覆盖面板里尚未保存的人工修改。试跑只针对已保存修订，发布要求同修订成功试跑；Pi 在对话中报告真实试跑结果及更新回执，面板同步读回。工具语义独立于 Pi 扩展传输，后续 MCP 适配复用同一验证与权限边界，不另建团队草稿接口或后台调度器。

## 场景与编辑器边界

团队、成员职责、流程及输入绑定由远端开发定义提供。桌面不得按合同、采购等场景写死成员、审批或模型。现有文本调试只是首版能力范围；结构化输入、外部工具隔离和实际 Loom 拓扑未接通时须明确保留为缺口，不能用场景专用指令或示意图宣称对应能力已开放。
