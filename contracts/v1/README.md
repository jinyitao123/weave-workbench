# 契约 v1

这些契约只描述跨组件传递的信息，不规定 Forge 内部对象结构或 Weave 内部执行方式。

所有请求都带有用户、组织和短期委托。所有会产生业务影响的动作都带有幂等键。执行结果允许明确表示“结果未知”，此时 Weave 必须先向 Forge 核对，不能直接重试。

材料通过受管理的引用传递。桌面本地路径不能直接成为远程系统可读取的材料地址；上传后用摘要校验内容是否一致。

## 企业身份会话

`enterprise-session.schema.json` 是桌面可见的账号投影，`account-binding.schema.json` 描述 Forge 账号到 Weave 用户的稳定绑定；两者都不包含密码、Cookie 或 Bearer Token。`task-delegation.schema.json` 描述任务范围内的短期授权。

- 调用者：Workbench Host 调用 Forge 登录和 Weave 绑定接口；界面只读取账号、组织和 Weave 角色投影。
- 身份来源：Forge 注册并验证账号，Weave 以 `issuer + subject + organization` 建立本地绑定。桌面不创建第二套账号。
- 单次登录：Workbench Host 把一次性账号密码请求发给 Forge，随后把 Forge 会话交给 Weave 验证并换取产品会话。渲染进程不保存密码，Weave 不接收或保存密码。
- 自动绑定：首次登录创建默认 `member` 用户；重复登录返回同一 Weave 用户且不覆盖管理员设置的角色；不同组织或身份来源不能按邮箱合并。
- 产品权限：Weave 直接用自身 `member / developer / admin` 控制团队使用、配置、调试、发布与平台管理。MVP1 不维护第二份能力投影，也不依赖外部权限引擎。
- 业务权限：Forge 对每次业务动作继续执行自身权限判断。Weave 角色不能扩大 Forge 数据和流程权限。
- 保存方式：设备会话令牌只允许由系统安全存储加密落盘。安全存储不可用时只保留到本次进程结束。
- 传输：Workbench 按部署配置连接 HTTP 或 HTTPS，账号投影中的 `environment.secure` 明确标识当前连接方式；客户内网可直接使用 HTTP。
- Weave 委托：身份提供方的长期会话令牌不得进入团队执行。由 Weave 接入与权限模块签发短期、限定动作、资源、任务和有效期的委托。
- 失效：Forge 返回 401 或 403 时，桌面清除本地会话并回到未登录；退出登录同样清除本地会话。
- 审计：登录、退出和委托签发记录主体、组织、设备会话、时间和结果，不记录密码与令牌正文。

## 开发观察

`development-observation.schema.json` 是 Workbench Host 从 Weave 读取后交给开发中心的只读投影。

- 调用者：已登录的 Workbench Host；只有 Weave `developer / admin` 可进入开发中心。
- 身份：每次请求携带当前 Weave 会话，按会话组织限定团队、工作流和运行记录。
- 输入：不接收业务对象或任意查询；第一版固定读取当前组织的可见团队、每个团队的工作流和归属运行。
- 输出：团队角色、准确的已发布或草稿版本、节点关系和运行摘要。空数组表示真实暂无数据，不生成示例记录。
- 错误：401/403 使设备会话失效并回到登录；单个团队的工作流或运行读取失败时整次读取失败，避免把不完整数据展示成完整事实。
- 幂等与取消：全程只读，无幂等键；窗口离开或刷新可以取消请求，不影响服务端状态。
- 审计：Weave 保留主体、组织、接口和结果；桌面不记录 Bearer Token 或工作流输入输出正文。

## 团队成员配置草稿

`team-member-config-draft.schema.json` 描述开发中心按“团队 + 智能体成员”保存的配置草稿。草稿与正在运行的智能体版本分离，保存草稿不会改变正在运行或新发起任务使用的配置。历史扩展字段 `publishedConfiguration` / `publishedRelationship` 为可选字段；当前实现读取的是注册配置与团队关系，不是发布时冻结的快照，桌面不得据此宣称“与已发布版本比较”。旧服务未返回这些字段时仍可读取与保存草稿。

- 调用者：已登录的 Workbench Host；只有 Weave `developer / admin` 可读取和保存。
- 身份：Weave 从当前会话取得主体和组织，成员必须属于请求中的团队。
- 并发与幂等：客户端提交已读取的 `revision`。同一修订只能成功保存一次；较旧修订返回 `409 draft_revision_conflict`，防止覆盖另一位开发者的修改。
- 输入与输出：草稿包含智能体身份与指令、模型和运行时、技能与工具、材料与输出约束、执行限制，以及该成员在团队中的职责和交接要求。密钥、请求头和长期凭据不进入草稿投影。
- 生效边界：本接口只保存草稿。发布必须由独立的验证和发布动作生成不可变智能体版本；MVP1 第一步不提供发布动作。
- 错误与取消：成员或团队不存在返回 404；无开发权限返回 403；请求取消时未提交的事务不产生草稿。
- 审计：保存记录操作者、组织、团队、成员、修订和时间，不记录密钥或令牌正文。

## 新建团队

`team-create.schema.json` 描述开发中心的最小新建输入。Workbench Host 根据名称和目标建立一个可继续编辑的团队，并同时建立“团队负责人”和“执行成员”两个初始成员，避免新团队再次落入无成员的死路。

- 调用者：已登录的 Workbench Host；向 Weave `developer / admin` 开放。
- 输入：开发者只填写团队名称和目标；内部名称、成员标识和默认协作关系由 Host 生成，不在界面展示。
- 默认成员：负责人负责理解目标、分派与汇总；执行成员负责完成任务并返回可核验结果。两者创建后均可在成员配置区修改。
- 一致性：Host 依次建立两个成员和团队；团队建立失败时回收本次已建立的成员。服务端原子创建向导接入后，可在不改变界面契约的前提下替换该适配。
- 错误：同名、权限或连接错误显示为可操作的创建失败；失败时不把团队加入本地列表。

## 团队与成员管理

`team-management.schema.json` 描述开发者修改团队资料、添加执行成员和将成员移出当前团队的桌面输入。移出只结束当前团队关系，不删除成员的不可变版本、既有运行或审计记录。

- 修改团队使用读取时的更新时间防止覆盖并发修改；名称和目标必须在刷新后稳定读回。
- 添加成员同时建立一个可编辑的 Weave 智能体和团队关系；任一步失败时不能在团队中留下半成品成员。
- 负责人不能通过成员移出入口删除；执行成员移出后不再参与新任务，历史任务继续显示当时冻结的成员名称与版本。
- 所有写入由 Weave 会话判断产品角色，Workbench 不在界面层伪造权限结果。

## 员工工作与人工交接

`work-request.schema.json` 在当前实现中由 Workbench Host 映射到 Weave 的固定输入版本和团队派发回执。每次独立工作使用新的 `workId`，原始说明摘要、团队、工作流和准确版本一并冻结；重复回执不能创建第二条运行。

`task-notification.schema.json` 的第一条通道由 Weave 人工待办提供。处理员工以自己的 Forge/Weave 身份提交决定，运行继续沿用发起员工冻结的执行主体；处理员工只成为人工转换的审计 actor，不能借此替换原任务身份或取得发起人的长期凭据。
