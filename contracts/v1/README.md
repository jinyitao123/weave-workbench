# 契约 v1

这些契约只描述跨组件传递的信息，不规定 Forge 内部对象结构或 Weave 内部执行方式。

所有请求都带有用户、组织和短期委托。所有会产生业务影响的动作都带有幂等键。执行结果允许明确表示“结果未知”，此时 Weave 必须先向 Forge 核对，不能直接重试。

## 三场景修复的执行约定

本节为 2026-09-24 并行修复的实现边界，仍须通过组件检查和桌面场景验收。

### 真实动作结果

- Forge 原生 MCP `run_action` 返回及权威业务记录决定业务结果；Weave 运行结束和模型文字不替代它。Weave 在现有运行活动/结果中记录动作事实，不新建执行队列、审批或独立终态。
- 每条事实绑定当前运行、节点、工具调用、动作名、对象和已冻结记录。只由能力桥写入；成员文字、材料或用户自填同名字段不能成为事实。状态为 `succeeded`、`failed`、`unknown`；只有 Forge 明确成功才记 succeeded，发送后丢失响应记 unknown，不能推断未执行。
- 下游成员只接收当前父运行内已确认的动作事实，可以描述其他节点已完成的动作，无需拥有该动作的写权限。平台指令须区分本节点和整个父运行。前序模型文本仍按工作数据处理，不能伪造工具回执。
- 员工续办接口在 `run.action_outcomes` 返回该运行的事实投影；字段为 `node_id`、`call_id`、`action_name`、`object_name`、可选 `record_id`、`status`、`summary`。summary 由平台根据已知动作名称及状态构成，不使用模型文本、不包含内部标识或原始错误。内部保存可以包含受限的原生结果数据，但不得保存凭据、请求头或模型私有思考。
- 原生收件箱继续使用现有 team-run-event：有业务动作时 summary 以动作事实生成，运行失败仍保留此前已经完成的动作；具体分析由员工打开原工作读取。没有动作事实时只称团队分析完成，不能称业务写入完成。未知结果不自动重放；取消不会删除已完成事实。
- action_outcomes 缺省表示该接口未提供动作事实，不是确认“未执行”。桌面保留原运行状态、独立显示/传给 Pi 的业务事实，不从模型段落猜测状态。

### 原生只读记录连接

- 桌面 Host 用当前员工 Forge 会话调用原生 MCP `list_objects`、`describe_object`、`query_records`、`get_record`。可查询范围来自原生读取授权，不以团队是否绑定写动作作为前提。禁止向此连接开放通用 create/update/delete 或任意 run_action。
- Pi 查询时只提交业务检索意图、目录返回的对象引用和分页参数；Host 验证对象来自本账号当前目录，排除 sys_*。结果携带名称、编码、获准状态/负责人及版本，返回不透明 record_key；无匹配、歧义、拒绝和服务失败分别表达。禁止无关唯一结果自动命中。
- 读取选定记录及关联明细时，只使用原生元数据中声明的关系和同一员工身份，不在桌面按合同/报价对象名特判。关联读取有数量上限并明确完整性；截断不能被当成完整报价。
- 当前 ObjectStack 17.3 的 MCP `describe_object` 只投影字段名称、类型、标签和必填性，未提供 `reference`；关系须从同一会话的原生具名元数据 `GET /api/v1/meta/object/{name}` 的 `item.fields.*.reference` 确认。先依据已读目录的对象名/标签收窄少数候选，再取具名元数据；不能每次读取全部对象定义，也不能仅因名称相似就认定关系。无法证明关联或子项读取不完整时返回 partial，不得宣称完整核算。
- 账号切换、员工轮次变化或取消使未完成的查询/交接结果失效。向团队交付的是该轮固定读取的字段、明细及版本，写动作仍沿既有单独授权与受保护对象绑定。业务保存时 Forge 再验证当前版本；读取不冻结后端业务记录。
- 首批只读快照由 Host 序列化进现有固定 `task` JSON，与 goal 分区，受已有 task 摘要和冻结意图保护；模型仅选择 record_key，不能转抄或覆盖快照。已由当前员工权限完整读取的明细关系，可在快照中按行顺序附带原生 `recordIds`，仅供受控领域动作填写明细引用，不作为页面展示内容；缺失、重复或越界的引用不得由模型猜造。登记仍使用已有 business_record 与可选 record_version，不另建快照表。原生没有可靠版本时不造值；报价主记录的 `pricing_version` 与快照格式 `version` 必须分开，领域保存动作仍按真实报价版本和明细归属校验。
- Forge 单行报价调价动作的对外参数使用 `expected_pricing_version`，值必须是本次获准读取的报价主记录 `pricing_version`，不得用快照格式 `version`。Forge 仍在同一事务核对当前版本、明细归属和幂等请求，再重算报价；参数改名不表示放宽版本冲突。既有调整回执内部仍可保留 `expected_version` 审计列。

### 报价起点与保存

- Forge 正常销售入口提供草稿创建、主表及明细编辑、保存后详情。权限按场景实际业务职责配置：销售处理本人线索、商机和报价；交付、商务在被分配的合同事项范围内读取与办理；团队开发者不因开发身份获得业务数据。独立核验是验收方式，不新增核验员或全销售域只读权限集。
- 优先用 ObjectStack 原生表单、列表、关系及事务能力；若原生组合保存不能保证头/行/汇总一致，只在 Forge 领域动作补这个原子保存边界。保存失败保留用户输入和可核对的结果，不用成功提示掩盖部分写入。
- 本批只含草稿：至少两行，数量、单价、税率与折扣由 Forge 共用计算规则生成小计和汇总，未知成本保留未知。原生对象与已有 `quotation_adjust_line_price` 复用；不追加审批、对外发送、转订单或多行通用模型写入。
- 验收先建立并重开 2300 元草稿；Pi 试算不写入，授权后只将设备单价改成 900，服务行及数量保持不变，总额 2100；并发旧版本拒绝，同请求重试返回同结果。

材料通过受管理的引用传递。桌面本地路径不能直接成为远程系统可读取的材料地址；上传后用摘要校验内容是否一致。

## 企业身份会话

`enterprise-session.schema.json` 是桌面可见的账号投影，`account-binding.schema.json` 描述 Forge 账号到 Weave 用户的稳定绑定；两者都不包含密码、Cookie 或 Bearer Token。`task-delegation.schema.json` 描述任务范围内的短期授权。

- 调用者：Workbench Host 调用 Forge 登录和 Weave 绑定接口；界面只读取账号、组织和 Forge 已验证的产品权限投影。
- 身份来源：Forge 注册并验证账号，Weave 以 `issuer + subject + organization` 建立本地绑定。桌面不创建第二套账号。
- 单次登录：Workbench Host 把一次性账号密码请求发给 Forge，随后把 Forge 会话交给 Weave 验证并换取产品会话。渲染进程不保存密码，Weave 不接收或保存密码。
- 自动绑定：首次登录创建稳定的 Weave 用户映射；重复登录返回同一 Weave 用户；不同组织或身份来源不能按邮箱合并。绑定只回答“这个 Forge 账号对应哪个 Weave 用户”，不保存独立产品角色。
- 产品权限：Forge 权限集是唯一来源。`智能体团队开发` 权限集开放团队配置、调试和发布；Forge 平台管理员增加平台管理能力。Weave 在登录交换时验证这些权限并签发短期会话，不允许本地角色覆盖验证结果。
- 业务权限：Forge 对每次业务动作继续执行自身权限判断。团队产品权限不能扩大 Forge 数据和流程权限。
- 保存方式：设备会话令牌只允许由系统安全存储加密落盘。安全存储不可用时只保留到本次进程结束。
- 传输：Workbench 按部署配置连接 HTTP 或 HTTPS，账号投影中的 `environment.secure` 明确标识当前连接方式；客户内网可直接使用 HTTP。
- Weave 委托：Workbench Host 只在固定输入登记请求的专用请求头中提交 Forge 会话。Weave 验证它与当前 Weave 用户的稳定绑定后，将凭据加密保存为不透明引用，并冻结准确输入版本、已发布工作流版本、本次员工意图允许的动作和任务正文摘要。团队发布能力只是上限；本次动作必须是其子集，空列表表示只处理材料、不允许业务写动作。凭据正文不进入任务、模型上下文、回执或审计记录；运行时只能在当前任务租约内解析引用并调用本次冻结动作。
- 失效：Forge 返回 401 或 403 时，桌面清除本地会话并回到未登录；退出登录同样清除本地会话。
- 审计：登录、退出和委托签发记录主体、组织、设备会话、时间和结果，不记录密码与令牌正文。

## 开发观察

`development-observation.schema.json` 是 Workbench Host 从 Weave 读取后交给开发中心的只读投影。

- 调用者：已登录的 Workbench Host；只有 Forge 已授予 `智能体团队开发` 或平台管理权限的账号可进入开发中心。
- 身份：每次请求携带当前 Weave 会话，按会话组织限定团队、工作流和运行记录。
- 输入：不接收业务对象或任意查询；第一版固定读取当前组织的可见团队、每个团队的工作流和归属运行。
- 输出：团队角色、准确的已发布或草稿版本、节点关系和运行摘要。空数组表示真实暂无数据，不生成示例记录。
- 错误：401/403 使设备会话失效并回到登录；单个团队的工作流或运行读取失败时整次读取失败，避免把不完整数据展示成完整事实。
- 幂等与取消：全程只读，无幂等键；窗口离开或刷新可以取消请求，不影响服务端状态。
- 审计：Weave 保留主体、组织、接口和结果；桌面不记录 Bearer Token 或工作流输入输出正文。

## 团队成员配置草稿

`team-member-config-draft.schema.json` 描述开发中心按“团队 + 智能体成员”保存的配置草稿。草稿与正在运行的智能体版本分离，保存草稿不会改变正在运行或新发起任务使用的配置。历史扩展字段 `publishedConfiguration` / `publishedRelationship` 为可选字段；当前实现读取的是注册配置与团队关系，不是发布时冻结的快照，桌面不得据此宣称“与已发布版本比较”。旧服务未返回这些字段时仍可读取与保存草稿。

- 调用者：已登录的 Workbench Host；只有 Forge 已授予团队开发权限的账号可读取和保存。
- 身份：Weave 从当前会话取得主体和组织，成员必须属于请求中的团队。
- 并发与幂等：客户端提交已读取的 `revision`。同一修订只能成功保存一次；较旧修订返回 `409 draft_revision_conflict`，防止覆盖另一位开发者的修改。
- 输入与输出：草稿包含智能体身份与指令、模型和运行时、技能与工具、材料与输出约束、执行限制，以及该成员在团队中的职责和交接要求。Loom 成员只能从组织已经接入且有正式版本的模型中选择，不允许手填一个无法运行的模型；Loom 由 Weave 调度，不显示运行位置，只有桌面 CLI 成员需要选择运行位置。密钥、请求头和长期凭据不进入草稿投影。
- 生效边界：本接口只保存草稿。发布必须由独立的验证和发布动作生成不可变智能体版本；MVP1 第一步不提供发布动作。
- 错误与取消：成员或团队不存在返回 404；无开发权限返回 403；请求取消时未提交的事务不产生草稿。
- 审计：保存记录操作者、组织、团队、成员、修订和时间，不记录密钥或令牌正文。

## 业务能力目录

`business-capability-catalog.schema.json` 是 Weave 从已连接 Forge 环境生成、供开发中心选择的业务能力目录。开发者看到并分配的是“查看销售合同”“提交销售合同”这类中文能力，不是 MCP 服务器、`run_action` 等通用工具或底层参数。

- 来源：Forge 只发布明确允许智能体使用的业务动作；未标记为可用的对象动作默认不进入目录。
- 连接：管理员配置一次 Forge 服务连接。连接地址、认证方式和密钥属于环境配置，不进入成员草稿。
- 分配：开发者把能力分配给团队成员，草稿只保存稳定的 `businessCapabilityIds`。发布版本冻结成员允许的能力标识；运行开始时，Weave 再以本次员工委托读取当前 Forge 动作目录，冻结动作说明、记录要求和声明参数。
- 执行目标：成员通过既有能力桥直接调用 Forge MCP 的受控业务动作；按员工真实授权限定范围。“交给团队看看”不构成正式提交审批授权，已有明确授权不重复弹窗。运行终态通知由系统自动产生，不作为每个团队必配的业务工具。
- 身份目标：Workbench Host 安全保管桌面会话；远端成员通过任务级委托调用 Forge。Workbench 根据本次员工表达从团队已发布能力中选择零个或少量业务动作，Weave 校验子集并冻结。Weave 以当前员工委托读取 Forge 动作目录；目录不可见、动作不存在或参数不合法时关闭该能力，不退回到自由填写 `params`。每次实际动作前再核对当前运行任务、员工、输入版本、本次动作范围和委托有效期，Forge 最后检查员工、组织、业务记录和当前流程状态。长期会话不进入模型或团队输入，也不能用共享管理员身份替代。
- 权限：Forge 每次执行仍按员工账号、组织、业务记录和当前流程状态判断是否允许。Weave 的团队配置不能扩大 Forge 权限。
- MVP1：合同场景先提供查看销售合同、查看关联报价、读取合同材料和提交销售合同四项；后续能力由真实场景缺口驱动增加。
- 部署：连接认证由环境接入统一管理，不重复写进团队配置。远端业务能力与受限委托是本批前置项；具体身份传递方式须核实 ObjectStack 当前能力后补齐契约，不预设某种 OAuth 实现已具备。
- 错误与审计：目录不可用时保留成员已有选择并标明不可用，不静默删除；发现、分配和调用分别记录操作者、能力、团队、任务和结果，不记录凭据正文。

## 新建团队

`team-create.schema.json` 描述开发中心的最小新建输入。Workbench Host 根据名称和目标建立一个可继续编辑的团队，并同时建立“团队负责人”和“执行成员”两个初始成员，避免新团队再次落入无成员的死路。

- 调用者：已登录的 Workbench Host；向 Forge 已授予团队开发权限的账号开放。
- 输入：开发者只填写团队名称和目标；内部名称、成员标识和默认协作关系由 Host 生成，不在界面展示。
- 默认成员：负责人负责理解目标、分派与汇总；执行成员负责完成任务并返回可核验结果。两者创建后均可在成员配置区修改。
- 一致性：Host 依次建立两个成员和团队；团队建立失败时回收本次已建立的成员。服务端原子创建向导接入后，可在不改变界面契约的前提下替换该适配。
- 错误：同名、权限或连接错误显示为可操作的创建失败；失败时不把团队加入本地列表。

## 团队与成员管理

`team-management.schema.json` 描述开发者修改团队资料、添加执行成员和将成员移出当前团队的桌面输入。移出只结束当前团队关系，不删除成员的不可变版本、既有运行或审计记录。

`workflow-management.schema.json` 描述开发者保存工作流草稿、检查并发布版本或归档流程的桌面输入。桌面编辑的是 Weave 草稿图，保存不改变已发布版本；发布仍由 Weave 校验并冻结依赖。

- 修改团队使用读取时的更新时间防止覆盖并发修改；名称和目标必须在刷新后稳定读回。
- 添加成员同时建立一个可编辑的 Weave 智能体和团队关系；任一步失败时不能在团队中留下半成品成员。
- 负责人不能通过成员移出入口删除；执行成员移出后不再参与新任务，历史任务继续显示当时冻结的成员名称与版本。
- 所有写入由 Weave 会话中经过 Forge 验证的权限判断，Workbench 不在界面层伪造权限结果。

## 员工工作与人工交接

`work-request.schema.json` 在当前实现中由 Workbench Host 映射到 Weave 的固定输入版本和团队派发回执。每次独立工作使用新的 `workId`，原始说明摘要、团队、工作流和准确版本一并冻结；重复回执不能创建第二条运行。

`agent-team-handoff.schema.json` 描述 Host 验证桌面运行时轮次后保存的固定交接包（轮次凭据只在内存中，不写入包）。当前已实现部分使用现有输入登记与派发接口；后续业务闭环补 Forge MCP 动作及受限委托，继续复用现有运行时。

- 调用者为 Pi / Prime / OMP 扩展；只有 Host 持有 Forge / Weave 会话。账号绑定包含服务来源、组织、Forge 员工与 Weave 用户；账号切换、退出或过期后旧轮次失效。
- Host 在桌面员工输入进入运行时之前使旧轮次失效。扩展在实际处理员工输入时领取该轮次凭据；工具调用只携带该凭据。Host 对照原会话中该轮次的真实员工消息和顺序，不将后来补充的消息替换为原授权依据。意图由 Pi 理解，不加关键词判断或固定确认弹窗。
- 搜索只读取可见团队的名称和目标，使用工作摘要进行词项相关性筛选；这是文本检索，语义判断仍由 Pi 完成。仅查看所选团队时读取其流程。接什么、需要什么、交付什么复用团队目标和流程说明，不强制增加结构化表单。
- Pi 明确指定本次材料路径及所见文件的 SHA-256。Host 限定在当前工作目录内读取 UTF-8 文本、Markdown、CSV、JSON、可提取文本的 PDF 与 DOCX，并以原始字节 SHA-256 冻结确切原件。原件每份最多 2 MiB、每次最多 8 MiB；提取文本合计最多 700,000 字节，最终 Weave `task` 最多 950,000 字节。三个预算独立核算，超限在上传/登记前拒绝，不默默截断。扫描 PDF 页、DOCX 嵌入图像及未支持内容明确记录 `partial` / `unsupported`，列出缺失页或内容数量；仅 `complete` 表示提取器已读到其声明覆盖的全部文本，不表示 OCR 或视觉内容已识别。
- `agent-team-handoff.schema.json` 描述桌面安全存储中的冻结包。每项 `materials` 使用 `materialId`、原件 `name/mediaType/bytes/sha256`、本地恢复所需的 `bytesBase64` 和提取记录 `extraction {status, mediaType, bytes, sha256, sourceSha256, content, extractor, coverage, limitations}`；`extraction.sourceSha256` 必须等于原件 `sha256`，提取摘要按 UTF-8 字节计算。原始 Base64 仅写入桌面加密固定意图，绝不放入 `work-request`、Weave `task`、模型输入或日志。发送给 Weave 的材料清单只含 `materialId`、Forge 文件引用、原件 MIME/长度/SHA 及提取状态/摘要/正文。
- Workbench 仍通过 ObjectStack storage presigned upload 的 `scope=attachments` 上传原件原始字节，不对 PDF/DOCX 做 UTF-8 解码/重编码；上传回执以 `materialId`、文件 ID、MIME、长度和 SHA 固定。Weave 的 `task` 提供与原件 SHA 绑定的提取文本及覆盖状态，运行成员可直接阅读；文件引用指向 Forge 中的原件供有权业务参与者查看。文本继续使用 `owned-text-material`。PDF/DOCX 原件通过 `GET /api/v1/workbench/materials/{fileId}/original` 读取未改写的 HTTP body，要求 `If-Match` 携带冻结的 SHA-256；Forge 只允许当前员工读取本人同组织、private、未绑定且已提交的 `scope=user|attachments` 文件，读取前核对元数据、MIME、长度、文件签名和原始字节 SHA。审批材料另用 `GET /api/v1/approvals/requests/{requestId}/workbench-context/files/{fileId}/original`，只允许当前待办审批人或未重提退回请求的原提交人，且 fileId 与 If-Match 必须和本次原生审批快照一致。两条原件路由均只支持 PDF/DOCX、单件不超过 2 MiB，返回原始字节及 `Content-Type`、`Content-Length`、`ETag`/`X-Content-SHA256`，设置 `Cache-Control: private, no-store`；不在 JSON、`approval-context.files`、Weave `task` 正文、模型输入或日志传输原件字节、Base64 或裸存储 URL。[owned-original-material](owned-original-material.schema.json) 冻结 `sourceKind=owner|approval`；`approval` 必须携带 `requestId`，`owner` 不得携带该字段。读取方只能按冻结来源调用对应原件路由，不得因 404 或状态冲突改试另一条路由。旧文本内容接口保持原样。owner 原件路由未登录返回 401，文件不存在或非本人所有返回 404，缺少或格式错误的 If-Match 返回 428，摘要不符返回 409，大小超限返回 413，MIME 不支持返回 415，元数据或签名无效返回 422，Storage 不可用返回 503。材料缺失、归属不符、快照失效、SHA 不符、MIME 不支持、字节签名不符或安全存储不可用时，停止交接；恢复只使用加密固定意图，不重新读取已变化文件。账号、消息、会话、目标、准确团队流程版本、本次动作范围和材料版本共同冻结。
- owner 原件读取未登录返回 401，文件不存在或非本人同组织、private、未绑定原件返回 404；缺少或格式错误的 If-Match 返回 428，SHA 不符返回 409，超限返回 413，MIME 不支持返回 415，元数据或签名无效返回 422，Storage 不可用返回 503。成功读取审计员工、组织、fileId、MIME、字节数和 SHA-256，不记录原文或请求凭据。
- 合同正式提交使用 Forge 动作 `contract_submit_frozen_material`，只接受准确合同记录以及本次 `forge-file` 的文件标识、名称和 SHA-256。Forge 把文件保存为合同的“本次提交版本”，并为合同建立唯一首次提交记录；同一材料重放返回原提交结果，另一材料竞争同一首次提交返回冲突。普通页面不把文件 UUID 或摘要当作业务编号展示。
- Host 以账号、会话、真实员工轮次与团队流程版本产生合法 UUID，首次发送前以受保护文件原子保存固定请求；相同请求重用同一请求体，并发合并。相同幂等键更换目标或材料版本须报冲突，不能覆盖。重试读取冻结包，不重新生成会话摘要或重读文件。
- `/v1/workbench/dispatch-inputs` 回执须匹配固定任务摘要，再调用 `/v1/teams/:id/dispatch`；每次网络发送前重新验证轮次与账号，使用已绑定账号的请求头。回执须包含输入版本、客户端请求、运行、任务与准确流程版本。网络失败保留包，显式重试用同一 UUID；没有有效回执只能报告结果未知。
- 新员工输入撤销尚未派发的旧交接，不自动重试。已经进入服务端的派发无法靠本地撤销保证回滚，需核对原回执并按现有运行取消语义处理；不能宣称“先别发”撤回了已接单任务。
- 交接成功只表示 Weave 已按固定版本接单，不代表智能体完成审阅或 Forge 业务审批通过。审计保留材料摘要和服务端关联标识，普通员工只看到业务名称、状态及材料名称。

`task-notification.schema.json` 是待与原生能力对齐的桌面展示投影草案，不要求新增持久化对象；描述 Forge 面向员工提供的工作事项投影，不绑定合同、审批或某一种业务对象。Weave 继续拥有团队运行与局部重跑状态；Forge 负责员工账号、事项归属、未读通知和员工续办状态；桌面合并显示两边的权威状态。

`team-run-event.schema.json` 是平台自动连接团队运行与员工收件箱的写入契约。调用者固定为 Weave 服务，不是团队成员或模型工具；Forge 以部署级服务凭据验证调用方，并把 `assigneeAccountId` 作为现有 ObjectStack 账号解析，不能由模型猜测接收人。事件只承载运行结果、失败、取消或需要补充的摘要及返回桌面的定位信息，不执行合同提交、审批或其他业务动作。

- 身份：Weave 从发起时已经绑定的 Forge 外部身份冻结接收账号和组织；运行结束后不得改用当前登录用户或共享管理员账号。
- 幂等：`eventId` 与 `source.idempotencyKey` 由准确运行和终态生成。相同键重复投递返回原通知；相同键更换内容返回冲突。
- 交付：Weave 先将待投递事件写入自己的系统事件 outbox，再异步调用 `POST /api/v1/apps/forge/weave-events/team-runs`。Forge 接入 ObjectStack `messaging.emit`，由其原生通知 outbox 完成收件箱写入、重试和去重。
- 失败与恢复：网络失败、`429` 和 `5xx` 留在 Weave outbox 并退避重试；`400`、`401`、`403` 和接收账号不存在属于永久配置错误，保留失败记录供运维恢复，不伪装成员工待办。Weave 重启扫描未完成事件，也会为尚未生成事件的已终态 Workbench 运行补建事件。
- 取消：运行尚未终结时不发送完成通知；终态事件一经 Forge 接收不删除。后续恢复或重跑产生新的运行和新事件，并通过工作引用保持上下文关系。
- 审计：两端记录事件、运行、工作、组织、目标账号、尝试次数和最终交付状态；不记录服务凭据、员工密码、Forge 会话或合同正文。

## Forge 原生审批上下文

`approval-context.schema.json` 定义 Workbench 打开单个 ObjectStack 原生审批时读取的受限展示上下文。Workbench 继续从原生审批列表读取本人事项，审批人仍用原生 approve/reject/revise 路由办理；退回后的修订递交必须经下文的材料绑定动作，不让桌面直接调用原生 resubmit。该读取契约不建立第二套待办或审批状态。

- 调用者是持有效 Forge 员工会话的 Workbench Host；员工账号从已验证的 Bearer 会话取得，不接受调用方传入 `userId`、岗位或受理人。
- 路径为 `GET /api/v1/approvals/requests/{requestId}/workbench-context`。Forge 必须先用 ObjectStack 原生 ApprovalsService 校验当前主体；`pending` 只向当前待处理 approver 返回，`returned` 只向原始 submitter 返回。已经办完的历史参与者、管理员覆盖权限均不因本只读接口获得材料上下文。
- 返回内容限于该审批请求冻结的字段快照、展示标签、退回意见、该快照明确绑定的文本文件，以及可选的 `originalFiles` 元数据。文本文件保持在 `files`；PDF/DOCX 只在 `originalFiles` 返回 [owned-original-material](owned-original-material.schema.json) 的 `sourceKind/fileId/name/mediaType/bytes/sha256`；审批来源另含 `requestId`，不返回 `content`、Base64 或预签名 URL。文件标识必须属于此请求的固定主件/附件版本，返回前核对其 SHA-256。供 Host 续办的 `businessObject` 来自原生请求的 `object_name`/`record_id`，`sourceMaterialVersion` 是冻结 payload 按 JSON 对象键递归排序、UTF-8 编码后的 SHA-256，文件 `fileId` 来自原请求快照；这些内部标识不在产品页面展示。`returnVersion` 是最新 `revise` 动作 ID，和同一动作的 `returnReason` 一起投影。任一必需来源缺失时不得准备修订提交，不从标题、消息正文或当前合同记录猜测。不得以提交岗位权限为由开放通用合同/附件读取。
- 二进制读取路径为 `GET /api/v1/approvals/requests/{requestId}/workbench-context/files/{fileId}/original`。Forge 每次请求重新从 Bearer 会话与 ObjectStack `ApprovalsService` 解析员工，只允许 `pending` 当前 approver 或 `returned` 原提交人；退回请求一旦被重提即返回 `409`，不允许读取旧轮次。`fileId` 必须在该 request 的冻结主件/附件字段集合中，`If-Match` 必须与冻结 SHA 完全一致；审批字段只读范围不会扩大为任意合同/附件读取。原始响应仅接受 PDF/DOCX 且每件最多 2 MiB，回传字节前核对记录引用关系、MIME、长度、签名和 SHA；设置 `Cache-Control: private, no-store`、`Content-Disposition: attachment`、`ETag` 和 `X-Content-SHA256`。未登录返回 401；未参与、不存在或不在本次快照中的文件统一 404；缺少或格式错误的 If-Match 返回 428；快照缺少冻结 SHA、字节/元数据无效返回 422；快照或摘要已变化返回 409；格式不支持 415；超限 413；存储不可用 503。原件不放进上下文 JSON 或审计日志。
- 非当前参与者或不存在的请求统一返回 `404 approval_context_not_found`，避免探测事项存在性；已变化的状态返回 `409 approval_context_stale`；认证失败返回 `401`；超限或不支持的材料返回 `413` / `422`。该读取无服务端副作用，无幂等键。
- Forge 审计员工、组织、requestId、读取结果和文件标识/摘要，不记录正文。二进制原件读取必须提供 If-Match；缺少或格式错误返回 428，快照 SHA 与 If-Match 不一致返回 409。读取成功时仅审计员工、组织、requestId、fileId、字节数、SHA-256 和结果，不记录字节、Base64、令牌或业务正文。Workbench 在 UI 展示前仍校验输入账号代次；不把返回正文写进日志、调试遥测或团队定义。
- 此上下文只读，不批准、不驳回、不更改业务记录。

### 退回后的材料递交

Workbench Host 只在原提交员工打开 `returned` 事项、Pi 根据其明确意图准备好新版本后调用 Forge 修订业务动作。Host 在首次网络发送前原子冻结当前账号、Pi 实际处理的员工轮次、`requestId`、`returnVersion`、`sourceMaterialVersion`、`businessObject`、完整主件与附件字节及各自 SHA-256、允许动作和 UUID 幂等键；断线恢复只读该包，不能重新采样变化的文件或会话。账号切换、员工说“先等等”、事项状态变化或新一轮退回使尚未提交的旧意图失效。模型不得提供操作者 ID、记录 ID、审批状态或自行选择文件 ID。

Forge 从当前员工会话和原生审批请求重新取得操作者及业务对象，核对该员工为最新退回请求的原提交人、本次 `returnVersion` 仍是最新退回动作、源快照未变、全部新文件已提交且字节/摘要/归属相符。Forge 的领域规则决定主件、附件及字段如何形成新材料版本；合同只是其中一种规则。相同幂等键与同一冻结包返回同一回执，换内容返回冲突；同一退回轮次不能并发绑定两个版本。明确的 `pending`、`committed`、`unknown` 回执要能按幂等键核对，未知结果先查询再决定是否恢复，不盲目重放业务写入。

ObjectStack 原生 ApprovalService 的所有 resubmit 入口必须在写审批动作前校验 Forge 产生的材料绑定；没有绑定、绑定过期、材料已变化或原提交人不符时拒绝，原审批状态和流程保持不变。绑定消费与审批动作写入须在同一数据库事务中确定结果。原生自动化恢复是事务后的另一阶段，须沿已有流程运行回执按同一幂等键核对并可安全续跑；数据库提交成功但恢复结果未知时不能写成“未提交”，也不能盲目执行第二次审批动作。恢复后下一轮审批请求读取新材料快照，旧轮次快照及意见保留。桌面不能调用原生 resubmit 路由绕过业务校验；Forge 不另建审批状态机或调度器。网络取消只停止尚未提交的本地准备或等待；若业务动作已提交，必须核对回执，取消 Weave 运行不撤销 Forge 结果。审计记录账号、组织、原请求与新请求、业务对象、源与新材料摘要、幂等键、动作结果及时间，不记录合同正文或长期凭据。**上述递交接口与原生守卫仍在实现中，不能把本契约当成已部署能力。**

当前候选的准确接口为 `POST /api/v1/approvals/requests/{requestId}/workbench-revision`，请求体遵守 `approval-revision.schema.json`：`returnVersion`、`sourceMaterialVersion`、UUID `idempotencyKey`、一份 `primary` 和至多十份 `attachments`，每份只携 Forge `fileId`、名称及 SHA-256。Host 必须先用原有 Forge 文件上传能力传递已冻结的真实字节；Forge 从会话取员工、从原生请求取业务对象，重新下载文件核对归属、长度、UTF-8 和 SHA，单件不超过 2 MiB、总量不超过 8 MiB。`GET /api/v1/approvals/requests/{requestId}/workbench-revision/{idempotencyKey}` 只读核对原员工的回执。`resumed` 表示已观察到下一轮请求；`prepared` 表示新材料已固定但原生动作尚未确认；`resume_unknown` 表示动作已写但下一轮未观察到。只有 `resumed` 可向员工称为递交成功；其余状态不得自动重放原生动作。

当前候选中同键同材料重试返回原绑定，换材料报 `409`；账号无权或事项不存在返回 `404`，过期轮次 `409`，文件校验失败 `422`，输入超限 `413`，服务暂不可用 `503`。这条接口由 Forge 插件填补原生能力缺口；Weave 团队正常的 Forge 业务动作继续通过 ObjectStack MCP `run_action`，不为续办另造团队调度。**限制：** 当前插件的准备记录与原生审批动作尚不能作为一个跨自动化恢复的原子操作；首次调用若在动作前失败，回执保留 `prepared` 且不会自动重试；多进程同时递交和真实数据库恢复尚未验收，C06 不能关闭。文件上传回执丢失时可能留孤立文件，仍由 N01 处理。

- `result`、`failure` 是通知，告知发起员工团队运行的终态，不要求 Pi 持续等待或轮询。
- `revision_required`、`human_review` 是可操作事项。它们必须指向同一笔原工作、明确材料版本、退回原因、责任员工、返回位置和复核范围；被指派员工打开事项后，桌面才把这些上下文交给该员工的 Pi。
- 正式业务提交前，智能体团队发现材料问题，以 Weave“需要补充”运行结果及系统事件返回原员工，不创建 Forge 修改事项。进入正式业务流程后，人类员工退回或业务规则要求补件，才通过 Forge 受控动作与原生审批形成可办理事项。合同只是首个验证场景，不改变这两个阶段的职责；具体实现缺口见阶段问题清单，不因契约写明而视为已完成。
- 退回后的新材料形成新版本，保留父事项和原运行引用。默认回到原复核位置；能够证明只影响部分成员时可请求局部重跑，实际执行范围仍由 Weave 校验。
- 创建和状态更新使用 `source.idempotencyKey` 去重。重复投递不产生第二个员工事项；并发办理必须由 Forge 的记录版本检查拒绝旧写入。
- Weave 的现有人工节点仍可作为团队运行中的同步等待点，但不再承担所有员工工作入口。处理员工以自己的身份办理，不能借此替换原任务执行主体或取得发起人的长期凭据。

2026-09-22 方向纠偏：已有 `create_employee_work_item` 签名 webhook 与通用事项对象为未验收试验，不再作为本链路的目标调用契约或部署前提。团队主动发起的修改、复核与提交通过 Forge MCP 业务能力完成；系统运行事件另行自动接入原生收件箱。具体 MCP 工具名、受限委托、原生事项映射、幂等回执查询及错误/取消/审计字段，须在原生能力核验后补齐并验证；当前 schema 或接口存在不代表此链路已接通。

## 审批退回与材料版本

### 本次对象绑定与续办的共同约束

调用者为受信任的桌面 Host，身份来自当前 Forge/Weave 登录及实际员工轮次。Host 在冻结包中保存 `businessContext`，登记固定输入时发送 `business_record: { object_name, record_id }`；不得从远端成员生成的任务正文反推授权对象。首批每次工作最多绑定一条业务记录，无对象的分析/创建动作可以不传。记录绑定表示本次操作范围，不等于记录内容版本或业务权限授权。

- Weave 将对象绑定计入整个登记请求的摘要，并在现有任务委托 `resources` 内保存 `forge-record`（`id`、`object_name`、二者规范 JSON 的 `sha256`）。不新增任务库或授权引擎。相同登记 UUID 更换对象返回 `409 input_registration_conflict`，不得刷新为另一个对象。
- 实际业务工具由 Forge 目录的 `requiresRecord` 决定是否必须绑定记录。必须绑定却缺失或对象类型不匹配时停止构建工具；运行时将冻结记录注入 `run_action.recordId`。模型省略该参数即可执行；显式传入另一记录在网络写入前拒绝。明确声明无需记录的动作不获得 `recordId`，即使同一任务为其他动作绑定了记录，模型也不能另填。Forge 在实际执行时仍校验员工权限及当前状态。
- Host 的业务查找没有正相关候选就返回未找到；有候选也仅供 Pi 根据员工上下文选择，不因只有一条而擅自确定对象。查找仍不等于员工最终意图正确性已被证明。
- 新员工输入或切换账号使尚未交付的旧轮次及其异步能力目录失效；已进入服务端的动作只能核对回执，取消不等于撤销。恢复原包仍须当前员工明确继续原版本，不能替换绑定对象。
- 审计沿用输入版本、员工、动作、登记摘要、运行及回执关联。模型提示、通知正文和工具调用文本均不是新的授权来源，不写入凭据。

版本、续办和工具参数必须共同满足：打开原事项取得最新业务状态及允许动作，办理时引用本次固定输入，修订形成新版本而恢复保留旧版本。此处首批只实现记录标识约束；文件参数保护、业务记录并发版本、完整主件附件包和结构化参数表达仍属于 C02/C05/C11，不能据此关闭这些问题。总仓桌面与 Weave 源码候选需配套部署；旧服务不识别新字段时明确失败，不降级成正文提示。

- Forge 原生审批请求及其动作历史是审批意见、处理人和状态的权威来源。桌面按当前员工身份读取本人待办；退回时读取 `GET /api/v1/approvals/requests/{id}/actions` 的最新 `revise` 意见，打开事项后再读取请求快照和有权访问的文件。通知仅用于提醒，不替代审批请求。
- 销售修订合同包时，必须明确绑定主合同和所有待复核附件。每份文件固定 Forge 文件标识、名称和 SHA-256；Forge 校验员工、合同、退回审批和文件归属后保存新材料清单。桌面始终不能直接调用原生 `resubmit`；Forge 材料动作经原生守卫原子继续审批。
- 修订绑定重复调用同一清单返回原结果；同一修订轮次更换清单必须显式报冲突。原生审批只接受原提交员工的受信任身份与有效绑定，ObjectStack 建立下一轮请求并重新解析审批人。旧轮次意见和文件保持可读，不覆盖旧快照。
- 桌面交给 Pi 的是当前员工可见的退回意见、业务字段及经摘要校验的文件正文。跨账号切换必须隔离本地会话与工作目录；仅隐藏旧会话列表不足以保护 Pi 的文件读取范围。
